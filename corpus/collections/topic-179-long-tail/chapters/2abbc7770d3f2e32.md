# Audit Governance Ontologies in Relational Schema Form

This chapter presents four ontological templates that formalize audit processes over datasets and directive controls. The templates are realized as a four-table relational schema in which primary and foreign keys encode the subclass and existential restrictions. The resulting structure supports multi-hop queries that recover the dataset under audit, the conducting person, the period, and the control directive being examined.

## 1. Ontological Templates and Table Projections

Four Manchester OWL axioms are projected to tables. Each table name corresponds to one template identifier. Column `x` always holds the subject class of the axiom; additional columns capture the object of the existential restriction when present. Foreign-key columns enforce the participation constraints stated in the axioms.

### 1.1 Dataset Under Audit

Axiom 2 states that a dataset is an artifact that participates in an audit process. Table `t_dataset_under_audit` therefore contains only the identifier of the dataset and its label. The single-column primary key `id` serves as the target for foreign-key references from period-linking rows.

```sql
CREATE TABLE t_dataset_under_audit (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| DS-001 | FinancialControlsQ2 |
| DS-002 | SupplierQualityRecords |
| DS-003 | EnvironmentalMetrics2023 |
| DS-004 | AccessControlLogs |
| DS-005 | InventoryValuation |

### 1.2 Audit for Period

Axiom 1 asserts that an audit process is defined for a specific audit period that references a dataset. Table `t_audit_for_period` therefore carries a foreign key `y` to `t_dataset_under_audit.id`. The primary key `id` identifies each period-specific audit instance.

```sql
CREATE TABLE t_audit_for_period (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_dataset_under_audit(id)
);
```

| id | x | y |
|----|---|---|
| AP-1001 | AuditPeriodQ2-2024 | DS-001 |
| AP-1002 | AuditPeriodQ2-2024 | DS-002 |
| AP-1003 | AuditPeriodFY2023 | DS-003 |
| AP-1004 | AuditPeriodQ1-2024 | DS-004 |
| AP-1005 | AuditPeriodQ3-2024 | DS-005 |

### 1.3 Audit Conducted By

Axiom 3 states that an audit process is conducted by a person. Table `t_audit_conducted_by` records the person identifier in column `x`. The primary key `id` permits later linkage to period rows when a full audit instance is assembled.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| ACB-7001 | J. Grant |
| ACB-7002 | D. Maher |
| ACB-7003 | L. Svensson |
| ACB-7004 | R. Patel |

### 1.4 Audit Subclass

Axiom 4 defines an audit subclass that audits a control directive information content entity. Table `t_audit_subclass` stores the directive label in column `x`. The primary key `id` allows the same audit instance to be referenced from other tables when the control scope must be recovered.

```sql
CREATE TABLE t_audit_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| ASC-4001 | ISO27001-A.5.1 |
| ASC-4002 | ISO27001-A.8.2 |
| ASC-4003 | ISO14001-6.1.2 |
| ASC-4004 | SOX-404 |
| ASC-4005 | GDPR-Art.32 |

## 2. Cross-Table Query Example

A multi-hop question is answered by successive key lookups. Consider the query: “Which person conducted the audit of dataset DS-001 during period AP-1001 and which control directive was examined?”

- Start at `t_audit_for_period` row AP-1001; foreign key `y` yields DS-001.
- The same row’s `id` is matched against `t_audit_conducted_by.id` (via an external join table or view that associates the audit instance) to obtain J. Grant.
- The identical `id` is matched against `t_audit_subclass.id` to obtain ISO27001-A.5.1.

Resulting joined row:

| audit_id | dataset | period | conducted_by | directive |
|----------|---------|--------|--------------|-----------|
| AP-1001 | FinancialControlsQ2 | AuditPeriodQ2-2024 | J. Grant | ISO27001-A.5.1 |

The same pattern extends to any other combination of period, dataset, person and directive by traversing the four primary-key/foreign-key links.
