# Chapter 4: Audit Process Ontologies Projected to Relational Schemas

This chapter defines four tables that realize the axioms audit_for_period, dataset_under_audit, audit_conducted_by and audit_subclass. The tables support cross-table joins that recover multi-hop facts such as the dataset audited in a given period, the person who conducted the audit, and the directive subclass under examination.

## 1. Table t_dataset_under_audit

Axiom 2 states that any instance of t_dataset_under_audit is an artifact placed under an audit process. Column id is the primary key. Column x holds the class reference that satisfies the Manchester restriction. No foreign keys are present.

| id | x |
| --- | --- |
| DS-001 | Q2_FY24_Shareholder_Update |
| DS-002 | Ashland_Water_Commission_Minutes_2016-08-16 |
| DS-003 | EB-2012-0246_Embedded_Generation_Comments |
| DS-004 | NOACC_Cost_Submission_Jan2013 |
| DS-005 | Walli_OEB_Jan25-13_MEGC |

## 2. Table t_audit_for_period

Axiom 1 states that an audit process is defined for a specific audit period realized by a dataset. Column id is the primary key. Column y is a foreign key referencing t_dataset_under_audit.id. Column x records the period class.

| id | x | y |
| --- | --- | --- |
| AP-010 | Period_Q2_FY24 | DS-001 |

## 5. Cross-join demonstration

To determine the person who conducted the audit of the Q2 FY24 shareholder update and the directive subclass examined, join t_audit_for_period to t_dataset_under_audit on y = id, then join the resulting audit identifier to t_audit_conducted_by and t_audit_subclass on matching id prefixes.
