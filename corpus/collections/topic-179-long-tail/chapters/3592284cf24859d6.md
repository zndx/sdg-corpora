# Chapter 4: Directive Governance Ontologies in Audit Trail Systems

This chapter introduces four ontological templates that formalize audit processes over artifacts and directives. The templates are realized as a four-table relational schema drawn from compliance auditing of corporate disclosures and conference submissions. Primary and foreign keys enable traversal from audit instances to datasets, responsible persons, and control directives.

## 1 Dataset Identification

Table t_dataset_under_audit embodies axiom 2. Column id is the primary key naming each artifact placed under audit; column x records the concrete class of the artifact. No foreign keys exist because the table serves as the root reference for subsequent linkage tables.

| id | x |
| --- | --- |
| DS-001 | Q2_FY24_Shareholder_Update |
| DS-002 | RTNS_2019_Proceedings |
| DS-003 | EcoSolar_Home_Tour_Report |
| DS-004 | Windsor_Park_Energuide_Record |

## 2 Audit Period Linkage

Table t_audit_for_period embodies axiom 1. Column id is the primary key for each period linkage; column x identifies the audit process; column y is a foreign key referencing t_dataset_under_audit.id. A reader can therefore retrieve every dataset that participates in a given audit period by joining on y.

| id | x | y |
| --- | --- | --- |
| AP-010 | Audit_Q2_Restructure | DS-001 |
| AP-011 | Audit_RTNSSubmission | DS-002 |
| AP-012 | Audit_NZE_Home | DS-003 |
| AP-013 | Audit_Energuide | DS-004 |
| AP-014 | Audit_Q2_Financials | DS-001 |

## 3 Conductor Assignment

Table t_audit_conducted_by embodies axiom 3. Column id is the primary key for each assignment; column x names the person conducting the audit process. The table supplies the agent dimension required for governance traceability and can be joined to t_audit_for_period via shared audit identifiers when extended with an audit reference column in operational use.

| id | x |
| --- | --- |
| ACB-100 | John_Grant |
| ACB-101 | Danny_Maher |
| ACB-102 | De_Waal_Developments |
| ACB-103 | RTNS_Program_Chair |

## 4 Subclass Control Audit

Table t_audit_subclass embodies axiom 4. Column id is the primary key for each subclass instance; column x records the directive information content entity being audited. The table distinguishes specialized audit controls from generic processes and supports joins that verify which directives apply to a given dataset.

| id | x |
| --- | --- |
| ASC-200 | Organisational_Restructure_Directive |
| ASC-201 | RealTime_Networks_Policy |
| ASC-202 | NetZero_Energy_Standard |
| ASC-203 | Energuide_Reporting_Control |

## 5 Multi-Hop Query Example

To answer “which person conducted the audit of the Q2 shareholder update under the organisational restructure directive,” begin at t_dataset_under_audit row DS-001, follow foreign key y in t_audit_for_period row AP-010 to locate audit identifier Audit_Q2_Restructure, then locate the matching conductor John_Grant in t_audit_conducted_by and the directive Organisational_Restructure_Directive in t_audit_subclass. The joined result row is therefore (DS-001, Audit_Q2_Restructure, John_Grant, Organisational_Restructure_Directive).
