# Audit Processes in Parish Governance Records

This chapter defines five relational tables that instantiate OWL axioms for audit processes. The tables support cross-table queries that trace periods, evidence, conductors, signers, and findings through shared entity references.

## 1. Scope and Table Construction

The tables embody the five supplied axioms. Each table uses an opaque surrogate primary key in column `id`. Columns `x` and `y` hold entity references that function as foreign keys when they match primary-key values in other tables of the same schema. Four to eight rows per table supply sufficient instances for multi-hop joins while remaining compact.

### 1.1 Table t_audit_for_period

This table directly realises axiom `audit_for_period`. Column `id` is the primary key; columns `x` and `y` are foreign-key references to audit-process and period entities respectively.

## 2. Cross-Join Example

To determine the evidence items and findings associated with the audit conducted by a given person for period Q4-2023, join `t_audit_for_period`, `t_verification_min_one_evidence`, and `t_audit_with_findings` on the shared process identifier in column `x`:

```
SELECT afp.x, afp.y AS period, vme.y AS evidence, awf.y AS finding
FROM t_audit_for_period afp
JOIN t_verification_min_one_evidence vme ON afp.x = vme.x
JOIN t_audit_with_findings awf ON afp.x = awf.x
WHERE afp.y = 'Q4-2023';
```

Result rows:

- FinancialAudit-2023 | Q4-2023 | BankStmt-001 | Finding-Overdue
- FinancialAudit-2023 | Q4-2023 | Receipt-003 | Finding-Overdue
- ComplianceAudit-2023 | Q4-2023 | Minutes-001 | Finding-Minutes
