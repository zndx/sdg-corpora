# Chapter 4: Directive Governance Processes in Audit Trails

This chapter defines five core ontological patterns for audit processes grounded in BFO process classes. Each pattern is projected to a dedicated relation whose columns capture the required slot fillers. The resulting schema supports cross-table joins that recover multi-hop facts such as the period, conductor, evidence, signatory and findings of any given audit instance.

## 1. Audit Period Relation

Axiom 1 states that an audit process exists for a designated audit period. Table t_audit_for_period therefore records the pairing of process identifier (column x) with period identifier (column y). Column id is the surrogate primary key; column y functions as a foreign key to any period registry.

```sql
CREATE TABLE t_audit_for_period (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

Example rows:

| id | x | y |
|----|----|----|
| ap1 | AUD-2024-001 | PER-2023-Q4 |
| ap2 | AUD-2024-002 | PER-2024-Q1 |
| ap3 | AUD-2024-003 | PER-2024-Q1 |
| ap4 | AUD-2024-004 | PER-2024-Q2 |

## 2. Evidence Production Relation

Axiom 2 requires every verification process to produce at least one evidence item. Table t_verification_min_one_evidence stores the process-to-evidence link. Column id is the primary key; column y references an evidence registry and satisfies the minimum-cardinality constraint when joined with the evidence table.

```sql
CREATE TABLE t_verification_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

Example rows:

| id | x | y |
|----|----|----|
| ve1 | AUD-2024-001 | EV-LOG-881 |
| ve2 | AUD-2024-001 | EV-MIN-112 |
| ve3 | AUD-2024-002 | EV-LOG-903 |
| ve4 | AUD-2024-003 | EV-MIN-117 |
| ve5 | AUD-2024-004 | EV-LOG-927 |

## 3. Conductor Relation

Axiom 3 asserts that an audit process is conducted by a person. Table t_audit_conducted_by therefore records the process-to-person assignment. Column id is the primary key; column x is the foreign key to the audit process.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 4. Attestation Signatory Relation

Axiom 4 requires every attestation process to be signed by at least one person. Table t_attestation_min_one_signer records the required signatory link. Column id is the primary key; column x references the attested process.

```sql
CREATE TABLE t_attestation_min_one_signer (
  id VARCHAR(255),
```

## 5. Findings Relation

Axiom 5 states that an audit process may possess findings. Table t_audit_with_findings captures each process-to-finding pair. Column id is the primary key; column y is a foreign key to the findings registry.

```sql
CREATE TABLE t_audit_with_findings (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 6. Cross-Join Demonstration

To retrieve the period, conductor, evidence items and findings for audit AUD-2024-001, the following equi-join path is used:

t_audit_for_period.x = t_audit_conducted_by.x  
t_audit_for_period.x = t_verification_min_one_evidence.x  
t_audit_for_period.x = t_audit_with_findings.x  
t_attestation_min_one_signer.x = t_audit_for_period.x
