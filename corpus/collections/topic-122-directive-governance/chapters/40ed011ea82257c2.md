# Chapter 4: Modeling Process Observations in System Audit Trails

This chapter presents a relational schema for representing process observations, event timings, and operator constraints drawn from an OWL ontology fragment. The model supports queries that traverse participant artifacts, temporal markers, and PID observations while respecting cardinality restrictions on operators.

## 1 Scope and Domain Selection

The chosen domain is operating-system audit logging with eBPF instrumentation. Tables record observations of processes, their start times, trace spans, assigned operators, and observed process identifiers. All column values are instances of the slot types declared in the source axioms.

## 2 Table Definitions and Axiom Embodiment

### 2.1 t_observation_with_participant

This table embodies AXIOM 1 by recording classes that are subclasses of bfo:0000015 and participate in an artifact. Column id is the primary key; column x holds the participant class reference.

```sql
CREATE TABLE t_observation_with_participant (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id   | x          |
|------|------------|
| obs1 | proc_4721  |
| obs2 | proc_4819  |
| obs3 | evt_3902   |
| obs4 | proc_5033  |

### 2.2 t_process_max_one_operator

This table embodies AXIOM 4 by asserting that each process has at most one operator. Column id is the primary key; column y is a foreign key referencing t_observation_with_participant(id).

```sql
CREATE TABLE t_process_max_one_operator (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_observation_with_participant(id)
);
```

Example rows:

| id    | x         | y    |
|-------|-----------|------|
| pmo1  | proc_4721 | obs1 |
| pmo2  | proc_4819 | obs2 |
| pmo3  | evt_3902  | obs3 |
| pmo4  | proc_5033 | obs4 |

### 2.3 t_schemaorg_event_starttime

This table embodies AXIOM 2 by attaching an event start time class to an artifact. Column id is the primary key; column y is a foreign key referencing t_observation_with_participant(id).

```sql
CREATE TABLE t_schemaorg_event_starttime (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_observation_with_participant(id)
);
```

Example rows:

| id   | x          | y    |
|------|------------|------|
| est1 | 2023-11-02T08:14:00Z | obs1 |
| est2 | 2023-11-02T08:17:22Z | obs2 |
| est3 | 2023-11-02T08:19:05Z | obs3 |
| est4 | 2023-11-02T08:21:41Z | obs4 |

### 2.4 t_trace_subclass

This table embodies AXIOM 3 by linking a trace subclass to a process that has a single operator. Column id is the primary key; column y is a foreign key referencing t_process_max_one_operator(id).

```sql
CREATE TABLE t_trace_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_process_max_one_operator(id)
);
```

Example rows:

| id   | x         | y    |
|------|-----------|------|
| tr1  | span_01   | pmo1 |
| tr2  | span_02   | pmo2 |
| tr3  | span_03   | pmo3 |
| tr4  | span_04   | pmo4 |

### 2.5 t_ebpf_event_observed_pid

This table embodies AXIOM 5 by recording eBPF events that observe a specific PID. Column id is the primary key; column y is a foreign key referencing t_process_max_one_operator(id).

```sql
CREATE TABLE t_ebpf_event_observed_pid (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_process_max_one_operator(id)
);
```

Example rows:

| id   | x         | y    |
|------|-----------|------|
| eep1 | pid_4721  | pmo1 |
| eep2 | pid_4819  | pmo2 |
| eep3 | pid_3902  | pmo3 |
| eep4 | pid_5033  | pmo4 |
