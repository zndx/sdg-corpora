# Modeling HIPAA and PCI DSS Directives as OWL Subclasses of cco:DirectiveICE

This chapter presents five OWL axioms that classify administrative, physical, and technical safeguards together with PCI DSS requirements. Each axiom is realized as a table whose rows are individuals or classes satisfying the Manchester syntax restrictions. Primary keys identify the directive instances; foreign keys encode the quantified object-property links, permitting cross-table joins that recover multi-hop inferences such as “which control addresses a given threat and simultaneously satisfies an administrative HIPAA safeguard.”

## 1. Axiom Structure and Table Layout

All five tables share the column pattern (id, x, y). Column id is the surrogate primary key. Column x holds the subclass of cco:DirectiveICE. Column y holds the filler of the respective object property. Foreign-key constraints between y and id realize the “some” and “only” restrictions stated in the axioms.

## 2. Cross-Join Demonstration

Question: Which administrative HIPAA safeguard and which PCI DSS requirement both reference the same control that exclusively addresses the threat class “AccessControlPolicy”?

2. Follow y to t_hipaa_safeguard_admin.id = 'hipaa-admin-03' → x = 'WorkforceTraining'.  
3. Follow the same ctrl-01.y into t_pci_dss_requirement where y = 'ctrl-01' → row pci-req-01, x = 'FirewallConfiguration'.
