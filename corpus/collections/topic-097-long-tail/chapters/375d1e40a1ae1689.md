# Syscall Classification in Kernel Audit Trails

This chapter defines four relational tables that instantiate the classification of designative information content entities (DesignativeICE) for syscalls. The tables encode subsystem membership and security tier constraints drawn from the supplied axioms. Primary keys are the id columns; cross-table joins are performed on the shared x and y class references to resolve multi-hop queries over syscall provenance.

## 1. Table Definitions and Axiom Embodiment

### 1.1 t_syscall_equiv_in_subsystem
This table embodies AXIOM 1, recording equivalence between a DesignativeICE class X and membership in a syscall subsystem Y. Column id is the primary key. Columns x and y function as entity references; equi-joins on x link equivalent classifications across tables.

| id | x | y |
| --- | --- | --- |
| eq01 | FileReadICE | VFS |
| eq02 | NetSendICE | Socket |
| eq03 | ProcExecICE | Task |
| eq04 | MemMapICE | MM |

### 1.2 t_syscall_only_in_kernel_subsystem
This table embodies AXIOM 2, capturing classes X that are restricted to exactly one kernel subsystem Y. Column id is the primary key. Column y supplies the sole permitted subsystem; joins on y with t_syscall_equiv_in_subsystem verify exclusivity.

| id | x | y |
| --- | --- | --- |
| only01 | FileReadICE | VFS |
| only02 | NetSendICE | Socket |
| only03 | AuditLogICE | Audit |

### 1.3 t_syscall_subclass
This table embodies AXIOM 3, asserting subclass membership of X under a DesignativeICE that participates in subsystem Y. Column id is the primary key. Column x references the subclass; joins on x to t_syscall_equiv_in_subsystem yield the concrete subsystem instance.

| id | x | y |
| --- | --- | --- |
| sub01 | FileReadICE | VFS |
| sub02 | NetSendICE | Socket |
| sub03 | ProcExecICE | Task |
| sub04 | MemMapICE | MM |
| sub05 | AuditLogICE | Audit |

### 1.4 t_syscall_at_security_tier
This table embodies AXIOM 4, assigning each class X to a security tier Y. Column id is the primary key. Column x references the classified entity; joins on x across the preceding three tables retrieve both subsystem and tier in a single traversal.

| id | x | y |
| --- | --- | --- |
| tier01 | FileReadICE | Tier2 |
| tier02 | NetSendICE | Tier3 |
| tier03 | ProcExecICE | Tier2 |
| tier04 | MemMapICE | Tier1 |
| tier05 | AuditLogICE | Tier3 |

## 2. Cross-Join Demonstration

Consider the query: for the designative entity FileReadICE, retrieve its equivalent subsystem, the exclusive subsystem constraint, and its security tier. The following mental join sequence is used:

- Start in t_syscall_equiv_in_subsystem on x = 'FileReadICE' → y = 'VFS'
- Confirm in t_syscall_only_in_kernel_subsystem on x = 'FileReadICE' → y = 'VFS'
- Retrieve tier from t_syscall_at_security_tier on x = 'FileReadICE' → y = 'Tier2'

Resulting joined row: (FileReadICE, VFS, VFS, Tier2). The identical y values across the first three tables confirm that FileReadICE satisfies both equivalence and exclusivity within the VFS subsystem at Tier2.
