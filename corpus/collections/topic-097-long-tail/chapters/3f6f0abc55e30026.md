# Syscall Subsystem Classification in eBPF Kernel Monitoring

This chapter defines four relational tables that encode the slot structures of cco:DesignativeICE axioms for syscall classification. The tables support cross-table queries that resolve multi-hop relations among syscall classes, subsystems, and security tiers. All rows are instances consistent with the Manchester axioms supplied in the ontology.

## 1 Table Definitions and Axiom Embodiment

### 1.1 t_syscall_equiv_in_subsystem

This table embodies AXIOM 1. Column id is the primary key. Columns x and y hold class references; y is required. A cross-join on y with t_syscall_subclass yields all equivalent classes that share a subsystem.

```sql
CREATE TABLE t_syscall_equiv_in_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|---|
| eq01 | read_class | file_subsystem |
| eq02 | write_class | file_subsystem |
| eq03 | open_class | file_subsystem |
| eq04 | mmap_class | memory_subsystem |
| eq05 | brk_class | memory_subsystem |
| eq06 | connect_class | network_subsystem |

### 1.2 t_syscall_only_in_kernel_subsystem

This table embodies AXIOM 2. Column id is the primary key. Columns x and y hold class references. A cross-join on x with t_syscall_at_security_tier returns the security tier for each class restricted to a single subsystem.

```sql
CREATE TABLE t_syscall_only_in_kernel_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|---|
| only01 | ptrace_class | process_subsystem |
| only02 | setuid_class | process_subsystem |
| only03 | clone_class | process_subsystem |
| only04 | reboot_class | system_subsystem |
| only05 | init_module_class | module_subsystem |

### 1.3 t_syscall_subclass

This table embodies AXIOM 3. Column id is the primary key. Columns x and y hold class references; y is required. A cross-join on y with t_syscall_equiv_in_subsystem identifies all subclasses that inherit a subsystem membership.

```sql
CREATE TABLE t_syscall_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|---|
| sub01 | pread64_class | file_subsystem |
| sub02 | pwrite64_class | file_subsystem |
| sub03 | sendto_class | network_subsystem |
| sub04 | recvfrom_class | network_subsystem |
| sub05 | mprotect_class | memory_subsystem |
| sub06 | munmap_class | memory_subsystem |

### 1.4 t_syscall_at_security_tier

This table embodies AXIOM 4. Column id is the primary key. Columns x and y hold class references; y is required. A cross-join on x with t_syscall_only_in_kernel_subsystem attaches the security tier to each kernel-only class.

```sql
CREATE TABLE t_syscall_at_security_tier (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|---|
| tier01 | ptrace_class | T2 |
| tier02 | setuid_class | T3 |
| tier03 | clone_class | T2 |
| tier04 | reboot_class | T3 |
| tier05 | init_module_class | T3 |
| tier06 | read_class | T1 |
| tier07 | mmap_class | T1 |
