# Kernel Syscall Classification via Designative Information Content Entities

This chapter presents four relational tables that instantiate axioms for classifying syscall-related designative information content entities. The tables encode subclass, equivalence, restriction, and tiering relations drawn from an OWL model anchored in cco:DesignativeICE. Primary and foreign key linkages permit multi-table joins that resolve questions about subsystem membership and security tier simultaneously.

## 1. Axiom Instantiation in Relational Form

The four tables below are derived directly from the supplied Manchester axioms. Each table name corresponds to one template identifier. Column x always holds a designative class; column y holds a subsystem or tier class. Joins are performed on shared class identifiers, allowing a reader to traverse from an individual syscall class through its subsystem membership to its security tier.

### 1.1 Equivalence within Subsystem

Table t_syscall_equiv_in_subsystem embodies axiom 1. Column id is the primary key. Column x denotes a class equivalent to a cco:DesignativeICE restricted by an existential to a syscall subsystem; column y supplies the target subsystem class and functions as a foreign key when matched against x values in other tables.

```sql
SELECT e.x, e.y
FROM t_syscall_equiv_in_subsystem e
WHERE e.y = 'file_io_subsystem';
```

### 1.2 Universal Restriction to Kernel Subsystem

Table t_syscall_only_in_kernel_subsystem embodies axiom 2. Column id is the primary key. Column x is a subclass of cco:DesignativeICE whose only permitted syscall subsystem is the value in y; y again serves as a join target.

```sql
SELECT o.x, o.y
FROM t_syscall_only_in_kernel_subsystem o
JOIN t_syscall_equiv_in_subsystem e ON o.y = e.y;
```

### 1.3 Existential Subclass Membership

Table t_syscall_subclass embodies axiom 3. Column id is the primary key. Column x is a subclass of cco:DesignativeICE that participates in at least one syscall subsystem given by y.

```sql
SELECT s.x, s.y
FROM t_syscall_subclass s
WHERE s.y IN (SELECT y FROM t_syscall_only_in_kernel_subsystem);
```

### 1.4 Security Tier Assignment

Table t_syscall_at_security_tier embodies axiom 4. Column id is the primary key. Column x is a subclass of cco:DesignativeICE located at the security tier named by y.

```sql
SELECT t.x, t.y
FROM t_syscall_at_security_tier t
JOIN t_syscall_subclass s ON t.x = s.x;
```

## 3. Multi-Hop Query Example

Question: which security tier governs the syscall class open_file when it participates in the file_io_subsystem and is known to be a subclass of a designative entity?

Execution proceeds by joining t_syscall_subclass (to confirm subsystem), t_syscall_equiv_in_subsystem (to confirm equivalence), and t_syscall_at_security_tier (to retrieve tier).

Result row:

- x = open_file
- subsystem = file_io_subsystem (from t_syscall_subclass.y and t_syscall_equiv_in_subsystem.y)
- tier = user_tier (from t_syscall_at_security_tier.y)
