# Syscall Classification in Kernel Subsystem Monitoring

This chapter specifies four relational tables that encode the classification of designative information content entities for syscalls. The tables are derived directly from the supplied OWL axioms and support cross-table queries that resolve multi-hop relations between syscall classes, subsystems and security tiers.

## 1 t_syscall_equiv_in_subsystem

This table embodies axiom 1 (syscall_equiv_in_subsystem). Column id is the primary key. Columns x and y hold class references; y is required. A reader can join this table to t_syscall_subclass on matching x values to retrieve all subsystems in which a given syscall class is both equivalent and a declared subclass.

```sql
CREATE TABLE t_syscall_equiv_in_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|----|
| eq-001 | FileOpen | FileIO |
| eq-002 | NetConnect | Network |
| eq-003 | MemMap | Memory |
| eq-004 | ProcFork | Process |
| eq-005 | FileRead | FileIO |
| eq-006 | NetSend | Network |

## 2 t_syscall_only_in_kernel_subsystem

This table embodies axiom 2 (syscall_only_in_kernel_subsystem). Column id is the primary key. Columns x and y hold class references. A reader can join this table to t_syscall_at_security_tier on matching x values to determine the security tier of each syscall that is restricted to a single subsystem.

```sql
CREATE TABLE t_syscall_only_in_kernel_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|----|
| only-001 | FileOpen | FileIO |
| only-002 | NetConnect | Network |
| only-003 | MemMap | Memory |
| only-004 | ProcFork | Process |
| only-005 | PrivIoctl | Device |
| only-006 | AuditLog | Audit |

## 3 t_syscall_subclass

This table embodies axiom 3 (syscall_subclass). Column id is the primary key. Columns x and y hold class references; y is required. A reader can join this table to t_syscall_equiv_in_subsystem on matching y values to list every subclass that participates in an equivalence declaration for a given subsystem.

```sql
CREATE TABLE t_syscall_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|----|
| sub-001 | FileOpen | FileIO |
| sub-002 | FileRead | FileIO |
| sub-003 | FileWrite | FileIO |
| sub-004 | NetConnect | Network |
| sub-005 | NetSend | Network |
| sub-006 | NetRecv | Network |
| sub-007 | MemMap | Memory |
| sub-008 | ProcFork | Process |

## 4 t_syscall_at_security_tier

This table embodies axiom 4 (syscall_at_security_tier). Column id is the primary key. Columns x and y hold class references; y is required. A reader can join this table to t_syscall_only_in_kernel_subsystem on matching x values to obtain the security tier for each syscall that appears in only one subsystem.

```sql
CREATE TABLE t_syscall_at_security_tier (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|----|
| tier-001 | FileOpen | Kernel |
| tier-002 | NetConnect | User |
| tier-003 | MemMap | Kernel |
| tier-004 | ProcFork | Kernel |
| tier-005 | PrivIoctl | Privileged |
| tier-006 | AuditLog | Privileged |
| tier-007 | FileRead | User |

## 5 Cross-join example

To retrieve every syscall that is declared equivalent in FileIO, restricted to that subsystem only, and assigned the Kernel tier, execute the following mental join sequence:

1. Select rows from t_syscall_equiv_in_subsystem where y = 'FileIO' → x = 'FileOpen'.
2. Join to t_syscall_only_in_kernel_subsystem on x → confirms FileOpen restricted to FileIO.
3. Join to t_syscall_at_security_tier on x → y = 'Kernel'.

Result row: (x='FileOpen', subsystem='FileIO', tier='Kernel').
