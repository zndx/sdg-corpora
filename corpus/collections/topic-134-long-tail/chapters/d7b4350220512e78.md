# Compliance Directive Modeling in Evidence-Based Audit Systems

This chapter defines a minimal relational schema that realizes five OWL axioms for directive governance. The schema supports attestation, PCI DSS requirement linkage, control evidence mandates, HIPAA technical safeguards, and equivalence-class specification of targets. All tables use entity references as identifiers; cross-table joins recover multi-hop compliance traces such as “which attestation supports a given control that requires evidence for a PCI DSS requirement.”

## 1 Scope and Schema Overview

The five tables below are derived directly from the supplied Manchester axioms. Primary keys are synthetic identifiers of the form `<table_abbrev>_<seq>`. Foreign keys implement the “some” restrictions and equivalence conditions stated in the axioms. Four to six rows per table suffice to demonstrate transitive navigation while remaining compact.

## 2 Table Definitions and Axiom Embodiment

This table embodies AXIOM 3: every row asserts that an instance of cco:DirectiveICE requires evidence of a pci_dss_requirement. Column `id` is the primary key; column `y` is a foreign key referencing `t_pci_dss_requirement.id`.

## 3 Cross-Join Demonstration

To retrieve the attestation identifier, the PCI DSS requirement identifier, and the controlling directive for requirement 12.1, execute the following mental join:

```
t_attestation_with_supporting_evidence.y = t_pci_dss_requirement.id
t_pci_dss_requirement.y = t_control_with_evidence_requirement.id
```

Result row:  
(att_100, pci_req_12_1, ctrl_001, AccessControlPolicy)
