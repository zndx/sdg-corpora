# Audit Governance Relations in Laboratory Compliance

This chapter presents five relational tables that instantiate axioms for directive governance processes. The tables record how audits, attestations, verifications, requirements, and controls are linked through entity references that function as primary and foreign keys. Cross-table joins on shared class references allow reconstruction of multi-step compliance chains such as “which person conducted the verification that produced evidence satisfying a given requirement.”

## 1. Table Structures and Axiom Embodiment

### 1.1 Audit Conducted By
The table t_audit_conducted_by embodies axiom 1 by recording each process class that is conducted by a person class. Column id is the primary key; column x holds the process class.

| id | x |
|----|---|
| acb-01 | LabEquipmentAudit |
| acb-02 | SampleIntegrityCheck |
| acb-03 | DataAccuracyReview |
| acb-04 | ContaminationResponseAudit |
| acb-05 | AnnualSafetyAudit |

### 1.2 Attestation With Supporting Evidence
The table t_attestation_with_supporting_evidence embodies axiom 2 by linking an attestation process class to its supporting evidence class. Column id is the primary key; column x holds the process class; column y is a foreign-key reference to an evidence class also appearing in t_verification_produces_evidence.

| id | x | y |
|----|---|---|
| awe-01 | LabEquipmentAudit | CalibrationLog2018 |
| awe-02 | SampleIntegrityCheck | TestReportMay2014 |
| awe-03 | DataAccuracyReview | MeetingMinutesCabinet |
| awe-04 | ContaminationResponseAudit | BodyFatMeasurementRecord |
| awe-05 | AnnualSafetyAudit | ComplianceCertificate |

### 1.3 Requirement Only Satisfied By
The table t_requirement_only_satisfied_by embodies axiom 3 by recording directive classes that are satisfied only by specific process or control classes. Column id is the primary key; column x holds the directive class; column y is a foreign-key reference to the satisfying class.

| id | x | y |
|----|---|---|
| ros-01 | SafetyProtocol | LabEquipmentAudit |
| ros-02 | DataAccuracyDirective | DataAccuracyReview |
| ros-03 | SampleChainOfCustody | SampleIntegrityCheck |
| ros-04 | ThreatMitigationPlan | ContaminationResponseAudit |
| ros-05 | AnnualComplianceMandate | AnnualSafetyAudit |

### 1.4 Verification Produces Evidence
The table t_verification_produces_evidence embodies axiom 4 by linking verification process classes to the evidence classes they produce. Column id is the primary key; column x holds the process class; column y is a foreign-key reference to an evidence class.

| id | x | y |
|----|---|---|
| vpe-01 | EquipmentCalibrationVerification | CalibrationLog2018 |
| vpe-02 | SampleTestVerification | TestReportMay2014 |
| vpe-03 | CabinetMinutesVerification | MeetingMinutesCabinet |

### 1.5 Control Only Addresses Threat Class
The table t_control_only_addresses_threat_class embodies axiom 5 by recording control classes that address only specified risk classes. Column id is the primary key; column x holds the control class; column y holds the risk class.

| id | x | y |
|----|---|---|
| coa-01 | AccessControlProcedure | DataTamperingRisk |
| coa-02 | VerificationProtocol | ContaminationThreat |
| coa-03 | ChainOfCustodyProcedure | SampleSwitchingRisk |

## 2. Cross-Join Demonstration

To determine the person who conducted the verification that produced the evidence satisfying the SafetyProtocol, first locate the satisfying process in t_requirement_only_satisfied_by (ros-01 yields LabEquipmentAudit). Join that value to t_audit_conducted_by on x to obtain the conducting person class (SeniorTechnician). The same process class appears in t_attestation_with_supporting_evidence (awe-01) whose y value (CalibrationLog2018) matches a row in t_verification_produces_evidence (vpe-01), confirming the evidence chain. The joined row is therefore:

SafetyProtocol → LabEquipmentAudit (conducted by SeniorTechnician) → CalibrationLog2018 (produced by EquipmentCalibrationVerification).
