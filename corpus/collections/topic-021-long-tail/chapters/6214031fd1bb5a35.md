# Directive Governance in Environmental Compliance Systems

This chapter presents four tables that implement axioms for modeling directives as controls and requirements. The tables support cross-table queries over class references to determine how controls address risks, how requirements carry priorities, and how requirements specify targets in audit contexts drawn from solid waste facility inspections.

## 1 Ontology-to-Relation Mapping

The axioms restrict subclasses of cco:DirectiveICE. Each table directly encodes one axiom by storing class references in columns typed as Class. Primary key column id uniquely identifies each assertion instance. Columns x, y, and z hold entity references that function as foreign keys when the same class literal appears in multiple tables, enabling equi-joins.

### 1.1 Control-Only Addresses Threat

Table t_control_only_addresses_threat_class embodies axiom 1. Column id is the primary key. Columns x and y are class references; y is existentially restricted to the threat class addressed exclusively by the control.

```sql
CREATE TABLE t_control_only_addresses_threat_class (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

### 1.2 Control Addresses Risk

Table t_control_addresses_risk embodies axiom 2. Column id is the primary key. Column x references the control class; column y references the risk class and is non-null.

```sql
CREATE TABLE t_control_addresses_risk (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.4 Requirement Specifies Target

Table t_requirement_equiv_specifies_target embodies axiom 4. Column id is the primary key. Column x references the requirement class; columns y and z are non-null references to the specified class and the target class respectively.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 2 Cross-Table Query Example

A multi-hop question is: which priority applies to the requirement that specifies the LeachateContainmentDirective for Cell3MonitoringWell and that also addresses SurfaceWaterImpactRisk?  

Join path: start in t_requirement_equiv_specifies_target on y = 'LeachateContainmentDirective' and z = 'Cell3MonitoringWell' to obtain x = 'QuarterlyLeachateInspectionRequirement'; join that value to t_requirement_has_priority on x to obtain y = 'HighPriority'; join the same x value through t_control_addresses_risk on x = 'LeachateContainmentDirective' to confirm y = 'SurfaceWaterImpactRisk'.  

Resulting joined row: (QuarterlyLeachateInspectionRequirement, HighPriority, LeachateContainmentDirective, Cell3MonitoringWell, SurfaceWaterImpactRisk).
