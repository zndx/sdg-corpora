# Audit Governance Relations in Directive Information Systems

This chapter presents five relational tables that realize axioms from an OWL ontology of directive governance. The tables encode processes and information content entities that participate in audits, requirements, policies, attestations, and periods. Primary and foreign key references permit cross-table queries that recover multi-hop facts such as the enforcer of a requirement that an audit addresses for a given period.

## 1 Scope and Table Construction

The tables follow the deterministic schemas projected from the five supplied axioms. Each row instantiates a class or individual that satisfies the Manchester OWL expression of its source axiom. Column values are entity references or literals consistent with the slot types. Three tables contain foreign-key columns whose values match primary keys in other tables, enabling joins that traverse conducted-by, specifies-target, enforced-by, evidence, and period relations.

### 1.1 Table t_audit_conducted_by

This table embodies Axiom 1. Column id is the primary key. Column x references a bfo:Process individual that is conducted by a cco:Person. The structure supports queries that retrieve the conducting person for any audit process.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

### 1.2 Table t_requirement_equiv_specifies_target

This table embodies Axiom 2. Column id is the primary key. Columns y and z are foreign keys referencing directive targets and subjects respectively. The table records the logical equivalence of a requirement to a directive that specifies one class and applies to another.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```
