# Chapter 4: Directive Governance Structures in Municipal Compliance Audits

This chapter presents five relational tables that instantiate the core axioms of directive governance. The tables capture audits as processes, requirements as directive information content entities, policies as enforceable directives, attestations as evidence-bearing processes, and audit periods as temporal bounds. All column values are drawn from the same closed set of entity identifiers used in the Town of Hinesburg and El Cerrito planning records.

## 1. Axiom Instantiation and Table Definitions

### 1.1 Audit Conducted By

Axiom 1 states that an audit is a process conducted by a person. Table t_audit_conducted_by therefore records the directed relationship between an audit instance and the conducting person. Column id is the primary key for the relationship record; column x is a foreign-key reference to an audit process identifier.

| id          | x           |
|-------------|-------------|
| acb_001     | audit_2016q2 |
| acb_002     | audit_2017q1 |
| acb_003     | audit_2016q4 |
| acb_004     | audit_2017q3 |

### 1.2 Requirement Equivalent Specifies Target

Axiom 2 defines a requirement as a directive information content entity that specifies one target class and applies to another. Table t_requirement_equiv_specifies_target therefore stores the three-part equivalence. Column id is the primary key; columns y and z are foreign-key references to the specified target and the applied-to class, respectively.

| id          | x               | y                | z             |
|-------------|-----------------|------------------|---------------|
| req_001     | setback_req     | target_setback   | zone_res_a    |
| req_002     | env_report_req  | target_report    | permit_app    |
| req_003     | parking_req     | target_spaces    | zone_com_b    |
| req_004     | stormwater_req  | target_drainage  | lot_042       |

### 1.3 Policy Minimum One Enforcer

Axiom 3 states that a policy is a directive information content entity enforced by at least one class. Table t_policy_min_one_enforcer records each policy-enforcer pair. Column id is the primary key; column y is a foreign-key reference to the enforcing class.

| id          | x               | y                  |
|-------------|-----------------|--------------------|
| pol_001     | zoning_policy   | planning_commission|
| pol_002     | env_policy      | conservation_commission |
| pol_003     | building_policy | building_official  |
| pol_004     | water_policy    | public_works       |

### 1.4 Attestation With Supporting Evidence

Axiom 4 states that an attestation is a process that occurs with supporting evidence. Table t_attestation_with_supporting_evidence therefore links each attestation to its evidence class. Column id is the primary key; column y is a foreign-key reference to the evidence class.

| id          | x               | y                  |
|-------------|-----------------|--------------------|
| att_001     | attestation_01  | evidence_minutes |
| att_002     | attestation_02  | evidence_photos  |
| att_003     | attestation_03  | evidence_report  |
| att_004     | attestation_04  | evidence_log     |

### 1.5 Audit For Period

Axiom 5 states that an audit is a process that occurs for a given audit period. Table t_audit_for_period records the temporal scoping. Column id is the primary key; column y is a foreign-key reference to the period class.

| id          | x           | y          |
|-------------|-------------|------------|
| afp_001     | audit_2016q2| period_q2  |
| afp_002     | audit_2017q1| period_q1  |
| afp_003     | audit_2016q4| period_q4  |
| afp_004     | audit_2017q3| period_q3  |

## 2. Cross-Join Demonstration

To determine which person conducted the audit whose requirement applies to zone_res_a and whose policy is enforced by the planning_commission, the following mental join is performed. First locate the requirement whose z column equals zone_res_a (req_001). Its x value (setback_req) is an instance of a directive. Locate the policy whose x value is zoning_policy (pol_001) and whose y value is planning_commission. The audit that satisfies both the requirement and the policy is audit_2016q2. Its conducting person is recovered from t_audit_conducted_by where x equals audit_2016q2, yielding the row whose id is acb_001. The joined result row is therefore (audit_2016q2, planning_commission, zone_res_a, setback_req, acb_001).
