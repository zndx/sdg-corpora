# Directive Governance in Municipal Compliance Audits

This chapter defines five ontological templates that capture directive governance relations within audit processes. Each template is projected to a relational table whose rows contain entity references consistent with the axioms. The tables share identifier values that function as implicit foreign keys, enabling cross-table queries that traverse from audits to requirements, policies, attestations, and periods.

## 1 Scope and Entity Inventory

The domain is compliance auditing of municipal records and health-service directives. Entity identifiers follow a prefix convention: AUD for audits, REQ for requirements, POL for policies, ATT for attestations, PER for periods, EV for evidence items, and OFF for officers. All column values are drawn from this controlled inventory.

## 2 Tables

### 2.1 Audit Conducted By

Table t_audit_conducted_by embodies AXIOM 1. Column id is the primary key for each template instantiation; column x references the audit process (bfo:0000015). No foreign-key column is required because the conducting person is supplied by the axiom’s existential restriction rather than stored in this projection.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 3 Cross-Join Example

Question: Which evidence item supports the attestation linked to the audit conducted in period PER-Q2-2016 that concerns requirement REQ-PLAN-01?

Execution path:  
1. Select rows from t_audit_for_period where y = 'PER-Q2-2016' → AUD-2016-0608, AUD-2016-0615.  
2. Join t_attestation_with_supporting_evidence on x values → ATT-2016-0608 (EV-MINUTES-0608), ATT-2016-0615 (EV-WEBVIEW-0615).  
3. Join t_requirement_equiv_specifies_target where x = 'REQ-PLAN-01' confirms the directive target; the matching attestation row yields EV-MINUTES-0608.

Result row: (AUD-2016-0608, ATT-2016-0608, EV-MINUTES-0608, REQ-PLAN-01, PER-Q2-2016).
