# Chapter 4: Claim Support and Lineage Attestation in GDPR Data Processing Records

This chapter defines five relational tables that realize the slot structures of the trace_supports_claim, gdpr_lawful_basis, column_lineage_for_compliance_claim, kernel_anomaly_supports_claim, and attestation_about_compliance_claim axioms. The tables record how processes and artifacts ground descriptive claims about lawful data handling. All column values are drawn from the slot types declared in the axioms; cross-table joins are performed on shared entity references that appear in the x and y columns.

## 1. Axiom Embodiment and Table Definitions

### 1.1 Trace Support for Descriptive Claims
Axiom 1 states that an entity of type X is a process that supports a descriptive information content entity. Table t_trace_supports_claim therefore stores the identity of each such process. Column id is the primary key. Column x holds the process class; identical x values across rows or tables serve as the join key for retrieving every claim supported by the same process.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

### 1.2 Lawful Basis Declarations
Axiom 2 states that an entity of type X is a directive information content entity that possesses a lawful basis of type Y. Table t_gdpr_lawful_basis records each such directive together with its basis. Column id is the primary key. Column x references the directive; column y references the basis class. The pair (x, y) can be joined to any table whose x column contains the same directive identifier.

```sql
CREATE TABLE t_gdpr_lawful_basis (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.3 Column Lineage Supporting Compliance Claims
Axiom 3 states that an artifact of type X supports a descriptive compliance claim. Table t_column_lineage_for_compliance_claim stores the lineage artifacts that fulfill this role. Column id is the primary key. Column x holds the artifact class; values of x that match entries in t_trace_supports_claim permit retrieval of the processes that produced the lineage artifact.

```sql
CREATE TABLE t_column_lineage_for_compliance_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

### 1.4 Kernel Anomaly Artifacts Supporting Claims
Axiom 4 likewise states that an artifact of type X supports a descriptive compliance claim. Table t_kernel_anomaly_supports_claim records anomaly-detection artifacts. Column id is the primary key. Column x holds the artifact class; shared x values with t_column_lineage_for_compliance_claim allow a reader to combine lineage and anomaly evidence for the same claim.

```sql
CREATE TABLE t_kernel_anomaly_supports_claim (
```

### 1.5 Attestations About Compliance Claims
Axiom 5 states that an entity of type X is a process that attests to a descriptive compliance claim. Table t_attestation_about_compliance_claim stores these attestation processes. Column id is the primary key. Column x holds the process class; x values that appear in t_trace_supports_claim or t_gdpr_lawful_basis enable retrieval of the underlying support and basis declarations.

```sql
CREATE TABLE t_attestation_about_compliance_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 2. Cross-Join Example

Consider the multi-hop question: “Which attestation processes cover the directive that uses Consent as its lawful basis and that is supported by the ColumnLineage:CustomerExport artifact?”  

The query is answered by three successive equi-joins:

1. Join t_gdpr_lawful_basis (y = 'Consent') with t_attestation_about_compliance_claim on x, yielding at-001 and at-004.  
2. Join the result with t_trace_supports_claim on x, confirming that the same processes also appear as traces.  
3. Join the intermediate result with t_column_lineage_for_compliance_claim on x = 'ColumnLineage:CustomerExport', retaining only at-001.

The joined row is therefore:

- Directive: ExportCustomerRecords  
- Lawful basis: Consent  
- Supporting trace: ProcessingActivity:ExportCustomerRecords  
- Supporting lineage artifact: ColumnLineage:CustomerExport  
- Attestation process: AttestationRun:ExportCustomerRecords
