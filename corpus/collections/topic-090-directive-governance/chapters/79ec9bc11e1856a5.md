# eBPF Kernel Audit Ontology

This chapter defines a minimal relational schema for representing designative information content entities in eBPF syscall monitoring. The schema supports queries that traverse security-tier membership and audit-process linkage using the two provided axioms.

## 1 Scope and Schema Overview

The model uses two core tables derived directly from the OWL axioms. Values in columns x and y are drawn from a controlled set of entity references. Primary keys ensure row identity; implicit foreign-key semantics exist between the x column of both tables and any external entity registry.

### 1.1 t_syscall_at_security_tier

This table embodies AXIOM 1 (syscall_at_security_tier). Column id is the primary key. Column x references a syscall class; column y references a security-tier class. A reader can join on x to locate all tiers declared for a given syscall.

```sql
CREATE TABLE t_syscall_at_security_tier (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id   | x                | y                |
|------|------------------|------------------|
| sat1 | open_syscall     | tier_restricted  |
| sat2 | read_syscall     | tier_restricted  |
| sat3 | write_syscall    | tier_confidential|
| sat4 | connect_syscall  | tier_restricted  |
| sat5 | execve_syscall   | tier_confidential|

### 1.2 t_syscall_audited_by

This table embodies AXIOM 2 (syscall_audited_by). Column id is the primary key. Column x references a syscall class that must be realized as a designative information content entity. A reader can join on x with the preceding table to retrieve both tier and audit-process information for the same syscall.

```sql
CREATE TABLE t_syscall_audited_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id   | x                |
|------|------------------|
| sab1 | open_syscall     |
| sab2 | read_syscall     |
| sab3 | write_syscall    |
| sab4 | connect_syscall  |

## 2 Cross-Join Example

Question: which audit process covers the open_syscall when it is constrained to tier_restricted?

Walk the links as follows:

1. Select rows from t_syscall_at_security_tier where x = 'open_syscall' and y = 'tier_restricted' → id = sat1.
2. Select rows from t_syscall_audited_by where x = 'open_syscall' → id = sab1.

Joined result row: (open_syscall, tier_restricted, sab1). The single x value supplies the common join key; no additional tables are required.
