# Audit Trail Modeling for Designative Syscall Entities

This chapter defines two ontological templates for representing system calls as designative information content entities within kernel audit trails. The templates are projected into a four-table relational schema that supports multi-hop queries over security tiers and audit processes. All instances satisfy the subclass axioms for cco:DesignativeICE.

## 1. Supporting Entity Tables

### 1.1 t_syscall
This table supplies concrete X individuals referenced by both axioms. Column syscall_id is the primary key. Rows represent distinct kernel entry points that can be placed at security tiers or marked as audited.

| syscall_id | syscall_name |
|------------|--------------|
| sc_01      | openat       |
| sc_02      | connect      |
| sc_03      | ptrace       |
| sc_04      | bpf          |
| sc_05      | clone        |

### 1.2 t_security_tier
This table supplies concrete Y individuals for Axiom 1. Column tier_id is the primary key. Each tier corresponds to an eBPF enforcement level.

| tier_id | tier_name   | level |
|---------|-------------|-------|
| t_1     | user        | 1     |
| t_2     | cap_net     | 2     |
| t_3     | cap_sys     | 3     |
| t_4     | kernel      | 4     |

## 2. Axiom Tables

### 2.1 t_syscall_at_security_tier
This table directly embodies Axiom 1 (syscall_at_security_tier). Column id is the primary key. Column x is a foreign key to t_syscall.syscall_id. Column y is a foreign key to t_security_tier.tier_id. A reader can join on x and y to retrieve the tier assigned to any syscall.

| id     | x     | y   |
|--------|-------|-----|
| sat_01 | sc_01 | t_1 |
| sat_02 | sc_02 | t_2 |
| sat_03 | sc_03 | t_3 |
| sat_04 | sc_04 | t_4 |
| sat_05 | sc_05 | t_2 |
| sat_06 | sc_01 | t_2 |

### 2.2 t_syscall_audited_by
This table directly embodies Axiom 2 (syscall_audited_by). Column id is the primary key. Column x is a foreign key to t_syscall.syscall_id. The absence of an explicit auditor column follows the axiom slot structure; the audit process is treated as an external bfo:0000015 occurrence linked by application context.

| id     | x     |
|--------|-------|
| sab_01 | sc_01 |
| sab_02 | sc_03 |
| sab_03 | sc_04 |
| sab_04 | sc_05 |

## 3. Cross-Join Example

Question: which security tier applies to the syscall openat when it is audited?  
Start at t_syscall_audited_by where x = sc_01. Follow x to t_syscall. Then follow the same x value into t_syscall_at_security_tier and join on y to obtain tier_name “user”.

Joined result row:  
(sab_01, sc_01, openat, sat_01, t_1, user, 1)
