# Chapter 7: Designative Information Content Entities for Syscall Security Classification

This chapter defines two axioms that classify system calls as designative information content entities within kernel-level security monitoring. The axioms are projected to a two-table relational schema supporting audit trails. Rows are populated from eBPF-based syscall instrumentation in managed IT environments. Primary and foreign key relationships enable retrieval of security tier assignments and audit process linkages.

## 1 Axiom Projections to Relational Tables

### 1.1 t_syscall_at_security_tier
This table embodies axiom syscall_at_security_tier. Column id is the primary key. Column x references a syscall class; column y references the associated security tier class. A reader can join this table to t_syscall_audited_by on x to retrieve both tier and audit status for any given syscall.

| id | x | y |
| id_001 | open_syscall | tier_2 |
| id_002 | read_syscall | tier_3 |
| id_003 | write_syscall | tier_3 |
| id_004 | close_syscall | tier_1 |
| id_005 | mmap_syscall | tier_4 |
| id_006 | connect_syscall | tier_3 |

### 1.2 t_syscall_audited_by
This table embodies axiom syscall_audited_by. Column id is the primary key. Column x references the same syscall class values used in t_syscall_at_security_tier. A reader can join this table to t_syscall_at_security_tier on x to obtain the full set of audit process references for syscalls that also carry tier assignments.

| id | x |
| id_a01 | open_syscall |
| id_a02 | read_syscall |
| id_a03 | write_syscall |
| id_a04 | close_syscall |
| id_a05 | connect_syscall |

## 2 Cross-Table Retrieval Example

To determine the security tier and audit status of the read_syscall when executed under monitored conditions, first select the row from t_syscall_at_security_tier where x equals read_syscall, yielding y equal to tier_3. Next join on x to t_syscall_audited_by, confirming the presence of an audit record (id_a02). The resulting joined tuple is (read_syscall, tier_3, id_a02).
