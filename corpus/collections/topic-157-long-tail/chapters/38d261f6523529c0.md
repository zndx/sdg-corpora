# Kernel Event Threading and Mass Function Equivalence

This chapter defines two core ontological patterns for representing processes that carry thread identifiers and for encoding descriptive information content entities that operate over frames of discernment while assigning masses. The patterns are projected into a minimal relational schema whose foreign-key constraints enable multi-hop retrieval of event-to-assignment provenance.

## 1 Ontological Patterns

### 1.1 Kernel Event with Thread Identifier

Axiom 1 states that any instance of a process may be further classified by the presence of a thread identifier. In the relational projection the identifier is materialised as a foreign key that points into the mass-function table, thereby anchoring each event record to the belief structure that interprets it.

### 1.2 Mass Function Frame and Assignment

Axiom 2 defines a DescriptiveICE that simultaneously scopes a frame of discernment and distributes mass to elements of that frame. Its relational projection records the two relata as foreign keys, one of which must resolve back to a kernel-event record, closing the referential loop required by the mutual existential restrictions.

## 2 Relational Projection

The two tables below are the deterministic projections of the axioms. Primary keys are the `id` columns; foreign-key columns implement the slot restrictions exactly as stated in the Manchester axioms.

### 2.1 Table t_kernel_event_with_tid

This table embodies Axiom 1. Column `id` is the primary key. Column `y` is a foreign key into `t_mass_function_equiv_frame_and_assignment.id`, supplying the thread-identifier class required by the axiom. A reader can therefore retrieve, for any event, the frame that supplies its thread context by a single equi-join on `y`.

```sql
CREATE TABLE t_kernel_event_with_tid (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_mass_function_equiv_frame_and_assignment(id)
);
```

### 2.2 Table t_mass_function_equiv_frame_and_assignment

This table embodies Axiom 2. Column `id` is the primary key. Columns `y` and `z` are foreign keys; `y` references `t_kernel_event_with_tid.id`, satisfying the frame-of-discernment restriction, while `z` names the element that receives mass. The circular foreign-key pair permits an event to be interpreted only inside a frame that itself references that event.

```sql
CREATE TABLE t_mass_function_equiv_frame_and_assignment (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_kernel_event_with_tid(id)
);
```

## 3 Cross-Join Example

Question: which frame of discernment interprets the thread identifier carried by kernel event `kevt-001`?

Walk the links:

1. Locate row in `t_kernel_event_with_tid` where `id = 'kevt-001'` → `y = 'mass-003'`.
2. Locate row in `t_mass_function_equiv_frame_and_assignment` where `id = 'mass-003'` → `y = 'kevt-001'`, `z = 'frame-011'`.

Resulting joined row:

| kevt_id | mass_id | frame |
| kevt-001 | mass-003 | frame-011 |
