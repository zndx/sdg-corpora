# Kernel Event Threading and Mass Assignment in Measurement Audit Trails

This chapter defines two core ontological templates that relate kernel-level process events to belief mass functions. The templates are realized as a minimal relational schema containing exactly two base tables. The schema supports deterministic cross-table navigation from thread-identified events to frame-and-assignment structures and back, enabling multi-hop retrieval of uncertainty assignments attached to specific process threads.

## 1 Ontological Templates

### 1.1 Kernel Event with Thread Identifier
Axiom 1 states that any instance of class X is a bfo:Process that carries a thread identifier drawn from the set of mass-function frames. The corresponding table records the process class, the thread identifier, and the foreign key that resolves the identifier to its owning frame.

### 1.2 Mass Function Equivalent to Frame and Assignment
Axiom 2 states that any instance of class X is equivalent to a cco:DescriptiveICE that is defined over a frame of discernment and that assigns mass to a target. The table therefore stores the DescriptiveICE class, the frame reference, the assignment target, and the foreign key back to the originating kernel event.

## 2 Relational Realization

### 2.1 t_kernel_event_with_tid
This table directly embodies Axiom 1. Column id is the primary key. Column y is a foreign key that must resolve to an existing row in t_mass_function_equiv_frame_and_assignment, thereby linking each kernel event to the frame that supplies its thread identifier. A reader can retrieve the frame assigned to any given thread by joining on y = id.

```sql
CREATE TABLE t_kernel_event_with_tid (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_mass_function_equiv_frame_and_assignment(id)
);
```

| id  | x                  | y   |
|-----|--------------------|-----|
| ke1 | KernelProcess:Scan | mf1 |
| ke2 | KernelProcess:Log  | mf2 |
| ke3 | KernelProcess:Calc | mf1 |
| ke4 | KernelProcess:Sync | mf3 |

### 2.2 t_mass_function_equiv_frame_and_assignment
This table embodies Axiom 2. Column id is the primary key. Column y is a foreign key that resolves to a row in t_kernel_event_with_tid, closing the reference cycle required by the paired axioms. Column z stores the target that receives the mass assignment.

```sql
CREATE TABLE t_mass_function_equiv_frame_and_assignment (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_kernel_event_with_tid(id)
);
```
