# Chapter 7: Kernel Events and Equivalent Mass Assignments

This chapter presents two ontological patterns that capture processes bearing thread identifiers and descriptive information content entities that assign belief masses over frames of discernment. The patterns are realized as a two-table relational schema drawn from an equipment audit trail for net-zero residential energy systems. All column values are instances of the declared slot types; primary-key and foreign-key links support direct cross-table retrieval of multi-hop facts such as the mass assigned to a given frame by the event that carries a specific thread identifier.

## 1 Kernel Event Pattern

The first pattern embodies AXIOM 1. Column id is the primary key. Column y is a foreign key that must resolve to an existing row in t_mass_function_equiv_frame_and_assignment; column x holds the subclass name of the process. A reader can locate every thread identifier that participates in a particular mass assignment by joining on y.

```sql
CREATE TABLE t_kernel_event_with_tid (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_mass_function_equiv_frame_and_assignment(id)
);
```

| ke04 | KernelProcess      | mf04 |

## 2 Mass Function Equivalence Pattern

The second pattern embodies AXIOM 2. Column id is the primary key. Columns y and z are foreign keys; y resolves to t_kernel_event_with_tid while z names the frame of discernment. Column x stores the DescriptiveICE subclass. Joining on y yields the originating kernel event for any mass assignment; joining onward on z recovers the frame receiving the mass.

```sql
CREATE TABLE t_mass_function_equiv_frame_and_assignment (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_kernel_event_with_tid(id)
);
```

| id   | x                        | y    | z          |
|------|--------------------------|------|------------|
| mf01 | DescriptiveMassFunction  | ke02 | FrameA     |
| mf02 | DescriptiveMassFunction  | ke03 | FrameB     |
| mf03 | EquivalentMassAssignment | ke01 | FrameC     |
| mf04 | DescriptiveMassFunction  | ke04 | FrameA     |
| mf05 | EquivalentMassAssignment | ke05 | FrameB     |
| mf06 | DescriptiveMassFunction  | ke06 | FrameC     |

## 3 Cross-Table Retrieval Example

To recover the mass-assignment identifier, the DescriptiveICE subclass, and the target frame for every kernel event whose thread identifier participates in FrameA, execute the following mental join:

SELECT ke.id, ke.x, mf.id, mf.x, mf.z  
FROM t_kernel_event_with_tid ke  
JOIN t_mass_function_equiv_frame_and_assignment mf ON ke.y = mf.id  
WHERE mf.z = 'FrameA';

Result rows:

ke02 | KernelProcess | mf01 | DescriptiveMassFunction | FrameA  
ke06 | KernelProcess | mf04 | DescriptiveMassFunction | FrameA

The same linkage traversed in the opposite direction recovers every kernel event that contributed a mass to a chosen frame, confirming that the foreign-key constraints close the two-hop path required by the axioms.
