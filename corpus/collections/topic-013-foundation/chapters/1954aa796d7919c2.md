# HIPAA Directive Governance in Relational Form

This chapter defines four core ontological templates for expressing directive controls under the CCO and SDG frameworks. Each template is realized as a table whose columns directly encode the Manchester OWL axioms. The resulting schema supports multi-table joins that recover full safeguard chains from individual threat-addressing statements.

## 1. Control–Threat Restriction Pattern

Axiom 1 states that a control class X addresses risk Y exclusively. The corresponding table therefore stores only the pair (X, Y) together with a surrogate identifier that later serves as a foreign-key target for safeguard tables.

```sql
CREATE TABLE t_control_only_addresses_threat_class (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_hipaa_safeguard_physical(id)
);
```

| id   | x                          | y          |
|------|----------------------------|------------|
| C001 | AccessControlPolicy        | T001       |
| C002 | AuditLogRetention          | T002       |
| C003 | WorkstationLock            | T003       |
| C004 | TransmissionEncryption     | T004       |
| C005 | WorkforceTraining          | T005       |

The primary key id uniquely identifies each control–threat pair. The column y is a foreign key into any of the three safeguard tables, allowing a reader to retrieve the concrete safeguard instance that realizes the threat restriction.

## 1.1 Physical Safeguard Realization

Axiom 2 asserts that a control provides a HIPAA physical safeguard. The table therefore records the control identifier together with the safeguard class that satisfies the existential restriction.

```sql
CREATE TABLE t_hipaa_safeguard_physical (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

| id   | x                          | y    |
|------|----------------------------|------|
| P001 | FacilityAccessControl      | C001 |
| P002 | DeviceAndMediaControl      | C003 |
| P003 | WorkstationUse               | C003 |
| P004 | PhysicalSafeguardsPolicy   | C001 |

Primary key id identifies each physical-safeguard assertion. Column y references the control table, establishing the link required by the existential restriction in Axiom 2.

## 1.2 Administrative Safeguard Realization

Axiom 3 captures administrative safeguards under the same existential pattern.

```sql
CREATE TABLE t_hipaa_safeguard_admin (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

| id   | x                          | y    |
|------|----------------------------|------|
| A001 | SecurityAwarenessTraining  | C005 |
| A002 | IncidentResponseProcedure  | C002 |
| A003 | SanctionPolicy               | C005 |
| A004 | BusinessAssociateContract  | C002 |

The foreign key y again points to t_control_only_addresses_threat_class, permitting an auditor to traverse from any administrative safeguard back to the originating threat-addressing control.

## 1.3 Technical Safeguard Realization

Axiom 4 completes the set with technical safeguards.

```sql
CREATE TABLE t_hipaa_safeguard_technical (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

| id   | x                          | y    |
|------|----------------------------|------|
| T001 | AccessControlMechanism     | C001 |
| T002 | AuditControls                | C002 |
| T003 | IntegrityControl             | C004 |
| T004 | TransmissionSecurity       | C004 |

Column y again references the control table, completing the uniform foreign-key pattern across all three safeguard tables.

## 2. Cross-Table Query Example

Consider the multi-hop question: “Which technical safeguard is required by the control that exclusively addresses threat T004?”  

Start at t_control_only_addresses_threat_class where y = 'T004' to obtain row C004.  
Join C004.id into t_hipaa_safeguard_technical on y to retrieve row T004 (TransmissionSecurity).  

The joined result row is therefore:

control_id = C004, control_x = TransmissionEncryption, threat = T004, safeguard_id = T004, safeguard_x = TransmissionSecurity

No additional rows satisfy the same threat identifier, confirming that the restriction “only” is respected by the data.
