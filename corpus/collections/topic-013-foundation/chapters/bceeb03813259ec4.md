# Chapter 4: DirectiveICE Controls and HIPAA Safeguard Classification

This chapter presents four tables that instantiate the Manchester axioms for cco:DirectiveICE subclasses. The tables record only the slot values required by each axiom and expose the foreign-key paths that permit multi-hop retrieval of safeguard-to-threat linkages.

## 1 Table t_control_only_addresses_threat_class

Axiom 1 states that a control class X addresses risk only of threat class Y. The table therefore stores one row per permitted (X, Y) pair. Column id is the primary key. Column y is a foreign key into t_hipaa_safeguard_physical.id, enforcing that every threat referenced by a control must itself be registered as a physical safeguard scope.

| id | x | y |
| id | x | y |
| ctrl-001 | AccessControlPolicy | phys-003 |
| ctrl-002 | AuditLogRetention | phys-001 |
| ctrl-003 | WorkstationLock | phys-002 |
| ctrl-004 | MediaDisposal | phys-004 |
| ctrl-005 | VisitorEscort | phys-001 |
| ctrl-006 | EncryptionAtRest | phys-003 |

## 1.1 Table t_hipaa_safeguard_physical

Axiom 2 classifies a directive X as carrying at least one physical HIPAA safeguard Y. Column id is the primary key. Column y is a foreign key into t_control_only_addresses_threat_class.id, allowing a reader to retrieve every control that is permitted to address the threat scope named by that safeguard.

| id | x | y |
| id | x | y |
| phys-001 | FacilityPerimeter | ctrl-002 |
| phys-002 | DeviceLock | ctrl-003 |
| phys-003 | MediaTransport | ctrl-001 |
| phys-004 | DisposalWitness | ctrl-004 |

## 1.2 Table t_hipaa_safeguard_admin

Axiom 3 records administrative safeguards under the same pattern. Column id is the primary key. Column y references t_control_only_addresses_threat_class.id so that administrative scope can be joined directly to the controls that address only the listed threats.

| id | x | y |
| id | x | y |
| adm-001 | SanctionPolicy | ctrl-002 |
| adm-002 | AccessAuthorization | ctrl-001 |
| adm-003 | IncidentResponse | ctrl-005 |
| adm-004 | BusinessAssociate | ctrl-006 |

## 1.3 Table t_hipaa_safeguard_technical

Axiom 4 records technical safeguards. Column id is the primary key. Column y again references t_control_only_addresses_threat_class.id, completing the set of safeguard families that may be traversed from any control row.

| id | x | y |
| id | x | y |
| tech-001 | UniqueUserID | ctrl-001 |
| tech-002 | IntegrityControl | ctrl-006 |
| tech-003 | AuditLog | ctrl-002 |
| tech-004 | TransmissionSecurity | ctrl-006 |

## 2 Cross-join example

Question: which administrative safeguard is carried by the same control that addresses only the threat registered under physical safeguard phys-003?

Start at t_hipaa_safeguard_physical row phys-003 (y = ctrl-001).  
Follow ctrl-001 into t_control_only_addresses_threat_class (x = AccessControlPolicy).  
Follow the same ctrl-001 into t_hipaa_safeguard_admin (x = AccessAuthorization).  

Joined result row:  
phys-003, AccessControlPolicy, ctrl-001, AccessAuthorization.
