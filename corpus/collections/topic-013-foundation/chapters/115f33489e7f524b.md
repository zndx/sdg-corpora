# Chapter 4: Directive Controls and HIPAA Safeguard Classification

This chapter defines four tables that represent the projection of OWL axioms for directive controls addressing risks and the classification of HIPAA safeguards. The tables support verification of subclass relationships through primary-key and foreign-key references. All rows use class identifiers consistent with the Manchester syntax axioms provided.

## 1 Scope and Table Structure

The four tables embody the axioms control_only_addresses_threat_class, hipaa_safeguard_physical, hipaa_safeguard_admin and hipaa_safeguard_technical. Each table contains an identifier column as primary key. Foreign-key columns enforce the permitted joins between a control class and its associated safeguard class.

### 1.1 t_control_only_addresses_threat_class

This table embodies axiom 1. Column id is the primary key. Column y is a foreign key referencing the id column of t_hipaa_safeguard_physical. A reader can join on y to retrieve the physical safeguard class addressed by a given control class.

| id | x | y |

## 2 Cross-Join Demonstration

To determine the administrative and technical safeguards required by the control class that addresses the physical safeguard LockedCabinet, first locate the row in t_control_only_addresses_threat_class where y equals phys_01. The matching row has id ctrl_01. Join ctrl_01 to t_hipaa_safeguard_admin on y and to t_hipaa_safeguard_technical on y. The joined result contains:

- ctrl_01, AccessControlPolicy, phys_01
- adm_01, RiskAssessmentProcedure, ctrl_01
- tech_02, UniqueUserID, ctrl_01
