# Chapter 7: Artifact GeoCoordinate Representation in Laboratory Information Systems

This chapter specifies the representation of artifacts that carry geo coordinates, using the subclass relation to cco:Artifact and the existential restriction on sdg:hasGeoCoordinates. The model is realized as a minimal relational schema that supports direct lookup and multi-table traversal for location-qualified laboratory records.

## 1 Scope and Axiom Application

The single axiom employed states that an artifact class X stands in the hasGeoCoordinates relation to a coordinate class Y. All table designs below are projections of this axiom. Primary keys identify either artifacts or coordinate instances; foreign keys encode the existential restriction so that every coordinate reference resolves to a valid Y.

## 1.1 t_schemaorg_place_geocoord Table

This table directly implements the axiom by storing the pair (X, Y). Column id is the primary key for the assertion instance. Column x references an artifact; column y is a non-null foreign key to a coordinate class. A reader can therefore retrieve every artifact that possesses coordinates by selecting on x and joining y to any coordinate registry.

```sql
CREATE TABLE t_schemaorg_place_geocoord (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 1.2 t_equipment Table

The equipment table supplies concrete artifact instances that satisfy the X position of the axiom. Its equipment_id column serves as primary key and appears as the x value in t_schemaorg_place_geocoord. A cross-join on equipment_id = x yields the coordinate class for any listed instrument.

| equip_spectrophotometer_03 | Nanodrop 2000 | 2023-09-21 |

## 1.3 t_lots Table

The lots table records reagent or sample lots that are also treated as artifacts. Its lot_id column is the primary key and may appear in the x column of t_schemaorg_place_geocoord. Joining lot_id to x produces the geo coordinate class attached to each lot.

| lot_id | product_code | received_date |
| lot_id | product_code | received_date |

## 2 Cross-Join Example

Question: return the coordinate class for the thermal cycler that processed lot_reagent_a.

Walk the links:  
- t_lots.lot_id = lot_reagent_a → no direct coordinate.  
- t_schemaorg_place_geocoord.x = lot_reagent_a yields y = coord_35_78.  
- t_equipment is not required for this path, yet the same y value also appears for equip_thermal_cycler_01, confirming shared site.

Result row after join:  
(lot_reagent_a, coord_35_78, equip_thermal_cycler_01)
