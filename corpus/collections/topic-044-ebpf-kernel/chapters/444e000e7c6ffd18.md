# Verification Relations in Equipment Compliance Records

This chapter introduces three process relations that structure audit, attestation and verification activities. Each relation is projected to a table whose rows record class instances satisfying the governing axioms. Primary keys identify individual relation instances while foreign-key columns reference shared class instances, permitting cross-table traversal.

1. Relation Definitions
1.1 Audit with Findings
The table t_audit_with_findings realises axiom 1. Column id is the primary key. Columns x and y are foreign-key references to process and finding classes respectively. A reader can join this table to t_verification_produces_evidence on y = x to retrieve the verification step that generated a given finding.

| id  | x                        | y                     |
|-----|--------------------------|-----------------------|
| af1 | AnnualEquipmentAudit     | SealWearFinding       |
| af2 | AnnualEquipmentAudit     | ResinResidueFinding   |
| af3 | HolderToolInspection     | AlignmentDriftFinding |
| af4 | HolderToolInspection     | SealFailureFinding    |
| af5 | QuarterlySafetyReview    | MountCrackFinding     |
| af6 | QuarterlySafetyReview    | ThreadWearFinding     |

1.2 Attestation with Supporting Evidence
The table t_attestation_with_supporting_evidence realises axiom 2. Column id is the primary key. Columns x and y are foreign-key references to process and evidence classes. Joining on y = x with t_verification_produces_evidence yields the originating verification record for each supporting evidence item.

| id  | x                          | y                      |
|-----|----------------------------|------------------------|
| ae1 | ComplianceAttestation      | ResinPourLog           |
| ae2 | ComplianceAttestation      | AlignmentGaugeRecord   |
| ae3 | ToolReusabilityStatement   | SealIntegrityReport    |
| ae4 | ToolReusabilityStatement   | StreetEllDimensionLog  |
| ae5 | MountCertification         | CrackInspectionPhoto   |
| ae6 | MountCertification         | ThreadGaugeCertificate |

1.3 Verification Produces Evidence
The table t_verification_produces_evidence realises axiom 3. Column id is the primary key. Columns x and y are foreign-key references to process and evidence classes. Joining on y = x with t_audit_with_findings or t_attestation_with_supporting_evidence traces evidence forward to findings or attestations.

| id  | x                       | y                      |
|-----|-------------------------|------------------------|
| ve1 | HolderToolVerification  | ResinPourLog           |
| ve2 | HolderToolVerification  | AlignmentGaugeRecord   |
| ve3 | StreetEllCheck          | SealIntegrityReport    |
| ve4 | StreetEllCheck          | StreetEllDimensionLog  |
| ve5 | MountDimensionalCheck   | CrackInspectionPhoto   |
| ve6 | MountDimensionalCheck   | ThreadGaugeCertificate |
| ve7 | QuarterlySafetyReview   | MountCrackFinding      |
| ve8 | QuarterlySafetyReview   | ThreadWearFinding      |

2. Cross-Table Traversal Example
Question: which verification step produced the evidence supporting the attestation that references the finding SealWearFinding?

Start at t_audit_with_findings row af1 (x = AnnualEquipmentAudit, y = SealWearFinding).  
Locate the matching y value in t_verification_produces_evidence: ve1 (x = HolderToolVerification, y = ResinPourLog).  
Locate the same y value in t_attestation_with_supporting_evidence: ae1 (x = ComplianceAttestation, y = ResinPourLog).

The joined path is therefore:
AnnualEquipmentAudit → SealWearFinding ← HolderToolVerification → ResinPourLog → ComplianceAttestation.
