# Directive Classes for HIPAA and PCI DSS Safeguards

This chapter presents five relational tables that instantiate OWL axioms for directive classes under the cco:DirectiveICE anchor. The tables encode subclass restrictions that link safeguard types to addressed risk classes, enabling verification of control coverage through primary-key and foreign-key joins.

## 1 Ontology-to-Relation Mapping

The axioms define five named templates. Each template restricts a directive class X by an existential or universal quantification over a risk or safeguard class Y. The corresponding tables preserve these restrictions as foreign-key constraints, so that every row satisfies the Manchester syntax restriction from which it derives.

### 1.1 Physical Safeguard Table

Axiom 1 states that class X is a cco:DirectiveICE that hipaa safeguard some Y. The table therefore stores pairs (X, Y) where Y must already exist as a control-only risk address. Column id is the primary key; column y is a foreign key into t_control_only_addresses_threat_class.

```sql
CREATE TABLE t_hipaa_safeguard_physical (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

### 1.2 Control-Only Risk Address Table

Axiom 2 states that class X addresses risk only Y. The table therefore records universal restrictions; every Y value must resolve to a physical safeguard identifier. Column id is the primary key; column y is a foreign key into t_hipaa_safeguard_physical.

```sql
CREATE TABLE t_control_only_addresses_threat_class (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255),
  y VARCHAR(255),
  FOREIGN KEY (y) REFERENCES t_hipaa_safeguard_physical(id)
);
```

## 2 Cross-Table Query Example

To determine which technical safeguard and PCI DSS requirement share a common control that addresses only the physical safeguard “Facility Access Control”, perform the following joins:

1. Select rows from t_hipaa_safeguard_physical where x = 'Facility Access Control' (phys_01).
2. Locate the control whose y references phys_01 (ctrl_01).
3. Join t_hipaa_safeguard_technical and t_pci_dss_requirement on that control identifier.

Resulting joined row:

phys_01 | Facility Access Control | ctrl_01 | Physical Barrier Policy | tech_01 | Audit Log Integrity Check | pci_01 | Build and Maintain Firewall

The row demonstrates that a single risk address (ctrl_01) satisfies four distinct directive axioms simultaneously.
