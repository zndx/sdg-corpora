# Chapter 4: DirectiveICE Subclasses for HIPAA and PCI DSS Controls

This chapter defines five templates that classify compliance directives as subclasses of cco:DirectiveICE. Each template is realized as a table whose rows instantiate the corresponding Manchester axiom. Primary-key and foreign-key columns encode the existential and universal restrictions, enabling cross-table traversal from a safeguard instance to the threat class it addresses.

## 1. Core Concepts

cco:DirectiveICE serves as the common parent class. The templates specialize this parent by adding either an existential restriction (hipaaSafeguard some Y) or a universal restriction (addressesRisk only Y). The resulting instances function as named control specifications that can be stored, audited, and joined in a relational schema.

### 1.1 Physical Safeguard Template

Axiom 1 states that a class X is a physical HIPAA safeguard when it stands in the hipaaSafeguard relation to a threat class Y. Table t_hipaa_safeguard_physical therefore stores the identifier of each safeguard together with the identifier of the threat class it safeguards. Column id is the primary key; column y is a foreign key that must resolve to an existing row in t_control_only_addresses_threat_class.

| id     | x                              | y      |
|--------|--------------------------------|--------|
| PHYS01 | FacilityAccessLock             | CTRL03 |
| PHYS02 | MediaDisposalShredder          | CTRL01 |
| PHYS03 | WorkstationPositioningScreen   | CTRL02 |
| PHYS04 | EquipmentSerialTag             | CTRL04 |

### 1.2 Threat-Addressing Control Template

Axiom 2 states that a class X addresses risk only when every risk it addresses belongs to threat class Y. Table t_control_only_addresses_threat_class therefore records the control identifier, the control class, and the single permitted threat class. Column id is the primary key; column y is a foreign key that must resolve to an existing row in t_hipaa_safeguard_physical.

| id     | x                        | y      |
|--------|--------------------------|--------|
| CTRL01 | DisposalProcedure        | PHYS02 |
| CTRL02 | PhysicalAccessLogReview  | PHYS01 |
| CTRL03 | VisitorEscortRequirement | PHYS03 |
| CTRL04 | AssetInventoryReconcile  | PHYS04 |

### 1.3 Technical Safeguard Template

Axiom 3 states that a class X is a technical HIPAA safeguard when it stands in the hipaaSafeguard relation to a threat class Y. Table t_hipaa_safeguard_technical stores each technical control and the threat class it safeguards. Column id is the primary key; column y is a foreign key referencing t_control_only_addresses_threat_class.

| id     | x                           | y      |
|--------|-----------------------------|--------|
| TECH01 | EncryptionAtRest            | CTRL01 |
| TECH02 | UniqueUserAuthentication    | CTRL02 |
| TECH03 | AutomaticLogoffTimer        | CTRL03 |
| TECH04 | IntegrityHashVerification   | CTRL04 |

### 1.4 Administrative Safeguard Template

Axiom 4 states that a class X is an administrative HIPAA safeguard when it stands in the hipaaSafeguard relation to a threat class Y. Table t_hipaa_safeguard_admin records each administrative control and its associated threat class. Column id is the primary key; column y is a foreign key referencing t_control_only_addresses_threat_class.

| id     | x                              | y      |
|--------|--------------------------------|--------|
| ADMN01 | WorkforceClearanceProcedure    | CTRL01 |
| ADMN02 | SecurityAwarenessTraining      | CTRL02 |
| ADMN03 | IncidentResponsePlan           | CTRL03 |
| ADMN04 | BusinessAssociateAgreement     | CTRL04 |

### 1.5 PCI DSS Requirement Template

Axiom 5 states that a class X satisfies a PCI DSS requirement when it stands in the pciDssRequirement relation to a threat class Y. Table t_pci_dss_requirement records each PCI DSS control and the threat class it must address. Column id is the primary key; column y is a foreign key referencing t_control_only_addresses_threat_class.

| id     | x                              | y      |
|--------|--------------------------------|--------|
| PCI01  | CardholderDataEncryption       | CTRL01 |
| PCI02  | NetworkSegmentationFirewall    | CTRL02 |
| PCI03  | VulnerabilityScanSchedule      | CTRL03 |
| PCI04  | AccessControlMatrixMaintenance | CTRL04 |

## 2. Cross-Table Traversal Example

To determine which physical safeguard and which PCI DSS requirement together address the threat class referenced by control CTRL01, perform the following joins:

- Start at t_control_only_addresses_threat_class row CTRL01 (y = PHYS02).
- Follow PHYS02 in t_hipaa_safeguard_physical to obtain x = MediaDisposalShredder.
- Follow CTRL01 in t_pci_dss_requirement to obtain x = CardholderDataEncryption.

The resulting joined tuple is (CTRL01, DisposalProcedure, PHYS02, MediaDisposalShredder, PCI01, CardholderDataEncryption). This path traverses three tables using only declared foreign-key relationships.
