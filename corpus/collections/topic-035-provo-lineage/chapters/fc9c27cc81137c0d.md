# Compliance Directives and Risk Controls

This chapter presents five tables that encode axioms for HIPAA physical, technical, and administrative safeguards together with PCI DSS requirements. All tables instantiate subclasses of cco:DirectiveICE. Primary-key and foreign-key columns enforce the existential and universal restrictions stated in the axioms, permitting cross-table queries that recover multi-hop safeguard-to-risk chains.

## 1. Control Risk Addressing Table

Axiom 2 states that a directive addresses risk only of a designated threat class. Table t_control_only_addresses_threat_class therefore carries the sole primary key id and a foreign key y that must resolve to a row in t_hipaa_safeguard_physical. The structure guarantees that every control instance is linked to exactly one admissible threat class.

```sql
CREATE TABLE t_control_only_addresses_threat_class (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_hipaa_safeguard_physical(id)
);
```

| id | x | y |
|----|---|---|
| ctrl-01 | AccessControl | phys-01 |
| ctrl-02 | AuditLog | phys-02 |
| ctrl-03 | Encryption | phys-03 |
| ctrl-04 | Training | phys-01 |
| ctrl-05 | Firewall | phys-04 |

## 2. Physical Safeguard Table

Axiom 1 asserts that a directive is a HIPAA physical safeguard of some threat class. Table t_hipaa_safeguard_physical therefore stores the existential restriction in column y, which references t_control_only_addresses_threat_class. The foreign-key direction permits a query that starts from a physical safeguard and recovers the unique control that addresses its risk.

```sql
CREATE TABLE t_hipaa_safeguard_physical (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

| id | x | y |
|----|---|---|
| phys-01 | FacilityLock | ctrl-01 |
| phys-02 | MediaDisposal | ctrl-02 |
| phys-03 | Workstation | ctrl-03 |
| phys-04 | DeviceControl | ctrl-05 |

## 3. Technical Safeguard Table

Axiom 3 likewise encodes a HIPAA technical safeguard. Table t_hipaa_safeguard_technical re-uses the same column pattern, with its foreign key again constrained to t_control_only_addresses_threat_class. This permits uniform join syntax across safeguard families.

```sql
CREATE TABLE t_hipaa_safeguard_technical (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

| id | x | y |
|----|---|---|
| tech-01 | AccessControl | ctrl-01 |
| tech-02 | Integrity | ctrl-02 |
| tech-03 | Transmission | ctrl-03 |
| tech-04 | Audit | ctrl-02 |

## 4. Administrative Safeguard Table

Axiom 4 captures administrative safeguards. Table t_hipaa_safeguard_admin follows the identical foreign-key pattern, allowing an administrative directive to be joined to the same control set used by physical and technical safeguards.

```sql
CREATE TABLE t_hipaa_safeguard_admin (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

| id | x | y |
|----|---|---|
| adm-01 | SanctionPolicy | ctrl-04 |
| adm-02 | AccessMgmt | ctrl-01 |
| adm-03 | IncidentProc | ctrl-02 |
| adm-04 | Workforce | ctrl-04 |

## 5. PCI DSS Requirement Table

Axiom 5 introduces PCI DSS requirements as an additional existential restriction on DirectiveICE. Table t_pci_dss_requirement therefore references the same control table, enabling a single query to retrieve both HIPAA and PCI DSS directives that share a given risk-addressing control.

```sql
CREATE TABLE t_pci_dss_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_only_addresses_threat_class(id)
);
```

| id | x | y |
|----|---|---|
| pci-01 | NetworkSeg | ctrl-05 |
| pci-02 | KeyMgmt | ctrl-03 |
| pci-03 | LogReview | ctrl-02 |
| pci-04 | Auth | ctrl-01 |

## 6. Cross-Table Query Example

To recover every physical safeguard whose control also satisfies a PCI DSS requirement, join t_hipaa_safeguard_physical to t_control_only_addresses_threat_class on y = id, then join the result to t_pci_dss_requirement on the control id. The query returns:

phys-01, FacilityLock, ctrl-01, AccessControl, pci-04, Auth

The single joined row demonstrates that FacilityLock safeguards the threat addressed exclusively by AccessControl, which also fulfills PCI DSS authentication requirements.
