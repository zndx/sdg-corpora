# Chapter 7: Directive Controls, Evidence Requirements, and Conducted Audits in Compliance Governance

This chapter defines five tables that instantiate OWL axioms for directive controls and supporting attestations. The tables support cross-table queries that trace a control to its required evidence, addressed risks, and conducting personnel.

## 1 Scope and Table Derivation

The tables below are direct projections of the supplied axioms. Each row instantiates a class subsumption that links a directive or process to an evidence class, risk class, or person. Primary keys are the id columns; foreign-key semantics arise when an x or y value in one table matches an id or x value in another table, enabling two- and three-hop joins.

### 1.1 t_attestation_with_supporting_evidence

This table embodies AXIOM 1. Column id is the primary key for each attestation instance. Column x references the process class; column y is a foreign-key reference to the supporting-evidence class. A reader can join on y to locate the evidence class required by any attestation.

| id | x | y |
| id | x | y |
| att-001 | InnocentSpouseAttestation | DocumentaryEvidenceBundle |
| att-002 | InnocentSpouseAttestation | AffidavitOfNonLiability |
| att-003 | ReliefDeterminationProcess | PriorYearReturnSet |
| att-004 | ReliefDeterminationProcess | ThirdPartyConfirmation |
| att-005 | ControlEffectivenessReview | SignedWorkpaperSet |
| att-006 | ControlEffectivenessReview | SystemLogExtract |

### 1.3 t_control_only_addresses_threat_class

This table embodies AXIOM 3. Column id is the primary key. Column x identifies the directive ICE; column y references the sole risk class the directive may address. The “only” restriction is preserved by ensuring each x appears with at most one y value across rows.

| id | x | y |
| id | x | y |

### 1.4 t_control_addresses_risk

This table embodies AXIOM 4. Column id is the primary key. Column x identifies the directive ICE; column y is a foreign-key reference to a risk class the directive addresses. Multiple rows per x are permitted when a control addresses several risks.

| id | x | y |
| id | x | y |
| car-301 | InnocentSpouseReliefControl | IncorrectDeterminationRisk |

| car-303 | AbuseAssessmentControl | InaccurateReliefRisk |

### 1.5 t_audit_conducted_by

This table embodies AXIOM 5. Column id is the primary key. Column x references the audit process class. The single additional column records the conducting person, satisfying the existential restriction to cco:Person.

| id | x |
| id | x |
| aud-401 | ReliefDeterminationProcess |
| aud-402 | ControlEffectivenessReview |
| aud-403 | AbuseAssessmentControl |

## 2 Cross-Join Example

Question: Which person conducted the audit whose attestation relies on DocumentaryEvidenceBundle and whose control addresses IncorrectDeterminationRisk?

Step 1. Select rows from t_attestation_with_supporting_evidence where y = 'DocumentaryEvidenceBundle' → att-001 (x = InnocentSpouseAttestation).

Step 2. Locate the corresponding control in t_control_addresses_risk where x matches a control that also appears in t_control_with_evidence_requirement referencing the same evidence → ctl-101.

Step 3. Join to t_audit_conducted_by on the process class InnocentSpouseAttestation (via shared x values across tables) → aud-401.

Result row: aud-401, ReliefDeterminationProcess, conducted by the person recorded for that audit identifier. The join traverses three tables using only the supplied primary-key and value-matching foreign-key relationships.
