# Chapter 4: Directive Governance Templates in Regulatory Audit Systems

This chapter presents five OWL-derived templates that formalize relationships among directives, evidence, risks, and audit processes. The templates are realized in a five-table relational schema drawn from financial-services compliance audits. Primary keys are uniformly named id; cross-table references occur through the x and y columns, enabling joins that answer multi-hop queries about control scope, evidence chains, and personnel accountability.

## 1. Schema Overview and Domain Grounding

The schema records attestations, controls, risk-addressing statements, and audit authorship. All rows are drawn from a 2022–2023 internal-control review at a mid-sized payments processor. Each table is preceded by a statement of the axiom it embodies, its key structure, and one representative join path.

### 1.1 Table t_attestation_with_supporting_evidence

This table embodies AXIOM 1: an attestation process is linked to a supporting-evidence class. Column id is the primary key; x identifies the attestation instance and y the evidence class. A reader can join y to the id of t_control_with_evidence_requirement to retrieve the control whose evidence requirement is satisfied by the attestation.

This table embodies AXIOM 5: an audit process is conducted by a named person. Column id is the primary key; x identifies the audit instance. The person value is stored in an implicit conducted_by column (derived from the axiom’s range restriction) and may be joined to external personnel records.

## 2. Cross-Join Demonstration

Consider the multi-hop question: “Which person conducted the audit that produced an attestation satisfying the evidence requirement of the control that addresses only UnauthorizedAccess risk?”

The path traverses four tables:

1. Start in t_control_only_addresses_threat_class where y = 'UnauthorizedAccess' → x = 'AccessControlReview'.
2. Join to t_control_with_evidence_requirement on x → y = 'EvidenceOfPolicyApproval'.
3. Join to t_attestation_with_supporting_evidence on y → x = 'AttestationOfControlDesign', id = 'att-001'.
4. Join to t_audit_conducted_by on a derived audit reference (aud-401) to obtain the conducting person.

The resulting joined row is:

att-001 | AttestationOfControlDesign | EvidenceOfPolicyApproval | AccessControlReview | UnauthorizedAccess | aud-401 | InternalControlAudit2022Q4 | conducted_by = J. Mwamba
