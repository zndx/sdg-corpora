# Kernel Audit Ontologies for Designative Syscall Entities

This chapter defines two OWL axioms that classify syscall representations as designative information content entities and demonstrates their projection into a minimal relational schema. The schema supports audit-trail queries over system-call instances, their classification, and the processes that audit them.

## 1. Axiom Definitions

### 1.1 syscall_basic
Manchester syntax: Class: {X:Class} SubClassOf: cco:DesignativeICE.  
The axiom asserts that X is a designative information content entity whose instances stand for kernel syscalls without additional relational constraints.

### 1.2 syscall_audited_by
Manchester syntax: Class: {X:Class} SubClassOf: cco:DesignativeICE, sdg:auditedBy some bfo:0000015.  
The axiom extends the basic classification by requiring that each X instance is audited by at least one bfo:0000015 process.

## 2. Relational Schema

The axioms project directly to two tables. A third table, t_process, supplies the bfo:0000015 instances referenced by foreign-key values. All tables use a surrogate primary key column named id. The column x in both syscall tables holds either a syscall class name or a foreign key to t_process.id.

### 2.1 t_syscall_basic
This table embodies axiom syscall_basic. Column id is the primary key. Column x stores the designative class name. No foreign keys are present.

| id                  | x          |
|---------------------|------------|
| scb-001             | open       |
| scb-002             | read       |
| scb-003             | write      |
| scb-004             | close      |
| scb-005             | mmap       |

### 2.2 t_syscall_audited_by
This table embodies axiom syscall_audited_by. Column id is the primary key. Column x stores a foreign key referencing t_process.id, thereby recording the auditing process.

| id                  | x          |
|---------------------|------------|
| sca-001             | prc-01     |
| sca-002             | prc-02     |
| sca-003             | prc-01     |
| sca-004             | prc-03     |
| sca-005             | prc-02     |

### 2.3 t_process
This table supplies the bfo:0000015 process individuals required by axiom syscall_audited_by. Column id is the primary key. Column name is a literal label.

| id                  | name               |
|---------------------|--------------------|
| prc-01              | eBPF_audit_loop    |
| prc-02              | seccomp_filter     |
| prc-03              | kprobe_handler     |
| prc-04              | auditd_daemon      |

## 3. Cross-Table Query Example

Question: which auditing process examined the write syscall?  
Start at t_syscall_basic where x = write (row scb-003). Locate the corresponding row in t_syscall_audited_by whose id begins with the same prefix pattern (sca-003). The value in its x column is prc-01. Join to t_process on id = prc-01 to obtain name eBPF_audit_loop. The joined result row is therefore (scb-003, write, sca-003, prc-01, eBPF_audit_loop).
