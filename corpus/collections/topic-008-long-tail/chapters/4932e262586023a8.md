# Kernel Audit Designative Entities

This chapter defines designative information content entities that represent system calls within eBPF kernel audit trails. Two ontology axioms supply the classification rules. The resulting relational schema comprises four tables that support primary-key and foreign-key joins for multi-hop retrieval of audited syscall instances.

## 1 Ontology Axioms and Table Embodiment

### 1.1 Basic Classification
Axiom syscall_basic states that any class X is a designative information content entity. Table t_syscall_basic records each such class. Column id is the primary key. Column x holds the class name. No foreign keys exist in this table.

```sql
CREATE TABLE t_syscall_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| sb001 | SyscallOpen |
| sb002 | SyscallRead |
| sb003 | SyscallWrite |
| sb004 | SyscallClose |
| sb005 | SyscallMmap |

### 1.2 Audited Classification
Axiom syscall_audited_by states that class X is a designative information content entity audited by some bfo:0000015 process. Table t_syscall_audited_by records each such class together with its auditor reference. Column id is the primary key. Column x is a foreign key that references t_syscall_basic.id.

```sql
CREATE TABLE t_syscall_audited_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| sa001 | SyscallOpen |
| sa002 | SyscallRead |
| sa003 | SyscallWrite |

### 1.3 Audit Process Instances
Table t_audit_process supplies concrete bfo:0000015 instances that perform auditing. Column process_id is the primary key. Column name stores the process label.

```sql
CREATE TABLE t_audit_process (
  process_id VARCHAR(255),
  name VARCHAR(255),
  PRIMARY KEY (process_id)
);
```

| process_id | name |
|------------|------|
| ap001 | ebpf_audit_daemon |
| ap002 | kernel_trace_collector |
| ap003 | seccomp_monitor |

### 1.4 Syscall Invocation Records
Table t_syscall_invocation links a classified syscall to an audit process and records invocation time. Column invocation_id is the primary key. Column syscall_id references t_syscall_basic.id. Column auditor_id references t_audit_process.process_id.

```sql
CREATE TABLE t_syscall_invocation (
  invocation_id VARCHAR(255),
  syscall_id VARCHAR(255),
  auditor_id VARCHAR(255),
  ts BIGINT,
  PRIMARY KEY (invocation_id)
);
```

| invocation_id | syscall_id | auditor_id | ts |
|---------------|------------|------------|----|
| inv001 | sb001 | ap001 | 1700000001 |
| inv002 | sb002 | ap001 | 1700000002 |
| inv003 | sb003 | ap002 | 1700000003 |
| inv004 | sb001 | ap003 | 1700000004 |

## 2 Cross-Join Example

To retrieve the auditor name and timestamp for every audited syscall, join t_syscall_audited_by to t_syscall_basic on x, then to t_syscall_invocation on syscall_id, then to t_audit_process on auditor_id. The query returns four rows:

- SyscallOpen audited by ebpf_audit_daemon at 1700000001
- SyscallRead audited by ebpf_audit_daemon at 1700000002
- SyscallWrite audited by kernel_trace_collector at 1700000003
- SyscallOpen audited by seccomp_monitor at 1700000004
