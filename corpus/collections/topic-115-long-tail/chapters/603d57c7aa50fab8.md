# Chapter 7: Claim-Support Artifacts in PCI DSS Audit Trails

This chapter defines five relational tables that instantiate the listed OWL axioms for compliance artifacts. The tables capture entities that support descriptive claims, satisfy PCI DSS directives, and record organizational tax identifiers. All column values are drawn from payment-processing audit scenarios. Primary keys are uniformly named `id`; cross-table joins occur on shared `x` and `y` values that denote the same cco:DescriptiveICE or cco:Artifact individuals.

## 3 Cross-Join Example

To determine which PCI DSS directive and which organization tax identifier jointly support claim-pci-47a, execute the following mental join:

- Start at t_pci_dss_requirement where y = claim-pci-47a → rows pci-301 (x = dir-req-12.1) and pci-305 (x = dir-req-8.2).
- Join t_schemaorg_org_taxid on y = claim-pci-47a → row tax-402 (x = org-processor-4).
- Join any of the three support tables on x = claim-pci-47a to confirm supporting artifacts (trace-001, trace-004, kanom-102, kanom-106, clin-202, clin-206).
