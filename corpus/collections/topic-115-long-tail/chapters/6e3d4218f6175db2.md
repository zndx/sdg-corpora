# Chapter 4: Artifact Classes Supporting Descriptive Claims in Regulatory Audit Models

This chapter specifies five ontological templates that classify artifacts and directives as supporters of compliance claims. Each template is projected to a relational table whose rows are populated with instances drawn from financial-reporting and data-lineage audit trails. The resulting schema permits cross-table joins that recover multi-hop provenance, such as the PCI DSS requirement and tax identifier associated with a given column-lineage artifact.

## 1 Axiom-to-Table Projections

### 1.1 t_trace_supports_claim
Axiom 1 classifies any trace as a bfo:0000015 process that supports a cco:DescriptiveICE claim. The table uses id as primary key; the x column holds the concrete trace identifier that participates in downstream joins.

| id     | x                  |
|--------|--------------------|
| TSC-01 | Trace-LIN-2020Q2-7 |
| TSC-02 | Trace-LIN-2020Q2-8 |
| TSC-03 | Trace-LIN-2020Q3-3 |
| TSC-04 | Trace-LIN-2020Q3-4 |

### 1.2 t_kernel_anomaly_supports_claim
Axiom 2 classifies kernel anomalies as cco:Artifact instances that likewise support cco:DescriptiveICE claims. Primary key is id; x stores the anomaly identifier usable as a foreign reference in compliance queries.

| id     | x                     |
|--------|-----------------------|
| KAC-01 | KernelAnom-PCI-0412   |
| KAC-02 | KernelAnom-PCI-0413   |
| KAC-03 | KernelAnom-TAX-0921   |

### 1.3 t_column_lineage_for_compliance_claim
Axiom 3 classifies column-lineage artifacts as cco:Artifact instances supporting cco:DescriptiveICE claims. Primary key is id; x stores the lineage identifier that may be joined to requirement or tax-identifier tables.

| id     | x                       |

### 1.4 t_pci_dss_requirement
Axiom 4 classifies directives that carry PCI DSS requirements. Primary key is id; x stores the directive identifier and y stores the requirement class identifier, the latter functioning as a foreign key to requirement definitions maintained elsewhere.

| id     | x               | y          |

| PDR-01 | Directive-PCI-1 | Req-12.3   |

### 1.5 t_schemaorg_org_taxid
Axiom 5 classifies artifacts that carry schema.org tax identifiers. Primary key is id; x stores the organizational artifact and y stores the tax-identifier class, serving as a foreign key to external tax records.

## 2 Cross-Table Query Example
