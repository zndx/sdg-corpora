# Regulatory Compliance Claim Support in Artifact Lineage Systems

This chapter defines five ontological categories of artifacts and directives that participate in compliance claims. The categories are realized as a fixed relational schema whose rows are populated from regulatory audit contexts. Primary keys are uniformly named `id`. Columns named `x` and `y` hold entity references that function as join keys across tables, enabling reconstruction of multi-hop claim provenance.

## 1. Trace Artifacts Supporting Descriptive Claims

Axiom 1 states that any class `X` is a processual entity (`bfo:0000015`) that supports a descriptive information content entity. Table `t_trace_supports_claim` therefore records each such `X` under column `x`. Column `id` is the primary key. Column `x` serves as a foreign-key reference that may be matched to `id` values or to `y` values in tables embodying Axioms 4 and 5.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 4. PCI DSS Directive Requirements

Primary key `id`; `y` is a mandatory foreign-key reference to a requirement identifier that may be matched against `x` values in the preceding tables.

```sql
CREATE TABLE t_pci_dss_requirement (
```
