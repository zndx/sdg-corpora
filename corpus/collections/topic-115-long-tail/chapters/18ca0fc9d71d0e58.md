# Chapter 4: Claim-Support Relations in Regulatory Artifact Models

This chapter defines five tables that instantiate OWL axioms for artifacts and directives supporting descriptive information content entities. The tables use shared entity references in the x and y columns to enable cross-table joins that resolve multi-hop compliance questions.

## 1 Axiom Instantiation and Table Structure

Each table corresponds to one axiom. Primary keys ensure row uniqueness. Values in x and y columns function as foreign references to entity identifiers appearing in other tables, permitting equi-joins on those columns.

### 1.1 Trace Support Table

The table t_trace_supports_claim embodies AXIOM 1. Column id is the primary key. Column x holds class references that join to x values in t_kernel_anomaly_supports_claim and t_column_lineage_for_compliance_claim.

| id          | x                  |
|-------------|--------------------|
| trace_001   | AuditTrace_01      |
| trace_002   | AuditTrace_02      |
| trace_003   | AuditTrace_03      |
| trace_004   | AuditTrace_04      |
| trace_005   | AuditTrace_05      |

### 1.2 Kernel Anomaly Support Table

## 2 Cross-Table Query Example

Question: which tax identifier is linked to the organization whose directive supports the claim referenced by KernelAnomalyReport_01?

Execution path:  
- Locate anomaly_002 row in t_kernel_anomaly_supports_claim where x = KernelAnomalyReport_01.  
- Match that x value to y = Req_12_3 in t_pci_dss_requirement (row pci_002).  
- Match y = Req_12_3 to x in t_schemaorg_org_taxid, returning rows tax_001 and tax_002.

Joined result rows:

| anomaly_id | anomaly_x               | pci_y   | tax_x        | tax_y       |
|------------|-------------------------|---------|--------------|-------------|
| anomaly_002| KernelAnomalyReport_01  | Req_12_3| Org_PCI_Comp | TaxID_US_42 |
| anomaly_002| KernelAnomalyReport_01  | Req_12_3| Org_PCI_Comp | TaxID_EU_17 |
