# Chapter 4: Verification Processes and Evidence Classification

This chapter defines three tables that realize axioms for processes producing evidence and for the classification of information content entities. The tables support joins that trace a verification process to its required evidence class and to any descriptive specializations of that evidence.

## 1 Ontological Axioms and Table Mapping

Axiom 1 states that a verification process is a bfo:Process that produces at least one information content entity as evidence. Axiom 2 states that certain classes are subclasses of cco:InformationContentEntity. Axiom 3 states that certain classes are subclasses of cco:DescriptiveICE. The relational schemas below encode these statements directly: primary keys identify each class declaration, and the single foreign key enforces the “min 1” evidence requirement.

### 1.1 t_subclass_to_information_content_entity

This table embodies Axiom 2. Column id is the primary key; column x holds the class name declared as an InformationContentEntity. A reader can join from t_verification_min_one_evidence.y to retrieve every evidence class that satisfies the production requirement of a given process.

| id   | x                    |
|------|----------------------|
| ice1 | AuditFinding         |
| ice2 | ComplianceCertificate|
| ice3 | TestResult           |
| ice4 | MaintenanceLog       |
| ice5 | IncidentReport       |

### 1.2 t_subclass_to_descriptive_ice

This table embodies Axiom 3. Column id is the primary key; column x holds the class name declared as a DescriptiveICE. Because DescriptiveICE is itself a subclass of InformationContentEntity, values in this table are valid targets for the y column of t_verification_min_one_evidence when additional descriptive structure is required.

| id    | x                    |
|-------|----------------------|
| dice1 | InspectionReport     |
| dice2 | ScheduleSummary      |
| dice3 | RegistrationRecord   |
| dice4 | EquipmentLog         |

### 1.3 t_verification_min_one_evidence

This table embodies Axiom 1. Column id is the primary key; column x names the verification process class; column y is a foreign key referencing t_subclass_to_information_content_entity.id. Every row therefore asserts that the process in x produces at least the evidence class referenced by y.

| id  | x                       | y    |
|-----|-------------------------|------|
| v1  | CourtInspection         | ice1 |
| v2  | EquipmentCalibration    | ice3 |
| v3  | StaffCredentialReview   | ice2 |
| v4  | IncidentInvestigation   | ice5 |
| v5  | FacilityMaintenanceCheck| ice4 |
| v6  | PrivateLessonAudit      | ice1 |

## 2 Cross-Table Query Example

To answer “which descriptive evidence class is produced by CourtInspection,” first locate the row in t_verification_min_one_evidence where x = CourtInspection; its y value is ice1. Next locate the row in t_subclass_to_information_content_entity where id = ice1; its x value is AuditFinding. Finally locate any row in t_subclass_to_descriptive_ice whose x value can specialize AuditFinding. The joined result is:

CourtInspection → ice1 (AuditFinding) → dice1 (InspectionReport)

The same three-table walk yields ScheduleSummary for any verification process whose evidence class is further typed as a DescriptiveICE.
