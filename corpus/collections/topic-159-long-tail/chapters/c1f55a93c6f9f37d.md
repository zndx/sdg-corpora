# Modeling Descriptive Information Entities in Audit Trails

This chapter presents five relational tables derived from OWL axioms that classify descriptive information content entities (DescriptiveICE) and their relations to events and processes. The tables support cross-table queries that resolve multi-hop questions about metrics, evidence, claims, and audits in a biodiesel quality laboratory.

## 1. Axiom-Derived Table Structures

### 1.1 Metric Observation Table

Axiom 2 classifies each metric as a DescriptiveICE observed at some event. The table t_metric_observed_by_event therefore stores one row per metric instance; column id is the primary key and column x holds the metric class.

```sql
SELECT m.x
FROM t_metric_observed_by_event m
WHERE m.id = 'metric_cetane_01';
```

| id                | x                    |
|-------------------|----------------------|
| metric_cetane_01  | CetaneNumber         |
| metric_calval_02  | CalorificValue       |
| metric_visc_03    | Viscosity            |
| metric_density_04 | Density              |
| metric_flash_05   | FlashPoint           |

### 1.2 Evidence Observation Table

Axiom 3 likewise classifies each evidence item as a DescriptiveICE observed at an event. Table t_evidence_observed_by_process uses id as primary key and x as the evidence class.

```sql
SELECT e.x
FROM t_evidence_observed_by_process e
JOIN t_audit_produces_evidence a ON a.x = e.id;
```

| id                 | x                  |
|--------------------|--------------------|
| evid_report_01     | LabReport          |
| evid_log_02        | InstrumentLog      |
| evid_photo_03      | SamplePhoto        |
| evid_cert_04       | SupplierCert       |
| evid_calib_05      | CalibrationRecord  |

### 1.3 Claim Observation Table

Axiom 4 classifies each claim as a DescriptiveICE observed at an event. Table t_claim_observed_by_event stores id as primary key and x as the claim class.

```sql
SELECT c.x
FROM t_claim_observed_by_event c
WHERE c.id = 'claim_compl_01';
```

| id                 | x                    |
|--------------------|----------------------|
| claim_compl_01     | ComplianceClaim      |
| claim_noncompl_02  | NonComplianceClaim   |
| claim_calib_03     | CalibrationClaim     |
| claim_trace_04     | TraceabilityClaim    |
| claim_stable_05    | StabilityClaim       |

### 1.4 Audit Process Table

Axiom 5 states that an audit process produces evidence. Table t_audit_produces_evidence therefore records each audit instance; id is the primary key and x references an evidence identifier.

```sql
SELECT a.id, a.x
FROM t_audit_produces_evidence a;
```

| id             | x               |
|----------------|-----------------|
| audit_annual_1 | evid_report_01  |
| audit_annual_2 | evid_log_02     |
| audit_spot_3   | evid_photo_03   |
| audit_spot_4   | evid_cert_04    |
| audit_cal_5    | evid_calib_05   |

### 1.5 Mass-Function Focal-Element Table

Axiom 1 requires every mass function to have at least one focal element that is a metric. Table t_mass_function_min_one_focal therefore links mass-function identifiers to metric identifiers via a foreign key on column y.

```sql
SELECT mf.id, m.x
FROM t_mass_function_min_one_focal mf
JOIN t_metric_observed_by_event m ON mf.y = m.id;
```

| id               | x                | y                |
|------------------|------------------|------------------|
| mf_cetane_01     | BeliefMass       | metric_cetane_01 |
| mf_calval_02     | BeliefMass       | metric_calval_02 |
| mf_visc_03       | BeliefMass       | metric_visc_03   |
| mf_density_04    | BeliefMass       | metric_density_04|
| mf_flash_05      | BeliefMass       | metric_flash_05  |
