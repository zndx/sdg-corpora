# Modeling Directive Information Content Entities in Audit Governance Schemas

This chapter specifies five relational tables that instantiate OWL axioms for directive information content entities. The tables support cross-table joins that resolve multi-hop queries over policies, jurisdictions, lawful bases, evidence requirements, and claim support. All column values are drawn from compliance audit contexts that align with the slot types declared in each axiom.

## 1 Table Definitions and Axiom Embodiment

### 1.1 t_policy_with_jurisdiction
This table embodies AXIOM 2. Column id is the primary key. Column y is a foreign key referencing t_gdpr_lawful_basis(id), enabling direct lookup of the lawful basis associated with a given policy jurisdiction.

### 1.2 t_gdpr_lawful_basis

## 2 Cross-Join Demonstration

Consider the multi-hop question: which policy jurisdiction and lawful basis are required by the control whose evidence trace supports the claim recorded under identifier trc_clm_002?  

Begin at t_trace_supports_claim where id = trc_clm_002. No foreign key exists, so the supporting claim is treated as an independent descriptive instance. The control AccessReviewControl (ctl_evd_001) is known from domain mapping to reference lfb_001. Join t_control_with_evidence_requirement.y to t_gdpr_lawful_basis.id yields x = Consent. The same row’s y value (lfb_001) joins onward to t_policy_with_jurisdiction where y = lfb_001, returning x = GDPR_Article_6.  

The joined result row is therefore:  
ctl_evd_001 | AccessReviewControl | lfb_001 | Consent | pol_jur_001 | GDPR_Article_6
