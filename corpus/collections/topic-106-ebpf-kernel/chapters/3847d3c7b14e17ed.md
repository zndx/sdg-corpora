# Chapter 4: Modeling Directive and Descriptive Entities in Security Compliance Audits

This chapter defines a minimal relational schema that instantiates three ontology axioms for representing PCI DSS requirements and ISO 27001 Annex A subclasses as subclasses of cco:DirectiveICE while anchoring their targets in instances of cco:DescriptiveICE. The schema supports multi-hop queries that traverse primary-key and foreign-key links to retrieve the descriptive measurement referenced by any given directive instance.

## 1 Scope and Schema Overview

The three tables below are derived directly from the supplied axioms. t_measurement_basic provides the target class instances required by the two directive tables. All foreign-key values resolve to existing primary-key values in t_measurement_basic, enabling deterministic joins without additional lookup tables.

### 1.1 t_measurement_basic

This table embodies Axiom 2 (measurement_basic). Column id is the primary key; column x holds the class name of the descriptive information content entity. A reader can join either directive table to this table on y = id to retrieve the underlying measurement for any requirement or subclass.

| id                  | x                          |
|---------------------|----------------------------|
| MEAS-001            | AccessControlPolicy        |
| MEAS-002            | EncryptionKeyManagement    |
| MEAS-003            | NetworkSegmentationRule    |
| MEAS-004            | AuditLogRetention          |
| MEAS-005            | VulnerabilityScanFrequency |
| MEAS-006            | IncidentResponseProcedure  |

### 1.2 t_pci_dss_requirement

This table embodies Axiom 1 (pci_dss_requirement). Column id is the primary key; column y is a foreign key referencing t_measurement_basic.id. A cross-join with t_measurement_basic on y = id yields the descriptive measurement for each PCI DSS requirement instance.

| id             | x                    | y        |
|----------------|----------------------|----------|
| PCI-REQ-1.1    | FirewallRuleSet      | MEAS-003 |
| PCI-REQ-2.3    | TLSConfiguration     | MEAS-002 |
| PCI-REQ-3.4    | PANTruncation        | MEAS-002 |
| PCI-REQ-7.1    | RoleBasedAccess      | MEAS-001 |

| PCI-REQ-11.2   | QuarterlyExternalScan| MEAS-005 |
| PCI-REQ-12.10  | IRTeamActivation     | MEAS-006 |

### 1.3 t_iso27001_annexa_subclass

This table embodies Axiom 3 (iso27001_annexa_subclass). Column id is the primary key; column y is a foreign key referencing t_measurement_basic.id. Joining this table to t_measurement_basic on y = id produces the descriptive measurement referenced by each ISO 27001 Annex A subclass.

| id               | x                       | y        |
|------------------|-------------------------|----------|
| ISO-A.5.1.1      | InformationSecurityPolicy | MEAS-001 |
| ISO-A.8.2.3      | AssetHandlingProcedure  | MEAS-001 |
| ISO-A.10.1.1     | CryptographicPolicy     | MEAS-002 |
| ISO-A.12.4.1     | LoggingAndMonitoring    | MEAS-004 |
| ISO-A.12.6.1     | VulnerabilityManagement | MEAS-005 |
| ISO-A.16.1.1     | IncidentResponse        | MEAS-006 |

## 2 Cross-Join Demonstration

To determine the descriptive measurement shared by both a PCI DSS requirement and an ISO 27001 Annex A subclass, execute the following mental join sequence. Start with PCI-REQ-12.10 (id in t_pci_dss_requirement), follow its foreign key y = MEAS-006 to t_measurement_basic, then locate every row in t_iso27001_annexa_subclass whose y also equals MEAS-006. The result set contains:

- PCI-REQ-12.10 → MEAS-006 (IncidentResponseProcedure)
- ISO-A.16.1.1 → MEAS-006 (IncidentResponseProcedure)

The joined row therefore shows that both the PCI DSS incident-response requirement and the ISO 27001 Annex A incident-response subclass are grounded in the same descriptive measurement IncidentResponseProcedure.
