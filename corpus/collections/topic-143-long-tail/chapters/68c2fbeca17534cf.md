# Chapter 4: Formal Specification of Belief Structures and Governance Directives

## 4.1 Scope and Preamble

This chapter establishes the formal ontological framework required to define, manage, and audit belief structures within a high-assurance governance environment. It details the logical underpinnings of class definitions via intersection and negation, the mathematical formalization of mass functions over frames of discernment, and the derivation of belief intervals. Furthermore, it explicates the provenance chain for governance directives, ensuring that automated or semi-automated directives are strictly traceable to their generating evidence structures. The definitions provided herein are binding for all subsequent compliance audits and system verification protocols.

## 4.2 Logical Class Definitions via Intersection and Negation

### 4.2.1 Axiomatic Foundation

The foundational logic of the ontology relies on the precise construction of classes through set-theoretic operations. Specifically, the axiom `equiv_intersect_with_negation` provides the mechanism for defining a target class {X} as the intersection of a base class {Y} and the logical complement of an exclusion class {Z}. In formal Manchester syntax, this is expressed as:

`Class: {X:Class} EquivalentTo: {Y:Class} and not {Z:Class}`

This construct is critical for defining exclusionary criteria in governance frameworks, such as identifying "Valid Records" that are members of "Audit Entries" but not "Redacted Entries." The verbalization asserts that {X} is equivalent to {Y} and not {Z}. This strict logical partitioning ensures that classification boundaries are mathematically rigorous and computationally verifiable.

### 4.2.2 Relational Implementation

The projection of this axiom into the relational schema utilizes the table `t_equiv_intersect_with_negation`. The primary key is the identifier `id`, which uniquely indexes the specific definition instance. The columns `x`, `y`, and `z` store the class names corresponding to the defined class, the parent class, and the excluded class, respectively.

The following data table illustrates the instantiation of this axiom for various governance scenarios, including network node status, credential validation, and packet inspection.

### 4.2.3 Verification Protocol

Auditors must verify that for any row in Table 4-1, the set of instances belonging to class `x` is exactly equal to the set difference between instances of class `y` and instances of class `z`. Failure to maintain this equivalence constitutes a logical violation of the ontology and invalidates any dependent reasoning chains.

## 4.3 Mass Functions and Frames of Discernment

### 4.3.1 Theoretical Basis

Evidence theory, specifically the Dempster-Shafer structure, is formalized through the axiom `mass_function_equiv_frame_and_assignment`. This axiom defines a class {X} as a `DescriptiveICE` (Information Content Entity) that functions as a mass function. It operates over a specific Frame of Discernment {Y} and assigns mass to a focal element {Z}. The Manchester syntax is defined as:

`Class: {X:Class} EquivalentTo: cco:DescriptiveICE and (sdg:overFrameOfDiscernment some {Y:Class}) and (sdg:assignsMassTo some {Z:Class})`

In this context, the Frame of Discernment {Y} must be a class defined via the logical intersection mechanisms described in Section 4.2. This constraint ensures that the domain over which evidence is aggregated is strictly bounded and logically consistent. The mass function {X} serves as the mathematical container for Basic Probability Assignments (BPA).

### 4.3.2 Relational Implementation and Constraints

The relational schema for this concept is encapsulated in `t_mass_function_equiv_frame_and_assignment`. The schema enforces a foreign key constraint where the `y` column (the Frame of Discernment) must reference a valid identifier in `t_equiv_intersect_with_negation`. This dependency guarantees that no mass function can be defined over an amorphous or undefined set; it must operate over a logically rigorous class definition.

### 4.3.3 Evidence Aggregation Rules

When populating Table 4-2, the `z` column (assignsMassTo) must represent a subset of the power set of the Frame of Discernment `y`. While the relational schema stores this as a class reference, the semantic implication is that the mass function {X} distributes a probability mass value to the proposition represented by {Z}. It is the responsibility of the inference engine to ensure that the sum of masses for a given {X} equals unity (1.0).

## 4.4 Belief Intervals and Uncertainty Bounds

### 4.4.1 Defining the Interval

To quantify uncertainty within the evidence framework, the ontology employs the axiom `belief_interval_equiv_bel_and_pl`. This axiom defines a class {X} as a `DescriptiveICE` representing a belief interval, characterized by a lower bound (Belief) and an upper bound (Plausibility). The formal definition is:

`Class: {X:Class} EquivalentTo: cco:DescriptiveICE and (sdg:hasBeliefLowerBound some {Y:Class}) and (sdg:hasPlausibilityUpperBound some {Z:Class})`

The Belief measure {Y} represents the total evidence strictly supporting a proposition, while the Plausibility measure {Z} represents the total evidence that does not refute the proposition. The interval $[Bel, Pl]$ encapsulates the epistemic uncertainty. Consistent with the mass function definitions, the bounds {Y} and {Z} are derived from the logical class definitions in Section 4.2.

### 4.4.2 Relational Mapping

The table `t_belief_interval_equiv_bel_and_pl` implements this structure. Both the `y` (Belief Lower Bound) and `z` (Plausibility Upper Bound) columns are foreign keys referencing the `t_equiv_intersect_with_negation` table. This structure enforces the requirement that uncertainty bounds are defined relative to specific, logically constructed states (e.g., "ConfirmedSecure" vs "PotentialSecure").

### 4.4.3 Interpretation of Bounds

In Table 4-3, `interval_01` defines a security confidence interval where the lower bound is the class `ConfirmedSecure` (defined in Table 4-1 as `SystemState` and not `VulnerableState`) and the upper bound is `PotentialSecure` (defined as `SystemState` and not `CompromisedState`). This distinction allows the system to differentiate between states that are verified as safe versus states that are merely not yet known to be compromised, a critical distinction in high-risk compliance environments.

## 4.5 Provenance of Governance Directives

### 4.5.1 Directive Authorization

The final concept links the evidence structures to actionable governance controls through the axiom `directive_authored_and_applies`. This axiom defines a Directive {X} as a `DirectiveICE` that is authored by a specific entity {Y} and applies to a target entity {Z}. The Manchester syntax is:

`Class: {X:Class} EquivalentTo: cco:DirectiveICE and (sdg:authoredBy some {Y:Class}) and (sdg:appliesTo some {Z:Class})`

In this framework, the "author" of a directive is not necessarily a human agent, but can be a specific evidence aggregation process—a mass function. This allows for the creation of "evidence-based directives" where the authority to act is derived directly from the mathematical confidence of the underlying evidence.

### 4.5.2 Relational Integrity and Audit Trails

The schema `t_directive_authored_and_applies` enforces a strict dependency where the author {Y} must be a valid instance from `t_mass_function_equiv_frame_and_assignment`. This creates a non-repudiable chain of custody: any directive {X} must be traceable back to the specific mass function {Y} that generated the mandate. The target {Z} represents the system component or entity to which the directive applies.
