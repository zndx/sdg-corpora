# Directive Governance Ontologies in Counterterrorism Policy

This chapter defines five core relations among directive instances that govern risk treatment in counterterrorism operations. Each relation is expressed both as an OWL axiom and as a corresponding relation table whose rows are populated with policy classes drawn from documented counter-subversion and risk-mitigation literature. The tables share entity references in the x and y columns, permitting cross-table joins that recover multi-hop chains such as “a requirement that has priority over a policy that supersedes a control addressing a given threat class.”

## 1 Requirement Priority Relation

The axiom requirement_has_priority states that any subclass of cco:DirectiveICE may be linked to a priority target via the sdg:hasPriority property. Table t_requirement_has_priority materializes this axiom; column id is the primary key for the assertion itself, while x and y are foreign references to directive classes. A reader can therefore join on y to locate every requirement that elevates a particular policy.

| id | x | y |
| id | x | y |
| reqpri-01 | PoliticalMobilizationRequirement | PoliticalSubversionCounterPolicy |
| reqpri-02 | ResourceAllocationRequirement | KineticStrikeDirective |
| reqpri-03 | NarrativeControlRequirement | CommunityEngagementDirective |
| reqpri-04 | LegalAuthorityRequirement | DetentionPolicy |
| reqpri-05 | IntelligenceSharingRequirement | CrossBorderExtraditionPolicy |
| reqpri-06 | BudgetOversightRequirement | PoliticalSubversionCounterPolicy |

## 2 Policy Supersession Relation

The axiom policy_supersedes captures the replacement of an earlier directive by a later one. Table t_policy_supersedes records each supersession; id again serves as primary key and the pair (x, y) encodes the ordered replacement. Joining this table on y with the priority table above yields chains that show which current policy has displaced a previously prioritized directive.

| id | x | y |
| id | x | y |
| psup-01 | PoliticalSubversionCounterPolicy | PhysicalDestructionDirective |
| psup-02 | CommunityEngagementDirective | KineticStrikeDirective |
| psup-03 | CrossBorderExtraditionPolicy | DetentionPolicy |
| psup-04 | IntegratedRiskFramework | PoliticalSubversionCounterPolicy |
| psup-05 | OversightAuditDirective | CommunityEngagementDirective |

## 3 Control-to-Risk Addressing Relation

The axiom control_addresses_risk asserts that a directive may address one or more risk classes. Table t_control_addresses_risk implements the existential form of the axiom. Because multiple controls may address the same risk, the y column is non-unique; joins on y therefore surface every control applicable to a given risk.

| id | x | y |
| id | x | y |
| car-01 | PoliticalSubversionCounterPolicy | SubversionOfLocalGovernance |
| car-02 | KineticStrikeDirective | ImmediatePhysicalThreat |
| car-03 | CommunityEngagementDirective | SubversionOfLocalGovernance |
| car-04 | DetentionPolicy | ImmediatePhysicalThreat |
| car-05 | CrossBorderExtraditionPolicy | TransnationalFinancingRisk |
| car-06 | IntegratedRiskFramework | SubversionOfLocalGovernance |
| car-07 | OversightAuditDirective | TransnationalFinancingRisk |

## 4 Universal Restriction on Threat Class

The axiom control_only_addresses_threat_class supplies the universal restriction counterpart: a control addresses risk only of the declared class. Table t_control_only_addresses_threat_class records this restriction; y may be null when no universal constraint is stated. A join between this table and t_control_addresses_risk on x confirms that every asserted risk for a control falls inside the permitted threat class.

| id | x | y |
| id | x | y |
| cotc-01 | PoliticalSubversionCounterPolicy | SubversionOfLocalGovernance |
| cotc-02 | CommunityEngagementDirective | SubversionOfLocalGovernance |
| cotc-03 | IntegratedRiskFramework | SubversionOfLocalGovernance |
| cotc-04 | OversightAuditDirective | TransnationalFinancingRisk |

## 5 Control Subclass Relation

The axiom control_subclass states that one directive mitigates the risk addressed by another. Table t_control_subclass captures the mitigation hierarchy; x is the mitigating subclass and y the mitigated superclass. Joining on y recovers the set of specialized controls that refine a broader directive.

| id | x | y |
| id | x | y |
| csub-01 | PoliticalSubversionCounterPolicy | IntegratedRiskFramework |
| csub-02 | CommunityEngagementDirective | IntegratedRiskFramework |
| csub-03 | OversightAuditDirective | IntegratedRiskFramework |
| csub-04 | NarrativeControlRequirement | PoliticalSubversionCounterPolicy |
| csub-05 | IntelligenceSharingRequirement | PoliticalSubversionCounterPolicy |

## 6 Worked Multi-Hop Query Example

Question: Which requirement has priority over a policy that both supersedes the PhysicalDestructionDirective and addresses the risk SubversionOfLocalGovernance?

Step 1. Locate the superseding policy in t_policy_supersedes where y = PhysicalDestructionDirective → row psup-01 yields x = PoliticalSubversionCounterPolicy.  
Step 2. Confirm the same policy addresses SubversionOfLocalGovernance in t_control_addresses_risk → row car-01 matches.  
Step 3. Join t_requirement_has_priority on y = PoliticalSubversionCounterPolicy → rows reqpri-01 and reqpri-06 are returned.

Resulting joined rows (id, x, y):

- reqpri-01, PoliticalMobilizationRequirement, PoliticalSubversionCounterPolicy  
- reqpri-06, BudgetOversightRequirement, PoliticalSubversionCounterPolicy
