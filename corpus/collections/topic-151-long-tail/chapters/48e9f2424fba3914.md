# Compliance Directive Classification in Regulated Data Environments

This chapter defines a minimal relational schema for representing directive classifications under HIPAA and PCI-DSS. The schema uses five tables derived directly from the supplied OWL axioms. All instances are drawn from administrative, physical, and technical control processes recorded in a regional health-system audit trail for the period 1 January 2018 to 31 March 2018.

## 1 Scope and Table Inventory

Five tables are maintained. t_classification_basic holds the core process classes. The remaining four tables record directive classes that stand in a “hipaaSafeguard” or “pciDssRequirement” relation to those processes. Primary keys are the id columns; foreign keys reference t_classification_basic.id only.

## 2 t_classification_basic

This table embodies AXIOM 2. Column id is the primary key. Column x stores the process label. No foreign keys exist. A reader can join any safeguard table on y = id to retrieve the safeguarded process label.

| id | x |
|----|---|
| P001 | AccessLogReview |
| P002 | EncryptionKeyRotation |
| P003 | FacilityPerimeterAudit |
| P004 | NetworkFirewallRuleReview |
| P005 | CHDDataRetentionCheck |
| P006 | WorkstationLockoutEnforcement |

## 3 t_hipaa_safeguard_admin

This table embodies AXIOM 1. Column id is the primary key. Column y is a foreign key to t_classification_basic.id. Column x names the administrative directive class. Example cross-join: select administrative directive, process label by joining on y.

| A001 | WorkforceAccessPolicy | P001 |
| A002 | KeyCustodianAssignment | P002 |

## 7 Cross-Join Example

Question: which PCI-DSS requirement and which HIPAA technical safeguard both reference the same process “AccessLogReview”?

Join path: t_pci_dss_requirement.y = t_classification_basic.id = t_hipaa_safeguard_technical.y where x = “AccessLogReview”.

Result rows:

- t_pci_dss_requirement: C004, Req_10_2_AuditTrail, P001
- t_hipaa_safeguard_technical: T004, LogCentralisationService, P001

The joined tuple therefore shows that requirement C004 and safeguard T004 both classify the identical process P001.
