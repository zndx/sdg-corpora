# Verification and Attestation Structures in Designative Information Content Entities

This chapter defines five relational tables that implement the core axioms for designative information content entities, attestations, and verifications. The tables support cross-table joins that trace evidence production and unique identification through primary-key and foreign-key references.

## 1. Foundational Tables for Designative Subclasses

### 1.1 t_designative_subclass_basic
Axiom 2 is embodied by this table. Column id is the primary key; column x holds the designative subclass name. A reader can join this table on id to any referencing foreign key to retrieve the concrete designative class used in an attestation or verification.

| id | x |
|----|---|
| dsb-001 | CertificateOfAnalysis |
| dsb-002 | EquipmentCalibrationLog |
| dsb-003 | SampleIdentifier |
| dsb-004 | VerificationReport |
| dsb-005 | ChainOfCustodyRecord |

### 1.2 t_subclass_to_designative_ice
Axiom 4 is embodied by this table. Column id is the primary key; column x holds the designative subclass name. The table supplies additional designative instances that can be referenced by identifier uniqueness constraints.

| id | x |
|----|---|
| sdi-001 | BatchReleaseAttestation |
| sdi-002 | TestMethodReference |
| sdi-003 | OperatorQualificationCard |
| sdi-004 | MeasurementTraceabilityNote |

## 2. Process Tables Linking Evidence and Attestation

### 2.1 t_verification_produces_evidence
Axiom 3 is embodied by this table. Column id is the primary key; column x names the verification process; column y is a foreign key to t_designative_subclass_basic.id. A reader can join y to t_designative_subclass_basic to obtain the evidence class produced by each verification.

| id | x | y |
|----|---|---|
| vpe-001 | CalibrationVerification | dsb-002 |
| vpe-002 | CompositionalAnalysis | dsb-001 |
| vpe-003 | TraceabilityAudit | dsb-005 |
| vpe-004 | MethodValidationCheck | dsb-004 |

### 2.2 t_attestation_with_supporting_evidence
Axiom 1 is embodied by this table. Column id is the primary key; column x names the attestation; column y is a foreign key to t_designative_subclass_basic.id. A reader can join y to t_designative_subclass_basic to retrieve the supporting evidence class for each attestation.

| id | x | y |
|----|---|---|
| awe-001 | BatchRelease | dsb-001 |
| awe-002 | EquipmentClearance | dsb-002 |
| awe-003 | SampleAcceptance | dsb-003 |
| awe-004 | ComplianceDeclaration | dsb-004 |

### 2.3 t_identifier_unique
Axiom 5 is embodied by this table. Column id is the primary key; column x names the identifier; column y is a foreign key to t_attestation_with_supporting_evidence.id. A reader can join y to t_attestation_with_supporting_evidence to locate the unique attestation that the identifier designates.

| id | x | y |
|----|---|---|
| iun-001 | COA-2024-8841 | awe-001 |
| iun-002 | CAL-2024-3172 | awe-002 |
| iun-003 | SID-2024-5590 | awe-003 |
| iun-004 | VCR-2024-2105 | awe-004 |

## 3. Cross-Join Example

To answer the multi-hop question “Which verification process produced the evidence supporting the attestation identified by COA-2024-8841?”, perform the following joins:

1. Start in t_identifier_unique where x = 'COA-2024-8841' to obtain y = 'awe-001'.
2. Join t_attestation_with_supporting_evidence on id = 'awe-001' to obtain y = 'dsb-001'.
3. Join t_verification_produces_evidence on y = 'dsb-001' to obtain x = 'CompositionalAnalysis'.

The resulting joined row is:

t_identifier_unique.id = iun-001, t_identifier_unique.x = COA-2024-8841, t_attestation_with_supporting_evidence.x = BatchRelease, t_designative_subclass_basic.x = CertificateOfAnalysis, t_verification_produces_evidence.x = CompositionalAnalysis
