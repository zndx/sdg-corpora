# Evidence and Attestation Structures in Designative Information Content Entities

This chapter defines five core ontological patterns that link processes of verification and attestation to designative information content entities. The patterns are realized as a fixed relational schema containing five tables. Primary keys identify individual entities; foreign keys encode the existential restrictions stated in the source axioms. Cross-table joins therefore recover the multi-hop relations required by the Manchester axioms.

## 1. Foundational Classes

Two tables implement the basic subclass axioms that place entities under cco:DesignativeICE.

### 1.1 Designative Subclass Table

Table t_designative_subclass_basic embodies axiom 2. Column id is the primary key. Column x holds the subclass name. No foreign keys are present.

| id  | x                          |
|-----|----------------------------|
| d01 | ResearchAttestation        |
| d02 | VerificationRecord         |
| d03 | EquipmentCalibrationLog    |
| d04 | SampleChainOfCustody       |
| d05 | TechnicianAuthorization    |
| d06 | ProtocolIdentifier         |

## 2. Process–Evidence Relations

Two tables capture the process restrictions that produce or support evidence.

### 2.1 Verification Produces Evidence Table

Table t_verification_produces_evidence embodies axiom 3. Column id is the primary key. Column y is a foreign key referencing t_designative_subclass_basic(id).

| id  | x                        | y   |
|-----|--------------------------|-----|
| v01 | CalibrationVerification  | d03 |
| v02 | CustodyVerification      | d04 |
| v03 | AuthorizationVerification| d05 |
| v04 | ProtocolVerification     | d06 |
| v05 | SampleVerification       | d04 |

### 2.2 Attestation with Supporting Evidence Table

Table t_attestation_with_supporting_evidence embodies axiom 1. Column id is the primary key. Column y is a foreign key referencing t_designative_subclass_basic(id).

| id  | x                       | y   |

| a02 | CalibrationAttestation  | d03 |

## 4. Cross-Join Example

Question: which unique identifier is attached to the attestation that is supported by the same designative entity produced by the verification step “CustodyVerification”?

Join path:  
t_verification_produces_evidence.y = t_designative_subclass_basic.id  
t_attestation_with_supporting_evidence.y = t_designative_subclass_basic.id  
t_identifier_unique.y = t_attestation_with_supporting_evidence.id  

Result row:  
(CUST-2023-0031, CustodyVerification, SampleChainOfCustody, CustodyAttestation)
