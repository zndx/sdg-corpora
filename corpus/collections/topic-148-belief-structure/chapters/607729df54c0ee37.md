# Chapter 7: Relational Projection of DescriptiveICE and DirectiveICE Axioms in Compliance Rule Evaluation

This chapter specifies four tables that realize the slot structures of the supplied OWL axioms. The tables encode class references for descriptive and directive information content entities together with their associated numeric parameters. All column values are drawn from PCI DSS compliance rule sets applied to transaction-log audits.

## 1 Table Derivation from Axioms

Each table corresponds to one axiom. Primary-key columns uniquely identify each class reference. Foreign-key columns enforce the existential restrictions stated in the Manchester syntax forms.

### 1.1 t_lift_basic

The table embodies Axiom 3. Column id is the primary key. Column x stores the Class that is declared a subclass of cco:DescriptiveICE. No foreign keys are present. A reader can list all pure descriptive entities by selecting every row and inspecting the x values without traversing additional tables.

```sql
SELECT x FROM t_lift_basic;
```

### 1.2 t_pci_dss_requirement

The table embodies Axiom 2. Column id is the primary key. Column x stores the Class declared a subclass of cco:DirectiveICE. Column y is a foreign key referencing t_lift_with_baseline_rate(id). The foreign-key link permits retrieval of the baseline rate that satisfies the pciDssRequirement restriction for any given directive entity.

```sql
SELECT d.x, b.y
FROM t_pci_dss_requirement d
JOIN t_lift_with_baseline_rate b ON d.y = b.id;
```

### 1.3 t_lift_with_baseline_rate

The table embodies Axiom 1. Column id is the primary key. Column x stores the Class declared a subclass of cco:DescriptiveICE. Column y is a foreign key referencing t_pci_dss_requirement(id). The mutual foreign-key relationship between this table and t_pci_dss_requirement allows bidirectional navigation between a lift expression and its governing directive.

```sql
SELECT l.x, r.x
FROM t_lift_with_baseline_rate l
JOIN t_pci_dss_requirement r ON l.y = r.id;
```

### 1.4 t_lift_with_support_count

The table embodies Axiom 4. Column id is the primary key. Column x stores the Class declared a subclass of cco:DescriptiveICE. Column y is a foreign key referencing t_pci_dss_requirement(id). The foreign-key column permits a three-table join that combines support-count data with both baseline-rate and directive information.

```sql
SELECT s.x, b.y, r.x
FROM t_lift_with_support_count s
JOIN t_pci_dss_requirement r ON s.y = r.id
JOIN t_lift_with_baseline_rate b ON r.y = b.id;
```

## 3 Cross-Join Example

The multi-hop query below retrieves the directive entity, its baseline-rate identifier, and the support-count identifier for the rule HighValueTxnLift. Execution walks the foreign-key chain t_lift_with_support_count.y → t_pci_dss_requirement.id → t_lift_with_baseline_rate.id.

```sql
SELECT s.x AS lift_class,
       r.x AS directive,
       b.id AS baseline_rate_id,
       s.id AS support_count_id
FROM t_lift_with_support_count s
JOIN t_pci_dss_requirement r ON s.y = r.id
JOIN t_lift_with_baseline_rate b ON r.y = b.id
WHERE s.x = 'HighValueTxnLift';
```

Result row:

lift_class = HighValueTxnLift, directive = Req-3.4-PAN-Masking, baseline_rate_id = BR-001, support_count_id = SC-001
