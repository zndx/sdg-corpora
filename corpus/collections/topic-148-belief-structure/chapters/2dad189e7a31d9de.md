# Association Rule Metrics for PCI DSS Requirement Classification

This chapter defines four relational tables that instantiate axioms for descriptive and directive information content entities. The tables capture baseline rates, support counts, and requirement linkages used in compliance pattern analysis. All rows satisfy the slot types and foreign-key constraints of the source axioms.

## 1 Scope and Table Organization

Section 2 presents each table together with the axiom it realizes. Primary-key columns uniquely identify individuals. Foreign-key columns enforce the existential restrictions stated in the Manchester axioms. Section 3 demonstrates a multi-hop query that traverses the foreign-key graph.

## 2 Tables and Axioms

### 2.1 t_lift_basic

This table embodies axiom 3. Column id is the primary key. Column x holds the class name of a descriptive information content entity. No foreign keys exist.

```sql
CREATE TABLE t_lift_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id       | x                          |
|----------|----------------------------|
| lb_001   | HighValueTxnRule           |
| lb_002   | EncryptionCheckPattern     |
| lb_003   | AccessLogRule              |
| lb_004   | PatchCompliancePattern     |
| lb_005   | NetworkSegmentRule         |

### 2.2 t_pci_dss_requirement

This table embodies axiom 2. Column id is the primary key. Column x names the directive class. Column y is a foreign key referencing t_lift_with_baseline_rate.id, satisfying the restriction sdg:pciDssRequirement some {Y}.

```sql
CREATE TABLE t_pci_dss_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_lift_with_baseline_rate(id)
);
```

## 3 Cross-Join Example

A compliance analyst requires the baseline rate class and support count class for requirement Req_3_ProtectCardholder. The query joins t_pci_dss_requirement on its primary key to both t_lift_with_baseline_rate (via y) and t_lift_with_support_count (via y).

```sql
SELECT r.x AS requirement,
       br.x AS baseline_class,
       sc.x AS support_class
FROM t_pci_dss_requirement r
JOIN t_lift_with_baseline_rate br ON r.y = br.id
JOIN t_lift_with_support_count sc ON r.id = sc.y
WHERE r.id = 'req_003';
```

Result row:

- requirement: Req_3_ProtectCardholder
- baseline_class: CardDataLift
- support_class: CardDataSupport
