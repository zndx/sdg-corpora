# Kernel Syscall Classification in eBPF Audit Trails

This chapter presents five relational tables that instantiate axioms for designative information content entities (ICEs) describing Linux syscalls. The tables support verification of subclass membership, subsystem placement, security tier assignment, return cardinality, and event invocation through primary-key and value-based joins on class references.

## 1 Table Embodiments of the Axioms

Each table directly encodes one Manchester axiom. The column `id` is the primary key. Columns `x` and `y` hold class references that serve as join keys across tables.

### 1.1 t_syscall_equiv_in_subsystem

This table embodies axiom 1, asserting equivalence of a designative ICE to membership in a syscall subsystem. The primary key `id` uniquely identifies each equivalence assertion; `y` is required and functions as a foreign reference to subsystem classes used in other tables.

```markdown
| id                        | x                  | y            |
|---------------------------|--------------------|--------------|
| equiv_file_open           | open               | file         |
| equiv_net_connect         | connect            | network      |
| equiv_proc_exec           | execve             | process      |
| equiv_mem_mmap            | mmap               | memory       |
| equiv_file_read           | read               | file         |
| equiv_net_send            | sendto             | network      |
```

### 1.2 t_syscall_at_security_tier

This table embodies axiom 2, placing each designative ICE at a security tier. The primary key `id` identifies the placement; `y` references tier classes that may be joined with return-type or event tables.

```markdown
| id                       | x                  | y            |
|--------------------------|--------------------|--------------|
| tier_open_user           | open               | user         |
| tier_connect_priv        | connect            | privileged   |
| tier_execve_kernel       | execve             | kernel       |
| tier_mmap_user           | mmap               | user         |
| tier_read_user           | read               | user         |
| tier_sendto_priv         | sendto             | privileged   |
| tier_clone_kernel        | clone              | kernel       |
```

### 1.3 t_syscall_max_one_return

This table embodies axiom 3, restricting each designative ICE to at most one return type. The primary key `id` identifies the restriction; `y` is nullable and references a return-type class.

```markdown
| id                        | x                  | y            |
|---------------------------|--------------------|--------------|
| ret_open_int              | open               | int          |
| ret_connect_int           | connect            | int          |
| ret_execve_int            | execve             | int          |
| ret_mmap_ptr              | mmap               | ptr          |
| ret_read_ssize            | read               | ssize_t      |
| ret_sendto_ssize          | sendto             | ssize_t      |
```

### 1.4 t_syscall_subclass

This table embodies axiom 4, asserting subclass membership of a designative ICE within a syscall subsystem. The primary key `id` identifies the assertion; `y` is required and references the same subsystem classes used in equivalence records.

```markdown
| id                         | x                  | y            |
|----------------------------|--------------------|--------------|
| sub_open_file              | open               | file         |
| sub_connect_network        | connect            | network      |
| sub_execve_process         | execve             | process      |
| sub_mmap_memory            | mmap               | memory       |
| sub_read_file              | read               | file         |
| sub_sendto_network         | sendto             | network      |
| sub_clone_process          | clone              | process      |
```

### 1.5 t_syscall_invoked_by_event

This table embodies axiom 5, linking each designative ICE to an invoking event class. The primary key `id` identifies the link; `y` is required and references event classes usable in further joins.

```markdown
| id                          | x                  | y               |
|-----------------------------|--------------------|-----------------|
| inv_open_sysenter           | open               | sysenter        |
| inv_connect_interrupt       | connect            | interrupt       |
| inv_execve_signal           | execve             | signal          |
| inv_mmap_pagefault          | mmap               | pagefault       |
| inv_read_sysenter           | read               | sysenter        |
| inv_sendto_interrupt        | sendto             | interrupt       |
```

## 2 Cross-Join Demonstration

A multi-hop query can determine the security tier and invoking event for any syscall that belongs to the file subsystem and possesses an integer return type. The query joins `t_syscall_subclass` on `x` with `t_syscall_at_security_tier` on `x`, then with `t_syscall_max_one_return` on `x`, and finally with `t_syscall_invoked_by_event` on `x`.

Example: locate the tier and event for `read`.

- Row from `t_syscall_subclass`: `sub_read_file`, `read`, `file`
- Matching row from `t_syscall_at_security_tier`: `tier_read_user`, `read`, `user`
- Matching row from `t_syscall_max_one_return`: `ret_read_ssize`, `read`, `ssize_t`
- Matching row from `t_syscall_invoked_by_event`: `inv_read_sysenter`, `read`, `sysenter`

Resulting joined tuple: (`read`, `file`, `user`, `ssize_t`, `sysenter`).
