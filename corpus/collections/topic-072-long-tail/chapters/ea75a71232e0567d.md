# Syscall Designative Information Content Entities

This chapter defines five relational tables that encode subclass and equivalence axioms for designative information content entities in syscall subsystems. The tables support direct foreign-key joins on the x and y columns to resolve multi-hop queries over subsystems, security tiers, return cardinalities, and invoking events.

## 1 Table Definitions and Axiom Embodiment

### 1.1 t_syscall_equiv_in_subsystem
This table embodies axiom 1 by recording equivalence between a designative ICE class X and membership in a syscall subsystem Y. Column id is the primary key; columns x and y function as entity references that may be joined to corresponding columns in the remaining tables.

```sql
CREATE TABLE t_syscall_equiv_in_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.2 t_syscall_at_security_tier
This table embodies axiom 2 by asserting that each designative ICE class X belongs to exactly one security tier Y. Column id is the primary key; x and y serve as join keys for cross-table resolution of tier constraints.

```sql
CREATE TABLE t_syscall_at_security_tier (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.3 t_syscall_max_one_return
This table embodies axiom 3 by restricting each designative ICE class X to at most one return type Y. Column id is the primary key; x is the join key while y may be null when no return type is declared.

```sql
CREATE TABLE t_syscall_max_one_return (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

### 1.4 t_syscall_subclass
This table embodies axiom 4 by placing each designative ICE class X inside a syscall subsystem Y. Column id is the primary key; x and y are foreign-key references usable for multi-table joins.

```sql
CREATE TABLE t_syscall_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.5 t_syscall_invoked_by_event
This table embodies axiom 5 by linking each designative ICE class X to an invoking event class Y. Column id is the primary key; x and y support joins that trace event provenance across subsystems and tiers.

```sql
CREATE TABLE t_syscall_invoked_by_event (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 2 Populated Instances

Each table contains six rows whose x values are consistent syscall classes and whose y values are drawn from the permitted ranges of subsystems, tiers, return types, and events.

### 2.1 t_syscall_equiv_in_subsystem rows
- sce_001, openat, file
- sce_002, connect, network
- sce_003, ptrace, process
- sce_004, bpf, kernel
- sce_005, clone, process
- sce_006, sendto, network

### 2.2 t_syscall_at_security_tier rows

- sat_002, connect, user
- sat_003, ptrace, kernel
- sat_004, bpf, kernel
- sat_005, clone, user
- sat_006, sendto, user

### 2.3 t_syscall_max_one_return rows
- smr_001, openat, fd

- sie_005, clone, sys_enter

## 3 Cross-Join Example
