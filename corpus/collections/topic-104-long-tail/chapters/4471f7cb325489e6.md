# Chapter 4: Modeling GDPR Directive Controls via Attestation and Verification Processes

This chapter introduces five interlinked ontological templates that formalize relationships among directives, lawful bases, evidence, and risk-addressing controls. The templates are realized as a five-table relational schema drawn from an audit-trail system used by the Birmingham Federation of Maintained Nursery Schools to document GDPR compliance activities. Each table is preceded by a description of the axiom it implements, its primary-key and foreign-key structure, and an example cross-table query. Data rows are restricted to values consistent with the slot types declared in the axioms.

## 1 Schema Overview and Domain Scope

The schema records how a DirectiveICE (a GDPR-relevant control or attestation) is linked to a lawful basis, produces or requires evidence, and addresses only permitted threat classes. Five tables implement the five axioms. Primary keys are string identifiers; foreign keys enforce the existential and universal restrictions expressed in the Manchester syntax. Cross-table joins therefore reconstruct the multi-hop chains required by the ontology (for example, “which verification produced the evidence supporting an attestation that rests on a given lawful basis?”).

## 2 Tables Derived from the Axioms

Axiom 2 states that a DirectiveICE has lawful basis some GDPR lawful basis class. The table therefore stores pairs of directive identifiers and lawful-basis identifiers. ## 3 Worked Multi-Hop Query Example

Question: “Which verification process produced the evidence supporting the attestation that rests on the Consent lawful basis, and which control addresses the associated threat class?”

Step 1. Start at t_attestation_with_supporting_evidence where y = 'lb-01'.  
Result row: (att-01, PolicyAttestation, lb-01).

Step 2. Join t_verification_produces_evidence on y = 'lb-01'.  
Result row: (vpe-01, AnnualAudit, lb-01).

Step 3. Join t_control_only_addresses_threat_class on y = 'lb-01'.  
Result row: (ctl-01, DataAccessControl, lb-01).

Joined result (one row):  
attestation=PolicyAttestation, verification=AnnualAudit, control=DataAccessControl, lawful_basis=Consent, threat_reference=lb-01.

The same pattern can be repeated for any other lawful basis by substituting the foreign-key value.
