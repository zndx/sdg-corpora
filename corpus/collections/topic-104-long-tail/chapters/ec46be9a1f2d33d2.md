# Chapter 7: Directive Governance Models for GDPR-Compliant Evidence Chains

This chapter defines five relational tables that instantiate the axioms attestation_with_supporting_evidence, gdpr_lawful_basis, verification_produces_evidence, control_only_addresses_threat_class, and control_with_evidence_requirement. The tables record classes of processing activities, lawful bases, controls, verifications, and attestations that satisfy the subclass and existential restrictions stated in each axiom. Primary and foreign keys enforce the directed relationships required by the Manchester syntax expressions.

## 1. Axiom Instantiation via Schema

Each table corresponds to one axiom. Column values are drawn from a closed set of class identifiers that represent GDPR-relevant entities such as processing activities, consent records, and risk controls. Foreign-key constraints implement the “some” and “only” restrictions; cross-table joins therefore reconstruct the chains of evidence and lawful-basis dependencies required by the ontology.

### 1.1 t_gdpr_lawful_basis

This table embodies axiom 2. Column id is the primary key. Column y is a foreign key referencing t_control_only_addresses_threat_class.id, thereby linking each lawful-basis class to the single threat class it may address.

## 2. Cross-Join Example

To determine which controls address threats under a lawful basis that also carries an attestation, join t_control_only_addresses_threat_class to t_gdpr_lawful_basis on y = id, then to t_attestation_with_supporting_evidence on lb.id = att.y. The join on lb_001 yields:

ctl_003 (EncryptionAtRest) addresses threat via lb_001 (ConsentBasedProcessing) attested by att_001 (ThirdPartyAuditReport).

The same pattern applied to lb_003 yields ctl_002 linked to att_003 and att_005, demonstrating two distinct evidence packages for the same lawful basis.
