# Regulatory Compliance Data Model for Municipal Facilities

This chapter defines a minimal relational schema that encodes five ontological axioms governing directive information content entities, artifacts, and supporting processes. The schema supports traceability from postal addresses through requirements, verifications, enforcements, and attestations. All tables are presented with primary-key and foreign-key constraints that permit deterministic cross-table joins.

## 1 Schema Overview

The five tables implement the slot structures of the supplied axioms without extension or omission. Column domains follow the declared slot types: entity references for classes and individuals, typed literals for data properties. Foreign-key declarations enforce the participation constraints expressed in the Manchester axioms.

### 1.1 t_schemaorg_place_address

This table embodies Axiom 1 (schemaorg_place_address), recording artifacts that possess postal addresses. Column id is the primary key; column y is a foreign key referencing t_requirement_equiv_specifies_target(id), allowing a place to be resolved to the requirement that specifies it.

```sql
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

### 1.2 t_requirement_equiv_specifies_target

This table embodies Axiom 2 (requirement_equiv_specifies_target), capturing directive information content entities that both specify a target and apply to a further class. Column id is the primary key; columns y and z are foreign keys to t_schemaorg_place_address(id).

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_schemaorg_place_address(id)
);
```

### 1.3 t_requirement_min_one_verification

This table embodies Axiom 3 (requirement_min_one_verification), asserting that each directive must be verified by at least one artifact. Column id is the primary key; column y is a foreign key to t_schemaorg_place_address(id).

This table embodies Axiom 5 (attestation_with_supporting_evidence), linking processes to the evidence artifacts that support them. Column id is the primary key; column y is a foreign key to t_schemaorg_place_address(id).

## 2 Cross-Join Example

To retrieve the postal address of the place that both verifies a requirement and supplies supporting evidence for an attestation, join t_requirement_min_one_verification to t_schemaorg_place_address on y, then join that address row to t_attestation_with_supporting_evidence on y. The query path traverses three tables via two foreign-key links.

Execution on the populated rows yields:

- Requirement: VAT Registration Directive (ver_020)
- Verified at address: addr_001 (Birstall Parish Council Offices)
- Evidence supplied by attestation: att_042 (Planning Meeting Record Attestation)
