# Chapter 4: Directive Information Content Entities in Municipal Planning Records

This chapter presents five relational tables that instantiate five OWL axioms governing artifacts, directive information content entities, and processes. The tables encode postal addresses of planning sites, requirements that specify targets and apply to locations, verification and enforcement constraints, and attestations backed by evidence. Primary and foreign keys enable cross-table traversal that recovers multi-hop facts such as the verification status of a requirement applicable to a given address.

## 1. Schemaorg Place Address Table

Axiom 1 states that an artifact bears a postal address. The table therefore stores the artifact identifier in column x and the linked requirement identifier in column y. Column id is the primary key; column y is a foreign key into t_requirement_equiv_specifies_target, permitting a join that recovers the directive that names the address.

| id                  | x                       | y                       |
|---------------------|-------------------------|-------------------------|
| addr_001            | 45 Birstall Road        | req_010                 |
| addr_002            | 12 Council Offices      | req_011                 |
| addr_003            | 7 Leicester Lane        | req_012                 |
| addr_004            | 22 Park View            | req_013                 |
| addr_005            | 3 High Street           | req_014                 |

## 2. Requirement Equiv Specifies Target Table

Axiom 2 defines a directive information content entity that both specifies a target and applies to a location. Column id is the primary key. Columns y and z are foreign keys into t_schemaorg_place_address, allowing retrieval of the address that satisfies the specification and the address to which the requirement applies.

| id                  | x                       | y                       | z                       |
|---------------------|-------------------------|-------------------------|-------------------------|
| req_010             | PlanningPermission      | addr_001                | addr_002                |
| req_011             | NoiseLimit              | addr_003                | addr_001                |
| req_012             | HeightRestriction       | addr_004                | addr_005                |
| req_013             | DrainagePlan            | addr_002                | addr_003                |
| req_014             | AccessRoute             | addr_005                | addr_004                |

## 6. Cross-Join Demonstration

To determine the evidence artifact supporting the verification of the requirement that applies to address addr_001, first join t_requirement_equiv_specifies_target (z = addr_001) to t_requirement_min_one_verification on x, then join the resulting y to t_attestation_with_supporting_evidence on y. The joined row is:

req_010, addr_001, ver_020, addr_001, att_040, addr_001
