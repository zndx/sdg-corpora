# Regulatory Compliance Ontologies in Audit Traceability Models

This chapter defines five core ontological patterns for compliance claims in regulatory filings and presents their projection into a relational schema. The patterns address claim support, evidence requirements, artifact lineage, anomaly detection, and attestation. All examples are drawn from insurance regulation amendments and SEC quarterly reports.

## 1 Scope and Domain Selection

The selected domain is audit-trail management for insurance regulation amendments (11 NYCRR) and SEC Form 10-Q filings. Compliance claims are treated as descriptive information content entities that must be supported by evidence traces, column lineage artifacts, kernel anomalies, and attestations. The five tables below implement the axioms while permitting cross-table joins that answer multi-hop regulatory questions.

## 2 Tables and Axiom Embodiment

### 2.1 Trace Support for Claims

Axiom 1 (trace_supports_claim) is embodied by table t_trace_supports_claim. Column id is the primary key; column x holds the class of the supporting trace. A reader can join this table to any evidence table on x to retrieve the concrete trace instances that satisfy a given claim.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| TR-001 | Fifth_Amendment_Trace |
| TR-002 | Quarterly_10Q_Trace |
| TR-003 | Form_Amendment_Trace |
| TR-004 | Regulation_206_Trace |
| TR-005 | Insurance_Regulation_Trace |

### 2.2 Minimum Evidence Requirement

Axiom 2 (claim_min_one_evidence) is embodied by table t_claim_min_one_evidence. Column id is the primary key; column x identifies the claim class; column y is a foreign key referencing t_trace_supports_claim.id. The NOT NULL constraint on y enforces the “min 1” cardinality. A reader can join on y to list every required trace for a claim and then traverse further to attestation records.

```sql
CREATE TABLE t_claim_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_trace_supports_claim(id)
);
```

### 2.4 Kernel Anomaly Support

Axiom 4 (kernel_anomaly_supports_claim) is embodied by table t_kernel_anomaly_supports_claim. Column id is the primary key; column x holds the anomaly artifact class. These artifacts participate in the same support relation as traces and can be joined on descriptive identifiers to the evidence table.

```sql
CREATE TABLE t_kernel_anomaly_supports_claim (
```

Axiom 5 (attestation_about_compliance_claim) is embodied by table t_attestation_about_compliance_claim. Column id is the primary key; column x holds the attestation process class. The table records the processes that close the evidence chain for each claim.

## 3 Multi-Hop Query Example

Question: Which attestation process covers the compliance claim that is supported by the Fifth Amendment trace and also carries a missing-amendment anomaly?

Step 1. Locate the trace: SELECT id FROM t_trace_supports_claim WHERE x = 'Fifth_Amendment_Trace' → TR-001.  
Step 2. Locate the evidence record: SELECT id, x FROM t_claim_min_one_evidence WHERE y = 'TR-001' → EV-100, Compliance_Claim_Form20.  
Step 3. Locate the supporting anomaly: SELECT id FROM t_kernel_anomaly_supports_claim WHERE x = 'Missing_Amendment_Anomaly' → AN-300 (joined on shared claim identifier Compliance_Claim_Form20).  
Step 4. Locate the attestation: SELECT x FROM t_attestation_about_compliance_claim WHERE id IN (SELECT id FROM t_claim_min_one_evidence WHERE x = 'Compliance_Claim_Form20') → SEC_Officer_Attestation.

The joined result row is: (EV-100, Compliance_Claim_Form20, TR-001, AN-300, AT-400).
