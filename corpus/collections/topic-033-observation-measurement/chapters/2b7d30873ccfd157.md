# PCI DSS Directive Governance in Audit Ontologies

This chapter presents five relational tables that instantiate OWL axioms for processes, directives, and attestations in PCI DSS compliance. The tables support cross-table joins that resolve multi-hop queries over conducted audits, requirements, verifications, satisfactions, and attestation periods.

## 1 Audit and Requirement Modeling

The axioms define classes of processes and directive information content entities together with their participation in conducted-by, verified-by, satisfied-by, and attestation relations. The relational projections preserve the existential and universal restrictions as foreign-key constraints.

### 1.1 Table t_audit_conducted_by

Axiom 1 classifies an audit process as a bfo:Process conducted by a person. Column id is the primary key; column x holds the process identifier.

| id     | x                  |
|--------|--------------------|
| ACB-01 | AnnualPCIReview    |
| ACB-02 | Q4MerchantScan     |
| ACB-03 | NetworkSegTest     |
| ACB-04 | AccessControlAudit |

A reader can join this table to any requirement table on process identifiers to list audits performed by named personnel.

### 1.2 Table t_pci_dss_requirement

Axiom 2 asserts that a directive is a cco:DirectiveICE possessing at least one PCI DSS requirement. Column id is the primary key; column y is a foreign key to t_requirement_min_one_verification.id.

| id      | x                    | y          |
|---------|----------------------|------------|
| REQ-10  | Req_1_1_Firewall     | VER-01     |
| REQ-11  | Req_2_1_VendorCreds  | VER-02     |
| REQ-12  | Req_3_4_PANMask      | VER-03     |
| REQ-13  | Req_4_1_EncryptTrans | VER-01     |
| REQ-14  | Req_6_2_PatchMgt     | VER-04     |

Joining on y yields the minimum verification class required for each directive.

### 1.3 Table t_requirement_min_one_verification

Axiom 3 states that a directive must be verified by at least one class. Column id is the primary key; column y is a foreign key to t_pci_dss_requirement.id, establishing the reciprocal link required by the paired axioms.

| id     | x                 | y       |
|--------|-------------------|---------|
| VER-01 | ExternalASVScan   | REQ-10  |
| VER-02 | QuarterlyRotaTest | REQ-11  |
| VER-03 | AnnualPenTest     | REQ-12  |
| VER-04 | ChangeControlLog  | REQ-14  |

A cross-join between t_pci_dss_requirement and t_requirement_min_one_verification on the mutual foreign keys recovers the closed set of directives and their mandatory verification classes.

### 1.4 Table t_requirement_only_satisfied_by

Axiom 4 restricts satisfaction of a directive to members of a designated class only. Column id is the primary key; column y is a foreign key to t_pci_dss_requirement.id.

| id      | x                 | y       |
|---------|-------------------|---------|
| SAT-01  | ApprovedVendor    | REQ-11  |
| SAT-02  | TokenizationSvc   | REQ-12  |
| SAT-03  | TLS1_2Endpoint    | REQ-13  |
| SAT-04  | PatchCABoard      | REQ-14  |

Joining on y lists, for each requirement, the sole class permitted to satisfy it.

### 1.5 Table t_attestation_at_period

Axiom 5 places an attestation process at a specific period class. Column id is the primary key; column y is a foreign key to t_pci_dss_requirement.id.

| id      | x               | y       |
|---------|-----------------|---------|
| ATT-01  | 2023Q4          | REQ-10  |
| ATT-02  | 2024Q1          | REQ-11  |
| ATT-03  | 2024Q1          | REQ-13  |
| ATT-04  | 2024Q2          | REQ-14  |

Joining on y associates each attested requirement with its temporal scope.

## 2 Cross-Join Demonstration

To determine which verification class must accompany the requirement satisfied solely by TLS1_2Endpoint and attested in 2024Q1, first locate the requirement identifier in t_requirement_only_satisfied_by where x equals TLS1_2Endpoint, yielding y = REQ-13. Next locate the verification class in t_requirement_min_one_verification where y = REQ-13, returning ExternalASVScan. Finally confirm the attestation period via t_attestation_at_period where y = REQ-13, returning 2024Q1. The joined row is therefore (REQ-13, ExternalASVScan, 2024Q1).
