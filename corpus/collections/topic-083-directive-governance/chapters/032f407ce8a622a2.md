# Directive Governance in Regulatory Compliance Auditing

This chapter specifies five relational tables that realize core axioms of directive governance. The tables capture supersession among policies, evidence production by verification processes, attestations supported by evidence, evidence requirements attached to controls, and jurisdictional scope of policies. All rows are drawn from compliance records of an Ontario energy-sector audit program conducted between 2012 and 2018.

## 1 Policy Supersession

Table t_policy_supersedes embodies axiom policy_supersedes. Column id is the primary key. Columns x and y are entity references to directive instances; y records the directive superseded by x. A reader can join this table to t_policy_with_jurisdiction on y = x to retrieve the jurisdiction formerly held by a superseded policy.

```sql
CREATE TABLE t_policy_supersedes (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 2 Evidence Production by Verification

Table t_verification_produces_evidence embodies axiom verification_produces_evidence. Column id is the primary key. Columns x and y are entity references; x denotes a verification process and y the evidence item it produces. Joining on y to the y column of t_attestation_with_supporting_evidence yields the attestation that later cites the produced evidence.

```sql
CREATE TABLE t_verification_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 3 Attestation Supported by Evidence

Table t_attestation_with_supporting_evidence embodies axiom attestation_with_supporting_evidence. Column id is the primary key. Columns x and y are entity references; x denotes an attestation process and y the supporting evidence. A cross-join with t_verification_produces_evidence on y = y recovers the verification process that originally generated the cited evidence.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 4 Evidence Requirement of Controls

Table t_control_with_evidence_requirement embodies axiom control_with_evidence_requirement. Column id is the primary key. Columns x and y are entity references; x denotes a control directive and y the evidence class it requires. Joining on y to t_verification_produces_evidence shows which verification processes can satisfy the control.

```sql
CREATE TABLE t_control_with_evidence_requirement (
  id VARCHAR(255),
```

## 5 Jurisdictional Scope of Policies

Table t_policy_with_jurisdiction embodies axiom policy_with_jurisdiction. Column id is the primary key. Columns x and y are entity references; x denotes a policy and y its jurisdictional scope. A reader can join on x to t_policy_supersedes.x to list all jurisdictions affected by a supersession chain.

```sql
CREATE TABLE t_policy_with_jurisdiction (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 6 Multi-Hop Query Example

Question: Which jurisdiction applies to the control that requires evidence produced by the verification whose output supports the 2017 attestation?

Walk the links:  
- Start at t_attestation_with_supporting_evidence where x = "Compliance Attestation 2017"; y = "Report-902".  
- Join to t_verification_produces_evidence on y = "Report-902"; x = "Annual Site Audit 2017".  
- Join to t_control_with_evidence_requirement on y = "Report-902"; x = "EB-2017-0301".  
- Join to t_policy_with_jurisdiction on x = "EB-2017-0301"; y = "Ontario Energy Board".

Result row: (attestation: Compliance Attestation 2017, verification: Annual Site Audit 2017, control: EB-2017-0301, jurisdiction: Ontario Energy Board).
