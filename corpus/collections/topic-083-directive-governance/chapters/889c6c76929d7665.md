# Directive Governance in Regulated Laboratory Compliance

This chapter specifies five relational tables that implement directive governance axioms for compliance verification in an ISO/IEC 17025-accredited testing laboratory. The tables encode policy supersession, evidence production, attestation support, evidence requirements, and jurisdictional scope. Primary keys are system-generated identifiers; foreign-key relationships exist between the x and y columns across tables, enabling multi-hop queries over policies, verifications, attestations, controls, and jurisdictions.

## 1 Policy Supersession

Axiom 1 (policy_supersedes) is embodied by table t_policy_supersedes. Column id is the primary key. Columns x and y are entity references; y is a foreign key to any prior policy identifier appearing as x in the same table or as x in t_policy_with_jurisdiction. A reader can join on y = x to retrieve the chain of superseding policies that remain in force within a given jurisdiction.

```sql
CREATE TABLE t_policy_supersedes (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 2 Verification Evidence Production

Axiom 2 (verification_produces_evidence) is embodied by table t_verification_produces_evidence. Column id is the primary key. Column x references a verification process; column y is a foreign key to evidence identifiers that appear as y in t_attestation_with_supporting_evidence. Joining x to a control identifier in t_control_with_evidence_requirement yields the evidence generated by each required verification.

```sql
CREATE TABLE t_verification_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 3 Attestation with Supporting Evidence

Axiom 3 (attestation_with_supporting_evidence) is embodied by table t_attestation_with_supporting_evidence. Column id is the primary key. Column x references an attestation process; column y is a foreign key to evidence produced by verifications. A cross-join on y with t_verification_produces_evidence links each attestation to the verifications that supplied its supporting evidence.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 4 Control Evidence Requirements

Axiom 4 (control_with_evidence_requirement) is embodied by table t_control_with_evidence_requirement. Column id is the primary key. Column x references a directive control; column y is a foreign key to verification processes. Joining y to t_verification_produces_evidence shows the evidence that satisfies each control’s requirement.

```sql
CREATE TABLE t_control_with_evidence_requirement (
  id VARCHAR(255),
```

## 5 Policy Jurisdiction

Axiom 5 (policy_with_jurisdiction) is embodied by table t_policy_with_jurisdiction. Column id is the primary key. Column x references a policy; column y is a foreign key to jurisdiction identifiers. A join on x with t_policy_supersedes returns only those superseding policies whose jurisdiction matches a required accreditation scope.

```sql
CREATE TABLE t_policy_with_jurisdiction (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 6 Multi-Hop Query Example

Question: Which evidence items satisfy the equipment calibration control under the jurisdiction of ISO-17025 and were produced by a verification required by that control?

Execution path:  
1. Select rows from t_control_with_evidence_requirement where x = 'EQU-CAL-CTRL' → yields verification 'CAL-VER-2023'.  
2. Join t_verification_produces_evidence on x = 'CAL-VER-2023' → yields evidence 'CAL-REC-331'.  
3. Confirm jurisdiction by joining the policy 'QM-2023' (via t_policy_supersedes if needed) to t_policy_with_jurisdiction where y = 'ISO-17025'.

(control = EQU-CAL-CTRL, verification = CAL-VER-2023, evidence = CAL-REC-331, jurisdiction = ISO-17025)
