# Municipal Record Linkage: Places, Addresses, and Descriptive Claims

This chapter defines a minimal relational schema that implements three ontology axioms for linking physical meeting places to descriptive information content entities. The schema supports multi-hop queries over town conservation commission records by treating addresses and geo-coordinates as foreign-key references to claim instances.

## 1. Ontology-to-Relation Mapping

The three axioms are realized by exactly three tables. t_outlier_claim_basic stores instances of cco:DescriptiveICE. Both t_schemaorg_place_address and t_schemaorg_place_geocoord store cco:Artifact individuals whose postal-address or geo-coordinate slots are satisfied by foreign-key references into the claim table. Primary keys are opaque identifiers; foreign keys enforce the existential restrictions stated in the axioms.

### 1.1 t_outlier_claim_basic

This table embodies Axiom 2. Column id is the primary key and serves as the stable referent for any descriptive claim. Column x holds the human-readable label of the claim.

### 1.2 t_schemaorg_place_address

This table embodies Axiom 3. Column id is the primary key of the place artifact. Column x names the place. Column y is a foreign key to t_outlier_claim_basic.id and supplies the required postal-address individual.

| id | x | y |
| id | x | y |

This table embodies Axiom 1. Column id is the primary key of the place artifact. Column x names the place. Column y is a foreign key to t_outlier_claim_basic.id and supplies the required geo-coordinate individual.

## 2. Cross-Join Example

Question: “Which descriptive claim supplies both the postal address and the geo-coordinates for the physical location used by the January 10, 2017 meeting?”

Walk the foreign keys:

- Start at t_outlier_claim_basic row claim-2017-01.
- Join t_schemaorg_place_address.y = claim-2017-01 yields no row.
- Join t_schemaorg_place_address.y = claim-addr-hines (the address claim referenced by the same meeting notice) returns place-hinesburg-th.
- Join t_schemaorg_place_geocoord.y = claim-geo-hines returns the same place-hinesburg-th.

Resulting joined row (abbreviated):

place-hinesburg-th | Hinesburg Town Hall | claim-addr-hines | claim-geo-hines

The two foreign-key traversals confirm that the single descriptive claim chain (claim-2017-01 → claim-addr-hines / claim-geo-hines) satisfies both address and coordinate axioms for the same artifact.
