# Chapter 11: Directive Governance Patterns in Food Processing Compliance

This chapter presents five relational tables that implement core axioms of directive governance. The tables record attestations, verifications, controls, and audits that arise in regulatory oversight of food processing units. Each table follows a deterministic projection of an OWL axiom; primary keys identify individual process or directive instances while the x and y columns encode the axiom’s class arguments, enabling cross-table joins that reconstruct multi-step compliance chains.

## 1. Table Definitions and Axiom Embodiment

### 1.1 Attestation with Supporting Evidence
The table t_attestation_with_supporting_evidence embodies AXIOM 1. Column id is the primary key for each attestation instance; column x references the attested process while column y references the supporting evidence class. A reader can join this table to t_verification_produces_evidence on y = x to retrieve the verification process that generated the cited evidence.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.2 Verification Produces Evidence
The table t_verification_produces_evidence embodies AXIOM 2. Column id is the primary key for each verification process; x identifies the verification activity and y identifies the evidence class it produces. Joining this table to t_audit_with_findings on y = x yields the audit that consumed the produced evidence.

### 1.3 Control Only Addresses Threat Class
The table t_control_only_addresses_threat_class embodies AXIOM 3. Column id is the primary key for each directive instance; x identifies the control and y the sole risk class it may address. Because the axiom uses “only”, every row asserts an exhaustive restriction.

```sql
CREATE TABLE t_control_only_addresses_threat_class (
```

### 1.4 Control Addresses Risk
The table t_control_addresses_risk embodies AXIOM 4. Column id is the primary key; x identifies the control and y a risk it addresses. Multiple rows may share the same x, reflecting that a single directive can address several risks.

```sql
CREATE TABLE t_control_addresses_risk (
```

### 1.5 Audit with Findings
The table t_audit_with_findings embodies AXIOM 5. Column id is the primary key for each audit process; x identifies the audit and y the finding class it records. Joining this table to t_control_addresses_risk on y = x recovers the control whose addressed risk was examined by the audit.

## 2. Cross-Join Demonstration

Consider the multi-hop question: “Which evidence supported the attestation of the control that addresses SupplyDisruptionRisk and was examined in ComplianceAudit-2020Q1?”

Start with t_control_addresses_risk where y = 'SupplyDisruptionRisk' to obtain x = 'GrievanceRedressalCell'.  
Join t_attestation_with_supporting_evidence on x = 'GrievanceRedressalCell' to obtain y = 'PIBNotice20200326'.  
Join t_verification_produces_evidence on y = 'PIBNotice20200326' to confirm the producing verification.  
Finally join t_audit_with_findings on x = 'ComplianceAudit-2020Q1' and y = 'SupplyDisruptionRisk' to close the chain.

The resulting joined row is:

GrievanceRedressalCell → PIBNotice20200326 (produced by ver-001) → examined in aud-001.
