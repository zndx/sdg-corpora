# Regulatory Directive Governance Models

This chapter defines five relational tables that instantiate axioms for directive governance, designative information content entities, and verification processes. The schema supports cross-table joins that trace policy review cycles, requirement priorities, and evidence-producing verifications within a net-zero energy compliance audit domain.

## 1 Scope and Table Overview

The tables embody five OWL axioms that classify directives, attach review cycles and priorities, and require evidence from verification processes. Primary keys are synthetic identifiers; foreign keys enforce references exclusively to `t_designative_subclass_basic`. All rows are consistent with the Manchester axioms supplied in the chapter specification.

### 1.1 t_designative_subclass_basic

This table directly realizes AXIOM 2 by recording subclasses of `cco:DesignativeICE`. Column `id` is the primary key; column `x` holds the class name. No foreign keys exist.

```sql
SELECT x FROM t_designative_subclass_basic WHERE id = 'DSB-003';
```

| id      | x                    |
|---------|----------------------|
| DSB-001 | ReviewCycle          |
| DSB-002 | PriorityLevel        |
| DSB-003 | EvidenceType         |
| DSB-004 | VerificationMethod   |
| DSB-005 | RequirementClass     |
| DSB-006 | PolicyIdentifier     |
| DSB-007 | AuditFinding         |

### 1.3 t_policy_with_review_cycle

This table realizes AXIOM 1 by linking a directive class to a review-cycle designative entity. Column `id` is the primary key; column `y` is a foreign key to `t_designative_subclass_basic(id)`.

```sql
SELECT p.x, d.x
FROM t_policy_with_review_cycle p
JOIN t_designative_subclass_basic d ON p.y = d.id;
```

| id      | x                  | y       |
|---------|--------------------|---------|
| PRC-001 | NetZeroPolicy      | DSB-001 |
| PRC-002 | EnerguideRating    | DSB-001 |
| PRC-003 | ComplianceCertificate | DSB-001 |
| PRC-004 | ReviewSchedule     | DSB-001 |

## 2 Cross-Join Example

Question: Which priority is attached to the NetZeroPolicy that is verified by a process producing EvidenceType evidence?

Step 1. Locate the policy in `t_policy_with_review_cycle` (PRC-001).  
Step 2. Join `t_requirement_has_priority` on the shared class name to obtain priority (DSB-002).  
Step 3. Join `t_verification_min_one_evidence` on the evidence foreign key to confirm the verification process.

Resulting joined row:

- policy: NetZeroPolicy  
- review_cycle: ReviewCycle  
- priority: PriorityLevel  
- verification: SiteInspection  
- evidence: EvidenceType
