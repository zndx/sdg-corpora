# Chapter 7: Process Verification and Attestation in Directive Governance

This chapter defines four tables that instantiate the axioms verification_min_one_evidence, verification_basic, audit_basic, and attestation_min_one_signer. The tables record processes that satisfy the BFO:Process classification together with the minimum cardinality restrictions on evidence production and signer participation. Primary keys are the id columns; foreign-key relationships are realized by matching x values across tables and by the y column in t_verification_min_one_evidence, which references evidence individuals required by the axiom.

## 1 Ontology-to-Relation Mapping

Each axiom projects directly to one table. The id column supplies a stable identifier for each asserted process individual. The x column records the process class or individual that satisfies the BFO:Process superclass. Additional columns capture the existential restrictions.

### 1.1 t_verification_min_one_evidence

This table embodies the axiom Class: {X:Class} SubClassOf: bfo:0000015, sdg:producesEvidence min 1 {Y:Class}. The primary key is id. The column y is a mandatory foreign-key reference to an evidence individual; every row therefore satisfies the minimum-one-evidence restriction. A reader can join on x to locate the same process recorded in t_verification_basic and then follow y to retrieve the supporting evidence record.

This table embodies the axiom Class: {X:Class} SubClassOf: bfo:0000015. The primary key is id. No further cardinality restrictions apply. Rows may be joined to t_verification_min_one_evidence on matching x values to determine which verification processes also carry evidence.

This table embodies the axiom Class: {X:Class} SubClassOf: bfo:0000015. The primary key is id. It records audit processes that participate in governance reporting chains. Cross-table joins on x reveal which audit processes are also attested or verified.

### 1.4 t_attestation_min_one_signer

This table embodies the axiom Class: {X:Class} SubClassOf: bfo:0000015, sdg:signedBy min 1 cco:Person. The primary key is id. Although the minimum-signer restriction is enforced at the axiom level, the table stores only the attested process; signer individuals are maintained in an external person registry referenced by operational queries.
