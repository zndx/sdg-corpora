# Chapter 4: Event-Observed Descriptive Entities in Laboratory Records

This chapter defines two ontological templates that classify descriptive information content entities by their observation at bfo:0000015 events. The templates are realized as relational tables whose rows serve as instances. Cross-table joins on shared class references recover multi-hop provenance such as the event context of a given claim or metric.

## 1 Scope and Table Construction

Two tables are supplied. Each table directly implements one axiom. Column “id” is the primary key. Column “x” holds the class that satisfies the SubClassOf restriction to cco:DescriptiveICE observedAt some bfo:0000015. No foreign-key columns are declared inside these tables; joins are performed on values of “x” that match class identifiers maintained in an external event registry.

### 1.1 t_claim_observed_by_event

This table embodies axiom claim_observed_by_event. Its primary key “id” uniquely identifies each claim instance; its column “x” stores the class asserted to be a descriptive information content entity observed at an event.

```sql
CREATE TABLE t_claim_observed_by_event (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id          | x                          |
|-------------|----------------------------|
| claim001    | SampleIntegrityStatement   |
| claim002    | ContaminationFlag          |
| claim003    | CalibrationDueNotice       |
| claim004    | BatchReleaseDeclaration    |

### 1.2 t_metric_observed_by_event

This table embodies axiom metric_observed_by_event. Its primary key “id” uniquely identifies each metric instance; its column “x” stores the class asserted to be a descriptive information content entity observed at an event.

```sql
CREATE TABLE t_metric_observed_by_event (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id         | x                       |
|------------|-------------------------|
| metric001  | TemperatureReading      |
| metric002  | pHValue                 |
| metric003  | TurbidityUnit           |
| metric004  | ConductivityResult      |
| metric005  | MassDeviation           |

## 2 Cross-Join Demonstration

To recover the event context for claim “claim001” and metric “metric001”, join both tables on matching values of “x” against an external event log whose rows contain the same class identifiers. The joined result yields:

- claim001 linked to event E-2023-104 via SampleIntegrityStatement  
- metric001 linked to the same event via TemperatureReading  

The single joined row therefore answers the multi-hop question: “Which descriptive entities were recorded for sample S at event E-2023-104 operated under technician T?” by returning the pair (SampleIntegrityStatement, TemperatureReading).
