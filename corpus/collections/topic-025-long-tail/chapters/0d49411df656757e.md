# Laboratory Observation Records in Process Monitoring Systems

This chapter defines two ontological templates for descriptive information content entities observed at events and demonstrates their projection into a minimal relational schema. The schema supports laboratory information management for coating process validation, where claims and metrics attach to discrete observation events. All entity references remain consistent with the slot types Class and Individual.

## 1. Domain Scope and Table Construction

The chosen domain is laboratory monitoring of alkyd emulsion production batches. Observation events record surface temperature and visual quality attributes of plastic-coated test panels. Two axiom templates are realized directly as tables; a supporting event table supplies the bfo:0000015 instances required by the observedAt restrictions.

### 1.1 t_observation_event
This table supplies the event individuals required by both axioms. Column id is the primary key. Column panel_ref is a foreign key to an external sample register (values shown for join illustration only). Each row represents one bfo:0000015 instance.

```
id                  | panel_ref     | start_time
--------------------|---------------|--------------------
EVT-001             | PANEL-2800-03 | 2003-10-07 14:00
EVT-002             | PANEL-2800-03 | 2003-10-07 16:30
EVT-003             | PANEL-2800-04 | 2003-10-08 09:15
EVT-004             | PANEL-2800-04 | 2003-10-08 11:45
```

### 1.2 t_claim_observed_by_event
This table embodies AXIOM 1. Column id is the primary key. Column x holds the Class identifier of the DescriptiveICE instance. Column event_id is a foreign key to t_observation_event.id, enforcing the observedAt restriction.

```
id                  | x                        | event_id
--------------------|--------------------------|----------
CLM-101             | SurfaceDefectClaim       | EVT-001
CLM-102             | SurfaceDefectClaim       | EVT-002
CLM-103             | AdhesionFailureClaim     | EVT-003
CLM-104             | ColorDeviationClaim      | EVT-004
CLM-105             | SurfaceDefectClaim       | EVT-004
```

### 1.3 t_metric_observed_by_event
This table embodies AXIOM 2. Column id is the primary key. Column x holds the Class identifier of the DescriptiveICE instance. Column event_id is a foreign key to t_observation_event.id.

```
id                  | x                        | event_id
--------------------|--------------------------|----------
MTR-201             | SurfaceTemperatureMetric | EVT-001
MTR-202             | SurfaceTemperatureMetric | EVT-002
MTR-203             | SurfaceTemperatureMetric | EVT-003
MTR-204             | FilmThicknessMetric      | EVT-004
```

## 2. Cross-Join Example

To retrieve the SurfaceTemperatureMetric value recorded on panel PANEL-2800-03 by technician T-07 using equipment TC-2800, join the three tables on the shared event identifiers:

```
SELECT e.panel_ref, m.x, e.start_time
FROM t_observation_event e
JOIN t_metric_observed_by_event m ON m.event_id = e.id
WHERE e.panel_ref = 'PANEL-2800-03'
  AND m.x = 'SurfaceTemperatureMetric';
```

Result rows:

```
panel_ref     | x                        | start_time
--------------|--------------------------|--------------------
PANEL-2800-03 | SurfaceTemperatureMetric | 2003-10-07 14:00
PANEL-2800-03 | SurfaceTemperatureMetric | 2003-10-07 16:30
```

The same pattern extends to claims by substituting t_claim_observed_by_event, confirming that any DescriptiveICE instance is reachable from its observation event in one join step.
