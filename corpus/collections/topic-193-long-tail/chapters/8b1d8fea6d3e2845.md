# Directive Governance in Product Conformity Systems

This chapter defines five relational tables that implement axioms for directive and descriptive information content entities. The tables capture minimum cardinality constraints on enforcement, evidence support, ownership, and scope restriction to artifacts. All column values are drawn from EU-style declarations and audit records for electromechanical products.

## 1 Table Definitions and Axiom Embodiment

### 1.1 t_policy_basic
This table embodies AXIOM 3 by recording every instance of a directive information content entity. Column id is the primary key; column x holds the class name of the directive.

```sql
CREATE TABLE t_policy_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id  | x                  |
|-----|--------------------|
| pb1 | RED_2014_53_EU     |
| pb2 | Machinery_2006_42  |
| pb3 | EMC_2014_30_EU     |
| pb4 | RoHS_2011_65_EU    |
| pb5 | LowVoltage_2014_35 |

### 1.2 t_policy_min_one_enforcer
This table embodies AXIOM 1 by asserting that each directive is enforced by at least one descriptive claim. Column id is the primary key; column y is a foreign key referencing t_claim_min_one_evidence.id.

```sql
CREATE TABLE t_policy_min_one_enforcer (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_claim_min_one_evidence(id)
);
```

| id   | x                  | y     |
|------|--------------------|-------|
| pe1  | RED_2014_53_EU     | ce1   |
| pe2  | Machinery_2006_42  | ce2   |
| pe3  | EMC_2014_30_EU     | ce3   |
| pe4  | RoHS_2011_65_EU    | ce4   |
| pe5  | LowVoltage_2014_35 | ce5   |

### 1.3 t_claim_min_one_evidence
This table embodies AXIOM 2 by asserting that each descriptive claim is supported by at least one policy enforcer record. Column id is the primary key; column y is a foreign key referencing t_policy_min_one_enforcer.id.

```sql
CREATE TABLE t_claim_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_policy_min_one_enforcer(id)
);
```

| id  | x                       | y   |
|-----|-------------------------|-----|
| ce1 | ConformityDeclaration   | pe1 |
| ce2 | RiskAssessmentReport    | pe2 |
| ce3 | EMC_TestCertificate     | pe3 |
| ce4 | SubstanceDeclaration    | pe4 |
| ce5 | SafetyTestReport        | pe5 |

### 1.4 t_control_min_one_owner
This table embodies AXIOM 4 by recording every directive that possesses at least one owner. Column id is the primary key; column x holds the directive class.

```sql
CREATE TABLE t_control_min_one_owner (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id  | x                  |
|-----|--------------------|
| co1 | RED_2014_53_EU     |
| co2 | Machinery_2006_42  |
| co3 | EMC_2014_30_EU     |

### 1.5 t_policy_only_governs_artifacts
This table embodies AXIOM 5 by restricting directive scope exclusively to artifact classes. Column id is the primary key; column x holds the directive class.

```sql
CREATE TABLE t_policy_only_governs_artifacts (
```

## 2 Cross-Join Example

To retrieve the evidence claim supporting the RED directive and the policy record that in turn supports that claim, execute:

```sql
SELECT pe.x AS policy, ce.x AS claim, pe2.x AS supporting_policy
FROM t_policy_min_one_enforcer pe
JOIN t_claim_min_one_evidence ce ON pe.y = ce.id
JOIN t_policy_min_one_enforcer pe2 ON ce.y = pe2.id
WHERE pe.x = 'RED_2014_53_EU';
```

Result row: policy=RED_2014_53_EU, claim=ConformityDeclaration, supporting_policy=RED_2014_53_EU.
