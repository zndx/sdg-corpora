# Research Governance Ontologies in Audit Trails

This chapter defines five relational tables that instantiate OWL axioms for directive information content entities and descriptive information content entities within university research administration. The tables capture minimum cardinality constraints on enforcement, evidence support, ownership, and scope restriction while preserving foreign-key integrity for cross-table navigation.

## 1 Policy and Claim Mutual Constraints

Two tables implement the paired axioms requiring a directive to be enforced by at least one descriptive claim and a claim to be supported by at least one directive.

### 1.1 Table t_policy_min_one_enforcer

Axiom 1 states that every instance of a directive information content entity must be linked to at least one descriptive information content entity via the enforcedBy relation. The primary key is the surrogate identifier id; the foreign key y references the primary key of t_claim_min_one_evidence, ensuring that each policy row resolves to a valid claim row. A reader can therefore join on y to retrieve the supporting claim text for any given policy identifier.

| pol_enf_001               | ResearchDataRetentionDirective         | clm_evd_003                |
| pol_enf_002               | HumanSubjectsOversightDirective        | clm_evd_001                |
| pol_enf_003               | EquipmentCalibrationDirective          | clm_evd_002                |
| pol_enf_004               | ConflictOfInterestDisclosureDirective  | clm_evd_004                |
| pol_enf_005               | DataSharingAgreementDirective          | clm_evd_005                |

### 1.2 Table t_claim_min_one_evidence

Axiom 2 states that every descriptive information content entity must be supported by at least one directive information content entity. The primary key is id; the foreign key y references the primary key of t_policy_min_one_enforcer. Joining on y yields the directive that the claim substantiates.

## 2 Standalone Directive Tables

Three additional tables represent simpler or differently constrained subclasses of directive information content entities.

### 2.1 Table t_policy_basic

Axiom 3 classifies an entity solely as a directive information content entity without further cardinality restrictions. The sole primary key is id; column x holds the class name of the directive.

| id                        | x                                      |
|---------------------------|----------------------------------------|
| pol_bas_001               | TravelPreApprovalDirective             |
| pol_bas_002               | PurchasingThresholdDirective           |
| pol_bas_003               | PublicationAcknowledgementDirective    |
| pol_bas_004               | LaboratoryAccessDirective              |

### 2.2 Table t_control_min_one_owner

Axiom 4 requires every directive to have at least one owner of type Person. The primary key is id; column x stores the directive class. Ownership is asserted outside the table via an external person registry referenced by application logic.

| id                        | x                                      |
|---------------------------|----------------------------------------|
| ctl_own_001               | BudgetReallocationControl              |
| ctl_own_002               | SafetyIncidentReportingControl         |
| ctl_own_003               | IntellectualPropertyAssignmentControl  |
| ctl_own_004               | VendorPerformanceReviewControl         |
| ctl_own_005               | StudentDataAccessControl               |

### 2.3 Table t_policy_only_governs_artifacts

Axiom 5 restricts the governsScope relation of a directive to instances of Artifact only. The primary key is id; column x records the directive class whose scope is thereby limited.

| pol_art_002               | ServerLogRetentionDirective            |

## 3 Cross-Join Demonstration

To determine which claim supports the ResearchDataRetentionDirective and which policy that claim in turn enforces, execute the following mental join:

Start with t_policy_min_one_enforcer where x = ResearchDataRetentionDirective (row pol_enf_001). Follow foreign key y to t_claim_min_one_evidence row clm_evd_003. The resulting joined tuple is (pol_enf_001, ResearchDataRetentionDirective, clm_evd_003, RetentionScheduleAdherenceClaim, pol_enf_001). This two-hop path confirms mutual satisfaction of the minimum-enforcer and minimum-evidence axioms.
