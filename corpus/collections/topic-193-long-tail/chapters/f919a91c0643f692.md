# Chapter 7: DirectiveICE and DescriptiveICE Modeling in Regulatory Compliance Records

This chapter specifies five relational tables that instantiate the ontology axioms for directive and descriptive information content entities. The tables capture minimum cardinality constraints on enforcement, evidence support, ownership, and scope restriction while preserving primary-key and foreign-key integrity for cross-table navigation.

## 1 Policy and Claim Tables

### 1.1 t_policy_min_one_enforcer

Axiom 1 states that every instance of a policy class is a directive information content entity enforced by at least one descriptive information content entity. The table therefore records the required enforcer link. Column id is the primary key. Column y is a foreign key referencing t_claim_min_one_evidence.id. A reader can join on y to retrieve the supporting claim for any given policy.

| id | x | y |
| id | x | y |
| pol-001 | FosterCareLicensureDirective | clm-003 |
| pol-002 | EquipmentCalibrationDirective | clm-001 |
| pol-003 | DataRetentionDirective | clm-004 |
| pol-004 | IncidentReportingDirective | clm-002 |
| pol-005 | HomeStudyDirective | clm-005 |

### 1.2 t_claim_min_one_evidence

Axiom 2 states that every instance of a claim class is a descriptive information content entity supported by at least one directive information content entity. The table therefore records the required evidence link. Column id is the primary key. Column y is a foreign key referencing t_policy_min_one_enforcer.id. A reader can join on y to retrieve the enforcing policy for any given claim.

| id | x | y |
| id | x | y |
| clm-001 | CalibrationRecordClaim | pol-002 |
| clm-002 | ReportingTimelinessClaim | pol-004 |
| clm-003 | LicensureValidityClaim | pol-001 |
| clm-004 | RetentionPeriodClaim | pol-003 |
| clm-005 | StudyCompletionClaim | pol-005 |

### 1.3 t_policy_basic

Axiom 3 states that a class is a directive information content entity without additional cardinality restrictions. The table therefore stores simple policy instances. Column id is the primary key. No foreign keys are present. A reader can select any row to obtain an unrestricted directive entity for further joins with t_policy_min_one_enforcer.

| id | x |
| id | x |
| pol-006 | MeetingNoticeDirective |
| pol-007 | EULAAcceptanceDirective |

### 1.4 t_control_min_one_owner

Axiom 4 states that every control class is a directive information content entity that has at least one person owner. The table therefore stores control instances satisfying the ownership constraint. Column id is the primary key. No foreign keys are declared. A reader can cross-reference any control id against t_policy_min_one_enforcer.id to locate an enforcing claim.

| id | x |
| id | x |
| ctl-001 | AccessControl |
| ctl-002 | ChangeControl |
| ctl-003 | ReviewControl |
| ctl-004 | ApprovalControl |
| ctl-005 | DistributionControl |

### 1.5 t_policy_only_governs_artifacts

Axiom 5 states that a policy class is a directive information content entity whose governance scope is restricted to artifacts only. The table therefore stores policy instances satisfying the scope restriction. Column id is the primary key. No foreign keys are declared. A reader can join any policy id with t_claim_min_one_evidence.y to verify artifact-governed claims.

| id | x |
| id | x |
| pol-011 | ArtifactVersioningPolicy |
| pol-012 | DocumentRetentionPolicy |
| pol-013 | EquipmentLabelingPolicy |
| pol-014 | RecordSealingPolicy |
| pol-015 | SampleChainPolicy |

## 2 Cross-Table Navigation Example

To answer the multi-hop question “Which claim supports the directive that enforces the timeliness claim for incident reporting?”, begin with row pol-004 in t_policy_min_one_enforcer. Its y value is clm-002. Row clm-002 in t_claim_min_one_evidence has y value pol-004, confirming the circular support link. The joined result row is therefore:

pol-004 | IncidentReportingDirective | clm-002 | ReportingTimelinessClaim | pol-004
