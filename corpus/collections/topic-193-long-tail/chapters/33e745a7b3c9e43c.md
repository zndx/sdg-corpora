# Directive and Descriptive Information Content Entities in Governance Schemas

This chapter introduces five relational tables that instantiate OWL axioms for directive information content entities (DirectiveICE) and descriptive information content entities (DescriptiveICE). The tables capture minimum cardinality constraints on enforcement, evidence support, ownership, and scope restriction to artifacts. All column values are drawn from instances of policy notices, session descriptions, and conference records.

## 1 Policy and Claim Axioms

The axioms require that every policy instance belongs to DirectiveICE and satisfies at least one enforcement link, while every claim instance belongs to DescriptiveICE and is backed by at least one evidence link. The following tables encode these constraints directly through primary-key and foreign-key declarations.

### 1.1 Basic Policy Table

Table t_policy_basic embodies axiom policy_basic. Column id is the primary key; column x holds the DirectiveICE identifier. No foreign keys are present.

| id | x |
| id | x |
| p_basic_01 | NoticeOfPublicMeeting |
| p_basic_02 | SessionOverview |
| p_basic_03 | ConferenceCall |
| p_basic_04 | PolicyDirective |

### 1.2 Policy with Minimum One Enforcer

Table t_policy_min_one_enforcer embodies axiom policy_min_one_enforcer. Column id is the primary key; column x holds the DirectiveICE identifier; column y is a foreign key referencing t_claim_min_one_evidence.id. A reader can join on y to retrieve the supporting claim for any enforced policy.

| id | x | y |
| id | x | y |
| p_enf_01 | NoticeOfPublicMeeting | c_evd_01 |
| p_enf_02 | SessionOverview | c_evd_02 |
| p_enf_03 | ConferenceCall | c_evd_03 |
| p_enf_04 | PolicyDirective | c_evd_04 |

### 1.3 Claim with Minimum One Evidence

Table t_claim_min_one_evidence embodies axiom claim_min_one_evidence. Column id is the primary key; column x holds the DescriptiveICE identifier; column y is a foreign key referencing t_policy_min_one_enforcer.id. A reader can join on y to retrieve the enforcing policy for any evidenced claim.

| id | x | y |
| id | x | y |
| c_evd_01 | ComplianceClaim | p_enf_01 |
| c_evd_02 | HearingLossClaim | p_enf_02 |
| c_evd_03 | RealTimeClaim | p_enf_03 |
| c_evd_04 | ScopeClaim | p_enf_04 |

### 1.4 Control with Minimum One Owner

Table t_control_min_one_owner embodies axiom control_min_one_owner. Column id is the primary key; column x holds the DirectiveICE identifier that must possess at least one owner of type Person. No foreign keys are declared.

| id | x |
| id | x |
| ctrl_01 | MeetingNoticeControl |
| ctrl_02 | AudiologySessionControl |
| ctrl_03 | RTNSProgramControl |

### 1.5 Policy Restricted to Artifact Scope

Table t_policy_only_governs_artifacts embodies axiom policy_only_governs_artifacts. Column id is the primary key; column x holds the DirectiveICE identifier whose governed scope is restricted to Artifact. No foreign keys are declared.

| id | x |
| id | x |

| p_art_02 | HearingProgramPolicy |
| p_art_03 | NetworkSystemsPolicy |

## 2 Cross-Table Query Example

To determine the DescriptiveICE claim that supports enforcement of the NoticeOfPublicMeeting policy, first locate the row in t_policy_min_one_enforcer where x equals NoticeOfPublicMeeting. Its y value (c_evd_01) is then used as the primary key in t_claim_min_one_evidence. The joined result yields:

- Policy: NoticeOfPublicMeeting (p_enf_01)
- Enforced by claim: ComplianceClaim (c_evd_01)
- Claim references back to: p_enf_01

The same pattern extends to t_control_min_one_owner and t_policy_only_governs_artifacts by matching x values across tables when an analyst requires owner or scope verification.
