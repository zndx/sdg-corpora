# Directive Information Content Entities in Research Governance

This chapter presents five relational tables that instantiate axioms for directive and descriptive information content entities. The tables model policy enforcement, claim support, ownership, and scope constraints within doctoral research administration at French higher education institutions. Primary and foreign keys enable verification of minimum cardinality constraints and cross-table navigation.

## 1 Axiom Instantiation Through Tables

### 1.1 Policy with Minimum Enforcer

Axiom 1 states that every instance of a directive information content entity must be enforced by at least one descriptive information content entity. Table t_policy_min_one_enforcer therefore records the required link. Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_claim_min_one_evidence. A reader can join on y to retrieve the supporting claim for any given policy.

| id  | x                          | y   |
|-----|----------------------------|-----|
| pe1 | DataRetentionDirective     | c1  |
| pe2 | EthicsApprovalDirective    | c2  |
| pe3 | PublicationMandate         | c1  |
| pe4 | IPDisclosureDirective      | c3  |
| pe5 | DataSharingDirective       | c2  |

### 1.2 Claim with Minimum Evidence

Axiom 2 states that every descriptive information content entity must be supported by at least one directive information content entity. Table t_claim_min_one_evidence records the reciprocal link. Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_policy_min_one_enforcer. Joining on y yields the policy that a claim supports.

| id  | x                       | y   |
|-----|-------------------------|-----|
| c1  | RetentionClaim2020      | pe1 |
| c2  | EthicsClaim2021         | pe2 |
| c3  | IPClaim2022             | pe4 |
| c4  | SharingClaim2023        | pe5 |

### 1.3 Basic Policy

Axiom 3 classifies an entity solely as a directive information content entity without additional cardinality constraints. Table t_policy_basic therefore contains only the identifier and the entity name. Column id is the primary key. No foreign keys are present; the table serves as a reference list for standalone policies.

| id  | x                          |
|-----|----------------------------|
| pb1 | LaboratoryAccessPolicy     |
| pb2 | EquipmentCalibrationPolicy |
| pb3 | SafetyProtocolPolicy       |
| pb4 | BudgetReportingPolicy      |
| pb5 | TravelAuthorizationPolicy  |
| pb6 | ConflictOfInterestPolicy   |

### 1.4 Control with Minimum Owner

Axiom 4 requires every directive information content entity that functions as a control to have at least one person as owner. Table t_control_min_one_owner records such controls. Column id is the primary key. The table is independent of the enforcement tables yet shares the same bfo anchor class.

| id  | x                          |
|-----|----------------------------|
| co1 | AccessControlDirective     |
| co2 | CalibrationControl         |
| co3 | SafetyControlDirective     |
| co4 | BudgetControlDirective     |
| co5 | TravelControlDirective     |

### 1.5 Policy Governing Only Artifacts

Axiom 5 restricts the governance scope of a directive information content entity to artifacts only. Table t_policy_only_governs_artifacts lists policies satisfying this universal restriction. Column id is the primary key. The table is independent yet can be joined manually to enforcement tables via shared policy names.

| id  | x                          |
|-----|----------------------------|
| pa1 | DataRetentionDirective     |
| pa2 | PublicationMandate         |
| pa3 | IPDisclosureDirective      |
| pa4 | DataSharingDirective       |
| pa5 | EquipmentCalibrationPolicy |

## 2 Cross-Table Query Example

To determine which claim supports the enforcement of DataRetentionDirective, first locate the row in t_policy_min_one_enforcer where x equals DataRetentionDirective (pe1). The foreign key value in column y is c1. The matching row in t_claim_min_one_evidence supplies the claim name RetentionClaim2020. The two-row join therefore returns the tuple (pe1, DataRetentionDirective, c1, RetentionClaim2020).
