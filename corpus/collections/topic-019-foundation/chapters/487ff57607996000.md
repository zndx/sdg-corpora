# Kernel Syscall Classification and eBPF Verification

This chapter presents five relational tables that encode axioms for syscall designative information content entities and eBPF artifacts. The tables support joins on shared class references to resolve multi-hop queries about security tier, subsystem membership, verification status, audit coverage, and return-type cardinality.

## 1 Schema Overview

The tables derive directly from the supplied OWL axioms. Each row instantiates a class-level assertion. Primary keys are opaque identifiers; the x and y columns hold class references that serve as join keys across tables.

### 1.1 t_syscall_at_security_tier

This table embodies axiom 1. Column id is the primary key. Column x names a syscall class; column y names its required security tier. A reader can join on x to locate every tier constraint for a given syscall.

```sql
CREATE TABLE t_syscall_at_security_tier (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_001 | open | USER |
| id_002 | read | USER |
| id_003 | write | KERNEL |
| id_004 | execve | USER |
| id_005 | connect | KERNEL |
| id_006 | mmap | KERNEL |

### 1.2 t_syscall_equiv_in_subsystem

This table embodies axiom 2. Column id is the primary key. Column x names a syscall class; column y names its containing subsystem. Joins on x reveal subsystem membership for any syscall already constrained by tier.

```sql
CREATE TABLE t_syscall_equiv_in_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_101 | open | FS |
| id_102 | read | FS |
| id_103 | write | FS |
| id_104 | execve | PROC |
| id_105 | connect | NET |
| id_106 | mmap | VM |

### 1.3 t_ebpfprogram_verified_safe

This table embodies axiom 3. Column id is the primary key. Column x names an eBPF program class; column y names its verifier. Joins on y link verified programs to the syscalls they instrument.

```sql
CREATE TABLE t_ebpfprogram_verified_safe (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_201 | fs_audit | BPF_VERIFIER |
| id_202 | net_monitor | LLVM |
| id_203 | proc_trace | BPF_VERIFIER |
| id_204 | vm_guard | LLVM |
| id_205 | sec_enforce | BPF_VERIFIER |

### 1.4 t_syscall_audited_by

This table embodies axiom 4. Column id is the primary key. Column x names a syscall class that must be audited. Absence of a y column indicates the audit relation is unary.

```sql
CREATE TABLE t_syscall_audited_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
| id_301 | open |
| id_302 | execve |
| id_303 | connect |
| id_304 | mmap |
| id_305 | write |

### 1.5 t_syscall_max_one_return

This table embodies axiom 5. Column id is the primary key. Column x names a syscall class; column y (nullable) names its single permitted return type when present.

```sql
CREATE TABLE t_syscall_max_one_return (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_401 | open | FD |
| id_402 | read | SIZE |
| id_403 | write | SIZE |
| id_404 | execve | PID |
| id_405 | connect | ERR |
| id_406 | mmap | ADDR |

## 2 Cross-Table Query Example

Question: which eBPF program, verified by BPF_VERIFIER, instruments the open syscall that must be audited, belongs to the FS subsystem, and is constrained to USER tier with return type FD?

Execution proceeds by successive equi-joins on x:

- t_syscall_at_security_tier.x = 'open' yields tier USER.
- t_syscall_equiv_in_subsystem.x = 'open' yields subsystem FS.
- t_syscall_audited_by.x = 'open' confirms audit requirement.
- t_syscall_max_one_return.x = 'open' yields return FD.
- t_ebpfprogram_verified_safe.y = 'BPF_VERIFIER' and linkage via shared subsystem context yields program fs_audit.

Result row after join:

fs_audit | BPF_VERIFIER | open | USER | FS | audited | FD

The same pattern extends to any other syscall by substituting the x value and repeating the four joins.
