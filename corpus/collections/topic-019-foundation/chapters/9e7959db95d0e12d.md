# Chapter 4: Designative Information Content Entities in eBPF Syscall Subsystems

This chapter defines five ontological templates that classify syscall designative information content entities and eBPF program artifacts according to security tier, subsystem membership, verification status, audit provenance, and return-type cardinality. The templates are realized as a five-table relational schema whose primary and foreign keys enable cross-table resolution of multi-hop queries over kernel audit records.

## 1 Ontological Templates and Relational Projection

The templates are drawn directly from the supplied OWL axioms. Each template is projected to one table whose columns correspond to the axiom’s slot types. Primary keys identify individual template instances; foreign-key columns hold references to other template instances or to external class identifiers, permitting joins that reconstruct the original class expressions.

### 1.1 Syscall Security Tier Assignment

Axiom 1 states that a class X is a subclass of cco:DesignativeICE and stands in the sdg:atSecurityTier relation to a class Y. Table t_syscall_at_security_tier materializes this relation. Column id is the primary key. Column x references a syscall designative entity; column y references a security-tier class. A reader can join this table to t_syscall_equiv_in_subsystem on x to retrieve both the tier and the subsystem of any given syscall.

```sql
CREATE TABLE t_syscall_at_security_tier (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|----|----|
| tier_001 | syscall_openat | tier_3 |
| tier_002 | syscall_read | tier_2 |
| tier_003 | syscall_write | tier_2 |
| tier_004 | syscall_close | tier_1 |
| tier_005 | syscall_mmap | tier_3 |
| tier_006 | syscall_clone | tier_3 |

### 1.2 Syscall Subsystem Equivalence

Axiom 2 declares that class X is equivalent to the intersection of cco:DesignativeICE and the existential restriction sdg:inSyscallSubsystem some Y. Table t_syscall_equiv_in_subsystem records the equivalence. Column id is the primary key. Columns x and y are mutually referential with corresponding columns in the other tables, allowing a join that recovers the full equivalent-class expression.

```sql
CREATE TABLE t_syscall_equiv_in_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|----|----|
| subsys_001 | syscall_openat | file_io |
| subsys_002 | syscall_read | file_io |
| subsys_003 | syscall_write | file_io |
| subsys_004 | syscall_close | file_io |
| subsys_005 | syscall_mmap | memory |

### 1.3 eBPF Program Verification Status

Axiom 3 places class X as a subclass of cco:Artifact and asserts that it is verifiedSafeBy some class Y. Table t_ebpfprogram_verified_safe implements the assertion. Column id is the primary key. Column x identifies an eBPF program artifact; column y identifies the verifier class. Joining on x with t_syscall_audited_by yields both verification and audit history for the same artifact.

```sql
CREATE TABLE t_ebpfprogram_verified_safe (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |

| verify_002 | prog_read_filter | verifier_v2 |
| verify_003 | prog_write_limit | verifier_v1 |
| verify_004 | prog_mmap_check | verifier_v2 |
| verify_005 | prog_clone_audit | verifier_v3 |

### 1.4 Audit Provenance

Axiom 4 states that class X is a subclass of cco:DesignativeICE and stands in the sdg:auditedBy relation to an instance of bfo:0000015. Table t_syscall_audited_by records the relation. Column id is the primary key; column x references a syscall designative entity. Because the table contains only one foreign-key column, it functions as a leaf node that other tables join to for provenance retrieval.

```sql
CREATE TABLE t_syscall_audited_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|----|
| audit_001 | syscall_openat |
| audit_002 | syscall_read |
| audit_003 | syscall_write |
| audit_004 | syscall_mmap |
| audit_005 | syscall_clone |

### 1.5 Return-Type Cardinality Constraint

Axiom 5 restricts class X to at most one return type Y. Table t_syscall_max_one_return captures the restriction. Column id is the primary key. Column x references a syscall; column y, when non-null, names the single permitted return type. A three-way join among this table, t_syscall_at_security_tier, and t_syscall_equiv_in_subsystem recovers the complete signature and security metadata for any syscall.

```sql
CREATE TABLE t_syscall_max_one_return (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|----|----|
| ret_001 | syscall_openat | int |
| ret_002 | syscall_read | ssize_t |
| ret_003 | syscall_write | ssize_t |
| ret_004 | syscall_close | int |
| ret_005 | syscall_mmap | void* |
| ret_006 | syscall_clone | pid_t |
