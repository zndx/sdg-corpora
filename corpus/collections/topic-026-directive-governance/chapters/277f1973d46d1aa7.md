# Directive Governance Models in Regulatory Audit Systems

This chapter defines five tables that instantiate OWL axioms for directive governance. The tables support cross-table joins that resolve multi-hop queries over lawful bases, jurisdictions, attestations, controls, and signatures in a compliance audit trail.

## 1. Table t_gdpr_lawful_basis

Axiom 1 states that a directive instance has a lawful basis that is itself a policy with jurisdiction. Column id is the primary key. Column y is a foreign key to t_policy_with_jurisdiction.id. A reader can join on y to retrieve the jurisdiction governing each lawful basis.

| id | x | y |
|----|---|---|
| LB-001 | Consent-Processing | PJ-010 |
| LB-002 | Contractual-Necessity | PJ-011 |
| LB-003 | Legal-Obligation | PJ-012 |
| LB-004 | Vital-Interests | PJ-010 |
| LB-005 | Public-Task | PJ-013 |

## 1.1 Table t_policy_with_jurisdiction

Axiom 2 states that a directive instance has a jurisdiction. Column id is the primary key. Column y is a foreign key to t_gdpr_lawful_basis.id. Joining on y yields the lawful basis that authorizes each jurisdictional policy.

| id | x | y |
|----|---|---|
| PJ-010 | EU-Member-State | LB-001 |
| PJ-011 | EEA-Agreement | LB-002 |
| PJ-012 | National-Statute | LB-003 |
| PJ-013 | Sectoral-Regulation | LB-005 |

## 1.2 Table t_attestation_with_supporting_evidence

Axiom 3 states that a process instance carries supporting evidence. Column id is the primary key. Column y is a foreign key to t_gdpr_lawful_basis.id. Joining on y links each attestation to the lawful basis under which its evidence was collected.

| id | x | y |
|----|---|---|
| AT-100 | Safety-Committee-Review | LB-003 |

## 1.3 Table t_control_with_evidence_requirement

Axiom 4 states that a directive instance requires evidence. Column id is the primary key. Column y is a foreign key to t_gdpr_lawful_basis.id. Joining on y shows which lawful basis mandates the evidence for each control.

## 1.4 Table t_attestation_signed_by

Axiom 5 states that a process instance is signed by a person. Column id is the primary key. No foreign-key column exists; linkage occurs through shared attestation identifiers used in application queries.

|----|---|
| AT-100 | J. A. Cyr |

## 2. Cross-Join Example

To answer “which person signed the attestation whose supporting evidence rests on the lawful basis authorized by jurisdiction PJ-010,” first locate LB-001 in t_gdpr_lawful_basis (y = PJ-010). Join to t_attestation_with_supporting_evidence on y to obtain AT-100. Join AT-100 to t_attestation_signed_by on id to obtain signer J. A. Cyr. The joined row is:

AT-100 | Safety-Committee-Review | LB-003 | PJ-010 | J. A. Cyr
