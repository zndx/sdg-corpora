# Chapter 4: Modeling Compliance Claims and Attestations

This chapter presents five relational tables that instantiate the ontology axioms trace_supports_claim, attestation_signed_by, gdpr_lawful_basis, kernel_anomaly_supports_claim and column_lineage_for_compliance_claim. The tables capture directed relationships between process classes, persons, lawful bases and descriptive information content entities within an audit-trail schema for data-processing records.

## 1 Schema Overview

The schema uses a minimal set of tables whose primary keys serve as stable identifiers for the classes that satisfy each axiom. Foreign-key references exist only where the gdpr_lawful_basis axiom explicitly requires a link to an attestation. All other tables remain independent, allowing direct inspection of the class that supports or is signed by a given entity.

### 1.1 t_trace_supports_claim

This table embodies the trace_supports_claim axiom by recording each class X that is a subclass of bfo:0000015 and supports a descriptive information content entity. Column id is the primary key; column x holds the class reference.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id | x |
|----|---|
| trc-001 | DataAccessTrace |
| trc-002 | ConsentVerificationTrace |
| trc-003 | RetentionCheckTrace |
| trc-004 | ExportLogTrace |
| trc-005 | DeletionAuditTrace |

### 1.2 t_attestation_signed_by

This table embodies the attestation_signed_by axiom by recording each class X that is a subclass of bfo:0000015 and is signed by a person. Column id is the primary key; column x holds the class reference.

```sql
CREATE TABLE t_attestation_signed_by (
```

### 1.3 t_gdpr_lawful_basis

This table embodies the gdpr_lawful_basis axiom by recording each directive information content entity X that has lawful basis Y. Column id is the primary key; column x holds the directive class; column y is a foreign key referencing t_attestation_signed_by(id).

```sql
CREATE TABLE t_gdpr_lawful_basis (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_signed_by(id)
);
```

Example rows:

| id | x | y |
|----|---|---|
| glb-001 | ConsentDirective | att-001 |
| glb-002 | ContractDirective | att-002 |
| glb-003 | LegalObligationDirective | att-004 |
| glb-004 | VitalInterestsDirective | att-003 |
| glb-005 | PublicTaskDirective | att-005 |

## 2 Cross-Table Query Example

To determine the lawful basis asserted by a signed attestation, join t_gdpr_lawful_basis to t_attestation_signed_by on the foreign-key column y. The query

```sql
SELECT g.x AS directive, a.x AS attestation
FROM t_gdpr_lawful_basis g
JOIN t_attestation_signed_by a ON g.y = a.id
WHERE a.id = 'att-004';
```

returns the single row (LegalObligationDirective, LawfulBasisConfirmation). The result shows that the attestation class LawfulBasisConfirmation supplies the signed evidence required by the LegalObligationDirective lawful-basis claim.
