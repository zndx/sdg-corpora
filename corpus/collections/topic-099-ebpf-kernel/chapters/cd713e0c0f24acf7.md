# Audit Trails for Regulatory Compliance

This chapter defines two core ontological patterns for modeling attestations and evidentiary traces within audit trail systems. The patterns are realized as a minimal relational schema that supports verification of signer identity and claim provenance through primary-key and foreign-key references.

## 1. Ontological Patterns

### 1.1 Attestation Signed by Person
The pattern classifies a process as one that must be signed by a person. In the relational projection the table records each qualifying process instance; the column x holds the identifier of the attested process.

### 1.2 Trace Supports Claim
The pattern classifies a descriptive information content entity as one that supports a claim. In the relational projection the table records each qualifying trace instance; the column x holds the identifier of the supported claim.

## 2. Supporting Entity Tables

Two auxiliary tables supply the entity references required by the foreign-key values stored in the pattern tables.

### 2.1 Persons
The table supplies signer identities referenced by attestation records.

```sql
CREATE TABLE t_persons (
  person_id VARCHAR(255) PRIMARY KEY,
  full_name VARCHAR(255)
);
```

### 2.2 Claims
The table supplies the claim identifiers referenced by trace records.

```sql
CREATE TABLE t_claims (
  claim_id VARCHAR(255) PRIMARY KEY,
  statement VARCHAR(255)
);
```

## 3. Pattern Tables

### 3.1 Attestation Signed by Person
The table embodies axiom 1. Column id is the primary key of each attested process record. Column x is a foreign key that resolves to a person_id, establishing the required signer relationship. A reader can join t_attestation_signed_by.x to t_persons.person_id to retrieve the signer of any attested process.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255)
);
```

### 3.2 Trace Supports Claim
The table embodies axiom 2. Column id is the primary key of each trace record. Column x is a foreign key that resolves to a claim_id, establishing the support relationship. A reader can join t_trace_supports_claim.x to t_claims.claim_id to retrieve the claim supported by any given trace.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255)
);
```

## 4. Cross-Join Example

To determine which person signed the attestation that produced a trace supporting claim C-47, first locate the trace row whose x equals C-47, then locate the attestation row whose id matches the trace id, then resolve the attestation x to the person row. The joined result is:

- trace id = TR-203, x = C-47
- attestation id = TR-203, x = P-112
- person person_id = P-112, full_name = "Elena Voss"
