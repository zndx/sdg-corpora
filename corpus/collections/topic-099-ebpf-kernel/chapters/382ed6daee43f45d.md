# Chapter 7: Attestation and Trace Structures in Regulatory Compliance Records

This chapter specifies two ontological templates for processes that participate in directive governance and long-tail evidence chains. The templates are realized in a minimal relational schema drawn from audit-trail systems that record regulatory submissions. All class and individual references conform to the supplied axioms; foreign-key values are restricted to identifiers declared in the same schema.

## 1. Axiom Definitions

### 1.1 Attestation Signed by Person
Axiom 1 states that a member of class bfo:0000015 may stand in the relation sdg:signedBy to an instance of cco:Person. The corresponding table records each such attestation event by storing a unique identifier for the attestation and a reference to the signing person.

### 1.2 Trace Supports Claim
Axiom 2 states that a member of class cco:DescriptiveICE may stand in the relation sdg:supportsClaim to another instance of cco:DescriptiveICE. The corresponding table records each supporting trace by storing a unique identifier for the trace and a reference to the claim it supports.

## 2. Relational Realization

Four tables implement the axioms while satisfying primary-key and foreign-key constraints required for multi-table queries. Column order follows the deterministic projection given in each axiom comment.

### 2.1 Table t_person
This reference table enumerates persons who may sign attestations. Its single-column primary key supplies the range of the foreign-key column x in t_attestation_signed_by.

```sql
CREATE TABLE t_person (
  person_id VARCHAR(255) PRIMARY KEY
);
```

### 2.2 Table t_descriptive_ice
This reference table enumerates descriptive information content entities that may serve as claims. Its single-column primary key supplies the range of the foreign-key column x in t_trace_supports_claim.

```sql
CREATE TABLE t_descriptive_ice (
  ice_id VARCHAR(255) PRIMARY KEY
);
```

### 2.3 Table t_attestation_signed_by
This table embodies Axiom 1. Column id is the primary key of the attestation instance; column x is a foreign key referencing t_person.person_id. A reader can therefore retrieve the signing person for any attestation by joining on x.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255) REFERENCES t_person(person_id)
);
```

### 2.4 Table t_trace_supports_claim
This table embodies Axiom 2. Column id is the primary key of the trace instance; column x is a foreign key referencing t_descriptive_ice.ice_id. A reader can therefore retrieve the supported claim for any trace by joining on x.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255) REFERENCES t_descriptive_ice(ice_id)
);
```

## 3. Cross-Join Demonstration

Consider the multi-hop question: which person signed the attestation that produced a trace supporting claim C-2020-06? Resolve the question by the following joins:

1. Locate the trace whose x equals C-2020-06 in t_trace_supports_claim.
2. Use the trace identifier to locate the attestation that generated it (via an implicit link maintained outside these tables but consistent with bfo:0000015 participation).
3. Join the attestation identifier to t_attestation_signed_by on id, then to t_person on x.
