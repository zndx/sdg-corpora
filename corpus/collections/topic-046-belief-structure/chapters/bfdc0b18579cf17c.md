# Audit Trails for Syscall Classification

This chapter defines the subclass relation that classifies certain entities as designative information content entities audited by processes, and shows how the relation is represented in a minimal relational schema supporting multi-table joins.

## 1 Ontological Classification

The axiom states that any class X satisfying the given restrictions is a subclass of cco:DesignativeICE and stands in the auditedBy relation to an instance of bfo:0000015. The restriction supplies a necessary condition for membership in the class of audited designative entities without asserting sufficiency.

### 1.1 Slot Typing and Instance Grounding

Slot X accepts only class-level references. Consequently every row in the corresponding table records a class rather than an individual, preserving the distinction between the ontological category and its instances.

## 2 Relational Realization

Three tables realize the axiom together with supporting audit-trail entities. Primary keys are single-column identifiers. Foreign-key columns implement the auditedBy participation and permit two-hop and three-hop navigation.

### 2.1 t_processes

The table embodies the range of the auditedBy property (bfo:0000015). Its primary key process_id is referenced by foreign keys in dependent tables.

```sql
CREATE TABLE t_processes (
  process_id VARCHAR(255) PRIMARY KEY,
  name VARCHAR(255)
);
```

| process_id | name          |
|------------|---------------|
| P001       | auditd        |
| P002       | ebpf_tracer   |
| P003       | seccomp_agent |

### 2.2 t_syscall_classes

The table supplies candidate values for slot X. Its primary key class_id is referenced by the foreign key x in t_syscall_audited_by.

```sql
CREATE TABLE t_syscall_classes (
  class_id VARCHAR(255) PRIMARY KEY,
  label VARCHAR(255)
);
```

| class_id | label               |
|----------|---------------------|
| C001     | open_syscall        |
| C002     | execve_syscall      |
| C003     | mmap_syscall        |
| C004     | connect_syscall     |

### 2.3 t_syscall_audited_by

The table directly implements axiom 1. Column id is the primary key. Column x is a foreign key referencing t_syscall_classes.class_id and thereby asserts that the referenced class is a designative information content entity audited by a process.

```sql
CREATE TABLE t_syscall_audited_by (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255) REFERENCES t_syscall_classes(class_id)
);
```

| id   | x    |
|------|------|
| A001 | C001 |
| A002 | C002 |
| A003 | C003 |
| A004 | C004 |

## 3 Cross-Join Example

To retrieve the process name responsible for auditing the open syscall class, join t_syscall_audited_by to t_syscall_classes on x = class_id and then to t_processes via an implicit participation link recorded in an audit event (extended here for illustration). The resulting row set contains:

- id = A001, x = C001, label = open_syscall, process_id = P001, name = auditd
