# Directive Governance Processes in Regulatory Compliance

This chapter defines five process classes used in directive governance and demonstrates their instantiation through a five-table relational schema. The schema supports cross-table queries that trace evidence, signatories, and audit linkages for any given process instance.

## 1. Ontology Axioms and Process Classification

Five axioms drawn from the directive-governance family classify processes that satisfy BFO process requirements while adding constraints on evidence, signatories, or audit status. Each axiom is realized by one table whose columns directly encode the axiom’s slot types.

### 1.1 Verification Requiring Evidence
Axiom 1 states that a verification process must produce at least one evidence item. Table t_verification_min_one_evidence implements this requirement.

The column id is the primary key. Column x identifies the verification process; column y is a foreign-key reference to an evidence entity. A cross-join on y with an evidence registry yields every verification that satisfies the min-one-evidence restriction.

## 2. Cross-Join Demonstration

To retrieve every verification that produced evidence, was later audited, and whose resulting attestation carries a signer, execute the following mental join sequence:

1. Start with t_verification_min_one_evidence (x = “WaterSampleVerification”, y = “Evidence-Log-2016-08-16”).
2. Join to t_verification_basic on x to confirm the process class.
3. Join to t_audit_basic on x = “AnnualWaterAudit”.
4. Join to t_attestation_min_one_signer on x = “CommissionMinutesAttestation”.

The resulting row set contains the single tuple (vme-01, WaterSampleVerification, Evidence-Log-2016-08-16, ab-01, ams-01), confirming that the August 2016 water-sample verification produced required evidence, participated in the annual audit, and was attested by a signer.
