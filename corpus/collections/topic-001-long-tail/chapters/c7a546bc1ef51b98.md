# Directive Governance Processes: Verification, Attestation, and Audit

This chapter defines five process classes drawn from the directive-governance family and shows how each class is realized as a row in a corresponding relational table. The tables share identifier values that function as primary keys within each table and as foreign-key references across tables, enabling multi-hop queries over evidence production, signer requirements, and audit lineage.

## 1. Verification with Evidence Requirement

Axiom 1 states that a verification process must produce at least one evidence item. Table t_verification_min_one_evidence therefore records both the verification process (column x) and the required evidence (column y). Column id is the primary key; column y acts as a foreign key that resolves to an identifier in t_audit_basic or t_attestation_basic.

| v1 | ComplianceVerification-20160816 | e1 |
| v2 | ComplianceVerification-20160816 | e2 |
| v3 | PermitReview-20190930 | e3 |
| v4 | PermitReview-20190930 | e4 |
| v5 | RegulationCheck-2016 | e5 |
| v6 | RegulationCheck-2016 | e1 |

## 1.1 Basic Verification Processes

Axiom 2 defines an unqualified verification process. Table t_verification_basic stores only the process identifier. Column id is the sole primary key; no foreign-key column is present, but values in column x may be joined to the x column of t_verification_min_one_evidence when a simple verification must be traced to its evidence.

## 2. Attestation with Signer Requirement

Axiom 3 requires that an attestation process be signed by at least one person. Table t_attestation_min_one_signer records the attestation process. Column id is the primary key. The table participates in cross-table joins when its x values appear as foreign-key targets in t_verification_min_one_evidence.y.

## 2.1 Basic Attestation Processes

## 3. Audit Processes

Axiom 4 defines an audit process. Table t_audit_basic records each audit. Column id is the primary key. Values in column x serve as foreign-key targets for t_verification_min_one_evidence.y when an audit record constitutes required evidence.

| id | x |

| au1 | AnnualAudit-2016 |
| au2 | EquipmentAudit-2019 |

## 4. Cross-Table Query Example

To determine which evidence items support the verification of the 16 August 2016 compliance check and whether those items are audits, execute the following mental join:

- Start with t_verification_min_one_evidence where x = 'ComplianceVerification-20160816'.
- Match t_verification_min_one_evidence.y to t_audit_basic.id.
- Result rows: (v1, ComplianceVerification-20160816, e1, au1, AnnualAudit-2016) and (v6, ComplianceVerification-20160816, e1, au1, AnnualAudit-2016).
