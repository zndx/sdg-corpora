# eBPF Artifact Safety Verification Schema

This chapter defines a minimal relational schema that implements the ebpfprogram_verified_safe axiom. The schema records eBPF programs as artifacts, the verifiers that establish their safety status, and the verification events that link each program to its verifier. Four tables are provided; three contain foreign-key references that permit two- and three-hop queries.

## 1. Supporting Entity Tables

### 1.1 t_ebpf_programs
This table embodies the Class slot X of the ebpfprogram_verified_safe axiom by storing each artifact that may be verified. Column program_id is the primary key; all foreign-key references to programs resolve to this column.

| program_id | name | hash_sha256 | submitted |
|------------|------|-------------|-----------|
| P001 | net_filter_v4 | a1b2c3d4e5f6... | 2023-11-02 |
| P002 | trace_sched | b2c3d4e5f6a1... | 2023-11-03 |
| P003 | seccomp_enforce | c3d4e5f6a1b2... | 2023-11-05 |
| P004 | cgroup_skb | d4e5f6a1b2c3... | 2023-11-07 |
| P005 | xdp_router | e5f6a1b2c3d4... | 2023-11-09 |

### 1.2 t_verifiers
This table embodies the Class slot Y of the ebpfprogram_verified_safe axiom by storing each entity capable of issuing a verified-safe assertion. Column verifier_id is the primary key.

| verifier_id | name | version | cert_body |
|-------------|------|---------|-----------|
| V01 | Linux Verifier 6.5 | 6.5.2 | kernel.org |
| V02 | Cilium Verifier | 1.14.0 | cilium.io |
| V03 | RedHat eBPF Verifier | 8.2.1 | redhat.com |

### 1.3 t_technicians
This table supplies operator context for verification events. Column technician_id is the primary key and is referenced by the verification session table.

## 2. Axiom Table

### 2.1 t_ebpfprogram_verified_safe
This table directly implements the ebpfprogram_verified_safe axiom. Column id is the primary key of each verification assertion; columns x and y are foreign keys referencing t_ebpf_programs.program_id and t_verifiers.verifier_id respectively. A row asserts that the program identified by x is verified safe by the verifier identified by y.

| id | x | y |
|----|---|---|
| VS001 | P001 | V01 |
| VS002 | P002 | V01 |
| VS003 | P003 | V02 |
| VS004 | P004 | V03 |
| VS005 | P005 | V01 |
| VS006 | P001 | V02 |

## 3. Cross-Join Example

Question: Which technician recorded the verification of program P001 by verifier V01?

Walk the links: start at t_ebpfprogram_verified_safe (VS001), follow x to t_ebpf_programs (P001), follow y to t_verifiers (V01). The verification event is further linked through an implicit session record (not shown) that carries technician_id T10. The joined result row is therefore (P001, net_filter_v4, V01, Linux Verifier 6.5, T10, J. Hearthway).
