# eBPF Program Verification Reference

This chapter specifies the relational encoding of the ebpfprogram_verified_safe axiom for audit-trail systems that record kernel-level eBPF artifacts. The model uses four tables whose primary-key and foreign-key constraints directly implement the subclass and existential restrictions stated in the axiom, enabling deterministic cross-table retrieval of verification provenance.

## 1 Ontology grounding

The single axiom supplied projects the class-level statement “X is something that verified safe by Y” onto a deterministic relational structure. X and Y are treated as named individuals of type cco:Artifact; the verification link is materialised as a row whose non-null foreign-key column y realises the restriction “verified safe by some Y”.

## 2 Relational tables

### 2.1 t_ebpf_program
The table materialises individuals that occupy the X position of the axiom. Its primary key program_id is referenced by the verification table; no foreign keys are present.

| program_id | program_name | bpf_type |
|------------|--------------|----------|
| P001 | net_filter_v1 | XDP |
| P002 | trace_sched | kprobe |
| P003 | sock_redir | cgroup |
| P004 | pkt_cls | tc |

### 2.2 t_verifier
The table materialises individuals that occupy the Y position of the axiom. Its primary key verifier_id is referenced by the verification table.

| verifier_id | verifier_name | version |
|-------------|---------------|---------|
| V01 | kernel_bpf_verifier | 5.15 |
| V02 | bpftool_static | 1.2 |
| V03 | cilium_agent | 1.11 |

### 2.3 t_ebpfprogram_verified_safe
The table directly encodes the axiom. Column id is the primary key; column x is a foreign key to t_ebpf_program.program_id; column y is a foreign key to t_verifier.verifier_id.

| id | x | y |
|----|---|---|
| VS001 | P001 | V01 |
| VS002 | P002 | V01 |
| VS003 | P003 | V02 |
| VS004 | P004 | V03 |
| VS005 | P001 | V02 |

### 2.4 t_audit_finding
The table records downstream audit events that reference verified programs, supplying an additional foreign-key path for multi-hop queries. Column finding_id is the primary key; column verified_safe_id references t_ebpfprogram_verified_safe.id.

| finding_id | verified_safe_id | subject | timestamp |
|------------|------------------|---------|-----------|
| F1001 | VS001 | host01 | 2024-03-12T09:15:00Z |
| F1002 | VS003 | host02 | 2024-03-12T10:02:00Z |
| F1003 | VS005 | host01 | 2024-03-13T14:40:00Z |
