# AUDIT TRAIL REFERENCE MODEL

This chapter specifies a minimal relational schema that implements the axiom {X:Class} SubClassOf bfo:0000015, sdg:hasFindings some {Y:Class}. The schema supports traceability from subjects through controls and tests to findings. All tables use entity identifiers that permit direct foreign-key joins.

## 1 Domain and Scope

The model records audit processes performed on regulatory subjects. Each process instance satisfies the subclass relation to bfo:0000015 and is linked to one or more findings. Data rows represent concrete instances drawn from compliance examinations conducted by public-sector bodies.

### 1.1 Table t_subject

This table enumerates the entities under examination. Column subject_id is the primary key; no foreign keys are present. A reader can join subject_id to any downstream table that records controls or tests applied to the same subject.

```sql
CREATE TABLE t_subject (
  id VARCHAR(255),
  subject_id VARCHAR(255) PRIMARY KEY,
  description VARCHAR(255)
);
```

### 1.2 Table t_control

This table records the control procedures applied to each subject. Column control_id is the primary key; subject_id is a foreign key to t_subject.subject_id. A cross-join on subject_id yields the set of controls executed for any given subject.

```sql
CREATE TABLE t_control (
  id VARCHAR(255),
  control_id VARCHAR(255) PRIMARY KEY,
  subject_id VARCHAR(255) REFERENCES t_subject(subject_id),
  description VARCHAR(255)
);
```

### 1.3 Table t_test

This table captures individual test executions. Column test_id is the primary key; control_id is a foreign key to t_control.control_id. Joining across t_subject, t_control and t_test produces the full chain of subject-control-test provenance.

```sql
CREATE TABLE t_test (
  id VARCHAR(255),
  test_id VARCHAR(255) PRIMARY KEY,
  control_id VARCHAR(255) REFERENCES t_control(control_id),
  description VARCHAR(255)
);
```

### 1.4 Table t_finding

This table stores the individual findings produced by tests. Column finding_id is the primary key. No foreign keys are declared; findings are referenced from t_audit_with_findings.

```sql
CREATE TABLE t_finding (
  id VARCHAR(255),
  finding_id VARCHAR(255) PRIMARY KEY,
  description VARCHAR(255)
);
```

### 1.5 Table t_audit_with_findings

This table directly implements the axiom by associating each process (X) with its findings (Y). Column id is the primary key; x references t_test.test_id and y references t_finding.finding_id. A join on x and y returns every finding attached to a given test process.

```sql
CREATE TABLE t_audit_with_findings (
  id VARCHAR(255),
  x VARCHAR(255) REFERENCES t_test(test_id),
  y VARCHAR(255) NOT NULL REFERENCES t_finding(finding_id),
  PRIMARY KEY (id)
);
```
