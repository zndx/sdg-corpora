# Directive Governance in Corporate Audit Processes

This chapter presents a relational model for directive information content entities and associated processes in corporate governance audits. The model is grounded in five ontological axioms that constrain verification, conduct, signing, and period scoping of audits and attestations. Data instances are drawn from equity shareholder meeting records and compliance attestations.

## 1. Requirement Verification Axiom

The table t_requirement_min_one_verification embodies the axiom that every directive information content entity must be verified by at least one entity. Column id is the primary key. Column x references the directive instance while y is a foreign key to a verifying process or person instance, enabling joins that confirm minimum verification cardinality.

| id | x | y |
| id_req_01 | meeting_notice_2015 | verification_attendance_01 |
| id_req_02 | meeting_notice_2015 | verification_attendance_02 |
| id_req_03 | quarter_commentary_q1 | verification_commentary_01 |
| id_req_04 | tool_diagram_holder | verification_diagram_01 |
| id_req_05 | tool_diagram_holder | verification_diagram_02 |
| id_req_06 | court_order_2015 | verification_order_01 |

## 2. Audit Conduct Axiom

The table t_audit_conducted_by embodies the axiom that an audit process is conducted by a person. Column id is the primary key. Column x identifies the audit process instance; no foreign key is present, yet x values join to foreign keys in other tables to trace conductor identity.

| id | x |
| id_cond_01 | audit_meeting_2015 |
| id_cond_02 | audit_commentary_q1 |
| id_cond_03 | audit_tool_diagram |
| id_cond_04 | audit_court_order |

## 3. Attestation Minimum Signer Axiom

The table t_attestation_min_one_signer embodies the axiom that an attestation process must be signed by at least one person. Column id is the primary key. Column x identifies the attestation process instance and serves as a join target for signer resolution.

| id | x |
| id_att_min_01 | attestation_attendance_slip |
| id_att_min_02 | attestation_commentary |
| id_att_min_03 | attestation_diagram_release |
| id_att_min_04 | attestation_court_convened |

## 4. Attestation Signed By Axiom

The table t_attestation_signed_by embodies the axiom that an attestation process is signed by a person. Column id is the primary key. Column x identifies the attestation process instance and supports joins that enumerate actual signers.

| id | x |
| id_att_sig_01 | attestation_attendance_slip |
| id_att_sig_02 | attestation_commentary |
| id_att_sig_03 | attestation_diagram_release |
| id_att_sig_04 | attestation_court_convened |
| id_att_sig_05 | attestation_attendance_slip |

## 5. Audit Period Axiom

The table t_audit_for_period embodies the axiom that an audit process is scoped to an audit period. Column id is the primary key. Column x references the audit process while y is a foreign key to the period instance, permitting joins that restrict results to a chosen temporal scope.

| id | x | y |
| id_per_01 | audit_meeting_2015 | period_dec_2015 |
| id_per_02 | audit_commentary_q1 | period_q1_2020 |
| id_per_03 | audit_tool_diagram | period_2015 |
| id_per_04 | audit_court_order | period_dec_2015 |

## 6. Cross-Join Demonstration

To determine the signer of the attestation covering the audit conducted on the December 2015 meeting notice, join t_attestation_signed_by.x to t_attestation_min_one_signer.x, then link the resulting x to t_audit_conducted_by.x and finally to t_audit_for_period.x where y equals period_dec_2015. The joined row yields attestation_attendance_slip signed under audit_meeting_2015 for period_dec_2015.
