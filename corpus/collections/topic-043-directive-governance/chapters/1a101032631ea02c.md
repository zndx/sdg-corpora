# Corporate Governance Directive Schema

This chapter defines a minimal relational schema for representing directive governance processes. The schema embodies five OWL axioms that constrain how directives, audits, and attestations are linked to verification steps, conducting persons, signers, and audit periods. All tables use entity references as foreign-key values so that cross-table joins recover multi-hop facts such as “which person verified the attendance requirement for the audit of the December 2015 court-convened meeting.”

## 1 Table Definitions and Axiom Embodiment

### 1.1 t_requirement_min_one_verification
The table materializes axiom 1: every directive information content entity must be verified by at least one entity. Column id is the primary key for the requirement instance; column x holds the directive class reference; column y is a non-null foreign key to the verifying entity. A reader can join y to any table that enumerates persons or roles to answer “which verifier is attached to a given directive.”

```sql
CREATE TABLE t_requirement_min_one_verification (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|---|
| req-001 | MeetingAttendanceDirective | Person:CompanySecretary |
| req-002 | EquityShareholderNotice | Person:Registrar |
| req-003 | CourtOrderPublication | Person:LegalCounsel |
| req-004 | QuorumVerification | Person:Chairman |

### 1.2 t_audit_conducted_by
The table materializes axiom 2: every audit process must be conducted by a person. Column id is the primary key for the audit instance; column x is a foreign key to the conducting person. Joining x to a person table yields the responsible individual for any audit.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| aud-2015-12 | Person:ExternalAuditor |
| aud-2016-03 | Person:InternalCompliance |
| aud-2015-12 | Person:CompanySecretary |

### 1.3 t_attestation_min_one_signer
The table materializes axiom 3: every attestation process must be signed by at least one person. Column id is the primary key for the attestation instance; column x is a non-null foreign key to a signer. The minimum-cardinality constraint is satisfied by ensuring at least one row exists for each attestation.

```sql
CREATE TABLE t_attestation_min_one_signer (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| att-court-2015 | Person:Director1 |
| att-court-2015 | Person:Director2 |
| att-quorum-2015 | Person:Chairman |

### 1.4 t_attestation_signed_by
The table materializes axiom 4: an attestation process may be signed by one or more persons. Column id is the primary key; column x is a foreign key to a signer. Multiple rows sharing the same id represent distinct signers for the same attestation.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| att-court-2015 | Person:Director1 |
| att-court-2015 | Person:CompanySecretary |
| att-quorum-2015 | Person:Chairman |
| att-notice-2015 | Person:Registrar |

### 1.5 t_audit_for_period
The table materializes axiom 5: every audit process is linked to an audit period. Column id is the primary key for the audit; column x references the audit instance; column y is a non-null foreign key to the period entity. Joining x to t_audit_conducted_by recovers both the conductor and the period in one query.

```sql
CREATE TABLE t_audit_for_period (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
|----|---|---|
| aud-2015-12 | aud-2015-12 | Period:FY2015-Q4 |
| aud-2016-03 | aud-2016-03 | Period:FY2016-Q1 |

## 2 Cross-Join Demonstration

Consider the multi-hop question: “Which person conducted the audit that covers the period of the court-convened meeting whose attendance directive was verified by the Company Secretary?”

Start with req-001 in t_requirement_min_one_verification (y = Person:CompanySecretary).  
Join t_audit_for_period on x = aud-2015-12 to obtain y = Period:FY2015-Q4.  
Join t_audit_conducted_by on id = aud-2015-12 to obtain x = Person:ExternalAuditor.

The joined row is therefore:

- Requirement: MeetingAttendanceDirective  
- Verified by: Person:CompanySecretary  
- Audit: aud-2015-12  
- Conducted by: Person:ExternalAuditor  
- Period: Period:FY2015-Q4
