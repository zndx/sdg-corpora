# Directive Governance Ontologies in Audit Trail Schemas

This chapter defines five relational tables that realize OWL axioms for directive information content entities, processes of audit and attestation, and their mandatory participation constraints. The schema supports verification of compliance artifacts through primary-key and foreign-key linkages that encode minimum-cardinality and existential restrictions.

## 1. Requirement Verification Constraint

Axiom 1 states that every directive information content entity must be verified by at least one agent. Table t_requirement_min_one_verification materializes this restriction by storing the requirement identifier in column x and the mandatory verifier class in column y. Column id is the primary key; column y functions as a foreign key into personnel or role registries.

```sql
CREATE TABLE t_requirement_min_one_verification (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 5. Audit Period Constraint

Axiom 5 states that an audit process is defined for a specific audit period. Table t_audit_for_period stores the audit identifier in column x and the period class in column y. Column id is the primary key; column y acts as a foreign key into a calendar or fiscal-period registry.

```sql
CREATE TABLE t_audit_for_period (
```

- Join t_attestation_signed_by on x = "Attestation-ShareholderResolution".
- Confirm linkage via t_audit_for_period where x = "Audit-CourtConvenedMeeting" and y = "Period-2015-12".
