# Designative Information Content Entities in Kernel Syscall Audit Trails

This chapter defines the subclass relation of designative information content entities to cco:DesignativeICE and projects the relation into an audit-trail schema for eBPF-traced syscalls. The schema supports multi-table joins that recover the full provenance of a syscall invocation from its identifier through the containing process and the recording session.

## 1. Axiom and Slot Projection

Axiom 1 states that any entity X is a designative information content entity when it functions as a stable referent for a kernel operation. The single relational projection is the table t_syscall_basic, whose column x holds the referent and whose column id supplies the primary key used by dependent audit tables.

## 2. Relational Schema

Table t_syscall_basic embodies Axiom 1. Column id is the primary key; column x records the designative label. No foreign keys are present in this base table.

| id          | x           |
|-------------|-------------|
| sc_read     | read        |
| sc_write    | write       |
| sc_openat   | openat      |
| sc_close    | close       |
| sc_mmap     | mmap        |
| sc_connect  | connect     |
| sc_accept   | accept      |
| sc_clone    | clone       |

Table t_process embodies Axiom 1 by treating each process identifier as a designative container for syscall instances. Column process_id is the primary key; column entry_sc_id is a foreign key to t_syscall_basic.id.

| process_id | entry_sc_id | start_ts            |
|------------|-------------|---------------------|
| p_4123     | sc_clone    | 2024-06-11T14:02:03 |
| p_4124     | sc_openat   | 2024-06-11T14:02:04 |
| p_4125     | sc_mmap     | 2024-06-11T14:02:05 |
| p_4126     | sc_connect  | 2024-06-11T14:02:06 |

Table t_audit_session embodies Axiom 1 by recording the session that captured each designative syscall. Column session_id is the primary key; column process_id is a foreign key to t_process.process_id.

| session_id | process_id | host      | duration_ms |
|------------|------------|-----------|-------------|
| s_9001     | p_4123     | node-07   | 1240        |
| s_9002     | p_4124     | node-07   | 980         |
| s_9003     | p_4125     | node-08   | 1530        |
| s_9004     | p_4126     | node-08   | 760         |

Table t_event embodies Axiom 1 by linking each observed occurrence to its designative syscall type. Column event_id is the primary key; column sc_id is a foreign key to t_syscall_basic.id; column session_id is a foreign key to t_audit_session.session_id.

## 3. Cross-Join Example

Question: which host recorded a successful write (ret = 512) performed by process p_4123?  
Join path: t_event.sc_id → t_syscall_basic.id, t_event.session_id → t_audit_session.session_id, t_audit_session.process_id → t_process.process_id.  

Result row after join:  
event_id=e_55002, sc_id=sc_write, ret=512, session_id=s_9001, process_id=p_4123, host=node-07.
