# Syscall Designation in Kernel Audit Trails

This chapter defines designative information content entities for system call identifiers and demonstrates their use in audit trail schemas. The model supports queries that traverse designation, event, and evidence records through primary and foreign key relationships.

## 1 Foundational Concept

The single axiom employed states that any class X is a designative information content entity when it serves to designate a kernel operation. The relational projection materialises this designation as stable identifiers that subsequent tables reference without duplication.

### 1.1 Table t_syscall_basic

This table directly realises the axiom by storing each designative class. Column id is the primary key; column x holds the lexical designation.

| id          | x       |
|-------------|---------|
| scb-001     | openat  |
| scb-002     | read    |
| scb-003     | write   |
| scb-004     | close   |
| scb-005     | mmap    |
| scb-006     | connect |

### 1.2 Table t_audit_event

This table records occurrences that instantiate a designated syscall. Column event_id is the primary key; column syscall_id is a foreign key to t_syscall_basic.id. A reader can join on syscall_id to retrieve the designation for any event.

| event_id   | syscall_id | pid  | ts                  |
|------------|------------|------|---------------------|
| evt-1001   | scb-001    | 4123 | 2024-01-15 09:12:01 |
| evt-1002   | scb-002    | 4123 | 2024-01-15 09:12:02 |
| evt-1003   | scb-003    | 4199 | 2024-01-15 09:12:05 |
| evt-1004   | scb-001    | 4201 | 2024-01-15 09:12:07 |
| evt-1005   | scb-004    | 4123 | 2024-01-15 09:12:09 |
| evt-1006   | scb-005    | 4199 | 2024-01-15 09:12:11 |

### 1.3 Table t_evidence

This table attaches supporting artefacts to events. Column evidence_id is the primary key; column event_id is a foreign key to t_audit_event.event_id. Cross-table traversal therefore reaches the original designation in two hops.

| evidence_id | event_id | type     | value               |
|-------------|----------|----------|---------------------|
| evd-9001    | evt-1001 | path     | /etc/passwd         |
| evd-9002    | evt-1002 | bytes    | 4096                |
| evd-9003    | evt-1003 | bytes    | 2048                |
| evd-9004    | evt-1004 | path     | /var/log/syslog     |
| evd-9005    | evt-1005 | fd       | 3                   |
| evd-9006    | evt-1006 | addr     | 192.168.1.10:443    |
| evd-9007    | evt-1001 | user     | root                |
| evd-9008    | evt-1003 | user     | daemon              |

## 2 Cross-Join Example

Question: which file path was accessed by the process that executed the “openat” designation at 09:12:01 and what evidence type confirms the access?

Execution steps:
1. Select row from t_syscall_basic where x = 'openat' → id = scb-001.
2. Select row from t_audit_event where syscall_id = scb-001 and ts = '2024-01-15 09:12:01' → event_id = evt-1001, pid = 4123.
3. Select row from t_evidence where event_id = evt-1001 and type = 'path' → value = '/etc/passwd'.

Joined result row: (scb-001, openat, evt-1001, 4123, 2024-01-15 09:12:01, evd-9001, path, /etc/passwd).
