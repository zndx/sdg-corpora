# Evidence Correlation Structures in Descriptive Measurement Models

This chapter specifies three interlinked relational tables that realize axioms for descriptive information content entities (DescriptiveICE) in measurement contexts. The tables encode evidence correlation, baseline rate attachment, and minimum-attribute outlier claims. All column values are instances or references satisfying the slot types of the source axioms. Primary and foreign key constraints enforce the permitted joins.

## 1 Scope and Table Overview

The model supports queries that traverse from an outlier claim through an evidence correlation to its associated baseline rate. Three tables are defined. Each table is preceded by a statement of the axiom it materializes, the key structure, and one example join path.

## 1.1 Table for Evidence Correlation

This table materializes axiom evidence_correlated_with. Column id is the primary key. Column y is a foreign key that must resolve to a row in t_lift_with_baseline_rate. A reader can join on y to retrieve the baseline rate attached to the correlated evidence.

```sql
CREATE TABLE t_evidence_correlated_with (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_lift_with_baseline_rate(id)
);
```

| id  | x                              | y    |
|-----|--------------------------------|------|
| ev1 | CardiacVolumeEvidence          | lb1  |
| ev2 | WallThicknessEvidence          | lb2  |
| ev3 | EjectionFractionEvidence       | lb1  |
| ev4 | MyocardialStrainEvidence       | lb3  |
| ev5 | PerfusionSignalEvidence        | lb2  |

## 1.2 Table for Baseline Rate Attachment

This table materializes axiom lift_with_baseline_rate. Column id is the primary key. Column y is a foreign key that must resolve to a row in t_evidence_correlated_with. The mutual foreign-key pair between this table and t_evidence_correlated_with permits two-hop traversal from any evidence instance to its lift and back to the originating evidence.

```sql
CREATE TABLE t_lift_with_baseline_rate (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_evidence_correlated_with(id)
);
```

| id  | x                       | y   |
|-----|-------------------------|-----|
| lb1 | VolumeLiftOverBaseline  | ev1 |
| lb2 | ThicknessLiftOverBaseline | ev2 |
| lb3 | StrainLiftOverBaseline  | ev4 |

## 1.3 Table for Outlier Claim with Minimum Attribute

This table materializes axiom outlier_claim_min_one_attribute. Column id is the primary key. Column y is a foreign key that must resolve to a row in t_evidence_correlated_with. The foreign key permits a reader to retrieve the evidence that grounds an outlier claim possessing at least one attribute.

```sql
CREATE TABLE t_outlier_claim_min_one_attribute (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_evidence_correlated_with(id)
);
```

| id   | x                        | y   |
|------|--------------------------|-----|
| oc1  | VolumeOutlierClaim       | ev1 |
| oc2  | ThicknessOutlierClaim    | ev2 |
| oc3  | EjectionOutlierClaim     | ev3 |
| oc4  | StrainOutlierClaim       | ev4 |
| oc5  | PerfusionOutlierClaim    | ev5 |
| oc6  | CompositeOutlierClaim    | ev1 |

## 2 Cross-Join Demonstration

To answer the multi-hop question “which baseline rate is referenced by the evidence grounding the volume outlier claim?”, start at t_outlier_claim_min_one_attribute row oc1, follow foreign key y to t_evidence_correlated_with row ev1, then follow foreign key y to t_lift_with_baseline_rate row lb1. The joined result is the single row:

oc1 | VolumeOutlierClaim | ev1 | CardiacVolumeEvidence | lb1 | VolumeLiftOverBaseline
