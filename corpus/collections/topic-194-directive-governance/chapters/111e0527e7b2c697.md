# Evidence Correlation Modeling for Descriptive Information Content Entities

This chapter defines a minimal relational schema that implements three ontology axioms for descriptive information content entities. The schema supports queries that traverse evidence correlations, baseline rates, and attribute sets through primary-key and foreign-key relationships. All column values are instances or references consistent with the slot types of the axioms.

## 1 Schema Structure and Axiom Embodiment

The three tables directly project the Manchester syntax axioms. Each table carries an explicit primary key on the `id` column. Foreign-key columns enforce the `some` and `min 1` restrictions by referencing the `id` values of related tables.

### 1.1 t_evidence_correlated_with

This table embodies Axiom 1 (`evidence_correlated_with`). Column `id` is the primary key. Column `y` is a foreign key that must resolve to a row in `t_lift_with_baseline_rate`. Column `x` holds the correlated descriptive entity. A reader can join on `y` to retrieve the baseline rate that supplies evidence for any given correlation.

| id                        | x                              | y                          |
|---------------------------|--------------------------------|----------------------------|
| ecw-001                   | MeasurementOutlierProcess      | lbr-010                    |
| ecw-002                   | RateDeviationReport            | lbr-011                    |
| ecw-003                   | AttributeAnomalySet            | lbr-012                    |
| ecw-004                   | EvidenceLinkageRecord          | lbr-013                    |
| ecw-005                   | BaselineShiftIndicator         | lbr-014                    |

### 1.2 t_lift_with_baseline_rate

This table embodies Axiom 2 (`lift_with_baseline_rate`). Column `id` is the primary key. Column `y` is a foreign key that must resolve to a row in `t_evidence_correlated_with`. Column `x` names the entity that carries the baseline rate. The mutual foreign-key relationship between this table and `t_evidence_correlated_with` permits two-hop traversal from any outlier claim to its supporting rate and back to its evidence source.

| id                        | x                              | y                          |
|---------------------------|--------------------------------|----------------------------|
| lbr-010                   | LiftCalculationMethod          | ecw-001                    |
| lbr-011                   | PopulationBaselineModel        | ecw-002                    |
| lbr-012                   | ControlGroupRate               | ecw-003                    |
| lbr-013                   | HistoricalReferenceRate        | ecw-004                    |
| lbr-014                   | AdjustedBaselineValue          | ecw-005                    |

### 1.3 t_outlier_claim_min_one_attribute

This table embodies Axiom 3 (`outlier_claim_min_one_attribute`). Column `id` is the primary key. Column `y` is a foreign key that must resolve to a row in `t_evidence_correlated_with`. Column `x` identifies the descriptive information content entity asserted to possess at least one attribute set. Joining on `y` yields the evidence correlation that justifies the outlier claim.

| id                        | x                              | y                          |
|---------------------------|--------------------------------|----------------------------|
| oca-100                   | TestResultOutlierClaim         | ecw-001                    |
| oca-101                   | EquipmentCalibrationAnomaly    | ecw-002                    |
| oca-102                   | SampleVarianceFlag             | ecw-003                    |
| oca-103                   | TechnicianProcedureDeviation   | ecw-004                    |
| oca-104                   | LotQualityOutlier              | ecw-005                    |
| oca-105                   | MeasurementScaleShift          | ecw-001                    |

## 2 Multi-Hop Query Example

Consider the question: given outlier claim `oca-100`, retrieve the baseline rate entity that supplies its supporting evidence. Begin at `t_outlier_claim_min_one_attribute` where `id = 'oca-100'`. Follow foreign key `y` to `t_evidence_correlated_with` row `ecw-001`. From that row follow foreign key `y` to `t_lift_with_baseline_rate` row `lbr-010`. The joined result is the single tuple:

```
(oca-100, TestResultOutlierClaim, ecw-001, MeasurementOutlierProcess, lbr-010, LiftCalculationMethod)
```

This traversal crosses three tables using only the declared primary-key and foreign-key constraints and directly satisfies the `min 1` and `some` restrictions expressed in the axioms.
