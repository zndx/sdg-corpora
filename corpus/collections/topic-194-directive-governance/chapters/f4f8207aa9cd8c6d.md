# Evidence Correlation in Descriptive Information Content Entities

This chapter examines three interlinked axioms governing descriptive information content entities within laboratory information management systems. The axioms formalize evidence correlation, baseline rate attachment, and minimum attribute cardinality for outlier claims. Each axiom projects directly to a relational table whose foreign-key constraints encode the existential restrictions. The resulting schema supports multi-hop queries that recover chains of evidence, baselines, and claims from raw measurement records.

## 1. Axiom-to-Table Projection

The three tables below instantiate the Manchester axioms exactly. Primary keys are opaque identifiers. Foreign keys enforce the slot restrictions stated in each verbalization. All column values are drawn from a cardiology-focused LIMS in which test-result claims are treated as DescriptiveICE instances.

### 1.1 t_lift_with_baseline_rate

This table embodies the axiom “lift_with_baseline_rate”. Column id is the primary key. Column y is a foreign key referencing t_evidence_correlated_with(id), satisfying the required existential link to an evidence entity. A reader can join on y to retrieve the correlated evidence for any given baseline rate.

```sql
SELECT l.x AS baseline, e.x AS evidence
FROM t_lift_with_baseline_rate l
JOIN t_evidence_correlated_with e ON l.y = e.id;
```

### 1.2 t_evidence_correlated_with

This table embodies the axiom “evidence_correlated_with”. Column id is the primary key. Column y is a foreign key referencing t_lift_with_baseline_rate(id). The mutual foreign-key pair between these two tables permits bidirectional traversal between evidence sets and their associated baseline rates.

```sql
SELECT e.x AS evidence, l.x AS baseline
FROM t_evidence_correlated_with e
JOIN t_lift_with_baseline_rate l ON e.y = l.id;
```

### 1.3 t_outlier_claim_min_one_attribute

This table embodies the axiom “outlier_claim_min_one_attribute”. Column id is the primary key. Column y is a foreign key referencing t_evidence_correlated_with(id), guaranteeing each outlier claim possesses at least one correlated evidence entity.

```sql
SELECT o.x AS claim, e.x AS evidence
FROM t_outlier_claim_min_one_attribute o
JOIN t_evidence_correlated_with e ON o.y = e.id;
```
