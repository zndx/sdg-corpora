# Kernel Syscall Classification via Designative Information Content Entities

This chapter defines four relational tables that instantiate axioms for designative information content entities in syscall and kernel-hook modelling. The tables support cross-table joins that resolve multi-hop queries over subsystems, return cardinalities, attachment constraints and security tiers.

## 1 Axiom Embodiment and Table Construction

### 1.1 Subsystem Equivalence

Table t_syscall_equiv_in_subsystem records the equivalence of a syscall class to a designated subsystem under the cco:DesignativeICE anchor. Column id is the primary key; column x identifies the syscall class and column y identifies the subsystem class. A reader can join this table to t_syscall_at_security_tier on x to obtain the security tier of every syscall belonging to a given subsystem.

```sql
CREATE TABLE t_syscall_equiv_in_subsystem (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
| id | x | y |
| equiv_fs_01 | sys_openat | fs |
| equiv_fs_02 | sys_read | fs |
| equiv_net_01 | sys_sendto | net |
| equiv_net_02 | sys_recvfrom | net |
| equiv_proc_01 | sys_execve | proc |
| equiv_sec_01 | sys_ptrace | sec |
| equiv_sec_02 | sys_setuid | sec |

### 1.2 Return-Type Cardinality

Table t_syscall_max_one_return captures the subclass axiom that each syscall class has at most one return type. Column id is the primary key; x references the syscall class and y the return-type class. Joining on x with t_syscall_equiv_in_subsystem yields the return type of every syscall in a subsystem.

```sql
CREATE TABLE t_syscall_max_one_return (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
| id | x | y |
| ret_01 | sys_openat | long |
| ret_02 | sys_read | ssize_t |
| ret_03 | sys_sendto | ssize_t |
| ret_04 | sys_execve | int |
| ret_05 | sys_ptrace | long |
| ret_06 | sys_setuid | int |

### 1.3 Kernel-Hook Attachment Constraint

Table t_kernelhook_max_one_program_attached records the axiom that each kernel hook artifact may have at most one attached program. Column id is the primary key; x names the hook artifact and y the program class. Cross-referencing x values with syscall tables is performed indirectly through shared subsystem identifiers stored in external mapping tables.

```sql
CREATE TABLE t_kernelhook_max_one_program_attached (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
| id | x | y |
| hook_fs_01 | kprobe_vfs_open | bpf_prog_fs_audit |
| hook_net_01 | kprobe_tcp_sendmsg | bpf_prog_net_filter |
| hook_proc_01 | kprobe_do_execve | bpf_prog_proc_trace |
| hook_sec_01 | kprobe_sys_ptrace | bpf_prog_sec_monitor |
| hook_sec_02 | kprobe_setuid | NULL |

### 1.4 Security-Tier Placement

Table t_syscall_at_security_tier places each syscall class at exactly one security tier. Column id is the primary key; x identifies the syscall and y the tier class. Joining on x with t_syscall_equiv_in_subsystem and t_syscall_max_one_return produces the complete profile of subsystem membership, return type and tier for any syscall.

```sql
CREATE TABLE t_syscall_at_security_tier (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
| id | x | y |
| tier_01 | sys_openat | user |
| tier_02 | sys_read | user |
| tier_03 | sys_sendto | user |
| tier_04 | sys_execve | privileged |
| tier_05 | sys_ptrace | kernel |
| tier_06 | sys_setuid | privileged |

## 2 Cross-Join Example

To determine the return type and security tier of every filesystem syscall, first select rows from t_syscall_equiv_in_subsystem where y = 'fs', then join on x to both t_syscall_max_one_return and t_syscall_at_security_tier:

- sys_openat (fs) → long, user  
- sys_read (fs) → ssize_t, user  

The resulting joined row set answers the query “what return type and tier apply to each filesystem syscall?” without requiring additional tables.
