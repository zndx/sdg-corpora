# Kernel Security Audit Data Model

This chapter specifies the relational encoding of four ontological axioms for syscall designative information content entities and kernel artifacts. The model supports audit trail reconstruction through primary-key and foreign-key linkages across four tables. All dimensions and references are expressed in entity identifiers; no external units apply.

## 1 Scope

These tables apply exclusively to deliveries of kernel audit records from the eBPF subsystem to the security logging client. Deviating column structures may be used only when agreed in writing for a specific deployment. Any conflicting identifier assignments are rejected at insertion time.

## 1.1 Table t_syscall_equiv_in_subsystem

This table embodies AXIOM 1 by recording the equivalence of each designative ICE to a syscall subsystem. Column id is the primary key; columns x and y are entity references with y required, enabling direct lookup of subsystem membership.

| id  | x                  | y               |
|-----|--------------------|-----------------|
| se1 | open               | file            |
| se2 | connect            | network         |
| se3 | mmap               | memory          |
| se4 | ptrace             | process         |
| se5 | read               | file            |
| se6 | sendto             | network         |

## 1.2 Table t_syscall_max_one_return

This table embodies AXIOM 2 by enforcing a maximum cardinality of one return type per designative ICE. Column id is the primary key; columns x and y are entity references, with y nullable to represent the optional single return.

| id  | x                  | y               |
|-----|--------------------|-----------------|
| sr1 | open               | int             |
| sr2 | connect            | int             |
| sr3 | mmap               | void*           |
| sr4 | ptrace             | long            |
| sr5 | read               | ssize_t         |
| sr6 | sendto             | ssize_t         |

## 2 Table t_kernelhook_max_one_program_attached

This table embodies AXIOM 3 by recording the attachment constraint between kernel artifacts and programs. Column id is the primary key; columns x and y are entity references, with y nullable to allow detached hooks.

| id  | x                  | y                    |
|-----|--------------------|----------------------|
| kh1 | kprobe_open        | bpf_prog_open_trace  |
| kh2 | tracepoint_tcp     | bpf_prog_tcp_audit   |
| kh3 | kretprobe_mmap     | NULL                 |
| kh4 | lsm_ptrace         | bpf_prog_lsm_ptrace  |
| kh5 | raw_trace_read     | bpf_prog_read_filter |

## 2.1 Table t_syscall_at_security_tier

This table embodies AXIOM 4 by associating each designative ICE with exactly one security tier. Column id is the primary key; columns x and y are entity references with y required.

| id  | x                  | y               |
|-----|--------------------|-----------------|
| st1 | open               | kernel          |
| st2 | connect            | user            |
| st3 | mmap               | kernel          |
| st4 | ptrace             | user            |
| st5 | read               | user            |
| st6 | sendto             | user            |

## 3 Cross-table query example

To determine the security tier and attached program for the hook monitoring the open syscall, join t_syscall_equiv_in_subsystem (se1) to t_syscall_at_security_tier on x, then to t_kernelhook_max_one_program_attached on the subsystem value mapped to hook identifier. The resulting row is:

id=se1, x=open, y=file, tier=kernel, program=bpf_prog_open_trace
