# Chapter 7 HIPAA Safeguard Directives in Information Content Entities

This chapter defines three subclasses of cco:DirectiveICE that encode HIPAA safeguard requirements and shows how their slot structures map to a minimal relational schema. The schema supports retrieval of safeguard targets across administrative, physical, and technical categories through shared class references.

## 1 Ontology Axioms and Slot Projection

Axiom 1 states that any class X that is a subclass of cco:DirectiveICE and stands in the relation sdg:hipaaSafeguard to a class Y is an administrative safeguard directive. Axiom 2 and Axiom 3 apply identical structure for physical and technical safeguards. Each axiom therefore projects to a table whose non-null column y records the safeguarded class while x records the directive class itself.

### 1.1 Administrative Safeguard Table

Table t_hipaa_safeguard_admin embodies Axiom 1. Column id is the primary key. Columns x and y are entity references to directive and target classes; no foreign-key constraint is declared because both values are drawn from an external class hierarchy rather than from another table in this schema. A reader can locate every directive that safeguards a given workforce procedure by selecting on y and projecting x.

```sql
CREATE TABLE t_hipaa_safeguard_admin (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.2 Physical Safeguard Table

Table t_hipaa_safeguard_physical embodies Axiom 2. Column id remains the primary key. Column y again records the safeguarded class, permitting direct comparison with rows in the administrative table when y values coincide. Column x records the physical directive class.

### 1.3 Technical Safeguard Table

Table t_hipaa_safeguard_technical embodies Axiom 3. Its structure is identical to the preceding tables, allowing uniform join logic across all three safeguard categories. Column y supplies the common join key for multi-category retrieval.

```sql
CREATE TABLE t_hipaa_safeguard_technical (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
```

## 2 Cross-Table Retrieval Example

A compliance query asks which directives safeguard the class ActivityReviewProcedure under more than one HIPAA category. The following walk-through uses primary-key identity within each table and value equality on y across tables.

1. Select rows from t_hipaa_safeguard_admin where y = 'ActivityReviewProcedure' → yields hipaa_admin_02.
2. Select rows from t_hipaa_safeguard_technical where y = 'ActivityReviewProcedure' → yields hipaa_tech_02.
3. The pair (hipaa_admin_02, hipaa_tech_02) constitutes the joined result; both directives share the same safeguarded class yet belong to distinct safeguard families.

The joined row set therefore contains two directive classes and one common target class, satisfying the multi-hop requirement without additional foreign-key columns.
