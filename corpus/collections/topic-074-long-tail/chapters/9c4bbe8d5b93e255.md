# Regulatory Directive Modeling for Compliance Controls

This chapter defines five relational projections of OWL axioms that classify subclasses of cco:DirectiveICE according to HIPAA physical, technical, and administrative safeguards, PCI DSS requirements, and ISO 27001 Annex A controls. The projections are realized as five tables that share identifier values across the x and y columns, enabling cross-table joins that answer multi-hop compliance queries.

## 1. Axiom Projections and Table Definitions

Each table directly implements one axiom. The id column is the primary key. The y column functions as a foreign key when its value matches an id value in another table, while the x column holds the subject directive. All column values are drawn from the domain of information-security controls applied to in-vitro diagnostic device manufacturing records.

## 2. Cross-Join Demonstration

To determine which administrative safeguards ultimately reference the same physical control that satisfies a PCI DSS requirement, execute the following mental join sequence:

Start at pci_req_02 (y = phys_003).  
Join phys_003 (y = admin_003).  
Join admin_003 (y = pci_req_03).

The resulting chain yields the joined row:

pci_req_02 | phys_003 | admin_003 | pci_req_03

This path shows that the DeviceDisposalProcedure physical safeguard participates in both a PCI DSS requirement and an administrative authorization control.
