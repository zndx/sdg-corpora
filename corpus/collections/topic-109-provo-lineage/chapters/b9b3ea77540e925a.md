# Measurement Provenance in Laboratory Information Systems

This chapter presents five relational tables that realize a minimal LIMS schema for recording laboratory runs, their produced measurements, method provenance, NIST control mappings, and column annotations. The schema supports multi-hop queries that traverse process-to-measurement, source-to-method, and control-to-annotation links while remaining faithful to the supplied OWL axioms.

## 1 Ontology-to-Relation Mapping

Each axiom is realized by one table. Primary keys identify individuals that instantiate the quantified class; foreign keys encode the existential restrictions. All column values are drawn from a controlled vocabulary of laboratory entities used in crop-health measurement protocols.

### 1.1 t_labrun_produces_measurement

Axiom 1 states that a laboratory run is a process that produces a descriptive information content entity. The table therefore stores the run identifier as primary key and the run class label as the sole data column; no foreign key is required.

```sql
CREATE TABLE t_labrun_produces_measurement (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example cross-table question: given a measurement identifier, retrieve the originating laboratory run class.

### 1.2 t_measurement_with_method

Axiom 3 states that a descriptive information content entity is realized via a method. The table therefore records the measurement identifier as primary key and the method class as a mandatory foreign key that must resolve to an existing row in t_table_provenance_source.

```sql
CREATE TABLE t_measurement_with_method (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_table_provenance_source(id)
);
```

### 1.3 t_table_provenance_source

Axiom 2 states that a descriptive information content entity is sourced from a table. The table records the source-table identifier as primary key and the measurement identifier as a mandatory foreign key that must resolve to an existing row in t_measurement_with_method, establishing the mutual provenance link required by the paired axioms.

```sql
CREATE TABLE t_table_provenance_source (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_measurement_with_method(id)
);
```

### 1.4 t_nist80053_control_subclass

Axiom 4 states that a directive information content entity is subject to an NIST 800-53 control. The table records the control-mapping identifier as primary key and the laboratory-run identifier as a mandatory foreign key referencing t_labrun_produces_measurement.

```sql
CREATE TABLE t_nist80053_control_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_produces_measurement(id)
);
```

### 1.5 t_column_tag_subclass

Axiom 5 states that a descriptive information content entity annotates a column. The table records the annotation identifier as primary key and the measurement identifier as a mandatory foreign key referencing t_measurement_with_method.

```sql
CREATE TABLE t_column_tag_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_measurement_with_method(id)
);
```

## 3 Multi-Hop Query Example

Question: Which NIST control applies to the laboratory run that produced the measurement whose method is sourced from the RawSpectraTable and that carries the UnitConversionTag annotation?

Walk the links:  
1. Start at TAG-300 (t_column_tag_subclass). Its foreign key y = MWM-100.  
2. MWM-100 (t_measurement_with_method) has foreign key y = TPS-010.  
3. TPS-010 (t_table_provenance_source) records x = RawSpectraTable.  
4. MWM-100 also records x = NutrientConcentrationResult.  
5. Trace MWM-100 back through LR-001 via the NIST mapping table: NIST-200 references LR-001.

Joined result row:
