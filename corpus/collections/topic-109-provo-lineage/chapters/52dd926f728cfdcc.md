# Measurement Provenance and Control Templates in Regulated Laboratory Systems

This chapter defines five relational tables that instantiate the listed OWL axioms for laboratory runs, measurements, provenance, methods, NIST 800-53 controls, and column annotations. The tables support cross-table joins that answer multi-hop queries about measurement origin, method application, and control compliance.

## 1 Scope and Table Organization

The schema comprises exactly the five tables projected from the axioms. Each table carries a primary key column named id. Three tables contain foreign-key columns that enforce the slot restrictions stated in the axioms. All row values are instances of the slot types Class or Individual.

## 1.1 t_labrun_produces_measurement

This table embodies Axiom 1. Column id is the primary key. Column x holds the identifier of any laboratory process that produces a DescriptiveICE. No foreign key is present.

```sql
SELECT id, x FROM t_labrun_produces_measurement;
```

Example rows:

| id                  | x                     |
|---------------------|-----------------------|
| LPM-001             | FoliarTrial-2023-09   |
| LPM-002             | FoliarTrial-2023-10   |
| LPM-003             | PestScan-2023-11      |
| LPM-004             | NutrientRun-2023-12   |
| LPM-005             | DiseaseAssay-2024-01  |

## 1.2 t_measurement_with_method

This table embodies Axiom 3. Column id is the primary key. Column y is a foreign key that references t_table_provenance_source.id, recording the table that supplied the measurement.

```sql
SELECT id, x, y FROM t_measurement_with_method;
```

Example rows:

| id                  | x                          | y                     |
|---------------------|----------------------------|-----------------------|
| MWM-010             | DiseaseIncidence           | TPS-100               |
| MWM-011             | PestCount                  | TPS-101               |
| MWM-012             | NutrientLevel              | TPS-102               |
| MWM-013             | ChlorophyllIndex           | TPS-103               |
| MWM-014             | YieldEstimate              | TPS-104               |

## 1.3 t_table_provenance_source

This table embodies Axiom 2. Column id is the primary key. Column y is a foreign key that references t_measurement_with_method.id, closing the provenance link between source table and measurement.

```sql
SELECT id, x, y FROM t_table_provenance_source;
```

Example rows:

| id                  | x                          | y                     |
|---------------------|----------------------------|-----------------------|
| TPS-100             | FieldObservationsSept      | MWM-010               |
| TPS-101             | PestTrapLogOct             | MWM-011               |
| TPS-102             | SoilSampleResultsNov       | MWM-012               |
| TPS-103             | LeafScanDec                | MWM-013               |
| TPS-104             | HarvestWeightsJan          | MWM-014               |

## 1.4 t_nist80053_control_subclass

This table embodies Axiom 4. Column id is the primary key. Column y is a foreign key that references t_labrun_produces_measurement.id, associating each directive with the laboratory run that generated supporting evidence.

```sql
SELECT id, x, y FROM t_nist80053_control_subclass;
```

Example rows:

| id                  | x                          | y                     |
|---------------------|----------------------------|-----------------------|
| NCS-200             | AC-2AccountManagement      | LPM-001               |
| NCS-201             | AU-6AuditReview            | LPM-002               |

| NCS-203             | SI-4SystemMonitoring       | LPM-004               |
| NCS-204             | RA-5VulnerabilityMonitoring| LPM-005               |

## 1.5 t_column_tag_subclass

This table embodies Axiom 5. Column id is the primary key. Column y is a foreign key that references t_measurement_with_method.id, indicating which measurement column receives the annotation.

```sql
SELECT id, x, y FROM t_column_tag_subclass;
```

Example rows:

## 2 Cross-Join Demonstration

A compliance query asks: “Which NIST control is supported by the measurement that was produced by laboratory run LPM-001 and recorded via method MWM-010 whose source table is TPS-100?”

The join path traverses three tables:

1. t_nist80053_control_subclass.y = t_labrun_produces_measurement.id  
2. t_labrun_produces_measurement.id = LPM-001  
3. t_measurement_with_method.id = MWM-010  
4. t_table_provenance_source.y = MWM-010 and t_table_provenance_source.id = TPS-100

Result row:

| NCS id | Control                | LabRun | Measurement   | Method Source Table   |
|--------|------------------------|--------|---------------|-----------------------|
| NCS-200| AC-2AccountManagement  | LPM-001| DiseaseIncidence | FieldObservationsSept |
