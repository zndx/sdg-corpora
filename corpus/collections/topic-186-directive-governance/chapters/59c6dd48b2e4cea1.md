# Chapter 4: Relational Modeling of Place Attestations and Audits

This chapter presents five tables that encode five OWL axioms for artifactual places, attestations, audits, and requirements. The tables support cross-table joins that resolve multi-hop queries over supporting evidence, findings, and directive targets. All column values are instances consistent with the slot types declared in the axioms.

## 1 Schema Structure and Axiom Projection

The schema consists of exactly the five tables whose column signatures are fixed by the axioms. Primary keys are the `id` columns. Foreign-key columns implement the existential restrictions and equivalence axioms, permitting joins that traverse from a place to its attestation, from an attestation to its supporting address, and from an audit or requirement to the address that grounds its evidence.

### 1.1 t_schemaorg_place_address

This table embodies AXIOM 1: each row asserts that an artifactual place `x` possesses a postal address witnessed by an attestation record. Column `id` is the primary key; column `y` is a foreign key to `t_attestation_with_supporting_evidence(id)`.

| addr_002 | St. Columban Main Building | attest_002 |
| addr_003 | Ministerial Office Block | attest_003 |

### 1.2 t_attestation_with_supporting_evidence

This table embodies AXIOM 2: each row records a process `x` that carries supporting evidence located at a postal address. Column `id` is the primary key; column `y` is a foreign key to `t_schemaorg_place_address(id)`.

### 1.3 t_schemaorg_place_geocoord

This table embodies AXIOM 3: each row states that an artifactual place `x` is located by geo-coordinates whose supporting evidence is an attestation. Column `id` is the primary key; column `y` is a foreign key to `t_attestation_with_supporting_evidence(id)`.

### 1.4 t_audit_with_findings

This table embodies AXIOM 4: each row represents an audit process `x` whose findings are documented at a postal address. Column `id` is the primary key; column `y` is a foreign key to `t_schemaorg_place_address(id)`.

| id | x | y |
|---|---|---|
| audit_001 | 2016 Housing Compliance Audit | addr_001 |
| audit_002 | MCA Course Regulation Audit | addr_005 |
| audit_003 | School Calendar Safety Audit | addr_002 |

### 1.5 t_requirement_equiv_specifies_target

This table embodies AXIOM 5: each row is a directive equivalent class that specifies a target `y` and applies to a subject `z`, both grounded at a postal address. Column `id` is the primary key; column `y` is a foreign key to `t_schemaorg_place_address(id)`.

| id | x | y | z |
|---|---|---|---|
| req_001 | R16 MCA Accreditation Directive | addr_001 | Siddharth Group of Institutions |

## 2 Cross-Join Example

To determine the geo-coordinates and supporting attestation for the place referenced by requirement `req_001`, join `t_requirement_equiv_specifies_target` to `t_schemaorg_place_address` on `y`, then to `t_attestation_with_supporting_evidence` on the address, then to `t_schemaorg_place_geocoord` on the attestation. The resulting joined row is:
