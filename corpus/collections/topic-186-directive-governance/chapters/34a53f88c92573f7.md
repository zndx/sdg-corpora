# Chapter 7: Spatial Governance and Asset Verification Protocols

This chapter delineates the regulatory framework governing the intersection of physical infrastructure and digital compliance records. It establishes the ontological relationships between physical artifacts, their spatial attributes, and the governance processes—such as attestation and auditing—that verify their existence and status. The protocols detailed herein ensure that every physical asset is anchored to a verifiable address and coordinate system, thereby maintaining the integrity of spatial data within the estate management register.

## 7.1 Artifact-Address Correlation

The foundational unit of estate governance is the `cco:Artifact`, representing any discrete physical asset under management. To ensure operational visibility, every artifact must be rigorously linked to a postal address. This linkage is not merely descriptive but serves as a compliance mechanism; the address acts as the primary legal identifier for service of notices and regulatory inspections.

The relationship between an artifact and its address is formalized through the axiom that an Artifact has a Postal Address. In the relational model, this creates a dependency where the address record itself must correspond to a valid attestation record (see Section 7.2). This structure prevents the creation of "orphan" addresses that lack evidentiary support.

The following table illustrates the mapping of specific artifacts to their registered postal addresses. The primary key (`id`) represents the relationship instance, while `x` denotes the artifact and `y` denotes the address entity (which, per the schema constraints, must exist as an attestation record).

## 7.2 Evidence-Based Attestation

Governance relies on the principle that all recorded data points must be backed by supporting evidence. An attestation is defined as a process (`bfo:Process`) that validates a specific claim. In this framework, an attestation is valid only if it possesses supporting evidence. This evidence is frequently the physical address record or the artifact itself, creating a bidirectional verification loop with the address correlation defined in Section 7.1.

This axiom ensures that for every address claim, there exists a procedural record of verification. The foreign key structure mandates that the supporting evidence (`y`) must reference a valid address record (`id` from `t_schemaorg_place_address`), thereby enforcing the circular integrity of the data: the address points to the attestation, and the attestation points back to the address evidence.

## 7.3 Geospatial Coordinate Integrity

In addition to postal addressing, high-value assets require precise geospatial localization. An artifact is asserted to have geo-coordinates, which are treated as a specific class of data within the system. To maintain high standards of data provenance, the geo-coordinate entity is modeled as a dependent of an attestation record.

This dependency implies that a set of coordinates is not merely a string of numbers but a verified datum (`y`) that must be backed by an attestation process (`t_attestation_with_supporting_evidence`). This ensures that geospatial data is not entered arbitrarily but is the result of a formal verification event.

The subsequent table details the assignment of geo-coordinates to artifacts. Note that the coordinate values (`y`) are references to attestation records that contain the specific coordinate data as evidence.

## 7.4 Audit Findings Localization

The audit function serves as the primary mechanism for ongoing compliance assurance. An audit is a process (`bfo:Process`) that yields findings. To be actionable, these findings must be spatially anchored. Consequently, the ontology defines that an audit has findings, and these findings are structurally linked to specific address records.

By linking the finding (`y`) to the address table, the governance framework ensures that audit results are not abstract but are tied directly to the physical location of the non-compliance or observation. This allows for the generation of location-specific remediation orders.

The table below captures the output of recent audit cycles, linking the audit event (`x`) to the specific finding (`y`), which is resolved to an address record.

## 7.5 Directive Targeting Specification

The final component of the governance framework is the specification of requirements. A requirement is modeled as a Directive (`cco:DirectiveICE`) that specifies a particular target and applies to that target. This structure allows the organization to issue binding mandates (e.g., safety upgrades, zoning restrictions) that are explicitly scoped to defined artifacts or locations.

The relational representation of this axiom requires that the target specified (`y`) must resolve to a valid address record. This ensures that directives are never issued to undefined or non-existent entities.
