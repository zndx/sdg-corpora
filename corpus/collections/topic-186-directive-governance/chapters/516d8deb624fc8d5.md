# Chapter 4: Ontological Structures for Spatial Governance and Audit Compliance

This chapter delineates the formal ontological structures underpinning spatial governance and audit compliance frameworks within the enterprise data environment. It establishes the axiomatic relationships between artifacts, processes, and directives, mapping these concepts to a rigorous relational schema to ensure data integrity and evidentiary traceability. The following sections provide a precise definition of each component, supported by illustrative data tables consistent with the defined constraints and foreign key dependencies. The objective is to facilitate a standardized approach to recording physical locations, verification processes, and regulatory findings.

## 1. Artifact-Address Relations

The foundational axiom for spatial governance, `schemaorg_place_address`, posits that any physical artifact (`cco:Artifact`) subject to regulatory oversight must be subclassified as possessing a postal address. In the context of compliance, this relationship is not merely descriptive; it serves as the primary index for jurisdictional determination and service delivery. The axiom asserts that {X} is something that has postal address {Y}, where {X} represents the artifact and {Y} represents the address entity.

This relationship is critical for establishing the "long tail" of data governance, where physical assets are anchored to verifiable postal codes. The relational schema enforces that the address record ({Y}) must exist as a valid attestation record, ensuring that no address is recorded without a corresponding verification context.

## 2. Process Attestation and Supporting Evidence

The `attestation_with_supporting_evidence` axiom defines the mechanism by which a process (`bfo:0000015`) is substantiated. Formally, {X} is something that with supporting evidence {Y}. In this framework, the attestation represents the administrative or procedural act of verification, while the supporting evidence constitutes the data or physical records that validate that act.

This axiom introduces a recursive validation structure within the relational model. The schema dictates that the supporting evidence ({Y}) for an attestation must reference a valid place address record. Simultaneously, as established in the previous section, the address record references the attestation. This circular dependency enforces a strict "closure" principle: an address cannot exist without an attestation process, and an attestation process cannot exist without the address as its evidence. This design pattern is typical in directive governance, where the existence of a location is defined by the act of verifying it.

## 3. Geospatial Coordinate Attribution

To enhance the precision of spatial governance, the `schemaorg_place_geocoord` axiom extends the definition of an artifact (`cco:Artifact`) to include geospatial coordinates. The axiom states that {X} is something that has geo coordinates {Y}. This allows for the integration of GIS data into the compliance framework, facilitating remote monitoring and automated regulatory checks.

The relational projection of this axiom links the coordinate data directly to the attestation process. By requiring the coordinate record ({Y}) to reference an attestation ID, the system ensures that geospatial data is not entered in isolation but is treated as a component of the verified evidence package. This prevents the introduction of "orphaned" coordinate data that has not been subjected to the requisite verification protocols.

## 4. Audit Findings and Location Linkage

The `audit_with_findings` axiom provides the structure for capturing the outcomes of compliance audits. It asserts that {X} is something that has findings {Y}, where {X} is the audit process (a subclass of `bfo:0000015`) and {Y} represents the specific findings or observations made during that audit.

In the relational schema, the findings are anchored to a specific address record via a foreign key constraint. This design ensures that audit findings are permanently associated with the physical location where the non-compliance or observation occurred. This linkage is essential for tracking remediation efforts and for historical reporting. By binding the findings to the address (`t_schemaorg_place_address`), rather than the audit event itself, the system maintains a persistent history of compliance status at a specific location, regardless of how many subsequent audits occur.

## 5. Directive Specification and Target Application

The final axiom, `requirement_equiv_specifies_target`, defines the logic of regulatory directives. It establishes that a Directive (`cco:DirectiveICE`) is equivalent to an entity that specifies a requirement ({Y}) and applies to a target ({Z}). This axiom operationalizes the application of governance rules, ensuring that every directive is explicitly mapped to both the requirement it enforces and the target entity it governs.

The relational schema for this axiom requires that the specified requirement ({Y}) be linked to a place address. This constraint enforces the principle of localized regulation: a directive does not exist in the abstract but is always applied to a specific, verified location. The structure captures the tripartite relationship between the rule (Directive), the specific obligation (Requirement/Address), and the entity subject to the rule (Target).
