# Regulatory Compliance Modeling for Public Facilities

This chapter defines a minimal relational schema that implements five ontological axioms for representing places, attestations, audits, and requirements. The schema supports cross-table joins that resolve multi-hop queries such as “which findings are associated with an attested address that satisfies a given requirement.”

## 1 Schema Overview

The five tables directly project the supplied axioms. Primary keys are opaque identifiers. Foreign-key columns enforce the existential restrictions stated in each axiom and permit deterministic traversal between address, attestation, and audit instances.

### 1.1 Table t_schemaorg_place_address

This table embodies AXIOM 1. Column id is the primary key. Column y is a foreign key referencing t_attestation_with_supporting_evidence(id) and records the supporting evidence required by the axiom.

| id | x | y |
|---|---|---|
| addr_001 | HousingEstate:Gladstone | attest_003 |
| addr_002 | Office:CabinetRoom | attest_001 |
| addr_003 | Facility:Beachfront | attest_002 |
| addr_004 | Depot:PublicWorks | attest_004 |

## 2 Cross-Join Example

To retrieve the audit findings linked to an address that carries both a geo-coordinate attestation and a regulatory requirement, join on the foreign-key columns:

```sql
SELECT a.x AS audit, addr.x AS address, r.x AS requirement
FROM t_audit_with_findings a
JOIN t_schemaorg_place_address addr ON a.y = addr.id
JOIN t_requirement_equiv_specifies_target r ON r.y = addr.id
WHERE addr.id = 'addr_001';
```

Result row:  
audit = Audit:Feb2016, address = HousingEstate:Gladstone, requirement = Requirement:Form20
