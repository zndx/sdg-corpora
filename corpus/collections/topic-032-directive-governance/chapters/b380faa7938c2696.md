# Regulatory Audit Processes: Ontological Structure and Relational Projection

This chapter defines five core ontological templates governing audit processes over datasets and demonstrates their embodiment in a relational schema. The model supports verification of audit periods, conducting agents, control subclasses, and findings through primary-key and foreign-key linkages. All instances are drawn from regulatory-basis financial audits of the type performed for municipal entities.

## 1 Scope and Schema Overview

The schema comprises exactly the five tables projected from the supplied axioms. Two tables carry foreign keys to the dataset-under-audit table, enabling two-hop and three-hop joins that recover period, conductor, subclass, and finding information for any given dataset.

### 1.1 t_dataset_under_audit

This table embodies AXIOM 2 (dataset_under_audit). Column id is the primary key; column x holds the class name of the artifact placed under audit.

| id   | x                                      |
|------|----------------------------------------|
| ds01 | FY2020_Financial_Statements            |
| ds02 | FY2020_Supplementary_Schedule          |
| ds03 | FY2020_Internal_Control_Documentation  |
| ds04 | FY2020_Grant_Compliance_File           |
| ds05 | FY2020_Revenue_Ledger_Extract          |

### 1.2 t_audit_for_period

This table embodies AXIOM 1 (audit_for_period). Column id is the primary key; column y is a foreign key referencing t_dataset_under_audit(id). Column x names the audit process class scoped to the referenced dataset.

| id    | x                       | y    |
|-------|-------------------------|------|
| afp01 | Annual_Financial_Audit  | ds01 |
| afp02 | Annual_Financial_Audit  | ds02 |
| afp03 | Control_Evaluation      | ds03 |
| afp04 | Compliance_Review       | ds04 |
| afp05 | Substantive_Testing     | ds05 |

This table embodies AXIOM 4 (audit_subclass). Column id is the primary key; column x names the directive subclass audited by the process.

### 1.5 t_audit_with_findings

This table embodies AXIOM 5 (audit_with_findings). Column id is the primary key; column y is a foreign key referencing t_dataset_under_audit(id). Column x names the finding class attached to the referenced dataset.

| id    | x                       | y    |
|-------|-------------------------|------|
| awf01 | Material_Weakness       | ds03 |
| awf02 | Significant_Deficiency  | ds01 |
| awf03 | Compliance_Exception    | ds04 |
| awf04 | Immaterial_Misstatement | ds02 |
| awf05 | Control_Deficiency      | ds05 |

## 2 Cross-Join Demonstration

To recover the conducting person, audit subclass, and finding for the financial statements dataset, join t_audit_for_period to t_dataset_under_audit on y = id, then join t_audit_with_findings on the same dataset id, and finally align the conductor and subclass rows by shared process identifiers. The resulting row for ds01 is:

- Dataset: FY2020_Financial_Statements
- Period audit: Annual_Financial_Audit (afp01)
- Conductor: JARRED_GILMORE_PHILLIPS_PA (acb01)
- Finding: Significant_Deficiency (awf02)
