# Directive Information Content Entities in Compliance Audit Trails

This chapter defines five relational tables that instantiate OWL axioms for HIPAA physical, technical, and administrative safeguards together with PCI DSS requirements and claim-supporting traces. All tables are populated from a single audit-trail corpus covering a state health-care payment system. Primary keys are the id columns; cross-table joins are performed on the shared x and y values that represent DirectiveICE subclasses.

## 1. Physical Safeguard Table

Table t_hipaa_safeguard_physical embodies AXIOM 1. Column id is the primary key. Columns x and y are foreign-key references to the same controlled vocabulary of policy classes used by the remaining tables; equi-joining on y yields every physical control referenced by a technical or administrative safeguard.

| id | x | y |
|----|---|---|
| phys-001 | FacilityEntryLog | LockedServerRoom |
| phys-002 | FacilityEntryLog | BadgeControlledPerimeter |
| phys-003 | MediaTransportLog | EncryptedMediaCourier |
| phys-004 | MediaTransportLog | TamperEvidentSeal |
| phys-005 | WorkstationPlacement | ScreenShieldPolicy |
| phys-006 | WorkstationPlacement | LockedWorkstationCabinet |

## 1.1 Technical Safeguard Table

Table t_hipaa_safeguard_technical embodies AXIOM 2. Column id is the primary key. Columns x and y again serve as join keys; a reader can therefore retrieve every technical control required by the same policy class that also mandates a physical control.

| id | x | y |
|----|---|---|
| tech-001 | AccessControlPolicy | UniqueUserIdentifier |
| tech-002 | AccessControlPolicy | AutomaticLogoffTimer |
| tech-003 | EncryptionStandard | AES256AtRest |
| tech-004 | EncryptionStandard | TLS12InTransit |
| tech-005 | AuditLogProcedure | ImmutableLogHashChain |
| tech-006 | AuditLogProcedure | DailyLogReviewAlert |

## 1.2 Administrative Safeguard Table

Table t_hipaa_safeguard_admin embodies AXIOM 3. Column id is the primary key. The x column references the same policy classes appearing in the physical and technical tables, permitting a three-way join that assembles the complete safeguard set for any given policy.

| id | x | y |
|----|---|---|
| adm-001 | RiskAssessmentDoc | AnnualThreatAnalysis |
| adm-002 | RiskAssessmentDoc | SanctionPolicyUpdate |
| adm-003 | AccessControlPolicy | WorkforceAuthorizationReview |
| adm-004 | AuditLogProcedure | LogRetentionSixYears |
| adm-005 | MediaTransportLog | CourierBackgroundCheck |
| adm-006 | FacilityEntryLog | VisitorEscortRequirement |

## 2. PCI DSS Requirement Table

Table t_pci_dss_requirement embodies AXIOM 4. Column id is the primary key. The y values are PCI DSS control classes that overlap with the y values of the HIPAA tables, allowing a compliance officer to locate every requirement that cites the same technical or administrative control.

| id | x | y |
|----|---|---|
| pci-001 | CardholderDataPolicy | Requirement_03_04 |
| pci-002 | CardholderDataPolicy | Requirement_07_01 |
| pci-003 | EncryptionStandard | Requirement_03_04 |
| pci-004 | AuditLogProcedure | Requirement_10_02 |
| pci-005 | AccessControlPolicy | Requirement_07_02 |
| pci-006 | RiskAssessmentDoc | Requirement_12_02 |

## 3. Trace-Support Table

Table t_trace_supports_claim embodies AXIOM 5. Column id is the primary key. Column x stores the identifier of an audit trace that supports a DescriptiveICE claim; the same x values appear in the safeguard tables, closing the loop from physical control to evidentiary trace.

| id | x |
|----|---|
| trace-001 | AuditLogProcedure |
| trace-002 | EncryptionStandard |
| trace-003 | AccessControlPolicy |
| trace-004 | RiskAssessmentDoc |
| trace-005 | FacilityEntryLog |
| trace-006 | MediaTransportLog |

## 4. Cross-Join Example

Question: Which PCI DSS requirement is supported by an immutable log hash chain that also satisfies an administrative retention rule for the same policy class?

Step 1. Join t_hipaa_safeguard_technical (y = ImmutableLogHashChain) to t_hipaa_safeguard_admin on x, yielding x = AuditLogProcedure.  
Step 2. Join the result to t_pci_dss_requirement on y = Requirement_10_02.  
Step 3. Join the result to t_trace_supports_claim on x = AuditLogProcedure.

Resulting row set:

- x: AuditLogProcedure  
- technical y: ImmutableLogHashChain  
- admin y: LogRetentionSixYears  
- pci y: Requirement_10_02  
- trace id: trace-001

The joined tuple demonstrates that a single policy class satisfies one physical, two technical, one administrative, and one PCI DSS control while being backed by an explicit evidentiary trace.
