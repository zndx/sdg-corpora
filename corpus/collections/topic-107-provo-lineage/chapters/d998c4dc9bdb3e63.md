# Regulatory Audit Modeling: Evidence Production and Directive Governance

This chapter defines a minimal relational schema for representing audit processes, evidence artifacts, directives, attestations, and claims within a quality-management compliance system. The schema directly implements five OWL axioms that constrain class hierarchies and object-property cardinalities. All column values are drawn from controlled vocabularies used in industrial-automation and healthcare-device audit programs.

## 1 Ontology-to-Relation Mapping

The five tables below are the deterministic relational projections of the supplied axioms. Primary-key columns uniquely identify each asserted class; foreign-key columns encode the existential restrictions and supporting-evidence relations required by the axioms. Cross-table joins therefore reconstruct the multi-hop chains expressed in the original Manchester syntax.

### 1.1 Audit Evidence Production

Axiom 1 states that any subclass of bfo:0000015 may produce a cco:DescriptiveICE. Table t_audit_produces_evidence records the class that satisfies the restriction; its single-column primary key serves as the target for later foreign-key references that count produced evidence items.

```sql
CREATE TABLE t_audit_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

|---------|-----------------------|
| AUD-001 | QualitySystemAudit    |
| AUD-002 | EquipmentCalibration  |
| AUD-003 | SupplierQualification |
| AUD-004 | ProcessValidation     |
| AUD-005 | CAPAClosure           |

CREATE TABLE t_evidence_basic (

### 1.3 Directive Authorship and Scope

Axiom 2 defines a directive that is authored by one attestation and applies to another class. Table t_directive_authored_and_applies therefore carries two foreign keys; the y column references an attestation that supplies supporting evidence, while the z column identifies the target of the directive.

```sql
CREATE TABLE t_directive_authored_and_applies (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_with_supporting_evidence(id)
);
```

|----------|--------------------|-----------|--------------------|
| DIR-010  | CalibrationPolicy  | ATT-200   | EquipmentCalibration |
| DIR-011  | CAPAProcedure      | ATT-201   | CAPAClosure        |

### 1.4 Attestation with Supporting Evidence

Axiom 4 requires an attestation (bfo:0000015) to be linked to at least one supporting evidence entity. Table t_attestation_with_supporting_evidence records the attestation class and its evidence reference; its foreign key points back to a directive, establishing the mutual governance link required by the axiom pair.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_directive_authored_and_applies(id)
);
```

| id      | x                    | y        |
|---------|----------------------|----------|
| ATT-200 | CalibrationAttest    | DIR-010  |
| ATT-201 | CAPAAttest           | DIR-011  |
| ATT-202 | SupplierAttest       | DIR-012  |
| ATT-203 | ValidationAttest     | DIR-013  |

### 1.5 Claim Requiring Minimum Evidence

Axiom 5 states that a descriptive information content entity must be supported by at least one evidence-producing audit. Table t_claim_min_one_evidence therefore records the claim class together with a foreign key to an audit that satisfies the minimum cardinality.

```sql
CREATE TABLE t_claim_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_audit_produces_evidence(id)
);
```

| id       | x                       | y       |
|----------|-------------------------|---------|
| CLM-300  | EquipmentComplianceClaim| AUD-002 |
| CLM-301  | SupplierApprovedClaim   | AUD-003 |
| CLM-302  | ProcessValidatedClaim   | AUD-004 |
| CLM-303  | CAPAEffectiveClaim      | AUD-005 |

## 2 Cross-Join Example

To determine the directive that governs a claim whose supporting audit produced a given evidence class, the following three-table join is executed:

```sql
SELECT c.x AS claim,
       a.x AS audit,
       d.x AS directive,
       e.x AS evidence
FROM   t_claim_min_one_evidence c
JOIN   t_audit_produces_evidence a ON c.y = a.id
JOIN   t_directive_authored_and_applies d ON d.z = a.x
JOIN   t_evidence_basic e ON e.id IN ('EV-100','EV-104')
WHERE  a.id = 'AUD-002';
```

Result row:

claim: EquipmentComplianceClaim  
audit: EquipmentCalibration  
directive: CalibrationPolicy  
evidence: CalibrationCertificate

The join traverses the foreign-key chain from claim to audit (Axiom 5), from audit class to directive scope (Axiom 2), and confirms the evidence class required by Axiom 3.
