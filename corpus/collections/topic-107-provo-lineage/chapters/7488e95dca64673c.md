# Audit Trail Modeling for Facility Maintenance Directives

This chapter defines five ontological templates that structure audit processes, directives, attestations, evidence, and claims within facility maintenance compliance records. The templates are projected directly into five relational tables whose primary-key and foreign-key relationships enable multi-hop retrieval of compliance lineage.

## 1 Ontological Templates and Relational Projections

The templates reuse BFO processes and CCO information content entities to capture how directives are authored, attested, and supported by evidence. Each template is realized by one table whose column structure follows the slot types declared in the Manchester axioms.

### 1.1 Audit Produces Evidence

Axiom 1 classifies any process that yields descriptive evidence. The table therefore stores only the identity of the producing class; its single-column primary key serves as the target for later foreign-key references from claim records.

```sql
CREATE TABLE t_audit_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| AUD-001 | MaintenanceAudit |
| AUD-002 | InstallationVerification |
| AUD-003 | FireSafetyAudit |
| AUD-004 | VentilationComplianceCheck |
| AUD-005 | PostRepairInspection |

### 1.2 Directive Authored and Applies

Axiom 2 defines a directive that is both authored by an attestation and applies to a target class. The composite foreign key on column y references the attestation table, enforcing that every directive record is grounded in a prior attestation.

```sql
CREATE TABLE t_directive_authored_and_applies (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_with_supporting_evidence(id)
);
```

### 1.3 Evidence Basic

Axiom 3 simply asserts that a class is a descriptive information content entity. The table therefore contains only the class identifier; its primary key is referenced by the audit table when evidence is produced.

```sql
CREATE TABLE t_evidence_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| EVB-001 | InstallationLog |

| EVB-004 | MaintenanceWorkOrder |
| EVB-005 | ComplianceCertificate |

### 1.4 Attestation With Supporting Evidence

Axiom 4 models a process that carries supporting evidence. Column y is a foreign key into the directive table, closing the authorship loop required by Axiom 2.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_directive_authored_and_applies(id)
);
```

| id | x | y |
|----|---|---|
| ATT-001 | LeadTechnicianAttestation | DIR-001 |
| ATT-002 | DirectorReviewAttestation | DIR-002 |
| ATT-003 | ForepersonSignoffAttestation | DIR-003 |
| ATT-004 | SafetyOfficerAttestation | DIR-004 |
| ATT-005 | ChildNutritionDirectorAttestation | DIR-005 |

### 1.5 Claim Requiring Minimum Evidence

Axiom 5 requires every claim to be supported by at least one evidence-producing audit. Column y therefore references the audit table.

```sql
CREATE TABLE t_claim_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_audit_produces_evidence(id)
);
```

|----|---|---|
| CLM-001 | SV24V-FireComplianceClaim | AUD-001 |
| CLM-002 | ActuatorOutputClaim | AUD-002 |
| CLM-003 | VentilationGroupClaim | AUD-003 |

## 2 Cross-Table Query Example

To retrieve the directive, attestation, and originating audit that support claim CLM-001, the following join path is traversed:

```sql
SELECT c.id AS claim,
       d.x AS directive,
       a.x AS attestation,
       au.x AS audit
FROM t_claim_min_one_evidence c
JOIN t_audit_produces_evidence au ON c.y = au.id
JOIN t_directive_authored_and_applies d ON d.y IN (
  SELECT id FROM t_attestation_with_supporting_evidence
)
JOIN t_attestation_with_supporting_evidence att ON att.y = d.id
WHERE c.id = 'CLM-001';
```

Result row:  
claim=CLM-001, directive=SV24V-InstallationDirective, attestation=LeadTechnicianAttestation, audit=MaintenanceAudit
