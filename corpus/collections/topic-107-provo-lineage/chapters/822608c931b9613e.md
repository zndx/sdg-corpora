# Chapter 7: Relational Encoding of Audit, Directive and Attestation Ontologies

This chapter presents five tables that realize five OWL axioms governing the production and support of descriptive information content entities within audit processes. The tables are populated with instances drawn from compliance verification of organizational meeting records. Primary-key and foreign-key columns implement the existential and cardinality restrictions stated in the axioms, permitting cross-table navigation that reconstructs chains of evidence, authorship and application.

## 1 Schema Overview

The schema comprises exactly the five tables projected from the supplied axioms. Each table is introduced by a statement of the axiom it materializes, followed by its column definitions and an example join path. All identifiers are opaque strings; foreign-key values are drawn exclusively from the primary-key column of the referenced table.

### 1.1 t_evidence_basic

Axiom 3 classifies any individual that is a descriptive information content entity. The table therefore stores only the identifier and the class reference. Column id is the primary key; column x records the class that satisfies the subclass axiom.

### 1.2 t_audit_produces_evidence

Axiom 1 states that an audit process produces at least one descriptive information content entity. Column id is the primary key; column x references an instance of t_evidence_basic, thereby recording the evidence produced. A reader can obtain the evidence class for any audit by joining on x = t_evidence_basic.id.

### 1.3 t_claim_min_one_evidence

Axiom 5 requires every claim (itself a descriptive information content entity) to be supported by at least one audit-produced evidence item. Column id is the primary key; column x names the claim class; column y is a foreign key to t_audit_produces_evidence.id. The join y = t_audit_produces_evidence.id yields the audit that generated the supporting evidence.

Column id is the primary key; column x holds the directive class; column y is a foreign key to t_attestation_with_supporting_evidence.id; column z records the target of application. The foreign-key constraint enforces that every directive is linked to a prior attestation.

Axiom 4 classifies an attestation process that carries supporting evidence supplied by a directive. Column id is the primary key; column x names the attestation class; column y is a foreign key to t_directive_authored_and_applies.id. The mutual foreign-key relationship between this table and t_directive_authored_and_applies permits bidirectional traversal between directive and attestation.

## 2 Cross-Join Example

To determine the directive class that ultimately supports claim cl-001, traverse the following path:

- cl-001.y → au-001 (t_audit_produces_evidence)
- au-001.x → ev-001 (t_evidence_basic)
- The same evidence identifier appears in the supporting chain of at-001.y → dr-001 (t_directive_authored_and_applies)
- dr-001.y → at-001 (t_attestation_with_supporting_evidence)

The joined row is therefore:

cl-001 | cco:DescriptiveICE | au-001 | ev-001 | at-001 | dr-001 | cco:DirectiveICE | mt-001
