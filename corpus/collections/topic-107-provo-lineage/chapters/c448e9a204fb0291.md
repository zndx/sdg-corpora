# Audit Evidence Structures in Compliance Reporting

This chapter defines five relational tables that realize an evidence-governance ontology for audit trails. The tables encode directives, attestations, audits, and claims while preserving primary-key and foreign-key constraints that support multi-hop queries over compliance records.

## 1 Ontology-to-Relation Mapping

The mapping follows five axioms that distinguish descriptive information content entities from processes that produce or reference them. Each table below is introduced by the axiom it directly implements, followed by its key structure and an example join path.

### 1.1 Evidence as Descriptive Information Content Entity

Axiom 3 classifies any entity that functions as a descriptive information content entity. Table t_evidence_basic therefore stores only the class identifier for each evidence item; its single-column primary key supplies stable references for later foreign-key chains.

```sql
CREATE TABLE t_evidence_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| ev-001 | CalibrationCertificate |
| ev-002 | TemperatureLog |
| ev-003 | MaterialTestReport |
| ev-004 | OperatorAttestation |
| ev-005 | EquipmentInspection |

### 1.2 Audits That Produce Evidence

Axiom 1 states that an audit process produces evidence. Table t_audit_produces_evidence therefore records each audit instance and the evidence class it yields. The primary key id identifies the audit; column x references an evidence class that may be joined to t_evidence_basic.

```sql
CREATE TABLE t_audit_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| au-101 | CalibrationCertificate |
| au-102 | TemperatureLog |
| au-103 | MaterialTestReport |
| au-104 | EquipmentInspection |

### 1.3 Directives Authored and Applied

Axiom 2 defines a directive that is both authored by an attestation and applies to a target class. Table t_directive_authored_and_applies therefore carries two foreign keys: y references an attestation identifier and z names the target class. The primary key id uniquely identifies each directive instance.

```sql
CREATE TABLE t_directive_authored_and_applies (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_with_supporting_evidence(id)
);
```

| id | x | y | z |
|----|---|---|---|
| dir-201 | QualityPolicy | att-301 | ProductionLine |
| dir-202 | CalibrationDirective | att-302 | TestEquipment |
| dir-203 | SamplingDirective | att-303 | RawMaterialLot |
| dir-204 | ReportingDirective | att-304 | ComplianceReport |

### 1.4 Attestations Carrying Supporting Evidence

Axiom 4 classifies an attestation process that references supporting evidence. Table t_attestation_with_supporting_evidence therefore records each attestation and its linked directive via foreign key y. The primary key id is referenced by both t_directive_authored_and_applies and later claim tables.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_directive_authored_and_applies(id)
);
```

| id | x | y |
|----|---|---|
| att-301 | LineSupervisorSignOff | dir-201 |
| att-302 | MetrologyManagerSignOff | dir-202 |
| att-303 | ReceivingInspectorSignOff | dir-203 |
| att-304 | QualityManagerSignOff | dir-204 |

### 1.5 Claims Requiring Minimum Evidence

Axiom 5 requires every claim to be supported by at least one audit-produced evidence item. Table t_claim_min_one_evidence therefore stores each claim together with a foreign key y that resolves to an audit identifier. The primary key id permits further joins to directive or attestation records.

```sql
CREATE TABLE t_claim_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_audit_produces_evidence(id)
);
```

| id | x | y |
|----|---|---|
| cl-401 | TemperatureWithinSpec | au-102 |
| cl-402 | MaterialHardnessPass | au-103 |
| cl-403 | EquipmentCalibrationCurrent | au-101 |
| cl-404 | DocumentationComplete | au-104 |

## 2 Cross-Join Example

To retrieve the directive, attestation signatory, and supporting audit evidence for claim cl-403, the following path is traversed:

1. Start at t_claim_min_one_evidence row cl-403 (y = au-101).
2. Join t_audit_produces_evidence on id = au-101 to obtain evidence class CalibrationCertificate.
3. Locate t_directive_authored_and_applies row whose y references an attestation that itself references dir-202.
4. Join t_attestation_with_supporting_evidence on id = att-302.

Resulting joined row:

cl-403 | EquipmentCalibrationCurrent | au-101 | CalibrationCertificate | dir-202 | CalibrationDirective | att-302 | MetrologyManagerSignOff

The same pattern extends to any claim by following the foreign-key chain from t_claim_min_one_evidence through t_audit_produces_evidence into the directive-attestation cycle.
