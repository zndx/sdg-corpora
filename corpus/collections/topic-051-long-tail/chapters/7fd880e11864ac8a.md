# Product Metadata Modeling for Design Artifact Catalogs

This chapter presents a minimal relational schema that captures descriptive metadata for design artifacts. The model uses five tables derived directly from OWL axioms for DescriptiveICE and Artifact classes. All tables share a uniform (id, x, y) structure in which x and y hold entity references, enabling cross-table joins on matching values to reconstruct multi-hop facts such as priced, branded items with documented provenance and topic tags.

## 1 Schema Overview

The five tables embody the five supplied axioms. Primary keys are the id columns. Foreign-key relationships are realized by storing the id value of one row inside the x or y column of another row; any equi-join on these columns is therefore valid. Four to six rows per table suffice to demonstrate the required joins.

### 1.1 t_table_topic_tag

This table realizes Axiom 1 (table_topic_tag). Column id is the primary key. Column x references an artifact; column y references a topic class. A reader can join this table to t_schemaorg_product_brand on y = x to retrieve every brand that carries a given topic.

```sql
CREATE TABLE t_table_topic_tag (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.2 t_table_provenance_source

This table realizes Axiom 2 (table_provenance_source). Column id is the primary key. Column x references an artifact; column y references the source table that supplied the record. Joining on x to any product table yields the origin of each metadata assertion.

```sql
CREATE TABLE t_table_provenance_source (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.3 t_schemaorg_product_price

This table realizes Axiom 3 (schemaorg_product_price). Column id is the primary key. Column x references an artifact; column y holds its price literal. A join from this table to t_table_provenance_source on x yields priced items together with their source tables.

```sql
CREATE TABLE t_schemaorg_product_price (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

```sql
CREATE TABLE t_schemaorg_product_brand (
```

### 1.5 t_schemaorg_place_address

This table realizes Axiom 5 (schemaorg_place_address). Column id is the primary key. Column x references an artifact or organization; column y holds the postal address literal. A three-way join across this table, t_schemaorg_product_brand, and t_schemaorg_product_price recovers priced, branded artifacts located at a given address.

```sql
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 2 Cross-Join Example

Question: “What is the price of each DavidDesign artifact that carries the Furniture topic and whose provenance is PressRelease2017?”

Step 1. Select rows from t_table_topic_tag where y = 'Furniture'.  
Result: (DD-2017-BW01, Furniture), (DD-2017-BW04, Furniture).

Step 2. Join those x values to t_table_provenance_source on x and retain only rows where y = 'PressRelease2017'.  
Result: DD-2017-BW01.

Step 3. Join the retained x value to t_schemaorg_product_brand on x and retain only rows where y = 'DavidDesign'.  
Result: DD-2017-BW01 confirmed.

Step 4. Join DD-2017-BW01 to t_schemaorg_product_price on x.  
Result rows:

- DD-2017-BW01, 1250
- DD-2017-BW01, 980

The two prices correspond to distinct catalog entries for the same artifact identifier.
