# Directive Governance Ontologies: Audit Processes

This chapter presents five relational tables that realize the slot structures of five OWL axioms governing audit processes. All processes are subclasses of bfo:0000015. The tables support primary-key and foreign-key joins that answer multi-hop queries about periods, conduct, evidence production, and attestation.

## 1. Foundational Process Table

t_audit_basic embodies AXIOM 5. Column id is the primary key. Column x stores the class-level identifier of the process. No foreign keys are present.

| id    | x                                      |
|-------|----------------------------------------|
| AB001 | MeetingMinutesMarch2020                |
| AB002 | MinisterialDiaryFebruary2016           |
| AB003 | ResolutionComplianceDecember2014       |
| AB004 | BoardAttendanceVerification2020        |
| AB005 | CabinetEvidenceCrossCheck2016          |

t_audit_for_period embodies AXIOM 1. Column id is the primary key. Column x is a foreign key referencing t_audit_basic.id. Column y stores the audit period class.

## 6. Multi-Hop Query Example

Question: Which evidence item was produced by the audit of the March 2020 meeting minutes, and which resolution audit supplied that evidence?

Join path: t_audit_basic (AB001) → t_audit_for_period (AFP001 confirms PeriodMarch2020) → t_verification_min_one_evidence (AVE001 supplies y = AB003) → t_audit_basic (AB003 supplies the evidence class ResolutionComplianceDecember2014).

AB001 | MeetingMinutesMarch2020 | PeriodMarch2020 | AB003 | ResolutionComplianceDecember2014
