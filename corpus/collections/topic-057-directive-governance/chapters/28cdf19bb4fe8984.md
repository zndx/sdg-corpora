# Audit Process Ontologies in Relational Form

This chapter specifies five relational tables that realize OWL axioms for directive governance processes. Each table corresponds to one axiom. Primary keys identify process instances; foreign-key columns encode the existential restrictions. Cross-table joins recover multi-hop facts such as the period, conductor, evidence items, and signatories of a given audit.

## 1. Axiom-to-Table Mapping

### 1.1 Audit Period Relation
Axiom 1 states that an audit process is defined for a specific audit period. Table t_audit_for_period therefore records the period class as a non-null column. Column id is the primary key; column y references a temporal class and functions as a foreign key when joined to period registries.

| id | x | y |
| id | x | y |
| t_audit_for_period_01 | Audit2020Mtg | Period2020Q1 |
| t_audit_for_period_02 | AuditGA69 | Period2014Dec |
| t_audit_for_period_03 | AuditWebView | Period2014Q4 |
| t_audit_for_period_04 | AuditBitterroot | Period2020Mar |

### 1.2 Conducted-By Relation
Axiom 2 asserts that an audit process is conducted by at least one person. Table t_audit_conducted_by therefore stores the conducting person via the x column. Column id is the primary key; x is a foreign key to person instances.

| id | x |
| id | x |
| t_audit_conducted_by_01 | Audit2020Mtg |
| t_audit_conducted_by_02 | AuditGA69 |
| t_audit_conducted_by_03 | AuditWebView |
| t_audit_conducted_by_04 | AuditBitterroot |

### 1.3 Evidence Production Relation
Axiom 3 requires every verification process to produce at least one evidence item. Table t_verification_min_one_evidence therefore links an audit instance to an evidence class. Column id is the primary key; both x and y are foreign keys.

| id | x | y |
| id | x | y |
| t_verification_min_one_evidence_01 | Audit2020Mtg | Minutes20200319 |
| t_verification_min_one_evidence_02 | AuditGA69 | ResolutionA69-454 |
| t_verification_min_one_evidence_03 | AuditWebView | HealthRecordAccessLog |
| t_verification_min_one_evidence_04 | AuditBitterroot | WebViewPolicyDoc |

### 1.4 Attestation Signer Relation
Axiom 4 requires every attestation process to be signed by at least one person. Table t_attestation_min_one_signer therefore records the signer via the x column. Column id is the primary key; x is a foreign key to person instances.

| id | x |
| id | x |
| t_attestation_min_one_signer_01 | Audit2020Mtg |
| t_attestation_min_one_signer_02 | AuditGA69 |
| t_attestation_min_one_signer_03 | AuditWebView |
| t_attestation_min_one_signer_04 | AuditBitterroot |

### 1.5 Basic Audit Relation
Axiom 5 classifies an entity as a process. Table t_audit_basic therefore enumerates the audit instances themselves. Column id is the primary key; x holds the process identifier.

| id | x |
| id | x |
| t_audit_basic_01 | Audit2020Mtg |
| t_audit_basic_02 | AuditGA69 |
| t_audit_basic_03 | AuditWebView |
| t_audit_basic_04 | AuditBitterroot |
| t_audit_basic_05 | AuditFollowUp2020 |

## 2. Cross-Table Query Example

To retrieve the period, conducting officer, and evidence document for Audit2020Mtg, join t_audit_basic to t_audit_for_period on x, then to t_audit_conducted_by on x, then to t_verification_min_one_evidence on x. The resulting row is:

- x = Audit2020Mtg
- y (period) = Period2020Q1
- conducted by = BryAnna Vaughan (via person registry)
- evidence = Minutes20200319

The same pattern applied to AuditGA69 yields period Period2014Dec, conducted by the Fourth Committee, evidence ResolutionA69-454.
