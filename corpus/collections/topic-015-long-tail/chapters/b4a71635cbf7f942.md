# Compliance Directive Schema for ISO 27001 and PCI DSS Controls

This chapter defines the relational projection of five OWL axioms that classify DirectiveICE instances drawn from ISO 27001 Annex A and PCI DSS. The resulting five tables share primary and foreign keys that permit cross-table retrieval of controls, addressed risks, and originating requirements.

## 1 Ontology-to-Relation Mapping

Each axiom is realized by one table. Primary-key columns uniquely identify each directive class. Foreign-key columns enforce the existential and universal restrictions stated in the axioms and enable the multi-hop joins illustrated in section 2.

### 1.1 t_iso27001_annexa_subclass

Axiom 1 states that a class X is a subclass of DirectiveICE and is existentially related to an ISO 27001 Annex A control Y. The table therefore records each Annex A subclass together with its mandatory target control. Column id is the primary key. Column y is a foreign key to t_control_only_addresses_threat_class.id. A reader can join on y to retrieve every control that an Annex A item classifies.

### 1.2 t_control_only_addresses_threat_class

Axiom 2 states that a control class X addresses only a given risk class Y. The table therefore stores the universal restriction. Column id is the primary key. Column y is a foreign key to t_iso27001_annexa_subclass.id. Joining on y yields the Annex A items whose controls are limited to a single risk class.

### 1.3 t_pci_dss_requirement

Axiom 3 states that a class X is a subclass of DirectiveICE and is existentially related to a PCI DSS requirement Y. The table records each such PCI DSS requirement together with its mandatory target control. Column id is the primary key. Column y is a foreign key to t_control_only_addresses_threat_class.id. A join on y returns the controls that satisfy a PCI DSS requirement.

### 1.4 t_requirement_equiv_specifies_target

Axiom 4 states that a requirement class X is equivalent to a DirectiveICE that both specifies a control Y and applies to a target Z. The table therefore stores the two existential restrictions. Column id is the primary key. Column y is a foreign key to t_iso27001_annexa_subclass.id. Joining on y retrieves the Annex A items that a PCI DSS requirement both specifies and applies to.

### 1.5 t_control_addresses_risk

Axiom 5 states that a control class X addresses some risk class Y. The table records the existential risk addressed by each control. Column id is the primary key. Column y is a foreign key to t_iso27001_annexa_subclass.id. A join on y yields every Annex A item whose control addresses a listed risk.

## 2 Cross-Join Example

To determine which PCI DSS requirement governs the control that addresses UnauthorizedAccessRisk on ExternalFacingSystems, begin with t_pci_dss_requirement row pci1 (y = ctlA5.1). Follow ctlA5.1.y into t_iso27001_annexa_subclass row annA5.1. Follow annA5.1.y into t_control_only_addresses_threat_class row ctlA5.1. The joined result is the single row:

pci1 | NetworkSegmentation | ctlA5.1 | annA5.1 | AccessControlPolicy | ExternalFacingSystems
