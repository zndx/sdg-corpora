# Modeling DirectiveICE Subclasses for ISO 27001 and PCI DSS Compliance

This chapter defines five relational tables that instantiate the slot structures of five OWL axioms governing cco:DirectiveICE subclasses. The tables record class-level relationships among annex controls, risk addresses, and PCI DSS requirements. All column values are entity references or literals consistent with the slot types. Primary-key and foreign-key constraints enable cross-table joins that answer multi-hop compliance queries.

## 1. Axiom Instantiation via Tables

### 1.1 t_iso27001_annexa_subclass
This table embodies AXIOM 1. Column id is the primary key. Column y is a foreign key referencing t_control_only_addresses_threat_class.id, recording the risk class addressed by the annex subclass. A reader can join on y to retrieve the control class that only addresses a given threat.

## 2. Cross-Join Demonstration

To answer the query “Which PCI DSS requirement is satisfied by the control that exclusively addresses the risk of the annex subclass A.5.1.1PoliciesForInformationSecurity?”, perform the following joins:

1. Select row from t_iso27001_annexa_subclass where x = 'A.5.1.1PoliciesForInformationSecurity' → y = 'ctl-01'.
2. Select row from t_control_only_addresses_threat_class where id = 'ctl-01'.
3. Select row from t_pci_dss_requirement where y = 'ctl-01' → x = 'Req-1.1FirewallStandards'.

The joined result row is: (isoA-01, A.5.1.1PoliciesForInformationSecurity, ctl-01, AccessControlPolicy, pci-01, Req-1.1FirewallStandards).
