# Chapter 4. Relational Projection of Directive ICE Governance Axioms

This chapter presents five tables that realize the Manchester OWL axioms for cco:DirectiveICE subclasses. The tables support cross-table queries that recover multi-hop relationships among ISO 27001 Annex A controls, threat classes, PCI DSS requirements, and risk-addressing specifications.

## 1. Ontology-to-Relation Mapping

The axioms define restricted subclasses of Directive ICE that either universally or existentially quantify over risk and requirement classes. Each table below is the direct relational image of one axiom; column domains are Class references or identifiers, and foreign-key constraints encode the quantified restrictions.

### 1.1 t_iso27001_annexa_subclass

Axiom 1 states that a class X is a subclass of Directive ICE that stands in the iso27001AnnexA relation to some Annex A control class Y. The primary key is id; the foreign key y references the control class that the Annex A entry addresses.

```sql
SELECT a.x, c.x
FROM t_iso27001_annexa_subclass a
JOIN t_control_only_addresses_threat_class c ON a.y = c.id;
```

| id | x | y |
| id | x | y |
| isoA-01 | A.5.1.1 | ctl-01 |
| isoA-02 | A.5.1.2 | ctl-02 |
| isoA-03 | A.6.1.1 | ctl-03 |
| isoA-04 | A.8.2.1 | ctl-04 |
| isoA-05 | A.12.4.1 | ctl-05 |

### 1.2 t_control_only_addresses_threat_class

Axiom 2 states that a control class X addresses risk only of threat class Y. The primary key is id; the foreign key y references the threat class that the control is permitted to address.

```sql
SELECT c.x, a.x
FROM t_control_only_addresses_threat_class c
JOIN t_iso27001_annexa_subclass a ON c.y = a.id;
```

### 1.5 t_control_addresses_risk

Axiom 5 states that a control class X addresses some risk class Y. The primary key is id; the foreign key y references the Annex A subclass that participates in the risk relation.

## 2. Cross-Join Demonstration

To recover the PCI DSS requirement satisfied by the control that addresses only the threat linked to Annex A entry A.5.1.1, the following three-table join is used:

```sql
SELECT p.x AS pci_requirement,
       c.x AS control,
       a.x AS annex_a
FROM t_pci_dss_requirement p
JOIN t_control_only_addresses_threat_class c ON p.y = c.id
JOIN t_iso27001_annexa_subclass a ON c.y = a.id
WHERE a.x = 'A.5.1.1';
```

Result row: pci_requirement = Req-1.1, control = A.5.1.1-OnlyThreat, annex_a = A.5.1.1.
