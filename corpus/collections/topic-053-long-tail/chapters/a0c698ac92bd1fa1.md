# Laboratory Data Models Grounded in Process Ontologies

This chapter specifies three tables that realize axioms for observations involving artifacts, column annotations on observations, and processes requiring at least one input observation. The tables support direct foreign-key joins that answer multi-hop queries over laboratory records.

## 1 Observation with Participant Axiom

Axiom 1 states that class X is a process having at least one artifact participant. The corresponding table supplies an identifier for each such process class together with the class name itself; the identifier functions as primary key and target for subsequent foreign-key references.

```sql
CREATE TABLE t_observation_with_participant (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id      | x                     |
|---------|-----------------------|
| obs001  | SampleAnalysis        |
| obs002  | EquipmentVerification |
| obs003  | DataRecording         |
| obs004  | QualityInspection     |
| obs005  | CalibrationCheck      |

## 1.1 Column Tag Subclass Axiom

Axiom 2 states that class X is a descriptive information content entity annotating a column of class Y. The table records each annotation class, the observation class it annotates, and enforces a foreign-key constraint from column y to t_observation_with_participant.id.

```sql
CREATE TABLE t_column_tag_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_observation_with_participant(id)
);
```

| id      | x                 | y      |
|---------|-------------------|--------|
| ct001   | ResultHeaderTag   | obs001 |
| ct002   | SerialNumberTag   | obs002 |
| ct003   | TimestampTag      | obs003 |
| ct004   | PassFailTag       | obs004 |
| ct005   | OffsetValueTag    | obs005 |

## 1.2 Process with Minimum One Input Axiom

Axiom 3 states that class X is a process possessing at least one input of class Y. The table records each process class, its required input observation class, and again references t_observation_with_participant.id via foreign key.

```sql
CREATE TABLE t_process_min_one_input (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_observation_with_participant(id)
);
```

| id      | x                    | y      |
|---------|----------------------|--------|
| pt001   | AnalysisWorkflow     | obs003 |
| pt002   | VerificationSequence | obs001 |
| pt003   | RecordingPipeline    | obs002 |
| pt004   | InspectionRoutine    | obs004 |
| pt005   | CalibrationRun       | obs005 |

## 2 Cross-Join Example

Consider the query: for each process that consumes an observation annotated by a column tag, return the process class, the observation class, and the annotation class. The join traverses t_process_min_one_input.y → t_observation_with_participant.id → t_column_tag_subclass.y.

```sql
SELECT p.x AS process, o.x AS observation, c.x AS annotation
FROM   t_process_min_one_input p
JOIN   t_observation_with_participant o ON p.y = o.id
JOIN   t_column_tag_subclass c          ON c.y = o.id;
```

Result rows include:

- AnalysisWorkflow, DataRecording, TimestampTag  
- VerificationSequence, SampleAnalysis, ResultHeaderTag  
- InspectionRoutine, QualityInspection, PassFailTag
