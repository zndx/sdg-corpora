# Directive Governance Ontologies in Compliance Audit Systems

This chapter presents five ontological templates that formalize attestation, lawful-basis declaration, signature, evidence production, and audit conduct within GDPR-aligned directive processes. Each template is realized as a relational table whose primary-key and foreign-key structure directly encodes the Manchester axioms. The resulting schema supports multi-hop queries that traverse evidence chains from attestation to lawful basis to verification outcome.

## 1. Attestation with Supporting Evidence

The table t_attestation_with_supporting_evidence embodies AXIOM 1. Column id is the primary key; column y is a foreign key into t_gdpr_lawful_basis.id, allowing an attestation instance to be joined to its required lawful-basis evidence.

| id | x | y |
|----|---|---|
| att-001 | DPIA-2024-Q3 | lb-consent-01 |
| att-002 | DPIA-2024-Q3 | lb-contract-02 |
| att-003 | RoPA-Update-11 | lb-legal-03 |
| att-004 | Vendor-DPA-07 | lb-legitimate-04 |
| att-005 | CrossBorder-Transfer | lb-consent-01 |

## 1.1 Lawful Basis Declaration

The table t_gdpr_lawful_basis embodies AXIOM 2. Column id is the primary key; column y is a foreign key into t_attestation_with_supporting_evidence.id, closing the mutual reference required by the paired axioms.

| id | x | y |
|----|---|---|
| lb-consent-01 | Processing-Consent | att-001 |
| lb-contract-02 | Processing-Contract | att-002 |
| lb-legal-03 | Processing-LegalObligation | att-003 |
| lb-legitimate-04 | Processing-LegitimateInterest | att-004 |

## 1.2 Signature of Attestation

The table t_attestation_signed_by embodies AXIOM 3. Column id is the primary key; the absence of a foreign-key column reflects the axiom’s single-slot structure restricted to a cco:Person.

The table t_verification_produces_evidence embodies AXIOM 4. Column id is the primary key; column y is a foreign key into t_gdpr_lawful_basis.id, linking each verification process to the lawful basis it substantiates.

## 1.4 Audit Conduct

The table t_audit_conducted_by embodies AXIOM 5. Column id is the primary key; the single-slot design records only the conducting person.

## 2. Cross-Join Example

To retrieve the lawful basis and verification outcome for an attestation signed by a given person, the following mental join is performed:

- Start at t_attestation_signed_by (id = sig-001) → x = att-001
- Join t_attestation_with_supporting_evidence on id = att-001 → y = lb-consent-01
- Join t_gdpr_lawful_basis on id = lb-consent-01 → x = Processing-Consent
- Join t_verification_produces_evidence on y = lb-consent-01 → x = External-Audit-2024

Result row: (att-001, Processing-Consent, External-Audit-2024)
