# Chapter 12: Directive Instances and Attestation Linkage in ISO 27001 Governance Records

This chapter defines the relational representation of five ontology axioms that govern ISO 27001 directive subclasses, requirement equivalence, and attestation signing constraints. The model uses five tables whose primary and foreign keys encode subclass, equivalence, and minimum-cardinality relations. All column values are drawn from the slot types declared in the axioms; cross-table joins therefore reconstruct the original Manchester expressions.

## 1 Scope and Table Overview

The five tables implement the deterministic schemas attached to each axiom. Three tables contain foreign-key columns that reference primary keys in other tables, enabling the multi-hop queries required by the axioms. Each table is preceded by a statement of the axiom it materializes, the key structure, and one example join path.

### 1.1 t_requirement_equiv_specifies_target

Axiom 4 is realized by this table. Column id is the primary key. Columns y and z are foreign keys; y references t_iso27001_clause_subclass.id while z holds the target class to which the requirement applies. A reader can join on y to retrieve every clause that participates in an equivalence axiom.

## 2 Cross-Join Demonstration

To recover every clause, its governing requirement, and the Annex A control it references, execute the following mental join:

```
t_iso27001_clause_subclass.y = t_requirement_equiv_specifies_target.id
t_requirement_equiv_specifies_target.id = t_iso27001_annexa_subclass.y
```

Result row for cls-010:
- clause x = A.9.1.1
- requirement x = AccessControlRequirement
- annex y = A.9

The same pattern extends to attestation tables by matching the requirement-derived process name to attestation x values, confirming at least one signer exists.
