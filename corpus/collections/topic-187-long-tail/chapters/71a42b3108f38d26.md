# Chapter 4: Directive Governance Processes in Audit Trails

This chapter presents four relational tables that instantiate OWL axioms for processes involving attestation, audit periods, basic classification, and evidence-producing verification. The tables support primary-key identification of process instances and foreign-key traversal across signer, period, and evidence references.

## 1 Table Definitions and Axiom Mappings

### 1.1 t_audit_basic
This table embodies AXIOM 3 by recording every process instance classified solely as bfo:0000015. Column id is the primary key; column x holds the process class reference.

```
id          x
AUD-001     QuarterlyComplianceReview
AUD-002     AnnualFinancialAttestation
AUD-003     ControlTestingCycle
AUD-004     EvidenceCollectionRun
AUD-005     PeriodEndVerification
```

### 1.2 t_audit_for_period
This table embodies AXIOM 2 by extending a process with a mandatory audit-period reference. Column id is the primary key; column x references a process in t_audit_basic; column y stores the period class.

```
id          x                    y
AFP-001     QuarterlyComplianceReview   Q2_2020
AFP-002     AnnualFinancialAttestation  FY_2020
AFP-003     ControlTestingCycle         Q3_2020
AFP-004     EvidenceCollectionRun       Q2_2020
AFP-005     PeriodEndVerification       FY_2020
```

### 1.3 t_attestation_min_one_signer
This table embodies AXIOM 1 by asserting that each listed process is signed by at least one person. Column id is the primary key; column x references a process already present in t_audit_basic.

```
id          x
ATT-001     AnnualFinancialAttestation
ATT-002     QuarterlyComplianceReview
ATT-003     PeriodEndVerification
ATT-004     ControlTestingCycle
```

### 1.4 t_verification_min_one_evidence
This table embodies AXIOM 4 by requiring each verification process to produce at least one evidence artifact. Column id is the primary key; column x references a process in t_audit_basic; column y stores the evidence class.

```
id          x                         y
VME-001     EvidenceCollectionRun     Form10QFiling
VME-002     PeriodEndVerification     SECWorkpapers
VME-003     ControlTestingCycle       AuditTrailLog
VME-004     QuarterlyComplianceReview BoardMinutes
VME-005     AnnualFinancialAttestation ExternalAuditorReport
```

## 2 Cross-Table Traversal Example

A reader can answer the multi-hop question “Which evidence supports the attestation of the FY_2020 audit that requires a signer?” by the following joins:

- Start at t_audit_for_period where y = 'FY_2020' → x = 'AnnualFinancialAttestation'
- Join t_attestation_min_one_signer on x = 'AnnualFinancialAttestation' (confirms signer requirement)
- Join t_verification_min_one_evidence on x = 'AnnualFinancialAttestation' → y = 'ExternalAuditorReport'

Resulting joined row: (AFP-002, AnnualFinancialAttestation, FY_2020, ATT-001, VME-005, ExternalAuditorReport)
