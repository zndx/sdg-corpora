# Modeling Claim Verification Structures via Ontological Templates

This chapter presents four interlinked ontological templates drawn from DescriptiveICE and Process categories. It shows their projection into four tables that support verification of claims against frames of discernment and supporting or refuting evidence. The schema permits cross-table traversal to resolve multi-hop questions about whether a given claim remains undisconfirmed within a specified evidentiary chain.

## 1 Ontological Templates and Schema Projection

Four templates define the permissible relations. Each template is realized as one table whose column values instantiate the slot types X and Y. Primary-key columns supply stable identifiers for each assertion instance. Foreign-key columns enforce the directed evidentiary links required by the axioms.

### 1.1 t_mass_function_subclass

Axiom 1 states that any X is a subclass of DescriptiveICE that holds over a frame of discernment Y. The table therefore stores the identifier of the mass-function subclass together with the identifier of the frame that bounds its application. Column id is the primary key. Column y is a foreign key that must resolve to an existing row in t_attestation_with_supporting_evidence, ensuring every frame is itself attested.

```sql
SELECT m.x, a.x
FROM t_mass_function_subclass m
JOIN t_attestation_with_supporting_evidence a ON m.y = a.id;
```

### 1.2 t_attestation_with_supporting_evidence

Axiom 2 states that any X is a subclass of Process that carries supporting evidence Y. The table records each attestation instance and the mass-function subclass that supplies its evidential grounding. Column id is the primary key. Column y is a foreign key that must resolve to an existing row in t_mass_function_subclass, closing the mutual dependency between attestation and frame.

```sql
SELECT a.x, m.x
FROM t_attestation_with_supporting_evidence a
JOIN t_mass_function_subclass m ON a.y = m.id;
```

### 1.3 t_claim_refuted_by_evidence

Axiom 3 states that any X is a subclass of DescriptiveICE that is refuted by evidence Y. The table captures each refuted claim and the attestation that supplies the refuting evidence. Column id is the primary key. Column y is a foreign key that must resolve to an existing row in t_attestation_with_supporting_evidence.

```sql
SELECT c.x, a.x
FROM t_claim_refuted_by_evidence c
JOIN t_attestation_with_supporting_evidence a ON c.y = a.id;
```

### 1.4 t_claim_not_disconfirmed

Axiom 4 states that any X is not identical with any Y. The table records claims that remain outside a given class of disconfirmation. Both columns are ordinary data columns; no foreign-key constraint is declared.

## 3 Cross-Join Demonstration

Question: Which mass-function frames remain undisconfirmed after traversing the attestation that refutes the claim of sole reasoning sufficiency?

Execution path:  
1. Locate row cre001 in t_claim_refuted_by_evidence (y = att002).  
2. Join att002 in t_attestation_with_supporting_evidence (y = mfs002).  
3. Join mfs002 in t_mass_function_subclass.  
4. Verify that FrameOfBhaktiPath does not appear in any row of t_claim_not_disconfirmed whose y equals FrameOfExclusiveJnana.

Resulting joined row:  
cre001, ClaimOfSoleReasoningSufficiency, att002, AttestationOfLongingKnowledge, mfs002, FrameOfBhaktiPath

The frame FrameOfBhaktiPath is therefore not disconfirmed by the refuting attestation.
