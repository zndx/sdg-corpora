# Measurement Processes and Artifact Participation

This chapter introduces four ontological templates that capture participation, temporal anchoring, and input/output relations for processes involving artifacts. The templates are realized as a fixed relational schema drawn from laboratory-style observation records. Four tables encode the templates; primary keys identify each assertion while foreign keys enforce participation and flow constraints.

## 1. Observation with Artifact Participant

Axiom 1 states that an observation is a process having at least one artifact participant. The table records each such observation by storing the observation identifier and the participant class.

The column `id` is the primary key. Column `x` holds the participant class. No foreign key is present.

Example mental query: list every observation whose participant class equals a given artifact.

```sql
SELECT id, x
FROM t_observation_with_participant
WHERE x = 'SkinfoldCaliper';
```

| id   | x                  |
|------|--------------------|
| obs1 | SkinfoldCaliper    |
| obs2 | Stopwatch          |
| obs3 | WeighingScale      |
| obs4 | SkinfoldCaliper    |
| obs5 | HeartRateMonitor   |
| obs6 | MeasuringTape      |

## 1.1 Event Start Time Attachment

Axiom 2 states that an artifact bears an event start time. The table links each artifact occurrence to a start-time class via a foreign key into the observation table.

Column `id` is the primary key. Column `x` holds the artifact class. Column `y` is a foreign key referencing `t_observation_with_participant.id`.

Example mental query: retrieve the start-time class for every observation that uses a given artifact.

```sql
SELECT s.id, s.x, s.y
FROM t_schemaorg_event_starttime s
JOIN t_observation_with_participant o ON s.y = o.id
WHERE o.x = 'SkinfoldCaliper';
```

| id    | x                  | y    |
|-------|--------------------|------|
| evt1  | SkinfoldCaliper    | obs1 |
| evt2  | Stopwatch          | obs2 |
| evt3  | WeighingScale      | obs3 |
| evt4  | SkinfoldCaliper    | obs4 |
| evt5  | HeartRateMonitor   | obs5 |
| evt6  | MeasuringTape      | obs6 |

## 2. Process Output Relation

Axiom 3 states that a process has at least one output. The table records each output assertion by linking a process class to an output class.

Column `id` is the primary key. Column `x` holds the process class. Column `y` is a foreign key referencing `t_observation_with_participant.id`.

Example mental query: list every output class produced by observations whose participant is a given artifact.

```sql
SELECT p.id, p.x, p.y
FROM t_process_min_one_output p
JOIN t_observation_with_participant o ON p.y = o.id
WHERE o.x = 'SkinfoldCaliper';
```

| id    | x               | y    |
|-------|-----------------|------|
| out1  | BodyFatPercent  | obs1 |
| out2  | ElapsedTime     | obs2 |
| out3  | BodyMassKg      | obs3 |
| out4  | BodyFatPercent  | obs4 |
| out5  | HeartRateBpm    | obs5 |
| out6  | CircumferenceCm | obs6 |

## 2.1 Process Input Relation

Axiom 4 states that a process has at least one input. The table records each input assertion by linking a process class to an input class.

Column `id` is the primary key. Column `x` holds the process class. Column `y` is a foreign key referencing `t_observation_with_participant.id`.

Example mental query: list every input class consumed by observations whose participant is a given artifact.

```sql
SELECT i.id, i.x, i.y
FROM t_process_min_one_input i
JOIN t_observation_with_participant o ON i.y = o.id
WHERE o.x = 'SkinfoldCaliper';
```

## 3. Cross-Table Query Example

Question: For the observation that records body-fat percentage using the skinfold caliper on an athlete, what start-time class and input class are associated?

Walk the links:

- Start at `t_process_min_one_output` row `out1` (`x` = BodyFatPercent, `y` = obs1).
- Join `t_observation_with_participant` on `obs1` to obtain participant `SkinfoldCaliper`.
- Join `t_schemaorg_event_starttime` on `y` = obs1 to obtain start-time class `SkinfoldCaliper`.
- Join `t_process_min_one_input` on `y` = obs1 to obtain input class `Athlete`.
