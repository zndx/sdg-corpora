# Laboratory Process Observation Schema

This chapter defines a four-table relational schema that directly implements four OWL axioms for observations, artifact participation, event timing, inputs, and outputs. All column values are drawn from laboratory measurement activities consistent with the axioms. Primary keys are the id columns; foreign keys on y columns in the timing, input, and output tables reference t_observation_with_participant.id and enable two- and three-table joins.

## 1. Core Observation Table

Table t_observation_with_participant realizes AXIOM 1. Column id is the primary key. Column x records the class asserted to be a process that has an artifact participant. No foreign keys exist.

| id     | x                     |
|--------|-----------------------|
| obs1   | BodyFatMeasurement    |
| obs2   | EventTiming           |
| obs3   | LocationLogging       |
| obs4   | FeeProcessing         |
| obs5   | ResultDerivation      |
| obs6   | SampleAcquisition     |

## 2. Event Start Time Table

Table t_schemaorg_event_starttime realizes AXIOM 2. Column id is the primary key. Column x identifies an artifact; column y is a foreign key to t_observation_with_participant.id and supplies the start-time observation.

| id    | x        | y     |
|-------|----------|-------|
| st1   | Calipers | obs2  |
| st2   | Form     | obs2  |
| st3   | Laptop   | obs2  |
| st4   | Printer  | obs2  |

## 3. Process Output Table

Table t_process_min_one_output realizes AXIOM 3. Column id is the primary key. Column x identifies a process class; column y is a foreign key to t_observation_with_participant.id and asserts at least one output observation.

| id     | x                  | y     |
|--------|--------------------|-------|
| po1    | BodyFatMeasurement | obs5  |
| po2    | EventTiming        | obs5  |
| po3    | LocationLogging    | obs3  |
| po4    | FeeProcessing      | obs4  |
| po5    | SampleAcquisition  | obs6  |

## 4. Process Input Table

Table t_process_min_one_input realizes AXIOM 4. Column id is the primary key. Column x identifies a process class; column y is a foreign key to t_observation_with_participant.id and asserts at least one input observation.

| id     | x                  | y     |
|--------|--------------------|-------|
| pi1    | BodyFatMeasurement | obs6  |
| pi2    | EventTiming        | obs2  |
| pi3    | LocationLogging    | obs3  |
| pi4    | FeeProcessing      | obs4  |
| pi5    | ResultDerivation   | obs5  |

## 5. Cross-Table Query Example

Question: which artifact records the start time of the BodyFatMeasurement process that accepts SampleAcquisition as input and produces ResultDerivation as output?

Execution path:  
- Locate BodyFatMeasurement in t_process_min_one_input where y = obs6 (SampleAcquisition).  
- Locate the same class in t_process_min_one_output where y = obs5 (ResultDerivation).  
- Join the matching observation id (obs1) to t_schemaorg_event_starttime on y, yielding artifact Calipers and start-time observation obs2.

Joined row: (obs1, BodyFatMeasurement, obs6, SampleAcquisition, obs5, ResultDerivation, st1, Calipers, obs2).
