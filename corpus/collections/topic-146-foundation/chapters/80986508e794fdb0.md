# Product Branding and Traceability in Supply Chain Quality Systems

This chapter defines the ontological relationship between artifacts and brands and demonstrates its implementation in a relational schema for supply chain quality management. The model supports traceability queries across products, lots, shipments, and quality checks while preserving foreign-key integrity.

## 1 Scope and Schema Overview

The single axiom treated here states that an artifact class stands in the relation hasBrand to a brand class. The relational projection materializes this axiom as table t_schemaorg_product_brand. Three additional tables extend the model to lots, shipments, and quality checks, each carrying primary keys and foreign keys that permit multi-hop joins. All column values are instances consistent with the axiom slot types.

### 1.1 t_schemaorg_product_brand

This table directly embodies the axiom Class {X} SubClassOf cco:Artifact, sdg:hasBrand some {Y}. Column id is the primary key. Column x references an artifact individual; column y references the corresponding brand. A reader can join on x to retrieve every brand asserted for a given product.

```sql
CREATE TABLE t_schemaorg_product_brand (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.2 t_product_lots

This table records lot instances that instantiate the artifacts listed in t_schemaorg_product_brand. Column lot_id is the primary key. Column product_id is a foreign key to t_schemaorg_product_brand.x. A cross-join on product_id yields the brand for any lot.

```sql
CREATE TABLE t_product_lots (
  lot_id VARCHAR(255),
  product_id VARCHAR(255) NOT NULL,
  manufacture_date DATE,
  quantity INTEGER,
  PRIMARY KEY (lot_id),
  FOREIGN KEY (product_id) REFERENCES t_schemaorg_product_brand(x)
);
```

### 1.3 t_shipments

This table captures movement of lots. Column shipment_id is the primary key. Column lot_id is a foreign key to t_product_lots.lot_id. Joining through lot_id reaches both the product identifier and its brand.

```sql
CREATE TABLE t_shipments (
  shipment_id VARCHAR(255),
  lot_id VARCHAR(255) NOT NULL,
  ship_date DATE,
  destination VARCHAR(255),
  PRIMARY KEY (shipment_id),
  FOREIGN KEY (lot_id) REFERENCES t_product_lots(lot_id)
);
```

### 1.4 t_quality_checks

This table stores inspection outcomes. Column check_id is the primary key. Column shipment_id is a foreign key to t_shipments.shipment_id. A three-table join from check_id through shipment_id and lot_id returns the brand of the inspected product.

```sql
CREATE TABLE t_quality_checks (
  check_id VARCHAR(255),
  shipment_id VARCHAR(255) NOT NULL,
  check_date DATE,
  auditor VARCHAR(255),
  result VARCHAR(255),
  PRIMARY KEY (check_id),
  FOREIGN KEY (shipment_id) REFERENCES t_shipments(shipment_id)
);
```

## 2 Cross-Join Demonstration

Question: Which brand was carried by the lot in shipment SHP-2003 that failed quality check QC-3003?

Execution path:  
QC-3003 → shipment_id = SHP-2003 (t_quality_checks)  
SHP-2003 → lot_id = LOT-1003 (t_shipments)  
LOT-1003 → product_id = PROD-4003 (t_product_lots)  
PROD-4003 → y = MedTech Global (t_schemaorg_product_brand)

Result row:  
check_id=QC-3003, shipment_id=SHP-2003, lot_id=LOT-1003, product_id=PROD-4003, brand=MedTech Global, result=Fail
