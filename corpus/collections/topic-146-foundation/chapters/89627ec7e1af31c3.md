# Artifact Brand Relations in Supply Chain Quality Models

This chapter defines the subclass relation of artifacts under the hasBrand property and projects it into a minimal relational schema. The schema supports traceability from branded artifacts through lots, shipments, and quality checks. All instances satisfy the axiom that an artifact X stands in the hasBrand relation to a brand Y.

## 1. Ontological Grounding

The single axiom employed is schemaorg_product_brand. It states that any individual of type cco:Artifact may be linked via the existential restriction sdg:hasBrand some {Y:Class}. The verbalization is therefore “X is something that has brand Y.” Slot types are restricted to Class for both X and Y; no data properties or additional object properties are admitted by the axiom.

### 1.1 Scope of Artifact and Brand

Only entities that can be asserted as cco:Artifact participate as values of column x. Brands occupy column y and are treated as named classes rather than individuals. The relation is many-to-one from artifacts to brands; a single artifact row may not reference more than one brand.

## 2. Relational Projection

Four tables realize the axiom together with the necessary supply-chain context. The first table directly encodes the axiom. The remaining tables supply foreign-key paths that permit multi-hop queries while preserving the brand linkage.

### 2.1 t_schemaorg_product_brand

This table is the direct projection of schemaorg_product_brand. Column id is the primary key. Column x references an artifact; column y references its brand. Every row asserts the hasBrand restriction for the artifact identified in x.

```sql
CREATE TABLE t_schemaorg_product_brand (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 2.2 t_lot

Each lot is a concrete portion of a single product. Column lot_id is the primary key. Column product_id is a foreign key to the x values of t_schemaorg_product_brand, thereby inheriting the brand assertion. Column creation_date records the production event.

### 2.3 t_shipment

A shipment moves one lot to a destination. Column shipment_id is the primary key. Column lot_id is a foreign key to t_lot. Column ship_date and destination are simple attributes.

### 2.4 t_quality_check

A quality check is performed on a shipment. Column check_id is the primary key. Column shipment_id is a foreign key to t_shipment. Column result records the binary outcome; column inspector records the performing agent.

## 3. Cross-Join Example

Question: “Which brand was carried by the lot that failed its quality check on 11 November 2016?”

Walk the foreign keys:

- Locate FAIL row in t_quality_check (qc-3002).  
- Follow shipment_id → shp-2002 in t_shipment.  
- Follow lot_id → lot-1002 in t_lot.  
- Follow product_id → product-002 in t_schemaorg_product_brand.  
- Read y = Brand-B.

The joined row is therefore:

(product-002, lot-1002, shp-2002, qc-3002, Brand-B, FAIL)
