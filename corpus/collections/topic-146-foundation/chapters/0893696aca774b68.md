# Artifact Branding in Municipal Procurement Records

This chapter defines the ontological relation between artifacts and brands and demonstrates its projection into a minimal relational schema. The schema supports traceability queries across suppliers, lots, and branded artifacts in a municipal compliance setting.

## 1 Scope and Domain

The model addresses city-procured artifacts that must satisfy brand provenance requirements during inspections. Only the axiom `schemaorg_product_brand` is used. All instances are drawn from records consistent with Chicago business compliance and university equipment registers.

### 1.1 Axiom Projection

The axiom states that an artifact class X stands in the relation `sdg:hasBrand` to a brand class Y. The deterministic relational projection yields a single table whose rows record exactly this existential restriction.

## 2 Relational Tables

Three tables realize the axiom together with the supporting identification of suppliers and lots. Primary keys are stable identifiers; foreign keys enforce referential integrity required for multi-hop retrieval.

### 2.1 Supplier Registry

This table enumerates legal entities that supply artifacts. Its primary key `supplier_id` is referenced by the lot table, enabling the first hop of any brand-provenance query.

```sql
CREATE TABLE t_supplier (
  supplier_id VARCHAR(255) PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  city_dept_ref VARCHAR(255)
);
```

### 2.2 Lot Identification

Each lot groups artifacts received under a single procurement action. The foreign key `supplier_id` links to `t_supplier`. The primary key `lot_id` is referenced by the brand table.

```sql
CREATE TABLE t_lot (
  lot_id VARCHAR(255) PRIMARY KEY,
  supplier_id VARCHAR(255) NOT NULL,
  receipt_date DATE,
  FOREIGN KEY (supplier_id) REFERENCES t_supplier(supplier_id)
);
```

### 2.3 Artifact-Brand Relation

This table is the direct projection of the axiom. Column `x` holds the artifact class; column `y` holds the brand class. The foreign key `lot_id` anchors each branded artifact to its originating lot.

```sql
CREATE TABLE t_schemaorg_product_brand (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255) NOT NULL,
  y VARCHAR(255) NOT NULL,
  lot_id VARCHAR(255) NOT NULL,
  FOREIGN KEY (lot_id) REFERENCES t_lot(lot_id)
);
```

## 3 Cross-Join Example

Question: Which brand of torque wrench was received from a supplier referenced by the City of Chicago inspections department?

Walk the foreign keys:

1. Start in `t_schemaorg_product_brand` where `x = 'Torque Wrench'`.
2. Follow `lot_id` to `t_lot`.
3. Follow `supplier_id` to `t_supplier` and test `city_dept_ref = 'CD-INS-03'`.

Resulting joined row:

- artifact: Torque Wrench
- brand: Snap-on
- lot: LOT-1003
- supplier: Acme Calibration Inc.
- department reference: CD-INS-03
