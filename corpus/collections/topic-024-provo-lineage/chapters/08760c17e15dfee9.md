# Representation of Descriptive Information Content Entities in Product Pricing Schemas

This chapter presents three relational tables that instantiate OWL axioms for descriptive information content entities and their extensions to priced artifacts. The tables support cross-table joins that resolve multi-hop queries over class references and attribute constraints. All column values conform to the slot types declared in the axioms, with foreign-key linkages preserving the subclass and existential restrictions.

## 1. Core Axiom for Descriptive Information Content Entities

The table t_outlier_claim_basic directly embodies axiom 2. Its primary key column id uniquely identifies each descriptive information content entity instance; the column x holds the class reference that satisfies the SubClassOf restriction to cco:DescriptiveICE. No foreign keys are present because the axiom declares a single unary class restriction.

```sql
CREATE TABLE t_outlier_claim_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id          | x                          |
|-------------|----------------------------|
| claim001    | PriceDeviationNotice       |
| claim002    | CatalogEntryAnomaly        |
| claim003    | RegulatoryPriceFlag        |
| claim004    | SupplierCostVariance       |
| claim005    | MarketOutlierAlert         |

A reader can select any id to retrieve the corresponding descriptive class without traversing additional tables.

## 1.1 Extension to Artifact Pricing

The table t_schemaorg_product_price embodies axiom 1. Its primary key id identifies each priced artifact; column x references the artifact class while column y is a foreign key to t_outlier_claim_basic.id, satisfying the existential restriction sdg:hasPrice some {Y:Class}. The foreign-key constraint enforces that every price record links to exactly one descriptive claim.

```sql
CREATE TABLE t_schemaorg_product_price (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_outlier_claim_basic(id)
);
```

Example rows:

| id         | x                  | y         |
|------------|--------------------|-----------|
| price001   | DiagnosticKit      | claim001  |
| price002   | ReagentLot         | claim002  |
| price003   | CalibrationStd     | claim003  |
| price004   | ConsumablePack     | claim001  |
| price005   | InstrumentProbe    | claim004  |
| price006   | BufferSolution     | claim005  |

Joining on y yields the descriptive claim class for any given artifact price.

## 1.2 Attribute Cardinality Constraint

The table t_outlier_claim_min_one_attribute embodies axiom 3. Its primary key id identifies each constrained claim; column x again holds the descriptive class while column y is a foreign key to t_schemaorg_product_price.id, satisfying the minimum cardinality restriction sdg:hasAttributeSet min 1 {Y:Class}. The foreign-key structure guarantees at least one priced artifact is attached to each qualifying claim.

```sql
CREATE TABLE t_outlier_claim_min_one_attribute (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_schemaorg_product_price(id)
);
```

Example rows:

| id          | x                          | y        |
|-------------|----------------------------|----------|
| attr001     | PriceDeviationNotice       | price001 |
| attr002     | CatalogEntryAnomaly        | price002 |
| attr003     | RegulatoryPriceFlag        | price003 |
| attr004     | SupplierCostVariance       | price005 |
| attr005     | MarketOutlierAlert         | price006 |

A cross-join between t_outlier_claim_min_one_attribute.y and t_schemaorg_product_price.id followed by a second join on t_schemaorg_product_price.y to t_outlier_claim_basic.id recovers the full chain from constrained claim through priced artifact to base descriptive entity.

## 2. Multi-Hop Query Example

Consider the question: given attribute claim attr003, retrieve the descriptive class of the underlying claim referenced by its priced artifact. Begin with t_outlier_claim_min_one_attribute where id = 'attr003', yielding y = 'price003'. Follow the foreign key into t_schemaorg_product_price where id = 'price003', yielding y = 'claim003'. Follow that foreign key into t_outlier_claim_basic where id = 'claim003', yielding x = 'RegulatoryPriceFlag'. The joined result row is therefore (attr003, RegulatoryPriceFlag).
