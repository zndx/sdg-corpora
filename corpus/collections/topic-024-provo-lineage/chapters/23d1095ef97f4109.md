# Chapter 7: Relational Encodings of Descriptive Information Content Entities for Artifact Pricing

This chapter presents three axioms that formalize descriptive claims about artifact prices and maps each axiom to a corresponding relational table. The tables share primary and foreign keys that permit cross-table joins, enabling retrieval of chained price attributes attached to specific claims. All column values are instances consistent with the slot types declared in the axioms.

## 1 Axiom-to-Table Projections

Each table is introduced by the axiom it directly implements. Primary-key columns uniquely identify rows; foreign-key columns enforce the existential restrictions expressed in the Manchester syntax.

### 1.1 t_outlier_claim_basic

Axiom 2 states that any individual occupying the position of X is a descriptive information content entity. The table therefore stores only the minimal identifier and the class reference required by the axiom. Column id is the primary key; column x holds the class name of the entity.

| id       | x                          |
|----------|----------------------------|
| claim001 | PriceDescriptionForAlpha   |
| claim002 | PriceDescriptionForBeta    |
| claim003 | PriceDescriptionForGamma   |
| claim004 | PriceDescriptionForDelta   |
| claim005 | PriceDescriptionForEpsilon |

A reader can select all descriptive claims whose class reference equals a given string; no foreign-key traversal is required for this single-table query.

### 1.2 t_schemaorg_product_price

Axiom 1 asserts that an artifact X possesses a price Y, where Y must itself be a descriptive information content entity. The table therefore records the artifact class in column x and the required price claim in column y. Column id is the primary key; column y is a foreign key referencing t_outlier_claim_basic(id).

| id       | x                 | y        |
|----------|-------------------|----------|
| price001 | ArtifactWidgetA   | claim001 |
| price002 | ArtifactWidgetB   | claim002 |
| price003 | ArtifactWidgetC   | claim003 |
| price004 | ArtifactWidgetD   | claim004 |
| price005 | ArtifactWidgetE   | claim005 |

Joining on y = id of t_outlier_claim_basic yields the descriptive claim that supplies the price for each artifact.

### 1.3 t_outlier_claim_min_one_attribute

Axiom 3 extends the descriptive claim by requiring at least one attribute set. The table therefore links each augmented claim (column x) to a price record (column y). Column id is the primary key; column y is a foreign key referencing t_schemaorg_product_price(id).

| id        | x                        | y        |
|-----------|--------------------------|----------|
| attr001   | AttributeSetAlpha        | price001 |
| attr002   | AttributeSetBeta         | price002 |
| attr003   | AttributeSetGamma        | price003 |
| attr004   | AttributeSetDelta        | price004 |
| attr005   | AttributeSetEpsilon      | price005 |
| attr006   | AttributeSetZeta         | price001 |
| attr007   | AttributeSetEta          | price003 |

Because y references a price row that itself references a basic claim, two successive equi-joins traverse the full existential chain from attribute set through price to the underlying descriptive claim.

## 2 Multi-Hop Retrieval Example

Consider the question: “Which attribute sets are attached to the price of ArtifactWidgetA, and what descriptive claim supplies that price?” The query is answered by the following equi-join path:

t_outlier_claim_min_one_attribute.y = t_schemaorg_product_price.id  
t_schemaorg_product_price.y = t_outlier_claim_basic.id

Execution yields the joined row:

attr001 | AttributeSetAlpha | price001 | ArtifactWidgetA | claim001 | PriceDescriptionForAlpha

A second row also satisfies the artifact filter because price001 participates in two attribute sets:

attr006 | AttributeSetZeta | price001 | ArtifactWidgetA | claim001 | PriceDescriptionForAlpha

No additional tables or columns are required; the foreign-key constraints alone guarantee that every returned tuple satisfies the three axioms simultaneously.
