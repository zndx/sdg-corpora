# Ontological Constraints in Supply Specification Systems

This chapter presents four tables that project Manchester axioms for artifact equivalence, directive specification, and cardinality restrictions onto a relational schema. The domain is school supply governance, where artifacts are physical items such as notebooks and binders, directives encode quantity rules, and cardinalities constrain part-whole relations.

## 1. Artifact–Part Equivalence

Table t_equiv_intersect_artifact_with_part embodies axiom 1. Column id is the primary key. Column y is a foreign key to t_requirement_equiv_specifies_target.id, establishing that each artifact equivalence is governed by a directive that names both target and applicability scope. A reader can join on y to retrieve the directive that licenses the part relation for a given artifact class.

| ART002 | ThreeRingBinder | REQ002 |
| ART003 | CompositionBook | REQ003 |

| ART005 | SpiralNotebook | REQ004 |

## 2. Requirement Directive Specification

Table t_requirement_equiv_specifies_target embodies axiom 2. Column id is the primary key. Columns y and z are foreign keys to t_equiv_intersect_artifact_with_part.id, recording the target class and the applicability class of each directive. A reader can join on y to obtain the artifact class that the directive specifies and on z to obtain the class to which the directive applies.

## 5. Cross-Join Example

To answer the multi-hop question “which artifact class must appear at least twice and is limited to three parts under directive REQ001,” begin with t_requirement_equiv_specifies_target where id = REQ001, follow the foreign key y to t_equiv_intersect_artifact_with_part (yielding x = WideRuleNotebook), then follow the foreign keys from t_cardinality_min_two_generic.y and t_cardinality_max_three_generic.y back to the same REQ001 row.
