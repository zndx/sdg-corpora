# Chapter 4: Relational Encoding of Artifact–Directive Equivalences and Cardinality Constraints

This chapter presents four tables that encode selected OWL axioms governing artifacts, directives, and numeric restrictions. The tables are populated with instances drawn from a laboratory supply-compliance system in which artifacts (notebooks, binders, folders) are subject to directive requirements that specify both targets and applicability scopes. Primary-key and foreign-key columns implement the slot mappings declared by each axiom, enabling cross-table navigation that recovers multi-hop entailments such as “which cardinality bounds apply to an artifact referenced by a given requirement.”

## 1. Axiom Embodiment and Table Definitions

### 1.1 Table t_equiv_intersect_artifact_with_part
Axiom 1 states that a class X is equivalent to the intersection of cco:Artifact and the existential restriction on bfo:0000051 (has_part) to class Y. The table therefore records pairs (x, y) together with a surrogate identifier. Column id is the primary key; column y is a foreign key into t_requirement_equiv_specifies_target, ensuring every part-class reference is justified by an existing requirement record.

| id          | x                  | y             |
|-------------|--------------------|---------------|
| equiv_001   | NotebookPaper      | req_010       |
| equiv_002   | ThreeRingBinder    | req_011       |
| equiv_003   | CompositionBook    | req_012       |
| equiv_004   | PocketFolder       | req_013       |
| equiv_005   | SpiralNotebook     | req_014       |

### 1.2 Table t_requirement_equiv_specifies_target
Axiom 2 defines a directive class X that is equivalent to cco:DirectiveICE conjoined with an sdg:specifies restriction to Y and an sdg:appliesTo restriction to Z. The table stores the triple (x, y, z). Column id is the primary key; column y is a foreign key into t_equiv_intersect_artifact_with_part, closing the mutual reference required by the two equivalences.

### 1.3 Table t_cardinality_max_three_generic
Axiom 3 asserts that class X is a subclass of a property p restricted to at most three instances of class Y. The table records the triple (x, p, y) via columns id, x, y. Column id is the primary key; column y references t_requirement_equiv_specifies_target, anchoring each upper-bound declaration to a governing requirement.

## 2. Cross-Join Demonstration

Consider the multi-hop question: “Which artifact classes are subject to both an upper cardinality bound of three and a lower cardinality bound of two under the SupplyListDirective that applies to JuniorHighGrade?”  

The query is answered by joining t_requirement_equiv_specifies_target (on id) with both cardinality tables (on y), then filtering where x = 'SupplyListDirective' and z = 'JuniorHighGrade'. The joined result contains two rows:

- ThreeRingBinder linked via req_011 (max 3 from card_max_02, min 2 from card_min_01)  
- CompositionBook linked via req_012 (max 3 from card_max_03, min 2 from card_min_04)

These rows are obtained solely by traversing the declared foreign-key references; no additional inference rules are required.
