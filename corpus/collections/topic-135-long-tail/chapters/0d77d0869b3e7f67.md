# Chapter 4: Modeling Directive and Descriptive Information Content Entities in Compliance Audit Trails

This chapter introduces five ontological templates that formalize directive and descriptive information content entities within compliance audit trails for clinical laboratory data handling. The templates are realized as a five-table relational schema whose primary and foreign keys enable multi-hop queries over requirements, baseline rates, evidence correlations, null rates, and safeguards. All instances are drawn from hospital-based records consistent with epidemiological assessment protocols.

## 1. Schema Overview and Domain Grounding

The schema captures PCI DSS requirements and HIPAA physical safeguards as subclasses of cco:DirectiveICE, while baseline rates, evidence correlations, and null rates are modeled as subclasses of cco:DescriptiveICE. Foreign-key references implement the “some” restrictions stated in each Manchester axiom, allowing a reader to traverse from a requirement instance through its associated lift measurement to the supporting evidence record and onward to null-rate profiles.

## 1.1 t_lift_with_baseline_rate

This table embodies AXIOM 2. Column id is the primary key. Column y is a foreign key referencing t_evidence_correlated_with.id, thereby linking each descriptive lift measurement to its correlated evidence record. A mental cross-join on y yields the evidence record whose correlation value supplies the baseline for the lift calculation.

```sql
CREATE TABLE t_lift_with_baseline_rate (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_evidence_correlated_with(id)
);
```

## 1.2 t_evidence_correlated_with

This table embodies AXIOM 3. Column id is the primary key. Column y is a foreign key referencing t_lift_with_baseline_rate.id, closing the mutual reference required by the paired axioms. Joining on this key returns the lift record whose baseline rate is justified by the evidence.

```sql
CREATE TABLE t_evidence_correlated_with (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_lift_with_baseline_rate(id)
);
```

## 1.3 t_pci_dss_requirement

This table embodies AXIOM 1. Column id is the primary key. Column y is a foreign key referencing t_lift_with_baseline_rate.id, satisfying the pciDssRequirement restriction. A cross-join on y retrieves the lift measurement that quantifies compliance deviation for the stated requirement.

```sql
CREATE TABLE t_pci_dss_requirement (
```

## 1.5 t_profile_has_null_rate
