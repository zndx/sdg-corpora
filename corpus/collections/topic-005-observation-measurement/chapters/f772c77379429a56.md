# Chapter 4: Modeling GDPR Directive Compliance Through Signed Attestations and Audit Subclasses

This chapter introduces five ontological templates that formalize relationships among attestations, GDPR articles, supporting evidence, data subject rights, and audits. The templates are projected into a five-table relational schema whose foreign-key links support multi-hop queries over school governance records at Heaton St.Barnabas CE Primary School.

## 1 Ontology-to-Relation Projection

Each axiom is realized by one table. Primary keys uniquely identify each row; foreign keys enforce the subclass and evidence relationships stated in the axioms.

### 1.1 Table t_attestation_signed_by

Axiom 1 states that an attestation is a process signed by a person. The table therefore stores only the attestation identifier and the class that represents the signed process. Column id is the primary key; column x holds the attestation class.

| id  | x                              |
|-----|--------------------------------|
| att01 | GovernorPrivacyAttestation     |
| att02 | DataRetentionAttestation       |
| att03 | SubjectAccessAttestation       |
| att04 | BreachNotificationAttestation  |
| att05 | ProcessorAgreementAttestation  |

### 1.2 Table t_gdpr_article_subclass

Axiom 2 states that a directive information content entity is a subclass of a GDPR article. The table therefore records the attestation class and the article class that specializes it. Column id is the primary key; column y is a foreign key referencing t_attestation_signed_by(id).

| id   | x                              | y     |
|------|--------------------------------|-------|
| ga01 | Article5Attestation            | att01 |
| ga02 | Article6Attestation            | att02 |
| ga03 | Article12Attestation           | att03 |
| ga04 | Article33Attestation           | att04 |

### 1.3 Table t_attestation_with_supporting_evidence

Axiom 3 states that an attestation process is accompanied by supporting evidence. The table therefore links each attestation class to an evidence class. Column id is the primary key; column y is a foreign key referencing t_gdpr_article_subclass(id).

| id   | x                              | y     |
|------|--------------------------------|-------|
| ev01 | MinutesOfGovernorMeeting       | ga01  |
| ev02 | RetentionScheduleDocument      | ga02  |
| ev03 | SARLogExtract                  | ga03  |
| ev04 | ICOBreachReport                | ga04  |

### 1.4 Table t_gdpr_data_subject_right

Axiom 4 states that a directive information content entity grants a data subject right. The table therefore records the attestation class and the right class it grants. Column id is the primary key; column y is a foreign key referencing t_attestation_signed_by(id).

| id   | x                              | y     |
|------|--------------------------------|-------|
| ds01 | AccessRightAttestation         | att03 |
| ds02 | ErasureRightAttestation        | att01 |
| ds03 | PortabilityRightAttestation    | att02 |

### 1.5 Table t_audit_subclass

Axiom 5 states that an audit is a process that audits a control directive information content entity. The table therefore stores the audit class. Column id is the primary key.

| id   | x                              |
|------|--------------------------------|
| au01 | AnnualGDPRComplianceAudit      |
| au02 | SubjectAccessAudit             |
| au03 | BreachResponseAudit            |

## 2 Cross-Join Demonstration

A reader can answer the multi-hop question “Which supporting evidence backs the GDPR article subclass that grants a data subject right under the attestation signed for the annual compliance audit?” by joining t_gdpr_data_subject_right to t_attestation_signed_by, then to t_gdpr_article_subclass, then to t_attestation_with_supporting_evidence.

Execution trace:  
- ds01.y = att03  
- att03 joins to ga03.y  
- ga03 joins to ev03.y  

Result row:  
att03 | SubjectAccessAttestation | ga03 | Article12Attestation | ev03 | SARLogExtract
