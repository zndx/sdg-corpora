# Chapter 4: Directive Governance and Attestation Structures in GDPR Compliance

This chapter defines five core ontological templates that capture the structure of signed attestations, GDPR article specialisations, evidence-supported processes, data subject rights grants, and audit classifications. These templates are materialised as a relational schema of five tables. The schema supports cross-table joins that answer multi-hop governance questions such as “which GDPR article subclass is attested by a given person and supported by which evidence object?” All column values are instances of the slot types declared in the axioms; primary keys are stable identifiers for the respective classes, and foreign keys encode the existential restrictions.

## 1. Schema Overview and Domain Grounding

The domain is GDPR compliance documentation maintained by school governors. Each table directly implements one axiom. Primary keys are opaque identifiers of the form “ATT-###”, “ART-###”, etc. Foreign keys reference those identifiers, enforcing the subclass and existential restrictions expressed in the Manchester syntax. Four to eight rows per table provide sufficient instances for mental cross-join evaluation while remaining compact.

## 1.1 Table t_attestation_signed_by

Axiom 1 states that any attestation process is signed by a person. The table therefore stores the class identifier of the attestation (column x) together with a surrogate primary key. No foreign key is present because the signing relation is the root of the dependency graph.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id     | x                                      |
|--------|----------------------------------------|
| ATT-001| DataProtectionImpactAssessment         |
| ATT-002| RecordsOfProcessingActivities          |
| ATT-003| DataBreachNotificationProcedure        |
| ATT-004| SubjectAccessRequestPolicy             |
| ATT-005| ConsentWithdrawalMechanism             |

A reader can ask: “Which attestation classes exist that are signed?” The answer is obtained by projecting column x.

## 1.2 Table t_gdpr_article_subclass

Axiom 2 specialises a directive information content entity by a concrete GDPR article. Column y is a foreign key to t_attestation_signed_by, ensuring every article subclass is grounded in a signed attestation.

```sql
CREATE TABLE t_gdpr_article_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_signed_by(id)
);
```

Example rows:

| id     | x                  | y       |
|--------|--------------------|---------|
| ART-001| Article30          | ATT-002 |
| ART-002| Article33          | ATT-003 |
| ART-003| Article15          | ATT-004 |
| ART-004| Article7           | ATT-005 |
| ART-005| Article35          | ATT-001 |

Joining on y yields the signed attestation class for each article.

## 1.3 Table t_attestation_with_supporting_evidence

Axiom 3 requires an attestation process to be accompanied by supporting evidence. Column y references t_gdpr_article_subclass, linking evidence to the article that the attestation realises.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_gdpr_article_subclass(id)
);
```

Example rows:

| id     | x                       | y       |
|--------|-------------------------|---------|
| EV-001 | DPIA-Report-2023        | ART-005 |
| EV-002 | ProcessingLog-Export    | ART-001 |
| EV-003 | BreachLog-Entry-47      | ART-002 |
| EV-004 | SAR-Response-Template   | ART-003 |
| EV-005 | ConsentForm-Archive     | ART-004 |

A two-table join (t_attestation_with_supporting_evidence.y = t_gdpr_article_subclass.id) returns the article and its evidence object for any attestation.

## 1.4 Table t_gdpr_data_subject_right

Axiom 4 captures the granting of data subject rights by a directive. Column y again references t_attestation_signed_by, allowing rights grants to be traced to the same signed attestations used for article subclasses.

```sql
CREATE TABLE t_gdpr_data_subject_right (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_signed_by(id)
);
```

Example rows:

| id     | x                       | y       |
|--------|-------------------------|---------|
| RT-001 | RightOfAccess           | ATT-004 |
| RT-002 | RightToErasure          | ATT-005 |
| RT-003 | RightToRectification    | ATT-004 |
| RT-004 | RightToPortability      | ATT-002 |
| RT-005 | RightToRestriction      | ATT-003 |

Because both t_gdpr_article_subclass and t_gdpr_data_subject_right reference the same attestation table, a three-table join can list every article and every right granted under a single signed attestation.

## 1.5 Table t_audit_subclass

Axiom 5 classifies an audit process as one that audits a directive information content entity. The table stores only the audit class identifier; the audited directive is recovered via joins through the evidence and article tables.

```sql
CREATE TABLE t_audit_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id     | x                          |
|--------|----------------------------|
| AUD-001| AnnualGDPRComplianceAudit  |
| AUD-002| IncidentResponseAudit      |
| AUD-003| ConsentAudit               |
| AUD-004| DPIAReviewAudit            |
| AUD-005| SARProcessAudit            |

## 2. Multi-Hop Query Example

Question: “Which evidence object supports the GDPR article that grants the Right of Access, and which attestation class was signed for that article?”

Step 1. Locate the right: RT-001 grants RightOfAccess and references ATT-004.  
Step 2. Find the article subclass that also references ATT-004: ART-003 (Article15).  
Step 3. Retrieve the evidence row whose foreign key equals ART-003: EV-004 (SAR-Response-Template).

Joined result row:

| right_id | right_name       | attestation_id | article_id | article_name | evidence_id | evidence_name         |
|----------|------------------|----------------|------------|--------------|-------------|-----------------------|
| RT-001   | RightOfAccess    | ATT-004        | ART-003    | Article15    | EV-004      | SAR-Response-Template |

The same pattern extends to any combination of the five tables, confirming that the foreign-key graph faithfully realises the existential restrictions of the source axioms.
