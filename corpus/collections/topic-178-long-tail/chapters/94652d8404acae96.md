# Ontological Foundations of Artifacts and Directives in Laboratory Information Systems

This chapter presents four tables that realize a minimal relational projection of an OWL ontology fragment. The tables encode equivalences and subclass axioms involving artifacts, directives, and descriptive information content entities. Primary and foreign keys implement the slot restrictions declared in each axiom, enabling cross-table joins that recover multi-hop relations such as “which descriptive specification governs a given artifact part.”

## 1 Schema Overview

The four tables correspond one-to-one with the supplied axioms. Column domains follow the slot types: identifiers of classes or individuals occupy VARCHAR(255) positions typed as Class or Individual; no additional columns are introduced. Foreign-key constraints are exactly those stated in the axiom comments and are the only sanctioned join paths.

### 1.1 t_subclass_to_descriptive_ice

This table embodies AXIOM 3. Column id is the primary key; column x holds the class asserted to be a subclass of cco:DescriptiveICE. No foreign keys exist. A reader can join x values to any other table’s class references to retrieve all descriptive specifications that classify a given entity.

```sql
SELECT d.x
FROM   t_subclass_to_descriptive_ice d
WHERE  d.x = 'TestMethod';
```

| id       | x                     |
|----------|-----------------------|
| DESC-001 | TestMethod            |
| DESC-002 | EquipmentSpecification|
| DESC-003 | SampleLabel           |
| DESC-004 | CalibrationRecord     |
| DESC-005 | ResultTemplate        |

### 1.2 t_directive_authored_and_applies

This table embodies AXIOM 4. Column id is the primary key. Columns y and z are foreign keys; y references t_requirement_equiv_specifies_target.id and z stores the class to which the directive applies. The structure records that a directive is authored by one requirement and applies to one target class.

```sql
SELECT d.id, d.x, r.x
FROM   t_directive_authored_and_applies d
JOIN   t_requirement_equiv_specifies_target r ON d.y = r.id;
```

### 1.3 t_requirement_equiv_specifies_target

This table embodies AXIOM 2. Column id is the primary key. Columns y and z are foreign keys; y references t_directive_authored_and_applies.id. The row asserts an equivalence between a requirement class and the conjunction of “specifies some Y” and “appliesTo some Z.”

```sql
SELECT r.id, r.x, d.x
FROM   t_requirement_equiv_specifies_target r
JOIN   t_directive_authored_and_applies d ON r.y = d.id;
```

| id       | x                       | y       | z             |

| REQ-002  | SampleRequirement       | DIR-002 | Sample        |

### 1.4 t_equiv_intersect_artifact_with_part

This table embodies AXIOM 1. Column id is the primary key. Column y is a foreign key referencing t_requirement_equiv_specifies_target.id. Each row states that an artifact class X is equivalent to the intersection of cco:Artifact and “hasPart some Y.”

```sql
SELECT a.id, a.x, r.x
FROM   t_equiv_intersect_artifact_with_part a
JOIN   t_requirement_equiv_specifies_target r ON a.y = r.id;
```

## 2 Cross-Join Example

Consider the multi-hop question: “Which descriptive specification governs the part of the artifact CalibratedBalance that is subject to EquipmentRequirement?”  

Execution proceeds as follows:

1. Locate the artifact row: ART-001 (x = CalibratedBalance, y = REQ-001).  
2. Follow REQ-001 into t_requirement_equiv_specifies_target (y = DIR-001).  
3. Follow DIR-001 into t_directive_authored_and_applies (z = Equipment).  
4. Join the class Equipment to t_subclass_to_descriptive_ice on x.

The joined row is:

| artifact_id | artifact_x        | requirement_id | requirement_x          | directive_id | directive_x          | applies_to | descriptive_id | descriptive_x |
|-------------|-------------------|----------------|------------------------|--------------|----------------------|------------|----------------|---------------|
| ART-001     | CalibratedBalance | REQ-001        | EquipmentRequirement   | DIR-001      | CalibrationDirective | Equipment  | DESC-002       | EquipmentSpecification |

The single row demonstrates that the descriptive specification EquipmentSpecification governs the relevant part of CalibratedBalance.
