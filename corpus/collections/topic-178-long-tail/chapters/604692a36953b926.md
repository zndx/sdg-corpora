# Modeling Artifacts and Directives in Laboratory Certification Records

This chapter defines four deterministic mappings from OWL axioms to relational tables. The tables capture class equivalences and subclass axioms for artifacts, directives, and descriptive information content entities. Primary and foreign keys enforce the slot restrictions stated in each axiom, enabling cross-table queries that resolve multi-hop relations such as “which directive authored by a given party applies to an artifact part referenced by a requirement.”

## 1 Foundational Subclass Axioms

### 1.1 Descriptive Information Content Entities
Axiom 3 states that any class X is a subclass of cco:DescriptiveICE. The table t_subclass_to_descriptive_ice therefore stores only the identifier of each such class. Column id is the primary key; column x holds the class name. No foreign keys exist because the axiom asserts a simple subsumption.

```sql
CREATE TABLE t_subclass_to_descriptive_ice (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| d1 | EquipmentSpecification |
| d2 | TestProtocol |
| d3 | CalibrationCertificate |
| d4 | MaintenanceLog |
| d5 | RegulatoryFiling |

### 1.2 DirectiveICE Authorship and Scope
Axiom 4 defines a class X as equivalent to cco:DirectiveICE that is authoredBy some Y and appliesTo some Z. Table t_directive_authored_and_applies records these three slots. Column id is the primary key. Column y is a foreign key referencing t_requirement_equiv_specifies_target(id), ensuring every directive is linked to a requirement that itself specifies a target.

```sql
CREATE TABLE t_directive_authored_and_applies (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

| id | x | y | z |
|----|---|----|----|
| dir1 | ISO17025Requirement | req2 | CalibrationLaboratory |
| dir2 | AES67Directive | req1 | AudioTestBench |
| dir3 | FCCPart15Directive | req3 | EmissionsTestStand |
| dir4 | InternalAuditDirective | req2 | CalibrationLaboratory |

### 1.3 Requirement Specification of Targets
Axiom 2 states that a class X is equivalent to cco:DirectiveICE that specifies some Y and appliesTo some Z. Table t_requirement_equiv_specifies_target stores these slots. Column id is the primary key. Column y is a foreign key referencing t_directive_authored_and_applies(id), closing the mutual reference between requirements and directives.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_directive_authored_and_applies(id)
);
```

| id | x | y | z |
|----|---|----|----|
| req1 | AES67IORequirement | dir2 | PAXModularBreakoutBox |
| req2 | AccreditationRequirement | dir1 | MeasurementTraceability |
| req3 | EmissionsRequirement | dir3 | ShieldedEnclosure |

### 1.4 Artifact–Part Intersection
Axiom 1 asserts that a class X is equivalent to cco:Artifact that hasPart some Y. Table t_equiv_intersect_artifact_with_part records the pair. Column id is the primary key. Column y is a foreign key referencing t_requirement_equiv_specifies_target(id), anchoring each part relation to a requirement that specifies its target.

```sql
CREATE TABLE t_equiv_intersect_artifact_with_part (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

| id | x | y |
|----|----|----|
| ap1 | PAXModularChassis | req1 |
| ap2 | ShieldedEnclosureAssembly | req3 |
| ap3 | TraceabilityChainDocument | req2 |
| ap4 | AmplifierModule | req1 |

## 2 Cross-Table Query Example

To retrieve the artifact part linked to the directive authored for the CalibrationLaboratory, join t_equiv_intersect_artifact_with_part to t_requirement_equiv_specifies_target on y = id, then to t_directive_authored_and_applies on the requirement’s y column. The join yields:

- Artifact part: TraceabilityChainDocument  
- Requirement: AccreditationRequirement  
- Directive: ISO17025Requirement authored for CalibrationLaboratory

The resulting row set is obtained solely by following the declared primary- and foreign-key constraints; no additional columns or external lookup tables are required.
