# Chapter 4: Modeling Directive Artifacts and Descriptive Entities in Administrative Compliance Records

This chapter presents four relational tables that implement a minimal ontological schema for administrative records. The tables capture intersections between artifacts and their parts, requirements that specify targets under directives, descriptive information content entities, and directives that are authored and scoped. All rows are drawn from program registration forms, doctoral candidate files, and board meeting minutes.

## 1. Subclass Membership in Descriptive Information Content Entities

Table t_subclass_to_descriptive_ice embodies AXIOM 3. Each row asserts that the value in column x is a subclass of cco:DescriptiveICE. Column id is the primary key; no foreign keys exist.

| id | x |
|----|---|
| d1 | RegistrationForm |
| d2 | FicheNavette |
| d3 | MeetingMinutes |
| d4 | ProgramDirective |
| d5 | ComplianceRecord |

A reader can list all descriptive entities by selecting x from this table.

## 2. Directive Authorization and Scope

Table t_directive_authored_and_applies embodies AXIOM 4. Column id is the primary key. Column y is a foreign key to t_requirement_equiv_specifies_target(id) and records the authoring requirement; column z records the target class to which the directive applies.

| id | x | y | z |
|----|---|---|---|
| dir1 | HighSchoolRegistration | req2 | LocalSchoolDistrict |
| dir2 | DoctoralFiche | req1 | UnivGrenobleAlpes |
| dir3 | BoardMinutes | req3 | RockfordBoard |
| dir4 | QualityDirective | req4 | CCBC |
| dir5 | AuditDirective | req2 | LocalSchoolDistrict |

A cross-join on y with t_requirement_equiv_specifies_target yields the requirement that authored each directive.

## 3. Requirement Specification of Targets

Table t_requirement_equiv_specifies_target embodies AXIOM 2. Column id is the primary key. Column y is a foreign key to t_directive_authored_and_applies(id) and identifies the directive that carries the requirement; column z identifies the class to which the requirement applies.

| id | x | y | z |
|----|---|---|---|
| req1 | FreshmanCompletion | dir2 | MasterOfPhilosophy |
| req2 | DistrictApproval | dir1 | HighSchoolStudent |
| req3 | PresidentCall | dir3 | BoardMember |
| req4 | SectorDeclaration | dir4 | IndustrialEngineering |
| req5 | LocationDeclaration | dir5 | France |

A cross-join on y with t_directive_authored_and_applies returns the directive and its author for any given requirement.

## 4. Artifact–Part Intersection via Requirements

Table t_equiv_intersect_artifact_with_part embodies AXIOM 1. Column id is the primary key. Column y is a foreign key to t_requirement_equiv_specifies_target(id) and links the artifact intersection to the requirement that specifies its part.

| id | x | y |
|----|---|---|
| art1 | RegistrationPacket | req1 |
| art2 | CandidateFile | req2 |
| art3 | MinutesPacket | req3 |
| art4 | ComplianceDossier | req4 |
| art5 | AuditTrail | req5 |

A cross-join on y with t_requirement_equiv_specifies_target followed by a second join on the resulting y with t_directive_authored_and_applies traverses from artifact part to directive author in two hops.

## 5. Multi-Hop Query Example

Question: Which directive authored the requirement that specifies the part of artifact art2?

Start at t_equiv_intersect_artifact_with_part where id = art2; read y = req2.  
Join to t_requirement_equiv_specifies_target on id = req2; read y = dir1.  
Join to t_directive_authored_and_applies on id = dir1; read x = HighSchoolRegistration.

Result row: (art2, req2, dir1, HighSchoolRegistration).
