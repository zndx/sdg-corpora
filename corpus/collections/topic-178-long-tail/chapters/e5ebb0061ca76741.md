# Chapter 4. Directive and Artifact Ontologies in Municipal Energy Compliance

This chapter presents four tables that encode selected OWL axioms as a queryable relational schema. The tables capture descriptive information content entities, directives that specify targets, authorship and application relations, and intersections of artifacts with their parts. All column values are drawn from the domain of municipal net-zero energy home certification.

## 1. Descriptive Information Content Entities

Axiom 3 states that any class placed in column x of t_subclass_to_descriptive_ice is a subclass of cco:DescriptiveICE. The single-column primary key id uniquely identifies each such class; no foreign keys are present.

```sql
CREATE TABLE t_subclass_to_descriptive_ice (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id       | x                        |
|----------|--------------------------|
| DICE-01  | EnergyGuideReport        |
| DICE-02  | EnerguideCalculation     |
| DICE-03  | ComplianceCertificate    |
| DICE-04  | ParkingDirective         |
| DICE-05  | DensityGuideline         |

## 2. Requirements That Specify Targets

Axiom 2 states that any class placed in column x of t_requirement_equiv_specifies_target is equivalent to cco:DirectiveICE and (sdg:specifies some y) and (sdg:appliesTo some z). Column id is the primary key. Column y is a foreign key referencing t_directive_authored_and_applies.id.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_directive_authored_and_applies(id)
);
```

|----------|-----------------------------|-----------|--------------|
| REQ-01   | NetZeroEnergyRequirement    | DIR-01    | Home         |
| REQ-02   | SecondarySuiteRequirement   | DIR-02    | Suite        |
| REQ-03   | VehicleChargingRequirement  | DIR-03    | Vehicle      |
| REQ-04   | StreetParkingRequirement    | DIR-04    | Street       |
| REQ-05   | DensityIncreaseRequirement  | DIR-05    | Lot          |

## 3. Directives With Authorship and Application

Axiom 4 states that any class placed in column x of t_directive_authored_and_applies is equivalent to cco:DirectiveICE and (sdg:authoredBy some y) and (sdg:appliesTo some z). Column id is the primary key. Column y is a foreign key referencing t_requirement_equiv_specifies_target.id.

```sql
CREATE TABLE t_directive_authored_and_applies (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

## 4. Artifact–Part Intersections

Axiom 1 states that any class placed in column x of t_equiv_intersect_artifact_with_part is equivalent to cco:Artifact and (bfo:0000051 some y). Column id is the primary key. Column y is a foreign key referencing t_requirement_equiv_specifies_target.id.

```sql
CREATE TABLE t_equiv_intersect_artifact_with_part (
  id VARCHAR(255),

  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
```

## 5. Cross-Table Query Example

To retrieve the descriptive report associated with the artifact part of the net-zero home whose directive applies to Windsor Park, execute the following mental join:

- Start at t_equiv_intersect_artifact_with_part where x = "WindsorParkNZEHome" (row ART-01).
- Follow y = "REQ-01" into t_requirement_equiv_specifies_target.
- Follow that row’s y = "DIR-01" into t_directive_authored_and_applies.
- The linked requirement row REQ-01 has z = "Home", confirming application scope.
- The descriptive entity linked via DICE-01 supplies the Energuide value 0 GJ/year.

The joined result row is therefore:

(WindsorParkNZEHome, REQ-01, DIR-01, DICE-01, 0 GJ/year)
