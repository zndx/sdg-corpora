# Directive Specification and Artifact Composition in Compliance Ontologies

This chapter presents four relational tables that encode the slot structures of four OWL axioms governing DirectiveICE, Artifact, and DescriptiveICE classes. The tables support primary-key and foreign-key joins that answer multi-hop questions about authorship, applicability, specification, and part-whole relations.

## 1 Ontological Axioms and Derived Tables

The axioms are realized as tables whose columns correspond exactly to the declared slots. Primary keys identify each class expression; foreign keys enforce the existential restrictions required by the Manchester syntax definitions.

### 1.1 Subclass assertions for DescriptiveICE

Axiom 3 states that any class placed in this table is a subclass of cco:DescriptiveICE. The single-column primary key supplies the class name that participates in later foreign-key references.

```sql
CREATE TABLE t_subclass_to_descriptive_ice (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| d1 | ComplianceDirective |
| d2 | InspectionDirective |
| d3 | MaintenanceDirective |
| d4 | CertificationDirective |

### 1.2 Directive authorship and applicability

Axiom 4 defines a DirectiveICE that is authored by one entity and applies to another. The primary key identifies the directive class; the foreign key on column y references a requirement that itself specifies a target.

```sql
CREATE TABLE t_directive_authored_and_applies (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

| id | x | y | z |
|----|---|---|---|
| dir1 | ComplianceDirective | req1 | SupervisorBoard |
| dir2 | InspectionDirective | req2 | FieldInspector |
| dir3 | MaintenanceDirective | req3 | PublicWorksDept |
| dir4 | CertificationDirective | req4 | CountyEngineer |

### 1.3 Requirement specification of targets

Axiom 2 defines a DirectiveICE that both specifies a target class and applies to a further class. The primary key identifies the requirement; the foreign key on column y closes the cycle with the directive table.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_directive_authored_and_applies(id)
);
```

| id | x | y | z |
|----|---|---|---|
| req1 | ComplianceRequirement | dir1 | ArtifactBridge |
| req2 | InspectionRequirement | dir2 | ArtifactRoadway |
| req3 | MaintenanceRequirement | dir3 | ArtifactFacility |
| req4 | CertificationRequirement | dir4 | ArtifactVehicle |

### 1.4 Artifact–part intersection

Axiom 1 asserts that a class is both an Artifact and has a part that satisfies a given requirement. The primary key identifies the intersection class; the foreign key on column y links to the requirement that supplies the part restriction.

```sql
CREATE TABLE t_equiv_intersect_artifact_with_part (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

| id | x | y |
|----|---|---|
| art1 | BridgeSpan | req1 |
| art2 | RoadSegment | req2 |
| art3 | PumpStation | req3 |
| art4 | FleetUnit | req4 |
| art5 | RetainingWall | req1 |

## 2 Cross-table Query Example

To determine which DescriptiveICE class governs the part-whole structure of an artifact that is subject to a directive authored by the SupervisorBoard, perform the following joins:

1. Start in t_directive_authored_and_applies where z = 'SupervisorBoard' (row dir1).
2. Follow y to t_requirement_equiv_specifies_target (row req1).
3. Follow the requirement id to t_equiv_intersect_artifact_with_part (row art1).
4. Join t_subclass_to_descriptive_ice on the directive class name.

The resulting joined row is:

(ComplianceDirective, SupervisorBoard, ComplianceRequirement, ArtifactBridge, BridgeSpan, d1)

This path traverses three foreign-key links and recovers the DescriptiveICE subclass that classifies the directive controlling the artifact part.
