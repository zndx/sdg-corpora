# Relational Modeling of GDPR Compliance Processes

This chapter defines a five-table relational schema that directly implements five OWL axioms for directive governance. The schema captures lawful bases, evidence requirements, verifications, attestations, and article subclasses in the setting of Palm Beach County Criminal Justice Commission data-handling controls. All column values are instances of the slot types declared in the axioms; foreign-key constraints enforce the SubClassOf restrictions and permit multi-hop joins.

## 1 Ontology Axioms and Table Projections

The axioms are presented in the order required by their foreign-key dependencies. Each table is preceded by a statement of the axiom it embodies, its primary-key definition, and its foreign-key target.

### 1.1 t_control_with_evidence_requirement

Axiom 5 states that a DirectiveICE requires evidence of a lawful basis. The table therefore stores the control identifier as primary key and records the required lawful-basis identifier as a non-null foreign key referencing t_gdpr_lawful_basis.

```sql
CREATE TABLE t_control_with_evidence_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_gdpr_lawful_basis(id)
);
```

### 1.2 t_gdpr_lawful_basis

Axiom 2 states that a DirectiveICE has a lawful basis that itself is a control with evidence requirement. The table therefore stores the basis identifier as primary key and records the controlling requirement identifier as a non-null foreign key referencing t_control_with_evidence_requirement.

```sql
CREATE TABLE t_gdpr_lawful_basis (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_with_evidence_requirement(id)
);
```

### 1.3 t_gdpr_article_subclass

Axiom 4 states that a DirectiveICE is subclassed under a specific GDPR article that is itself a control with evidence requirement. The table therefore stores the subclass identifier as primary key and records the article control identifier as a non-null foreign key referencing t_control_with_evidence_requirement.

```sql
CREATE TABLE t_gdpr_article_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_with_evidence_requirement(id)
);
```

### 1.4 t_verification_produces_evidence

Axiom 3 states that a Process produces evidence of a lawful basis. The table therefore stores the verification identifier as primary key and records the produced lawful-basis identifier as a non-null foreign key referencing t_gdpr_lawful_basis.

```sql
CREATE TABLE t_verification_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_gdpr_lawful_basis(id)
);
```

### 1.5 t_attestation_with_supporting_evidence

Axiom 1 states that a Process attests to a lawful basis with supporting evidence. The table therefore stores the attestation identifier as primary key and records the supported lawful-basis identifier as a non-null foreign key referencing t_gdpr_lawful_basis.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_gdpr_lawful_basis(id)
);
```

## 2 Cross-Join Demonstration

To determine the GDPR article and verification that support the lawful basis for control “CJ-Consent-01”, join t_control_with_evidence_requirement to t_gdpr_lawful_basis on y, then to t_gdpr_article_subclass on the same control identifier, and finally to t_verification_produces_evidence on the lawful-basis identifier.
