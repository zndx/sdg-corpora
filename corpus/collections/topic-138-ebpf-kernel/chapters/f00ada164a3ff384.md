# Modeling GDPR Directive Governance via Attestation and Control Tables

This chapter specifies a five-table relational schema that implements five OWL axioms for directive governance. The tables encode attestations, lawful bases, verifications, article subclasses, and evidence requirements as foreign-key relationships, enabling multi-hop queries over compliance records.

## 1 Schema Overview

The schema follows directly from the slot structures of the axioms. Each table contains an opaque identifier column as primary key together with two reference columns. Foreign-key constraints enforce the existential restrictions stated in the Manchester syntax forms. Four to six rows per table suffice to demonstrate cross-table navigation.

### 1.1 t_control_with_evidence_requirement

This table embodies axiom 5 (control_with_evidence_requirement). Column id is the primary key; column y is a foreign key into t_gdpr_lawful_basis. A reader can join on y to retrieve the lawful basis required by each control.

| id | x | y |
|---|---|---|
| ctrl-001 | DataRetentionDirective | basis-01 |
| ctrl-002 | CrossBorderTransfer | basis-02 |
| ctrl-003 | AutomatedDecisionMaking | basis-01 |
| ctrl-004 | ProcessorContractClause | basis-03 |
| ctrl-005 | SecurityMeasures | basis-02 |

### 1.2 t_gdpr_lawful_basis

This table embodies axiom 2 (gdpr_lawful_basis). Column id is the primary key; column y is a foreign key into t_control_with_evidence_requirement. The join on y yields the control that supplies the lawful basis.

| id | x | y |
|---|---|---|

### 1.3 t_attestation_with_supporting_evidence

This table embodies axiom 4 (gdpr_article_subclass). Column id is the primary key; column y is a foreign key into t_control_with_evidence_requirement. Joining on y retrieves the control that implements each GDPR article subclass.
