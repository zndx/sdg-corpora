# Compliance Attestation Schema for HIPAA and PCI DSS Directives

This chapter defines a five-table relational schema that implements five OWL axioms for directive information content entities. The schema records administrative, physical, and technical HIPAA safeguards together with PCI DSS requirements, each linked to attestations that carry supporting evidence. All column values are instances of the slot types declared in the axioms; foreign-key joins therefore correspond directly to the existential restrictions in the Manchester syntax.

## 1 Ontological Axioms and Schema Projection

Five axioms supply the only named classes and object properties used in the schema. Each axiom projects to one table; primary-key columns hold the subject class of the axiom while foreign-key columns hold the object class.

### 1.1 t_hipaa_safeguard_admin

Axiom 1 states that a class X is a DirectiveICE that hipaaSafeguard some Y. The table therefore stores administrative-safeguard directives; its foreign key y references an attestation that supplies the required evidence.

```sql
CREATE TABLE t_hipaa_safeguard_admin (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_with_supporting_evidence(id)
);
```

| id | x | y |
|----|---|---|
| HSA-001 | Access Control | ATT-001 |
| HSA-002 | Workforce Training | ATT-002 |
| HSA-003 | Incident Response | ATT-003 |
| HSA-004 | Business Associate Contracts | ATT-004 |
