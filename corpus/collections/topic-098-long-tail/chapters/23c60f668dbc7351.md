# Chapter 4. Modeling Interdependent Compliance Directives

This chapter defines five relational tables that instantiate the ontology axioms for directive instances, attestations, and safeguard requirements. The tables capture class-level relationships required by the axioms while exposing primary-key and foreign-key linkages that support multi-table queries over compliance records.

## 1. Table Definitions and Axiom Embodiment

### 1.1 t_attestation_with_supporting_evidence
This table embodies AXIOM 2. Column id is the primary key. Column y is a foreign key that references t_hipaa_safeguard_admin.id, establishing the supporting-evidence direction required by the axiom. A reader can join on y to retrieve the safeguard class that backs a given attestation class.

| id       | x                              | y        |
|----------|--------------------------------|----------|
| ATT-001  | AnnualComplianceAttestation    | ADM-001  |
| ATT-002  | QuarterlyAccessReview          | ADM-002  |
| ATT-003  | IncidentResponseAttestation    | ADM-003  |
| ATT-004  | VendorRiskAttestation          | ADM-004  |

### 1.2 t_hipaa_safeguard_admin
This table embodies AXIOM 1. Column id is the primary key. Column y is a foreign key that references t_attestation_with_supporting_evidence.id, closing the mutual reference required by the paired axioms. A reader can join on y to obtain the attestation class that an administrative safeguard class supports.

| id       | x                              | y        |
|----------|--------------------------------|----------|
| ADM-001  | AccessControlPolicy            | ATT-001  |
| ADM-002  | WorkforceTrainingDirective     | ATT-002  |
| ADM-003  | SanctionPolicy                 | ATT-003  |
| ADM-004  | BusinessAssociateAgreement     | ATT-004  |

### 1.3 t_hipaa_safeguard_physical
This table embodies AXIOM 3. Column id is the primary key. Column y is a foreign key that references t_attestation_with_supporting_evidence.id. A reader can join on y to list every physical safeguard class that participates in a given attestation.

| id       | x                              | y        |
|----------|--------------------------------|----------|
| PHY-001  | FacilityAccessBadge            | ATT-001  |
| PHY-002  | WorkstationLock                | ATT-002  |
| PHY-003  | MediaDisposalStation           | ATT-003  |
| PHY-004  | ServerRoomSurveillance         | ATT-004  |

### 1.4 t_hipaa_safeguard_technical
This table embodies AXIOM 4. Column id is the primary key. Column y is a foreign key that references t_attestation_with_supporting_evidence.id. A reader can join on y to retrieve technical safeguard classes linked to each attestation class.

| id       | x                              | y        |
|----------|--------------------------------|----------|
| TEC-001  | EncryptionAtRest               | ATT-001  |
| TEC-002  | AuditLogIntegrity              | ATT-002  |
| TEC-003  | AutomaticLogoff                | ATT-003  |
| TEC-004  | TransmissionSecurity           | ATT-004  |

### 1.5 t_pci_dss_requirement
This table embodies AXIOM 5. Column id is the primary key. Column y is a foreign key that references t_attestation_with_supporting_evidence.id. A reader can join on y to obtain the PCI DSS requirement classes that an attestation class satisfies.

| id       | x                              | y        |
|----------|--------------------------------|----------|
| PCI-001  | Requirement_1_Firewall         | ATT-001  |
| PCI-002  | Requirement_2_Defaults         | ATT-002  |
| PCI-003  | Requirement_3_CardholderData   | ATT-003  |
| PCI-004  | Requirement_4_Transmission     | ATT-004  |
