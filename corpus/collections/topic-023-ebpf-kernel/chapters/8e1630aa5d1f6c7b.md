# Evidence Requirements in Compliance Audits

This chapter defines four tables that implement axioms for directive governance. The tables record how controls require evidence, how verifications produce evidence, how constraints are evaluated during processes, and how attestations carry supporting evidence. All column values are entity references or identifiers consistent with the axioms; primary keys ensure uniqueness while foreign-key values in the x and y columns enable two- and three-table joins.

## 1 Schema Overview

The four tables share a uniform column layout derived directly from the slot structure of the source axioms. Each row asserts a directed relationship between two entities. The id column is the primary key. The x column names the subject entity of the axiom; the y column names the object entity. Cross-table queries are formed by matching a y value in one table to an x or id value in another table.

### 1.1 t_control_with_evidence_requirement

This table embodies the axiom “control_with_evidence_requirement” by recording each directive that must be supported by a specific evidence entity. The id column is the primary key; the x column repeats the control identifier while the y column holds the required evidence identifier, which functions as a foreign key to rows in t_attestation_with_supporting_evidence or t_verification_produces_evidence.

| id  | x   | y    |
|-----|-----|------|
| CR1 | C01 | A01  |
| CR2 | C01 | V01  |
| CR3 | C02 | A02  |
| CR4 | C02 | V02  |
| CR5 | C03 | A03  |
| CR6 | C03 | V03  |

### 1.2 t_verification_produces_evidence

This table embodies the axiom “verification_produces_evidence” by linking each verification process to the evidence item it yields. The id column is the primary key; x identifies the verification process and y identifies the produced evidence, serving as a foreign key usable by t_control_with_evidence_requirement and t_attestation_with_supporting_evidence.

| id  | x   | y    |
|-----|-----|------|
| VP1 | V01 | E01  |
| VP2 | V02 | E02  |
| VP3 | V03 | E03  |
| VP4 | V04 | E04  |
| VP5 | V05 | E01  |

### 1.3 t_constraint_evaluated_during

This table embodies the axiom “constraint_evaluated_during” by associating each regulatory constraint with the verification interval during which it was assessed. The id column is the primary key; x names the constraint and y names the verification process, allowing joins to t_verification_produces_evidence.

| id  | x   | y    |
|-----|-----|------|
| CE1 | K01 | V01  |
| CE2 | K01 | V02  |
| CE3 | K02 | V03  |
| CE4 | K02 | V04  |
| CE5 | K03 | V05  |

### 1.4 t_attestation_with_supporting_evidence

This table embodies the axiom “attestation_with_supporting_evidence” by capturing each signed statement together with the evidence that substantiates it. The id column is the primary key; x names the attestation and y names the supporting evidence item, which may be referenced from t_control_with_evidence_requirement.

| id  | x   | y    |
|-----|-----|------|
| AE1 | A01 | E01  |
| AE2 | A02 | E02  |
| AE3 | A03 | E03  |
| AE4 | A04 | E04  |
| AE5 | A05 | E01  |
| AE6 | A01 | E05  |

## 2 Multi-Hop Query Example

To determine which constraint was evaluated during the verification that produced the evidence required by control C01, first locate the evidence identifiers required by C01 in t_control_with_evidence_requirement (rows CR1, CR2). These identifiers match y values in t_verification_produces_evidence. The matching verification identifiers (V01) are then joined to t_constraint_evaluated_during on the y column, yielding constraint K01. The joined result row is therefore (C01, CR2, V01, VP1, K01, CE1).
