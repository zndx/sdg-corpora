# Chapter 4: Process Subclassing for Metric Emission and Alerting in eBPF Observability

This chapter defines four process subclasses that structure metric handling, outlier targeting, alert generation, and attribute attachment within eBPF-based system monitoring. The definitions are realized as a four-table relational schema whose primary-key and foreign-key constraints enforce the subclass axioms and enable cross-table retrieval of multi-hop relationships.

## 1 Ontology-to-Schema Mapping

The four axioms are projected directly onto tables whose column domains and referential constraints preserve the Manchester syntax restrictions. Each table is introduced by the axiom it materializes, followed by its primary-key and foreign-key structure and an example join path.

### 1.1 t_outlier_detection_targets_dataset

Axiom 2 states that a class X is a process that targets an artifact. The table therefore stores every such X as a row whose single non-key column holds the class name. The column id serves as the primary key and is referenced by the foreign keys of the two metric-emission and alert-trigger tables.

```sql
CREATE TABLE t_outlier_detection_targets_dataset (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example cross-join: given a dataset identifier, retrieve every metric-emission subclass and every alert that references it by joining on the shared foreign-key column y.

### 1.2 t_metric_emission_subclass

Axiom 1 states that a class X is a process that emits metric Y. The table records each such pair; column y is a foreign key that must resolve to an existing row in t_outlier_detection_targets_dataset, thereby guaranteeing that every emitted metric is grounded in a declared target artifact.

```sql
CREATE TABLE t_metric_emission_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_outlier_detection_targets_dataset(id)
);
```

Example cross-join: start from a metric-emission row, follow y to its dataset, then follow the same dataset identifier into t_alert_triggered_by to obtain the alert that the metric ultimately fires.

### 1.3 t_alert_triggered_by

Axiom 3 states that a class X is a process triggered by metric Y. The table stores each triggering relationship; column y again references t_outlier_detection_targets_dataset, ensuring that every alert is associated with a metric whose target artifact has already been declared.

```sql
CREATE TABLE t_alert_triggered_by (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_outlier_detection_targets_dataset(id)
);
```

Example cross-join: locate an alert row, traverse y to the dataset, then traverse the same dataset identifier backward through t_metric_emission_subclass to list every subclass that can emit the triggering metric.

### 1.4 t_ebpf_event_min_one_attribute

Axiom 4 states that a class X is a process possessing at least one designative information-content entity. The table therefore records every such X; because the minimum-cardinality restriction is satisfied by the existence of the row itself, no additional foreign-key column is required.

```sql
CREATE TABLE t_ebpf_event_min_one_attribute (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example cross-join: an eBPF event identifier can be joined with any of the preceding tables when the event class name appears as the value of column x in those tables, thereby attaching attribute-bearing events to metric and alert lineages.

## 3 Multi-Hop Retrieval Example

Question: which alert is triggered by a metric emitted by the subclass ThreadCPUSampler and whose target dataset is also referenced by an eBPF event class?

Walk the keys:  
- Locate mes_cpu2 in t_metric_emission_subclass; its y value is dataset_cpu.  
- Locate atb_cpu and atb_cpu2 in t_alert_triggered_by where y equals dataset_cpu.  
- Confirm that dataset_cpu appears in t_outlier_detection_targets_dataset and that an eBPF event row exists whose x column can be aligned with the same lineage.

Resulting joined row (mental projection):  
mes_cpu2.ThreadCPUSampler → dataset_cpu → atb_cpu.HighCPUAlert (and atb_cpu2.SustainedLoadAlert).
