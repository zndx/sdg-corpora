# Chapter 4: Directive ICE Modeling for Regulatory Safeguards

This chapter defines five core ontological templates that classify DirectiveICE instances according to their HIPAA and PCI DSS safeguard semantics. Each template is projected to a dedicated relational table whose foreign-key graph supports multi-hop retrieval of control-to-threat mappings.

## 1. Axiom-to-Schema Mapping

The five axioms share the common anchor cco:DirectiveICE. Their relational projections therefore differ only in the safeguard or requirement property they reify. Primary keys are opaque identifiers; foreign keys encode the existential or universal restrictions stated in each Manchester axiom.

### 1.1 Administrative Safeguard Table

Axiom 1 (hipaa_safeguard_admin) asserts that an administrative directive provides a HIPAA safeguard for a control that itself addresses only a designated threat class. Column id is the primary key; column y is a foreign key into t_control_only_addresses_threat_class.

| id          | x                                      | y          |
|-------------|----------------------------------------|------------|
| admin_001   | Workforce Security Policy              | ctrl_101   |
| admin_002   | Access Authorization Procedure         | ctrl_102   |
| admin_003   | Contingency Plan Maintenance           | ctrl_103   |
| admin_004   | Incident Response Reporting            | ctrl_104   |

### 1.2 Threat-Addressing Control Table

Axiom 2 (control_only_addresses_threat_class) restricts a control to address only one threat class. Column id is the primary key; column y is a foreign key into t_hipaa_safeguard_admin, closing the mutual reference required by the paired axioms.

| id         | x                                      | y          |
|------------|----------------------------------------|------------|
| ctrl_101   | Unique User Identification             | admin_001  |
| ctrl_102   | Encryption of PHI at Rest              | admin_002  |
| ctrl_103   | Automatic Logoff Mechanism             | admin_003  |
| ctrl_104   | Integrity Controls for ePHI            | admin_004  |
| ctrl_105   | Transmission Security Validation       | admin_001  |

### 1.3 Technical Safeguard Table

Axiom 3 (hipaa_safeguard_technical) classifies technical directives that implement HIPAA safeguards. Column id is the primary key; column y references t_control_only_addresses_threat_class.

| id           | x                                      | y          |
|--------------|----------------------------------------|------------|
| tech_001     | Audit Control Implementation           | ctrl_101   |
| tech_002     | Person or Entity Authentication        | ctrl_102   |
| tech_003     | Integrity Mechanism Deployment         | ctrl_103   |

### 1.4 Physical Safeguard Table

Axiom 4 (hipaa_safeguard_physical) classifies physical directives. Column id is the primary key; column y references t_control_only_addresses_threat_class.

| id           | x                                      | y          |
|--------------|----------------------------------------|------------|
| phys_001     | Facility Access Control                | ctrl_104   |
| phys_002     | Workstation Use Policy                 | ctrl_105   |
| phys_003     | Device and Media Controls              | ctrl_101   |

### 1.5 PCI DSS Requirement Table

Axiom 5 (pci_dss_requirement) classifies directives that satisfy PCI DSS requirements. Column id is the primary key; column y references t_control_only_addresses_threat_class.

| id           | x                                      | y          |
|--------------|----------------------------------------|------------|
| pci_001      | Build and Maintain Secure Network      | ctrl_102   |
| pci_002      | Protect Cardholder Data                | ctrl_103   |
| pci_003      | Maintain Vulnerability Management      | ctrl_104   |
| pci_004      | Implement Strong Access Control        | ctrl_105   |

## 2. Multi-Hop Query Example

To retrieve the administrative directive and the PCI DSS requirement that together govern the threat addressed by control ctrl_102, the following joins are required:

- Start at t_control_only_addresses_threat_class (id = ctrl_102)
- Follow y to t_hipaa_safeguard_admin (admin_002)
- Follow y from ctrl_102 to t_pci_dss_requirement (pci_001)

(Workforce Security Policy, Encryption of PHI at Rest, Build and Maintain Secure Network)
