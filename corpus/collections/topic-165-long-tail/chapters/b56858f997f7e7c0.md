# Chapter 4. Directive Governance in PCI DSS Compliance Records

This chapter presents five tables that instantiate axioms for directive information content entities, attestations, and risk-addressing controls. The tables support cross-table joins that resolve multi-hop queries over requirements, their targets, signatures, supporting traces, and threat restrictions. All column values are instances consistent with the slot types of the source axioms.

## 1. Requirement Classification and Equivalence

Axiom 1 (pci_dss_requirement) classifies an entity X as a subclass of cco:DirectiveICE that carries a pciDssRequirement relation to a target Y. Table t_pci_dss_requirement therefore stores the identifier of each requirement instance together with its source class and the identifier of the corresponding equivalence specification. Column id is the primary key; column y is a foreign key into t_requirement_equiv_specifies_target.

```sql
CREATE TABLE t_pci_dss_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

| id          | x                        | y           |
|-------------|--------------------------|-------------|
| req-001     | Requirement12.1          | equiv-001   |
| req-002     | Requirement3.4           | equiv-002   |
| req-003     | Requirement8.2           | equiv-003   |
| req-004     | Requirement11.3          | equiv-004   |

## 2. Equivalence Specification of Targets

Axiom 4 (requirement_equiv_specifies_target) defines an equivalence between a directive class X, a specification target Y, and an applicability scope Z. Table t_requirement_equiv_specifies_target therefore records each equivalence instance, its directive class, the requirement it references, and the asset class to which it applies. Column id is the primary key; column y is a foreign key into t_pci_dss_requirement.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_pci_dss_requirement(id)
);
```

| id          | x                        | y         | z                  |
|-------------|--------------------------|-----------|--------------------|
| equiv-001   | Requirement12.1          | req-001   | CardholderData     |
| equiv-002   | Requirement3.4           | req-002   | PANStorage         |
| equiv-003   | Requirement8.2           | req-003   | AuthenticationData |
| equiv-004   | Requirement11.3          | req-004   | NetworkSegment     |

## 3. Control Restriction to Threat Class

Axiom 5 (control_only_addresses_threat_class) restricts a directive X to address only risk class Y. Table t_control_only_addresses_threat_class therefore stores each such restriction together with its directive and the referenced requirement that supplies the risk class. Column id is the primary key; column y is a foreign key into t_pci_dss_requirement.

```sql
CREATE TABLE t_control_only_addresses_threat_class (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_pci_dss_requirement(id)
);
```

| id          | x                        | y         |
|-------------|--------------------------|-----------|
| ctrl-001    | FirewallRuleSet          | req-001   |
| ctrl-002    | EncryptionControl        | req-002   |
| ctrl-003    | AccessReviewProcess      | req-003   |
| ctrl-004    | VulnerabilityScan        | req-004   |

## 4. Attestation Signature Record

Axiom 2 (attestation_signed_by) asserts that a process X is signed by a person. Table t_attestation_signed_by therefore records each attestation instance and the person identifier that performed the signature. Column id is the primary key.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id          | x                  |
|-------------|--------------------|
| att-001     | Person:AuditorLend |
| att-002     | Person:SecurityOff |
| att-003     | Person:Compliance  |
| att-004     | Person:RiskMgr     |

## 5. Trace Supporting Descriptive Claim

Axiom 3 (trace_supports_claim) asserts that a process X supports a descriptive information content entity. Table t_trace_supports_claim therefore records each trace instance and the claim identifier it supports. Column id is the primary key.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```
