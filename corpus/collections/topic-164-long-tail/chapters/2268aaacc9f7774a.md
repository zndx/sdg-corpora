# Chapter 4: Relational Encodings of Process and Measurement Constraints

This chapter presents four tables that encode selected OWL axioms for processes and measurements. The tables use primary-key and foreign-key columns to enforce minimum cardinality on inputs and outputs, equivalence conditions on descriptive information content entities, and cardinality limits on operators. All rows are drawn from a laboratory information management scenario involving sample handling and dimensional measurements.

## 1 Axiom Overview

The axioms constrain classes that satisfy bfo:0000015 (process) or cco:DescriptiveICE. Each table below materializes one axiom by storing the class variables X, Y, and (where required) Z together with the necessary foreign-key references that realize the slot restrictions.

### 1.1 Table t_process_min_one_input

This table embodies axiom 1 (process_min_one_input). Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_measurement_equiv_with_dim_unit, thereby guaranteeing that every process instance possesses at least one input measurement. A reader can obtain the dimension and unit of an input by joining on y.

| id | x | y |
| id | x | y |
| pmi-001 | SampleReception | me-101 |
| pmi-002 | SampleReception | me-102 |
| pmi-003 | TemperatureEquilibration | me-103 |
| pmi-004 | VolumeMeasurement | me-104 |
| pmi-005 | pHAdjustment | me-105 |
| pmi-006 | ConductivityCheck | me-106 |

### 1.2 Table t_measurement_equiv_with_dim_unit

This table embodies axiom 2 (measurement_equiv_with_dim_unit). Column id is the primary key. Columns y and z are foreign keys; y references t_process_min_one_input.id, satisfying the mutual existential restriction between processes and measurements. The combination of y and z therefore records both the required dimension class and the required unit class for each descriptive ICE.

| id | x | y | z |
| id | x | y | z |
| me-101 | VolumeValue | pmi-001 | UnitLiter |
| me-102 | MassValue | pmi-002 | UnitGram |
| me-103 | TemperatureValue | pmi-003 | UnitCelsius |
| me-104 | LengthValue | pmi-004 | UnitMeter |
| me-105 | pHValue | pmi-005 | UnitPH |
| me-106 | ConductivityValue | pmi-006 | UnitSiemensPerMeter |

### 1.3 Table t_process_min_one_output

This table embodies axiom 3 (process_min_one_output). Column id is the primary key. Column y is a foreign key referencing t_measurement_equiv_with_dim_unit.id, ensuring every process instance produces at least one output measurement whose dimension and unit are already declared.

| id | x | y |
| id | x | y |
| pmo-001 | SampleReception | me-101 |
| pmo-002 | TemperatureEquilibration | me-103 |
| pmo-003 | VolumeMeasurement | me-104 |
| pmo-004 | pHAdjustment | me-105 |
| pmo-005 | ConductivityCheck | me-106 |
| pmo-006 | FinalReporting | me-102 |

### 1.4 Table t_process_max_one_operator

This table embodies axiom 4 (process_max_one_operator). Column id is the primary key. Column y is an optional foreign key referencing t_measurement_equiv_with_dim_unit.id; the maximum-cardinality restriction is realized by permitting at most one non-null y value per process.

| id | x | y |
| id | x | y |
| pmo-101 | SampleReception | me-101 |
| pmo-102 | TemperatureEquilibration | NULL |
| pmo-103 | VolumeMeasurement | me-104 |
| pmo-104 | pHAdjustment | me-105 |
| pmo-105 | ConductivityCheck | NULL |
| pmo-106 | FinalReporting | me-102 |

## 2 Cross-Table Query Example

To retrieve the unit of the output measurement for the process whose input measurement carries dimension VolumeValue, perform the following joins:

- Start at t_process_min_one_input where x = SampleReception (row pmi-001).
- Follow y to t_measurement_equiv_with_dim_unit row me-101.
- Follow that row’s y to t_process_min_one_output row pmo-001.
- Read the unit from the joined t_measurement_equiv_with_dim_unit row me-101 (UnitLiter).

The resulting joined tuple is (pmi-001, SampleReception, me-101, VolumeValue, UnitLiter, pmo-001, SampleReception, me-101).
