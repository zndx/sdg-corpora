# Chapter 4: Relational Encoding of Measurement Processes and Descriptive Instances

This chapter presents four tables that encode selected axioms from an OWL ontology of processes and measurements. The tables are populated with instances drawn from climatic data validation workflows. Each table is introduced by a statement of the axiom it realises, followed by its primary-key and foreign-key structure and an example cross-table traversal.

## 1 Axiom 1: process_min_one_input

The axiom states that every member of a process class has at least one input that is a member of a measurement class. Table t_process_min_one_input therefore records the required input relation. Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_measurement_equiv_with_dim_unit.

| id | x | y |
| id001 | CalibrationProcess | meas001 |
| id002 | ValidationProcess | meas002 |
| id003 | BenchmarkingProcess | meas003 |
| id004 | HomogenisationProcess | meas001 |
| id005 | AggregationProcess | meas004 |

## 1.1 Axiom 2: measurement_equiv_with_dim_unit

The axiom asserts equivalence between a measurement class and the conjunction of cco:DescriptiveICE with existential restrictions on hasDimension and hasUnit. Table t_measurement_equiv_with_dim_unit therefore stores the dimension and unit slots. Column id is the primary key. Columns y and z are foreign keys that resolve to ids in t_process_min_one_input and t_process_min_one_output respectively.

| id | x | y | z |
| meas001 | TemperatureReading | id001 | id006 |
| meas002 | PrecipitationReading | id002 | id007 |
| meas003 | PressureReading | id003 | id008 |
| meas004 | HumidityReading | id004 | id009 |
| meas005 | WindSpeedReading | id005 | id010 |

## 1.2 Axiom 3: process_min_one_output

The axiom requires every process class member to possess at least one output belonging to a measurement class. Table t_process_min_one_output records the output relation. Column id is the primary key. Column y is a foreign key referencing t_measurement_equiv_with_dim_unit.id.

| id | x | y |
| id006 | CalibrationProcess | meas001 |
| id007 | ValidationProcess | meas002 |
| id008 | BenchmarkingProcess | meas003 |
| id009 | HomogenisationProcess | meas004 |
| id010 | AggregationProcess | meas005 |

## 2 Axiom 4: process_max_one_operator

The axiom restricts each process class member to at most one operator. Table t_process_max_one_operator therefore records an optional operator slot. Column id is the primary key. Column y is a foreign key referencing t_measurement_equiv_with_dim_unit.id.

| id | x | y |
| id011 | CalibrationProcess | meas002 |
| id012 | ValidationProcess | meas003 |
| id013 | BenchmarkingProcess | meas001 |
| id014 | HomogenisationProcess | meas005 |
| id015 | AggregationProcess | meas004 |

## 3 Cross-table query example

To retrieve the unit associated with the output of the process whose input is TemperatureReading, the following joins are required. Start with row id001 in t_process_min_one_input (x = CalibrationProcess, y = meas001). Follow y to row meas001 in t_measurement_equiv_with_dim_unit. From meas001 follow z to row id006 in t_process_min_one_output (y = meas001). The unit value attached to meas001 is therefore the required result. The joined row is:

CalibrationProcess → meas001 (TemperatureReading, Celsius) → id006
