# Chapter 4. Directive Instances and Evidence Chains in ISO 27001 Audit Records

This chapter presents a relational schema that records instances of ISO 27001 directive classes, their priority assignments, clause mappings, and verification processes that produce evidence. The five tables implement the slot structures of the supplied axioms and support cross-table joins that answer multi-hop compliance queries.

## 1. Schema Overview

The tables follow directly from the Manchester axioms. Each row stores an identifier together with the two class-valued slots required by the corresponding axiom. Primary keys are the id columns. Foreign-key columns enforce the slot-type restrictions stated in the axiom comments and permit the joins demonstrated later in this chapter.

### 1.1 Table t_requirement_has_priority

This table embodies axiom 2. Column id is the primary key. Column x holds the subclass of cco:DirectiveICE; column y holds the priority class and is a foreign key to t_iso27001_annexa_subclass.id. A reader can join on y to retrieve the annex-A category assigned to each priority declaration.

| id  | x                          | y     |
|-----|----------------------------|-------|
| rp1 | AccessControlPolicy        | as1   |
| rp2 | EncryptionStandard         | as2   |
| rp3 | IncidentResponsePlan       | as3   |
| rp4 | RiskAssessmentProcedure    | as4   |
| rp5 | SupplierDueDiligence       | as1   |

### 1.2 Table t_iso27001_annexa_subclass

This table embodies axiom 1. Column id is the primary key. Column x holds the subclass of cco:DirectiveICE; column y holds the annex-A reference class and is a foreign key to t_requirement_has_priority.id. Joining on y recovers the priority that governs each annex-A control.

| id  | x                          | y   |
|-----|----------------------------|-----|
| as1 | A5_InformationSecurity     | rp2 |
| as2 | A10_Encryption             | rp1 |
| as3 | A16_IncidentManagement     | rp3 |

### 1.3 Table t_iso27001_clause_subclass

This table embodies axiom 3. Column id is the primary key. Column x holds the subclass of cco:DirectiveICE; column y holds the clause reference class and is a foreign key to t_requirement_has_priority.id. A join on y links each clause instance to its governing priority record.

### 1.4 Table t_verification_produces_evidence

This table embodies axiom 4. Column id is the primary key. Column x holds the process subclass of bfo:0000015; column y holds the evidence class and is a foreign key to t_iso27001_annexa_subclass.id. Joining on y yields the annex-A control for which evidence was generated.

| id   | x                          | y   |
|------|----------------------------|-----|
| ve1  | InternalAudit2024Q2        | as1 |
| ve2  | PenetrationTest2024Q2      | as2 |

### 1.5 Table t_verification_min_one_evidence

This table embodies axiom 5. Column id is the primary key. Column x holds the process subclass of bfo:0000015; column y holds the evidence class and is a foreign key to t_iso27001_annexa_subclass.id. The min-1 cardinality is satisfied by the non-null foreign-key constraint.

## 2. Cross-Join Example

To determine the annex-A category and priority that govern the evidence produced by the process identified as ve1, the following path is traversed: t_verification_produces_evidence.y → t_iso27001_annexa_subclass.id → t_iso27001_annexa_subclass.y → t_requirement_has_priority.id. The joined row is:

ve1 | InternalAudit2024Q2 | as1 | A5_InformationSecurity | rp2 | EncryptionStandard

The result shows that the InternalAudit2024Q2 process produced evidence for the A5_InformationSecurity annex-A control, which carries the priority declared in rp2.
