# Chapter 7: Directive Subclassing and Evidence Production in ISO 27001 Compliance Records

This chapter defines five relational tables that implement the subclass and evidence axioms for ISO 27001 directive instances. The tables record control requirements, their annex and clause membership, assigned priorities, and verification processes that generate required evidence. All rows use identifiers that satisfy the declared foreign-key constraints, enabling direct cross-table retrieval of multi-step compliance chains.

## 1 Schema Overview

The tables follow the slot structures of the five axioms without extension or omission. Primary keys are the id columns. Foreign keys enforce the subclass and evidence relations stated in the axioms. Four to eight rows per table suffice to demonstrate joins that answer questions such as “which priority applies to an annex-A control verified by a given process.”

### 1.1 t_iso27001_annexa_subclass

This table implements AXIOM 1 by storing pairs of directive classes where the first is a subclass of a member of iso27001AnnexA. Column id is the primary key; column y is a foreign key to t_requirement_has_priority.id. A reader can join on y to retrieve the priority of any annex-A control.

| id          | x                       | y            |
|-------------|-------------------------|--------------|
| ANNEX-001   | AccessControlPolicy     | REQ-010      |
| ANNEX-002   | EncryptionStandard      | REQ-011      |
| ANNEX-003   | IncidentResponsePlan    | REQ-012      |
| ANNEX-004   | SupplierAssessment      | REQ-013      |
| ANNEX-005   | LoggingRetentionRule    | REQ-014      |

### 1.2 t_requirement_has_priority

This table implements AXIOM 2 by recording the hasPriority relation on directive classes. Column id is the primary key; column y is a foreign key to t_iso27001_annexa_subclass.id. Joining on y yields the annex membership of any prioritized requirement.

| id          | x                       | y            |

| REQ-010     | AccessControlPolicy     | ANNEX-001    |
| REQ-011     | EncryptionStandard      | ANNEX-002    |

### 1.3 t_iso27001_clause_subclass

This table implements AXIOM 3 by storing pairs of directive classes where the first is a subclass of a member of iso27001Clause. Column id is the primary key; column y is a foreign key to t_requirement_has_priority.id. A join on y recovers the priority associated with each clause-linked requirement.

### 1.4 t_verification_produces_evidence

This table implements AXIOM 4 by recording processes that produce evidence for directive classes. Column id is the primary key; column y is a foreign key to t_iso27001_annexa_subclass.id. Joining on y lists the annex controls for which a verification process supplies evidence.

| id          | x                       | y            |
|-------------|-------------------------|--------------|
| VER-001     | InternalAudit           | ANNEX-001    |
| VER-002     | ExternalAssessment      | ANNEX-002    |
| VER-003     | ManagementReview        | ANNEX-003    |
| VER-004     | SupplierAudit           | ANNEX-004    |
| VER-005     | LogAnalysis             | ANNEX-005    |

### 1.5 t_verification_min_one_evidence

This table implements AXIOM 5 by recording processes required to produce at least one evidence item. Column id is the primary key; column y is a foreign key to t_iso27001_annexa_subclass.id. The same join pattern used in the preceding table also satisfies the minimum-cardinality constraint.

| id          | x                       | y            |
|-------------|-------------------------|--------------|
| VER-006     | PenetrationTest         | ANNEX-001    |
| VER-007     | ConfigurationReview     | ANNEX-002    |
| VER-008     | IncidentSimulation      | ANNEX-003    |
| VER-009     | ContractAudit           | ANNEX-004    |
| VER-010     | RetentionSampling       | ANNEX-005    |

## 2 Cross-Join Demonstration

To determine the priority of the annex-A control verified by InternalAudit, begin with row VER-001 in t_verification_produces_evidence (y = ANNEX-001). Follow the foreign key to t_iso27001_annexa_subclass row ANNEX-001 (y = REQ-010). Continue to t_requirement_has_priority row REQ-010 (y = ANNEX-001). The resulting joined row is:

id=VER-001, x=InternalAudit, y=ANNEX-001, x=AccessControlPolicy, y=REQ-010, x=AccessControlPolicy, y=ANNEX-001.

The priority value attached to REQ-010 is thereby obtained without additional lookup.
