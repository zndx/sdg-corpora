# Outlier Detection in Climatic Data Records

This chapter defines a relational representation of outlier detection applied to temperature series maintained by national climatic data centers. The model uses five tables that directly instantiate the supplied axioms, enabling queries that traverse from baseline rates through evidence correlations to produced claims.

## 1 Schema Overview

The schema captures descriptive information content entities that state outlier claims and the processes that generate or qualify those claims against baselines. All primary keys are the column `id`. Foreign-key columns enforce the slot restrictions declared in each axiom.

### 1.1 t_outlier_claim_basic

This table embodies axiom 3 (outlier_claim_basic). Column `id` is the primary key; column `x` holds the class identifier of the descriptive information content entity. A reader can join this table on `id` to any table whose foreign key references it in order to retrieve the textual claim associated with a given evidence correlation.

| id | x |
| id | x |
| ocb-001 | TemperatureSeriesOutlierClaim |
| ocb-002 | StationShiftOutlierClaim |
| ocb-003 | SeasonalAnomalyOutlierClaim |
| ocb-004 | InstrumentChangeOutlierClaim |

### 1.2 t_evidence_correlated_with

This table embodies axiom 1 (evidence_correlated_with). Column `id` is the primary key; column `y` is a foreign key to `t_outlier_claim_basic.id`. Column `x` records the class of supporting evidence. Joining on `y` yields the claim text for any evidence instance.

| id | x | y |
| id | x | y |
| ecw-010 | HomogenizationEvidence | ocb-001 |
| ecw-011 | MetadataAuditEvidence | ocb-002 |
| ecw-012 | NeighborStationEvidence | ocb-003 |
| ecw-013 | CalibrationLogEvidence | ocb-004 |
| ecw-014 | DuplicateRecordEvidence | ocb-001 |

### 1.3 t_outlier_detection_produces_claim

This table embodies axiom 2 (outlier_detection_produces_claim). Column `id` is the primary key; column `y` is a foreign key to `t_evidence_correlated_with.id`. Column `x` records the detection process class. A cross-join from this table through `y` to `t_evidence_correlated_with` and onward to `t_outlier_claim_basic` recovers the full chain from process to claim.

| id | x | y |
| id | x | y |
| odp-020 | IQRBasedDetectionProcess | ecw-010 |
| odp-021 | ChangePointDetectionProcess | ecw-011 |
| odp-022 | SpatialConsistencyProcess | ecw-012 |
| odp-023 | SensorDriftDetectionProcess | ecw-013 |

### 1.4 t_outlier_detection_with_baseline

This table embodies axiom 4 (outlier_detection_with_baseline). Column `id` is the primary key; column `y` is a foreign key to `t_evidence_correlated_with.id`. Column `x` records the detection process that operates against a baseline. Joining on `y` links each baseline-qualified process to its correlated evidence and claim.

| id | x | y |
| id | x | y |
| odb-030 | IQRBasedDetectionProcess | ecw-010 |
| odb-031 | ChangePointDetectionProcess | ecw-011 |
| odb-032 | SpatialConsistencyProcess | ecw-014 |

### 1.5 t_lift_with_baseline_rate

This table embodies axiom 5 (lift_with_baseline_rate). Column `id` is the primary key; column `y` is a foreign key to `t_evidence_correlated_with.id`. Column `x` records the lift descriptor that carries the numeric baseline rate. A join on `y` supplies both the rate and the claim it qualifies.

| id | x | y |
| id | x | y |
| lbr-040 | 0.012 | ecw-010 |
| lbr-041 | 0.007 | ecw-011 |
| lbr-042 | 0.015 | ecw-012 |
| lbr-043 | 0.009 | ecw-013 |

## 2 Cross-Join Example

Question: Which baseline rate and detection process produced the claim whose evidence is HomogenizationEvidence?

Walk the foreign keys:  
`lbr-040.y` → `ecw-010` → `ocb-001`  
`ecw-010` is referenced by `odp-020.y` and by `odb-030.y`.

Resulting joined row (mental projection):

- claim_x = TemperatureSeriesOutlierClaim  
- evidence_x = HomogenizationEvidence  
- baseline_rate = 0.012  
- detection_process = IQRBasedDetectionProcess
