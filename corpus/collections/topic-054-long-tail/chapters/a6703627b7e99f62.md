# Ontological Representation of Outlier Claims in Climatic Data Processing

This chapter defines five relational tables that instantiate OWL axioms for descriptive information content entities and processes involved in outlier detection. The tables support cross-table joins that trace evidence correlations, claim production, and baseline comparisons within climatic benchmark workflows.

## 1 Axiom Embodiment and Table Definitions

### 1.1 t_outlier_claim_basic
Axiom 3 is embodied by this table: each row records an instance of a descriptive information content entity that functions as an outlier claim. Column id serves as primary key; column x holds the class reference for the claim. A reader can join this table on id to t_evidence_correlated_with.y to retrieve all evidence items linked to a given claim.

| id | x |
| --- | --- |
| claim_001 | TemperatureSpikeAsheville |
| claim_002 | DiurnalRangeAnomaly |
| claim_003 | MonthlyMeanDeviation |
| claim_004 | StationShiftArtifact |
| claim_005 | SeasonalCycleBreak |

### 1.2 t_evidence_correlated_with
Axiom 1 is embodied by this table: each row asserts that a descriptive information content entity (x) is evidence correlated with an outlier claim (y). Column id is primary key; column y is foreign key to t_outlier_claim_basic.id. Joining on y yields the set of supporting evidence for any selected claim.

| id | x | y |
| --- | --- | --- |
| ev_001 | RawDailySeries | claim_001 |
| ev_002 | NeighbourStationDelta | claim_001 |
| ev_003 | MetadataAuditLog | claim_002 |
| ev_004 | HomogenisedSeries | claim_003 |
| ev_005 | InstrumentLog | claim_004 |
| ev_006 | QCFlagHistory | claim_005 |

### 1.3 t_outlier_detection_produces_claim
Axiom 2 is embodied by this table: each row records a process (x) that produces an outlier claim (y). Column id is primary key; column y is foreign key to t_evidence_correlated_with.id. A join across t_outlier_detection_produces_claim.y and t_evidence_correlated_with.id followed by t_evidence_correlated_with.y recovers the originating process for any claim.

| id | x | y |
| --- | --- | --- |
| proc_001 | BenchmarkingRoutine2013 | ev_001 |
| proc_002 | PairwiseComparison | ev_003 |
| proc_003 | TrendSegmenter | ev_004 |
| proc_004 | MetadataCrossCheck | ev_005 |

### 1.4 t_outlier_detection_with_baseline
Axiom 4 is embodied by this table: each row records a detection process (x) performed against a baseline (y). Column id is primary key; column y is foreign key to t_evidence_correlated_with.id. Joining on y permits retrieval of the baseline evidence used by each detection run.

| id | x | y |
| --- | --- | --- |
| det_001 | 2013WorkshopPipeline | ev_002 |
| det_002 | RegionalReferenceMethod | ev_006 |
| det_003 | StationHistoryFilter | ev_003 |

### 1.5 t_lift_with_baseline_rate
Axiom 5 is embodied by this table: each row records a descriptive information content entity (x) that carries a baseline rate value (y). Column id is primary key; column y is foreign key to t_evidence_correlated_with.id. A join on y links the rate statement to its supporting evidence correlation.

| id | x | y |
| --- | --- | --- |
| rate_001 | LiftMetricAsheville | ev_001 |
| rate_002 | LiftMetricDiurnal | ev_006 |
| rate_003 | LiftMetricMonthly | ev_004 |

## 2 Multi-Hop Query Example

To answer “which detection process produced the claim TemperatureSpikeAsheville and against which baseline evidence was it evaluated?”, start at t_outlier_claim_basic where x = TemperatureSpikeAsheville (claim_001). Follow the foreign key from t_evidence_correlated_with.y = claim_001 to obtain ev_001 and ev_002. Then follow t_outlier_detection_produces_claim.y into ev_001 to reach proc_001 (BenchmarkingRoutine2013). Finally follow t_outlier_detection_with_baseline.y into ev_002 to reach det_001 (2013WorkshopPipeline). The joined result row is therefore:

claim_001, ev_001, proc_001, ev_002, det_001.
