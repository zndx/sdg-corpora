# Outlier Detection in Climatic Data Records

This chapter presents five ontological templates that formalize the production and correlation of outlier claims within observational processes. The templates are instantiated in a relational schema drawn from climate data quality workflows at national repositories. Primary and foreign key constraints encode the directed relationships among claims, evidence, and detection processes, enabling verification of multi-hop derivations.

## 1. Core Claim Entities

Axiom 3 defines the minimal descriptive information content entity that constitutes an outlier claim. Table t_outlier_claim_basic therefore stores only the claim identifier and its textual designation. The single-column primary key supports direct reference by evidence tables; no foreign keys are present.

| id          | x                                      |
|-------------|----------------------------------------|
| claim001    | Positive temperature outlier at Asheville 2013-07-02 |
| claim002    | Negative temperature outlier at Asheville 2013-07-01 |
| claim003    | Positive temperature outlier at Madrid 2013-07-02 |
| claim004    | Negative temperature outlier at Madrid 2013-07-03 |

## 2. Evidence Correlation

Axiom 1 states that a descriptive entity may be evidence-correlated with an outlier claim. Table t_evidence_correlated_with therefore records pairs of evidence identifiers and claim references. Column y is a foreign key to t_outlier_claim_basic.id; column id serves as the primary key for subsequent process tables.

| id           | x               | y         |
|--------------|-----------------|-----------|
| evid001      | Station log 42  | claim001  |
| evid002      | Station log 43  | claim002  |
| evid003      | Station log 19  | claim003  |
| evid004      | Station log 20  | claim004  |
| evid005      | Station log 42  | claim002  |

## 3. Detection Processes Producing Claims

Axiom 2 classifies an outlier detection process by the claim it produces. Table t_outlier_detection_produces_claim therefore links each process instance to exactly one evidence-correlated claim. Column y is a foreign key to t_evidence_correlated_with.id; id is the primary key. A reader can join this table to t_outlier_claim_basic via the evidence table to recover the originating claim text for any detection run.

| id            | x                        | y        |
|---------------|--------------------------|----------|
| detect001     | z-score threshold 3.5    | evid001  |
| detect002     | z-score threshold 3.5    | evid002  |
| detect003     | median absolute deviation| evid003  |
| detect004     | median absolute deviation| evid004  |

## 4. Baseline-Conditioned Detection

Axiom 4 extends the detection process by an explicit baseline reference. Table t_outlier_detection_with_baseline therefore records the same process instances against a chosen baseline evidence set. Column y is a foreign key to t_evidence_correlated_with.id; id remains the primary key. Cross-joining with t_outlier_detection_produces_claim on id yields the full specification of each detection run, including both produced claim and baseline.

| id            | x                        | y        |
|---------------|--------------------------|----------|
| detect001     | z-score threshold 3.5    | evid005  |
| detect003     | median absolute deviation| evid001  |

## 5. Lift Relative to Baseline Rate

Axiom 5 attaches a quantitative lift descriptor to an evidence-correlated claim. Table t_lift_with_baseline_rate therefore stores the lift value together with its supporting evidence reference. Column y is a foreign key to t_evidence_correlated_with.id; id is the primary key. Joining through t_evidence_correlated_with to t_outlier_claim_basic recovers both the lift figure and the claim text in one traversal.

| id           | x     | y        |
|--------------|-------|----------|
| lift001      | 2.8   | evid001  |
| lift002      | 0.4   | evid002  |
| lift003      | 3.1   | evid003  |
| lift004      | 0.3   | evid004  |

## 6. Worked Multi-Hop Query Example

To recover the lift value associated with the claim produced by detection process detect001, traverse the foreign-key chain: start at t_outlier_detection_produces_claim (y = evid001), follow t_evidence_correlated_with (id = evid001) to its y value (claim001), then follow t_lift_with_baseline_rate (y = evid001) to obtain lift 2.8. The joined row is therefore (detect001, evid001, claim001, 2.8).
