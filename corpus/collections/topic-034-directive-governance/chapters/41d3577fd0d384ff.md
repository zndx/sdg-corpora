# Kernel Event Ontologies in Relational Audit Trails

This chapter defines four ontological templates for eBPF-mediated observation and maps each template to a table in an audit-trail schema. The tables record process instances, metric-triggered alerts, syscall invocations, and cross-references between events and designative information content entities. All column values are instances that satisfy the slot restrictions stated in the axioms.

## 1 Scope and table construction rules

Four tables are derived directly from the supplied Manchester axioms. Each table carries a single-column primary key named id. Foreign-key columns reference the id column of t_ebpf_event_min_one_attribute. Rows are populated only with values that instantiate the declared slot types (Class or DesignativeICE). Cross-table joins therefore reconstruct the existential restrictions expressed by the axioms.

### 1.1 t_ebpf_event_min_one_attribute

Axiom 1 states that every member of the class X is a bfo:Process possessing at least one cco:DesignativeICE attribute. The table therefore stores one row per process instance together with a reference to its mandatory attribute class. The column id is the primary key; the column x records the attribute class.

```sql
SELECT e.id, e.x
FROM t_ebpf_event_min_one_attribute e
WHERE e.x = 'FileOpenICE';
```

### 1.2 t_alert_triggered_by

Axiom 2 states that an alert process X is triggered by some metric Y. The table records each alert instance and the metric class that satisfied the trigger condition. Column y is a foreign key to t_ebpf_event_min_one_attribute.id.

```sql
SELECT a.id, e.x
FROM t_alert_triggered_by a
JOIN t_ebpf_event_min_one_attribute e ON a.y = e.id;
```

### 1.3 t_syscall_invoked_by_event

Axiom 3 states that a syscall designative ICE X is invoked by some event Y. The table therefore stores each syscall instance and the event that caused its invocation. Column y is a foreign key to t_ebpf_event_min_one_attribute.id.

```sql
SELECT s.id, e.x
FROM t_syscall_invoked_by_event s
JOIN t_ebpf_event_min_one_attribute e ON s.y = e.id;
```

### 1.4 t_ebpfevent_observes_syscall_xref

Axiom 4 states that an eBPF event process X observes at least one syscall designative ICE. The table records each such observation link. Column id is the primary key; column x identifies the observed syscall class.

```sql
SELECT x.id, x.x
FROM t_ebpfevent_observes_syscall_xref x;
```

## 2 Worked multi-hop query

Question: which metric class triggered the alert that recorded the openat syscall invoked by event ev_004?

Execution path:  
t_alert_triggered_by.y → t_ebpf_event_min_one_attribute.id (ev_004)  
t_syscall_invoked_by_event.y → t_ebpf_event_min_one_attribute.id (ev_004)  
t_ebpfevent_observes_syscall_xref.x yields the syscall class.

Result row after successive joins:

alert_002 | MetricCPU | ev_004 | openat | FileOpenICE
