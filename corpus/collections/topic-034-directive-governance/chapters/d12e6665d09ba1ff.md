# Chapter 7: Projection of eBPF Process Axioms onto Kernel Trace Schemas

This chapter defines four relational tables that realize the slot structures of the supplied OWL axioms for eBPF events, metric-triggered alerts, and syscall designative entities. The tables support direct foreign-key traversal to answer multi-hop questions over observed kernel activity.

## 1 Schema Realization of Axioms

Each table is introduced by the axiom whose slots it materializes. Primary-key columns uniquely identify individuals of the anchor class; foreign-key columns enforce the existential restrictions stated in the Manchester syntax.

### 1.1 Table t_ebpf_event_min_one_attribute

Axiom 1 requires every instance of an eBPF event process to possess at least one designative attribute. The table therefore stores the event identifier together with its mandatory attribute reference; the single-column primary key guarantees uniqueness of each process occurrence.

```sql
CREATE TABLE t_ebpf_event_min_one_attribute (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example cross-join: join on id to retrieve the attribute of any given event.

### 1.2 Table t_alert_triggered_by

Axiom 2 states that an alert process is triggered by a metric that is itself an eBPF event. The table therefore records the alert identifier, the alert class, and a non-null foreign key referencing t_ebpf_event_min_one_attribute.id.

```sql
CREATE TABLE t_alert_triggered_by (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_ebpf_event_min_one_attribute(id)
);
```

Example cross-join: join y to id to obtain the triggering metric for any alert.

### 1.3 Table t_syscall_invoked_by_event

Axiom 3 asserts that a syscall designative information content entity is invoked by an eBPF event. The table therefore stores the syscall identifier, the syscall class, and a non-null foreign key referencing t_ebpf_event_min_one_attribute.id.

```sql
CREATE TABLE t_syscall_invoked_by_event (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_ebpf_event_min_one_attribute(id)
);
```

Example cross-join: join y to id to recover the invoking event for any syscall designator.

### 1.4 Table t_ebpfevent_observes_syscall_xref

Axiom 4 requires an eBPF event process to observe at least one syscall designative entity. The table therefore records the event identifier together with the observed syscall reference; the primary key again identifies the process occurrence.

```sql
CREATE TABLE t_ebpfevent_observes_syscall_xref (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example cross-join: join id to t_ebpf_event_min_one_attribute.id to list observed syscalls per event.

## 2 Worked Multi-Hop Query

Question: which alert was raised by the metric observed when syscall “openat” was invoked by event “tracepoint/syscalls/sys_enter_openat”?

Walk the links as follows:

1. Locate the syscall row in t_syscall_invoked_by_event where x = 'openat'; its y value yields the event identifier (E1).
2. Locate the alert row in t_alert_triggered_by whose y equals E1; its x value yields the alert identifier (A1).
3. The resulting joined tuple is (syscall='openat', event=E1, alert=A1).
