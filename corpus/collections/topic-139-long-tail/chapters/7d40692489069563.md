# Chapter 7: Process Subclassing, Protocol Adherence and Kernel Traceability in Laboratory Monitoring

This chapter defines five interlinked classes that capture metric emission, protocol following, syscall traceability, alert generation and eBPF observation within laboratory process executions. The classes are materialised as a five-table relational schema whose primary and foreign keys encode the existential restrictions stated in the source axioms. All column values are drawn from the same controlled vocabulary of laboratory identifiers used in equipment calibration logs and kernel audit trails.

## 1 Ontological Axioms and Table Projections

Five Manchester OWL axioms are projected to tables. Each table is introduced by a short statement of the axiom it realises, followed by its primary-key and foreign-key structure and one illustrative join path.

### 1.1 Metric Emission Subclass

Axiom 1 states that every instance of a metric-emitting process is a subclass of bfo:0000015 and stands in the relation sdg:emitsMetric to a laboratory run. The table t_metric_emission_subclass therefore stores the pair (x, y) where y is the identifier of the referenced laboratory run.

```sql
CREATE TABLE t_metric_emission_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_with_protocol(id)
);
```

### 1.2 Laboratory Run with Protocol

Axiom 2 states that a laboratory run follows a protocol. The table t_labrun_with_protocol stores the pair (x, y) where y references a metric emission subclass, closing the existential restriction.

```sql
CREATE TABLE t_labrun_with_protocol (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_metric_emission_subclass(id)
);
```

### 1.3 Syscall Traceable Entity

Axiom 3 states that a designative information content entity is traceable by a laboratory run. The table t_syscall_traceable records the pair (x, y) whose foreign key y points to t_labrun_with_protocol.

```sql
CREATE TABLE t_syscall_traceable (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_with_protocol(id)
);
```

### 1.4 Alert Triggered by Metric

Axiom 4 states that an alert process is triggered by a metric. The table t_alert_triggered_by stores the pair (x, y) whose foreign key again references t_labrun_with_protocol.

```sql
CREATE TABLE t_alert_triggered_by (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_with_protocol(id)
);
```

### 1.5 eBPF Event Observing Syscall

Axiom 5 states that an eBPF-traced process observes a syscall designative ICE. The table t_ebpfevent_observes_syscall_xref therefore contains only the identifier of the observing process.

```sql
CREATE TABLE t_ebpfevent_observes_syscall_xref (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```
