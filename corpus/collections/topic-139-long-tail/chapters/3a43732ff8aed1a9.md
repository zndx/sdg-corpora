# Chapter 7: Relational Encoding of Metric-Emission and Traceable Process Classes

This chapter presents five tables that instantiate the slot structures of five OWL axioms. The tables support primary-key and foreign-key navigation sufficient to answer multi-hop queries over laboratory runs, emitted metrics, triggered alerts, and eBPF-observed syscalls.

## 1 Axiom-to-Table Mapping

Each table directly projects one axiom. Column names preserve the slot variables X and Y. Primary keys are synthetic identifiers; foreign keys enforce the existential restrictions stated in the Manchester syntax forms.

### 1.1 t_labrun_with_protocol

The table embodies AXIOM 2. Column id is the primary key. Column y is a foreign key referencing t_metric_emission_subclass.id, recording that a laboratory run follows a protocol that itself emits a metric.

```sql
CREATE TABLE t_labrun_with_protocol (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_metric_emission_subclass(id)
);
```

Example rows:

| id          | x                        | y             |
|-------------|--------------------------|---------------|
| LR-001      | RTNS_LabRun_2019         | ME-010        |
| LR-002      | Barn_Protocol_Filly      | ME-011        |
| LR-003      | LENDERS_Run_Mortgage     | ME-012        |
| LR-004      | RTNS_LabRun_2019         | ME-013        |

### 1.2 t_metric_emission_subclass

The table embodies AXIOM 1. Column id is the primary key. Column y is a foreign key referencing t_labrun_with_protocol.id, closing the mutual restriction between emission and protocol adherence.

```sql
CREATE TABLE t_metric_emission_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_with_protocol(id)
);
```

Example rows:

| id     | x                  | y      |
|--------|--------------------|--------|
| ME-010 | Metric_SeattleSlew | LR-001 |
| ME-011 | Metric_AckAck      | LR-002 |

### 1.3 t_alert_triggered_by

The table embodies AXIOM 4. Column id is the primary key. Column y is a foreign key referencing t_labrun_with_protocol.id, linking an alert process to the metric emitted by a protocol-following run.

```sql
CREATE TABLE t_alert_triggered_by (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_with_protocol(id)
);
```

Example rows:

| id       | x                 | y      |

| AL-100   | Alert_HighLoad    | LR-001 |

### 1.4 t_syscall_traceable

The table embodies AXIOM 3. Column id is the primary key. Column y is a foreign key referencing t_labrun_with_protocol.id, asserting that a designative information content entity is traceable through a laboratory run.

```sql
CREATE TABLE t_syscall_traceable (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_with_protocol(id)
);
```

Example rows:

| id       | x                    | y      |
|----------|----------------------|--------|

### 1.5 t_ebpfevent_observes_syscall_xref

The table embodies AXIOM 5. Column id is the primary key. No foreign key is declared; the table supplies the cco:DesignativeICE instances referenced existentially by AXIOM 3.
