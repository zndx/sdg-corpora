# Laboratory Execution Ontologies and Kernel Traceability

This chapter presents five relational tables that realize a compact OWL fragment for laboratory processes. The tables encode subclass and existential restrictions drawn from BFO and CCO, allowing multi-table joins that recover metric emission, protocol adherence, alert causation, and syscall observability.

## 1 Schema Overview

The schema comprises exactly the tables projected from the supplied axioms. Primary keys are string identifiers; foreign keys implement the “some” restrictions. All column values are drawn from the same controlled vocabulary of laboratory classes so that joins remain semantically valid.

### 1.1 t_metric_emission_subclass

This table embodies Axiom 1. Column id is the primary key; column y is a foreign key into t_labrun_with_protocol, expressing that an emission subclass necessarily follows a protocol run.

| id   | x                    | y     |
|------|----------------------|-------|
| ME01 | EmissionTemp         | LR02  |
| ME02 | EmissionPressure     | LR01  |
| ME03 | EmissionVibration    | LR03  |
| ME04 | EmissionCurrent      | LR02  |

### 1.2 t_labrun_with_protocol

This table embodies Axiom 2. Column id is the primary key; column y is a foreign key into t_metric_emission_subclass, closing the mutual restriction between protocol runs and metric emissions.

| id   | x               | y    |
|------|-----------------|------|
| LR01 | RunStdProtocol  | ME02 |
| LR02 | RunHighLoad     | ME01 |
| LR03 | RunCalibCycle   | ME03 |
| LR04 | RunStressTest   | ME04 |

### 1.3 t_syscall_traceable

This table embodies Axiom 3. Column id is the primary key; column y is a foreign key into t_labrun_with_protocol, recording that a designative information content entity is traceable through a specific protocol run.

| id    | x                 | y    |
|-------|-------------------|------|
| ST01  | SyscallReadTemp   | LR01 |
| ST02  | SyscallWriteLog   | LR02 |
| ST03  | SyscallSetGain    | LR03 |
| ST04  | SyscallFlushCache | LR01 |

### 1.4 t_alert_triggered_by

This table embodies Axiom 4. Column id is the primary key; column y is a foreign key into t_labrun_with_protocol, capturing that an alert process is triggered by a metric emitted during a protocol run.

| id    | x             | y    |
|-------|---------------|------|
| AL01  | AlertHighTemp | LR02 |
| AL02  | AlertOverload | LR01 |
| AL03  | AlertDrift    | LR03 |
| AL04  | AlertSpike    | LR04 |

### 1.5 t_ebpfevent_observes_syscall_xref

This table embodies Axiom 5. Column id is the primary key; the single column x references a class that observes a syscall designative ICE. No foreign key is required by the axiom.

| id   | x                  |
|------|--------------------|
| EB01 | EbpfEventRead      |
| EB02 | EbpfEventWrite     |
| EB03 | EbpfEventIoctl     |
| EB04 | EbpfEventFsync     |
| EB05 | EbpfEventMmap      |

## 2 Cross-Join Example

To recover the alert that fired on the temperature metric emitted by equipment whose run followed the standard protocol and was observed by an eBPF event, the following path is traversed: t_alert_triggered_by.y → t_labrun_with_protocol.id → t_metric_emission_subclass.y → t_labrun_with_protocol.id (self-join) → t_syscall_traceable.y. The join yields the single row (AL01, AlertHighTemp, LR02, ME01, EmissionTemp, ST02, SyscallWriteLog, EB02, EbpfEventWrite).
