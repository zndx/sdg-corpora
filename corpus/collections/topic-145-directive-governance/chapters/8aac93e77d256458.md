# Chapter 12: Structural Verification of Mass Functions in Descriptive Information Content Entities

## 12.1 Scope and Preamble

This chapter establishes the formal protocols for defining and verifying Mass Functions within the context of Descriptive Information Content Entities (ICE). It details the axiomatic requirements linking specific function classes to their respective Frames of Discernment and Mass Assignment targets, providing a deterministic framework for ontology alignment. The content herein is intended to guide system architects and compliance officers in validating the structural integrity of belief representation models, ensuring that all instantiated entities adhere to the rigorous standards set forth in the governing ontology.

## 12.2 Axiomatic Definition of Mass Functions

In the domain of uncertainty representation, the Mass Function serves as a foundational construct for quantifying belief within a specific evidential framework. According to the governing ontology, a Mass Function is not merely a standalone computational object but is formally axiomatized as a subclass of the Descriptive Information Content Entity (`cco:DescriptiveICE`). This equivalence mandates that any entity classified as a Mass Function must satisfy two existential constraints: it must operate over a defined Frame of Discernment, and it must assign mass to a specific target set.

The structural integrity of this definition is verified through the `mass_function_equiv_frame_and_assignment` axiom. This axiom asserts that a class `X` (the Mass Function) is equivalent to the intersection of being a Descriptive ICE, having a relationship `sdg:overFrameOfDiscernment` with a class `Y` (the Frame), and having a relationship `sdg:assignsMassTo` with a class `Z` (the Target). This tripartite structure ensures that belief is never quantified in isolation but is always anchored to a domain of discourse and a specific object of belief.

To facilitate the auditing of these class definitions, the following registry table enumerates the valid configurations of Mass Functions currently sanctioned within the system. Each row represents a distinct class definition (`x`) that satisfies the equivalence axiom, explicitly linking it to the required Frame of Discernment (`y`) and the Mass Assignment Target (`z`).

### 12.2.1 The Role of the Descriptive ICE

The parent class, `cco:DescriptiveICE`, categorizes the Mass Function as an entity that is about something—it carries descriptive content. In the context of an audit, this distinction is critical. It separates the mathematical structure of the belief (the function itself) from the raw data it processes. When verifying compliance, auditors must ensure that the instance of the Mass Function contains metadata or descriptive attributes that characterize the nature of the uncertainty being modeled. This ensures that the information content is traceable and semantically grounded, rather than being an abstract or opaque calculation.

### 12.2.2 Frame of Discernment Constraints

The slot `sdg:overFrameOfDiscernment` (represented by column `y` in the registry) identifies the set of mutually exclusive hypotheses that define the universe of discourse for the Mass Function. The axiom requires that the Mass Function be defined *over* this frame. In practice, this means the cardinality and exclusivity of the Frame must be established prior to the instantiation of the Mass Function.

For instance, the `BasicBeliefAssignment` (Row 1) is strictly defined over a `BinaryHypothesisFrame`. Any attempt to assign a mass value to a ternary set using this specific class definition would constitute a structural violation of the ontology. The registry enforces this by explicitly mapping the class `BasicBeliefAssignment` to the class `BinaryHypothesisFrame`. This binding prevents category errors where a function optimized for binary outcomes might be erroneously applied to complex, multi-state environments.

### 12.2.3 Mass Assignment Targets

The final component of the axiom, `sdg:assignsMassTo` (column `z`), specifies the nature of the subsets to which the belief mass is allocated. In Dempster-Shafer theory, mass is not assigned to individual hypotheses directly in all cases, but often to subsets (focal elements) of the Frame of Discernment. The ontology captures this by requiring a specific class for the target.

As shown in Table 12.1, the `ConjunctionMassFunction` is axiomatically linked to the `IntersectionSet`. This indicates that the function is designed to handle the logical intersection of evidence, aggregating mass by calculating the overlap of focal elements. Conversely, the `DisjunctiveMassFunction` is linked to the `UnionSet`, reflecting its role in combining evidence through logical disjunction. The explicit definition of these target classes in the registry ensures that the algebraic properties of the Mass Function are consistent with the set-theoretic nature of the evidence being processed.

### 12.3.1 Analysis of Compliance Failures

The failures identified in Table 12.2 highlight the importance of strict adherence to the `mass_function_equiv_frame_and_assignment` axiom.

In the case of `AUD_2023_091`, the `Temporal_Predictor_Gamma` instance utilized a `ConditionalMassFunction`. According to the registry (Table 12.1), this class is axiomatically coupled with the `AntecedentSet` as its mass assignment target. However, the operational data revealed that the system was attempting to assign mass to a `UnionSet`. This represents a semantic violation: the conditional logic intended to model temporal dependencies based on antecedents was being incorrectly applied to a broad, disjunctive set of outcomes. Such discrepancies can lead to significant errors in belief propagation, rendering the output of the Information Content Entity unreliable for decision-making purposes.

Similarly, `AUD_2023_093` demonstrates a Frame mismatch. The `DisjunctiveMassFunction` is defined over a `ContinuousStateFrame` (or generally a frame supporting disjunction across complex states), yet the instance was operating over a `BinaryHypothesisFrame`. While a binary frame technically permits union operations, the ontology class `DisjunctiveMassFunction` is reserved for higher-order complexity where the frame supports continuous or multi-state logic. Applying it here may not result in a calculation error, but it violates the structural governance of the ontology, leading to "class bloat" and maintenance inefficiencies.

## 12.4 Governance and Maintenance of the Registry

The maintenance of the `t_mass_function_equiv_frame_and_assignment` table is a critical governance function. As new forms of evidence aggregation are developed, or as existing frames are refined, the ontology must be updated to reflect these changes. However, such updates must not be performed ad-hoc.

Any addition to the registry must undergo a formal review process to ensure that the new Class `X` is genuinely a Descriptive ICE and that the relationships to `Y` and `Z` are both necessary and sufficient for the definition. The deterministic nature of the schema—specifically the `NOT NULL` constraints on `y` and `z`—enforces a discipline where no Mass Function can be entered into the system without a complete definition of its context and targets.

Furthermore, the `id` field serves as a persistent identifier for the axiom itself. This allows for version control and traceability. If the definition of `BasicBeliefAssignment` were to change in future iterations of the ontology—for example, if it were expanded to include a `TemporalFrame`—the `id` would remain constant, but the `y` and `z` values would be superseded by a new registry entry. This ensures that historical audit logs remain valid against the schema version active at the time of the audit.
