# Chapter 12: Ontological Formalization of Uncertainty in Audit Evidence

## 12.1 Scope and Preamble

This chapter establishes the ontological framework required to quantify and manage uncertainty within automated audit environments. As per the Governance Frameworks Directive (GFD-2024), audit evidence must not be treated as binary but rather as a spectrum of belief derived from heterogeneous data sources. To achieve this, the chapter introduces the formal concept of the Mass Function, grounded in the Common Core Ontology (CCO) and the Evidence Data Governance (SDG) extension. The definitions provided herein are binding for all compliance modules utilizing Dempster-Shafer theory for evidence aggregation.

## 12.2 The Frame of Discernment

Before a belief can be assigned, the audit system must define the universe of possible propositions. In formal ontology, this is referred to as the Frame of Discernment. It represents the set of mutually exclusive and exhaustive hypotheses relevant to a specific audit query.

For instance, in a financial compliance audit, the Frame of Discernment regarding a specific transaction might consist of the classes `Compliant`, `NonCompliant`, and `Suspicious`. The frame acts as the boundary condition for any subsequent evidence processing. Without a rigorously defined Frame, the assignment of mass (belief) is mathematically invalid and procedurally unsafe.

The following table outlines standard Frames of Discernment utilized within the Automated Audit Protocol (AAP). These frames serve as the semantic boundaries for evidence evaluation.

**Table 12.1: Standard Frames of Discernment in Audit Protocols**

| Frame ID | Frame Name | Description | Hypothesis Classes |
| :--- | :--- | :--- | :--- |
| `FD_001` | `TaxComplianceFrame` | Delineates states of fiscal adherence for corporate tax returns. | `FullyCompliant`, `PartiallyCompliant`, `NonCompliant` |
| `FD_002` | `AccessControlFrame` | Defines states of user authentication and authorization integrity. | `Authorized`, `Unauthorized`, `Compromised` |
| `FD_003` | `DataIntegrityFrame` | Specifies the veracity states of database records. | `Valid`, `Corrupted`, `Stale` |
| `FD_004` | `RegulatoryReportingFrame` | Covers the completeness status of mandatory regulatory filings. | `Complete`, `Incomplete`, `Late` |

## 12.3 The Descriptive Information Content Entity

All audit artifacts are formally classified as Information Content Entities (ICE). Specifically, when these entities describe a state of affairs or a belief regarding the Frame of Discernment, they are categorized as `cco:DescriptiveICE`. This distinction is critical; it separates raw data (e.g., a log file) from the interpretive layer (e.g., a belief function derived from that log).

In the context of our ontology, the Mass Function is not merely a mathematical tool but a specific subclass of `DescriptiveICE`. It is an artifact that encodes the degree of support an auditor—or an automated agent—has for various subsets of the Frame of Discernment. By treating the Mass Function as an ICE, the framework allows for versioning, access control, and lineage tracking of belief structures, just as one would manage a standard document.

## 12.4 The Mass Function Class

The core of this chapter defines the Mass Function (`X`) through a specific equivalence axiom. A Mass Function is formally defined as a `cco:DescriptiveICE` that satisfies two structural constraints:

1.  It must be defined over a specific Frame of Discernment (`Y`).
2.  It must assign a mass value to a specific target subset or hypothesis (`Z`).

This relationship is captured in the following axiom:
`Class: {X:Class} EquivalentTo: cco:DescriptiveICE and (sdg:overFrameOfDiscernment some {Y:Class}) and (sdg:assignsMassTo some {Z:Class})`

This definition ensures that every instance of a Mass Function is traceable to the context (Frame) in which it operates and the specific proposition (Target) it supports. This prevents "orphaned" beliefs—mass values that exist without a defined hypothesis space.

### 12.4.1 Implementation and Instantiation

When the audit system generates a Mass Function, it instantiates this class structure. For example, if a system analyzes a transaction and determines a 70% likelihood of compliance, it creates a Mass Function instance. This instance is linked to the `TaxComplianceFrame` (the `Y` slot) and assigns mass to the `FullyCompliant` class (the `Z` slot).

## 12.5 Relational Mapping and Data Integrity

To ensure the persistence and queryability of these ontological structures, the Mass Function axiom is projected onto a relational schema. This mapping enforces the logical constraints defined in Section 12.4 at the database level.

The schema `t_mass_function_equiv_frame_and_assignment` serves as the primary registry for the definition of these classes. It does not store the dynamic mass values (which are time-series data), but rather the structural definitions of which Mass Function Classes operate over which Frames and assign mass to which Targets.

### 12.5.1 Schema Constraints

The primary key for this structure is the `id` column, which uniquely identifies the definition rule. The columns `y` (Frame) and `z` (Assignment Target) are constrained as `NOT NULL`, ensuring that every Mass Function definition is explicitly bound to a context and a target. This enforces the axiom `sdg:overFrameOfDiscernment some {Y:Class}` and `sdg:assignsMassTo some {Z:Class}` at the data layer.

Any attempt to insert a row defining a Mass Function Class (`x`) without a corresponding Frame (`y`) or Target (`z`) will result in a constraint violation, thereby maintaining the logical integrity of the audit knowledge base.
