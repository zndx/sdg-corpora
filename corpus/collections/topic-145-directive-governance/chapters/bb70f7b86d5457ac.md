# Chapter 4: Formalization of Evidence Mass Functions in Descriptive Information Content Entities

## 4.1 Scope and Preamble

This chapter establishes the formal ontological framework for representing uncertainty within descriptive information content entities (ICEs) utilized in high-assurance reporting environments. In accordance with the evidence-based auditing standards mandated for regulatory compliance, it is insufficient to report discrete data points without a quantifiable measure of confidence or evidential support. Consequently, this section defines the structural constraints for "Mass Functions"—mathematical objects derived from Dempster-Shafer theory that must be embedded within Descriptive ICEs. The definitions provided herein are binding for all systems generating Form 10-Q equivalent disclosures, internal audit reports, and governance frameworks requiring the representation of non-deterministic states.

## 4.2 The Descriptive Information Content Entity (cco:DescriptiveICE)

### 4.2.1 Definition and Context

The foundational container for all evidentiary data within this framework is the `cco:DescriptiveICE`. As defined by the Common Core Ontologies (CCO), a Descriptive Information Content Entity is a type of information content entity that is about some entity—or, in the context of this framework, a set of propositions. Unlike prescriptive information (which dictates behavior), a Descriptive ICE encapsulates the state of the world as observed or inferred by the reporting system.

In the context of audit reporting, a Descriptive ICE is not merely a text string or a numeric value; it is a structured artifact that carries the semantic weight of the observation. For a Descriptive ICE to serve as a valid vehicle for uncertainty representation, it must satisfy specific equivalence axioms. It cannot exist in isolation; it must be functionally bound to a Frame of Discernment and a mechanism for Mass Assignment.

### 4.2.2 Role in Evidence Aggregation

The Descriptive ICE acts as the immutable record. When an automated system generates a compliance flag (e.g., "High Risk"), the Descriptive ICE is the object that is persisted, hashed, and logged. However, to satisfy the requirements of this ontology, the Descriptive ICE must be explicitly typed as a Mass Function. This typing ensures that downstream consumers—such as regulatory analysts or automated governance engines—understand that the entity contains probabilistic metadata rather than deterministic facts.

## 4.3 The Frame of Discernment (sdg:overFrameOfDiscernment)

### 4.3.1 Defining the Hypothesis Space

The second critical component of this axiom is the `sdg:overFrameOfDiscernment`. In Dempster-Shafer theory, the Frame of Discernment (often denoted as $\Theta$) represents the set of mutually exclusive and exhaustive hypotheses relevant to a specific domain of inquiry.

Within the relational schema of this ontology, the property `sdg:overFrameOfDiscernment` links the Descriptive ICE (the Mass Function) to a specific Class that defines the boundaries of the uncertainty. This linkage is mandatory. A Mass Function reporting on "Financial Solvency" cannot be defined over a Frame of Discernment intended for "Network Security Protocols." The ontology enforces strict type checking to prevent category errors in evidential reasoning.

### 4.3.2 Structural Constraints

The Frame of Discernment is modeled as a Class (`Y` in the axiom). This allows for hierarchical structuring of hypotheses. For instance, a high-level Frame of Discernment for "Audit Status" might contain the hypotheses {Compliant, Non-Compliant, Inconclusive}. The Mass Function exists *over* this Frame, meaning its mass values are distributed across the power set of these hypotheses.

## 4.4 Mass Assignment (sdg:assignsMassTo)

### 4.4.1 The Basic Probability Assignment

The third component, `sdg:assignsMassTo`, defines the functional relationship between the Descriptive ICE and the actual belief values. The "Mass" (denoted as $m(A)$) represents the degree of belief allocated specifically to a subset of the Frame of Discernment, based on available evidence.

Unlike probability theory, where probability is assigned to singletons, Mass Functions allow for the assignment of belief to sets of hypotheses (e.g., "either Compliant or UnderReview") without requiring specificity that the evidence does not support. The property `sdg:assignsMassTo` maps the Descriptive ICE to a Class (`Z`) that represents the structure or instance of these mass assignments.

### 4.4.2 Validation of Evidence

For a Descriptive ICE to be valid, the sum of all masses assigned via `sdg:assignsMassTo` must equal 1.0 (or 100%). The ontology treats the Mass Assignment Class (`Z`) as a data structure subject to mathematical validation. If an audit report attempts to assign a mass of 0.6 to "Compliant" and 0.6 to "Non-Compliant" without accounting for the overlap or ignorance, the ICE violates the axiom and must be rejected by the validation layer.

## 4.5 Axiomatic Integration: The Mass Function Equivalence

### 4.5.1 The Equivalence Axiom

The core of this chapter is the formal equivalence axiom that binds the preceding concepts. The axiom states:

> **Class:** `{X:Class}` **EquivalentTo:** `cco:DescriptiveICE` **and** (`sdg:overFrameOfDiscernment` **some** `{Y:Class}`) **and** (`sdg:assignsMassTo` **some** `{Z:Class}`)

This axiom asserts that any entity `X` is a Mass Function if and only if it is a Descriptive ICE, it is defined over a specific Frame of Discernment `Y`, and it assigns mass to a specific structure `Z`. This is a necessary and sufficient condition. An entity cannot be a Mass Function if it lacks the descriptive capacity, the hypothesis space, or the mass assignment mechanism.

### 4.5.2 Relational Schema Implementation

To operationalize this axiom within a relational database infrastructure—such as that supporting a SEC filing system or an internal audit ledger—the following schema is mandated. This table enforces the foreign key relationships that guarantee the integrity of the evidential chain.

The table `t_mass_function_equiv_frame_and_assignment` serves as the registry for all valid Mass Function classes (`X`) utilized by the system. It explicitly links the Mass Function to its authorized Frame (`Y`) and its Assignment Target (`Z`).

**Schema Explanation:**
The primary key for this table is the `id` column, which serves as the unique identifier for the specific equivalence definition. The column `x` represents the Class of the Mass Function itself (the subject of the definition). The column `y` is a mandatory foreign key reference to the Class defining the Frame of Discernment, ensuring that the Mass Function is semantically bound to a valid hypothesis space. The column `z` is a mandatory foreign key reference to the Class defining the Mass Assignment, ensuring that the function outputs values compatible with the system's evidential reasoning engine.

## 4.6 Compliance and Verification

### 4.6.1 Audit Trail Requirements

Any generation of a `Mass Function` instance must log the creation of the corresponding Descriptive ICE with a timestamp and the cryptographic hash of the Frame of Discernment definition. This ensures that if the Frame of Discernment is updated (e.g., adding a new hypothesis), historical Mass Functions remain valid relative to the Frame that existed at the time of their creation.

### 4.6.2 Automated Governance

Systems implementing this ontology must include a validation rule that checks for the existence of a record in `t_mass_function_equiv_frame_and_assignment` prior to the instantiation of any Descriptive ICE intended to carry uncertainty data. If a software module attempts to instantiate a class `FinancialAuditMassFunction` that is not registered in the table with a valid `y` and `z` mapping, the instantiation must fail with a `SchemaViolationException`.
