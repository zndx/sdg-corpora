# Chapter 8: Specification of Mass Functions in Evidence-Based Governance Frameworks

This chapter delineates the formal ontological definition and relational implementation of the Mass Function construct within the Evidence Theory module of the governance framework. It establishes the necessary and sufficient conditions for an entity to be classified as a Mass Function, specifically its equivalence to a Descriptive Information Content Entity (ICE) and its dependence on a defined Frame of Discernment. The following sections provide the axiomatic derivation, the relational schema required for audit persistence, and the operational data tables utilized in compliance reporting.

## 1. Axiomatic Definition of the Mass Function

### 1.1 The Equivalence to Descriptive ICE

The foundational axiom for the Mass Function is derived from the template `mass_function_equiv_frame_and_assignment`. In accordance with the ontology, the Mass Function (denoted as variable `X`) is formally defined as a Class that is EquivalentTo the intersection of three specific constraints. First, `X` must be a subclass of `cco:DescriptiveICE`. This alignment anchors the Mass Function within the upper-level ontology of Information Content Entities, ensuring that it is treated as a distinct, independent information artifact rather than a physical object or a dependent data value. This distinction is critical for audit trails, as it separates the *evidence* (the Mass Function) from the *subject of the evidence* (the system or process under observation).

The equivalence relation implies that any entity classified as a Mass Function inherently possesses the characteristics of a Descriptive ICE. It is a "bearer of information" that can be serialized, stored, and transmitted across compliance systems. By anchoring this class to `cco:DescriptiveICE`, the framework ensures that all instances of Mass Functions are subject to the same information governance policies as other descriptive entities, such as audit reports or log entries.

### 1.2 Constraints of Frame of Discernment

The second constraint in the axiom dictates that a Mass Function (`X`) must be associated with a Frame of Discernment (`Y`) via the object property `sdg:overFrameOfDiscernment`. The Frame of Discernment represents the exhaustive set of mutually exclusive hypotheses relevant to a specific audit query or risk assessment.

In the context of this specification, the Frame of Discernment is not merely a background context but a formal ontological class to which the Mass Function is structurally bound. The use of the existential restriction (`some`) indicates that for a Mass Function to exist, it must define at least one Frame of Discernment. This relationship ensures that every belief assignment is grounded in a defined universe of discourse. For instance, a Mass Function assessing "Financial Integrity" cannot exist in a vacuum; it must be explicitly over a Frame of Discernment such as "SolvencyStatus" (containing hypotheses like Solvent, Insolvent, or Undetermined). This constraint prevents ambiguous or undefined evidence from entering the compliance record.

### 1.3 Mass Assignment Semantics

The third component of the axiom involves the object property `sdg:assignsMassTo`, which links the Mass Function (`X`) to a specific Focal Element (`Z`). A Focal Element is a subset of the Frame of Discernment to which a non-zero belief mass (basic probability assignment) is allocated.

The axiom requires that the Mass Function assigns mass to some class `Z`. This class `Z` represents the specific state or hypothesis within the Frame that the evidence supports. Unlike probabilistic models which assign weight to single points, evidence theory allows for the assignment of mass to sets (focal elements). Therefore, `Z` may represent a single hypothesis (e.g., "Non-Compliant") or a composite set (e.g., "Non-Compliant or Undetermined"). The relational implementation of this axiom must capture this tripartite structure: the Information Entity (`X`), the Universe of Discourse (`Y`), and the Target of Belief (`Z`).

## 2. Relational Implementation

### 2.1 Schema Structure and Integrity Constraints

The logical structure defined by Axiom 1 is projected deterministically into a relational schema to support persistent storage and query execution within the compliance database. The primary table, `t_mass_function_equiv_frame_and_assignment`, serves as the central registry for all Mass Function instances utilized in audit evidence.

The table structure is designed to enforce the axiomatic constraints at the database level. The primary key is the `id` column, which provides a unique identifier for each Mass Function instance. The columns `x`, `y`, and `z` are defined as `VARCHAR(255)` to store the URI or local identifier of the respective ontology classes. The columns `y` and `z` are marked `NOT NULL`, enforcing the existential restrictions defined in the Manchester syntax (`some {Y:Class}` and `some {Z:Class}`). This ensures that a row cannot be created unless the Frame of Discernment and the Mass Assignment target are explicitly defined. The `bfo_anchor` comment associated with the schema (`cco:DescriptiveICE`) serves as metadata for data governance tools, indicating the top-level ontology class to which the instance belongs.

The instances presented in Table 2-1 demonstrate the application of the axiom across different domains of governance. The Frame of Discernment acts as the universal set for a specific evidence context. It defines the boundaries of what is knowable or hypothesizable within that specific audit scope.
