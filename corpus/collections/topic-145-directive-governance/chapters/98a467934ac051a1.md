# Chapter 4: Formal Specification of Evidentiary Mass Functions in Information Systems

## 4.1 Scope and Preamble

This chapter establishes the formal criteria for the representation and management of evidentiary uncertainty within ontological information systems. It provides a detailed examination of the axiomatic structure required to define Mass Functions as Descriptive Information Content Entities (DescriptiveICE). The guidelines herein are intended for system architects, data governance officers, and compliance auditors who must ensure that probabilistic reasoning models are rigorously defined and semantically grounded. The content delineates the necessary relationships between a mass function, its frame of discernment, and the focal elements to which it assigns belief mass, ensuring consistency with high-level regulatory frameworks for data integrity.

## 4.2 The Axiomatic Definition of Mass Functions

In the context of ontological modeling, a Mass Function is not merely a mathematical distribution but a distinct information artifact that must be classified and structured according to strict logical axioms. The foundational axiom for this concept asserts that any entity classified as a Mass Function is equivalent to the intersection of three specific conditions: it must be a `cco:DescriptiveICE`; it must operate over a specific `sdg:overFrameOfDiscernment`; and it must `sdg:assignsMassTo` a specific class of focal elements.

This structure ensures that every instance of a mass function is traceable to a defined context (the frame of discernment) and a defined set of propositions (the focal elements). For compliance purposes, this means that a mass function cannot exist in isolation; it must be explicitly anchored to the domain it describes. For example, in a safety-critical system monitoring hydraulic pressure, a mass function representing the belief in various system states must be formally linked to the "HydraulicPressureFrame" and must assign mass to specific subsets of that frame, such as "NominalRange" or "CriticalOverpressure."

### 4.2.1 The Role of DescriptiveICE

The classification of a Mass Function as a `cco:DescriptiveICE` places it within the hierarchy of Information Content Entities. This designation is critical for audit trails, as it distinguishes the *description* of the uncertainty (the mathematical object) from the physical entities being described (e.g., the sensors or the hydraulic fluid). In a regulatory audit, this distinction allows an investigator to separate the metadata regarding the system's knowledge state from the operational logs of the machinery itself.

## 4.3 The Frame of Discernment

The `sdg:overFrameOfDiscernment` slot represents the set of mutually exclusive and exhaustive hypotheses that define the universe of discourse for a specific evidentiary problem. In the relational projection of the ontology, this is modeled as a mandatory class reference (`y`). The frame of discernment acts as the semantic boundary for the mass function; no belief can be assigned outside of this set.

From a governance perspective, the definition of the frame of discernment is a control point. If the frame is defined too narrowly (e.g., excluding "Unknown Failure Modes"), the system may produce overconfident, incorrect results. Conversely, a frame defined too broadly may dilute the evidentiary power of the mass function. The following table illustrates the registration of distinct frames of discernment utilized in a hypothetical industrial audit scenario.

| Frame ID | Frame Class Name | Domain Context | Hypothesis Cardinality |
| :--- | :--- | :--- | :--- |

In Table 4.1, the `SystemOperationalStatus` frame, for instance, might consist of the hypotheses {Operational, Degraded, Failed}. The axiomatic structure requires that any mass function claiming to describe system status must reference this specific class (`y`) as its frame.

## 4.4 Mass Assignment and Focal Elements

The third component of the axiom, `sdg:assignsMassTo`, links the Mass Function to a class of Focal Elements (`z`). A focal element is a subset of the frame of discernment to which a non-zero mass (belief) is directly assigned. Unlike probability theory, where mass is assigned only to singletons (elementary hypotheses), evidence theory allows for the assignment of mass to sets of hypotheses. This capability is crucial for modeling ignorance or uncertainty where the evidence supports a set of possibilities but does not distinguish between them.

For example, a mass function might assign 0.3 mass to the set {Operational, Degraded}, indicating that the evidence supports the system being in one of these states but cannot determine which one with higher specificity. The class `z` in the axiom represents the *type* or *category* of these focal elements.

## 4.5 Implementation and Governance

Implementing the axiom `mass_function_equiv_frame_and_assignment` requires strict database constraints. The relational schema provided in the technical appendix mandates that `y` and `z` are non-nullable. This constraint enforces the rule that a mass function cannot be defined without a context and a target for its belief. In practical terms, this prevents the generation of "orphan" uncertainty metrics that cannot be traced back to a frame of discernment, a common finding in non-compliant legacy systems.

Furthermore, the equivalence to `cco:DescriptiveICE` implies that all metadata regarding the creation of the mass function (author, timestamp, algorithm version) must be preserved. When an auditor reviews the system logs, they must be able to retrieve the row from `t_mass_function_equiv_frame_and_assignment` corresponding to the analysis performed and verify that the mathematical operations used were valid for the defined `x`, `y`, and `z` classes.

Failure to maintain this linkage—such as assigning mass to a `z` class that is not a subset of the defined `y` frame—constitutes a critical semantic violation. It renders the evidentiary calculation mathematically invalid and the resulting decision support non-compliant with the established governance framework.
