# Directive Governance in Regulatory Audit Systems

This chapter presents five relational tables that instantiate axioms for directive governance. The tables capture processes that conduct audits, produce evidence, receive attestations, and satisfy requirements. All column values are drawn from a compliance audit program operating under ISO 17025 laboratory accreditation.

## 1 Scope and Table Construction

The domain models regulatory audits performed on testing laboratories. Each table directly projects one axiom. Primary keys are surrogate identifiers. Foreign-key relationships exist where an x, y, or z value in one table matches an identifier used as x in another table, enabling joins that traverse from requirements through verifications to signatories and evidence.

### 1.1 Table t_audit_conducted_by

This table embodies axiom 1: every row represents a process (x) that is conducted by a person. Column id is the primary key; column x holds the process identifier.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 2 Cross-Table Query Example

To determine which evidence supports requirement Req_Traceability when applied to Target_Method_01, first locate the requirement row in t_requirement_equiv_specifies_target where x = 'Req_Traceability' and z = 'Target_Method_01'. This yields y = 'Outcome_Calibration'. Join on y to t_verification_min_one_evidence where x matches a satisfier listed for the same requirement in t_requirement_only_satisfied_by. The join returns two evidence rows: Evidence_CalibCert_3921 and Evidence_RawData_7844. These rows are the only evidence items permitted under the axiom that restricts satisfaction of Req_Traceability to Verify_Method_01 processes.
