# Directive Governance in Audit Trails

This chapter defines five core ontological patterns for modeling compliance processes in regulatory audit systems. The patterns are realized as a fixed relational schema whose primary and foreign keys enable multi-hop queries over conducted audits, evidence requirements, specification targets, attestation signers, and satisfaction constraints.

## 1 Scope and Schema Overview

The domain is audit-trail governance for taxpayer-relief determinations. Five tables directly project the supplied axioms. Each table carries an explicit primary key on column `id`. Columns named `x`, `y`, and `z` function as foreign-key references to class instances; equality of values across tables supplies the join paths required for verification and attestation workflows.

### 1.1 Table t_audit_conducted_by

Axiom 1 classifies an audit process by the person who conducted it. Column `id` is the primary key; column `x` is a foreign key referencing an audit instance that must later be joined to evidence or attestation records.

## 2 Cross-Join Demonstration

To determine the evidence supporting an audit conducted by a given person and attested under a requirement satisfied only by income documentation, join `t_audit_conducted_by`, `t_verification_min_one_evidence`, and `t_requirement_only_satisfied_by` on matching `x` values:

- Start with `t_audit_conducted_by` row `acb-001` (`x` = AUD-IRS-2023-0142).  
- Locate `t_verification_min_one_evidence` rows whose `x` equals AUD-IRS-2023-0142 (none in the sample) or follow the verification identifier through an intermediate attestation link.  
- Cross to `t_requirement_only_satisfied_by` where `x` = REQ-6015-ELIG yields `y` = SAT-INCOME-DOC, confirming the sole satisfier.

The resulting joined tuple is (AUD-IRS-2023-0142, VER-REL-2023-07, EV-DEC-8821, REQ-6015-ELIG, SAT-INCOME-DOC).
