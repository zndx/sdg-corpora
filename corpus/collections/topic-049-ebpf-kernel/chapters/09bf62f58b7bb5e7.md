# Audit Trails for Descriptive Claims in Observational Datasets

This chapter defines four ontological templates that classify descriptive information content entities arising during dataset audits and shows their deterministic projection onto a four-table relational schema. The schema supports verification that every outlier claim references at least one supporting trace and that audited datasets are linked to the processes that generate such traces.

## 1 Ontological Templates

Four Manchester OWL axioms govern the placement of claims and traces. Axiom 3 states that any individual classified as outlier_claim_basic is a descriptive information content entity. Axiom 2 states that any individual classified as trace_supports_claim is a process that supports some descriptive information content entity. Axiom 1 states that any individual classified as outlier_claim_min_one_attribute is a descriptive information content entity that has at least one attribute set whose members are trace_supports_claim individuals. Axiom 4 states that any individual classified as dataset_under_audit is an artifact that stands under audit by some process.

## 2 Relational Projection

The axioms map directly to four tables whose column types and foreign-key constraints preserve the slot restrictions. Primary keys are string identifiers; foreign keys enforce the “supports” and “has attribute” relations required by the axioms.

### 2.1 t_trace_supports_claim

This table embodies Axiom 2. Column id is the primary key; column x holds the process identifier that supports a descriptive claim.

### 2.4 t_outlier_claim_min_one_attribute

This table embodies Axiom 1. Column id is the primary key; column x holds the claim identifier; column y is a foreign key referencing t_trace_supports_claim.id and thereby guarantees the required minimum cardinality of one supporting trace.

## 3 Cross-Join Demonstration

To retrieve the audit process that supports the first attribute of claim_101, join t_outlier_claim_min_one_attribute to t_trace_supports_claim on y = id and filter where x = claim_101. The joined row is:

attr_301 | claim_101 | trace_001 | process_audit_17

A second hop from t_trace_supports_claim.x to t_dataset_under_audit.x shows that process_audit_17 is recorded against dataset_201, confirming that the outlier claim is grounded in an audited financial extract.
