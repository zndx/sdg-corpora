# Evidence Networks in Directive Compliance Modeling

This chapter defines five ontological templates for representing directive and descriptive information content entities. It demonstrates each template through a fixed relational schema whose foreign-key links permit multi-hop queries over compliance evidence.

## 1 Scope and Schema Overview

The schemas instantiate the five Manchester axioms supplied in Section 2. Each table carries an identifier column as primary key. Foreign-key columns reference identifiers in other tables, enabling joins that recover the slot fillers of the original axioms. All column values are drawn from a payment-card security evaluation domain so that every row satisfies the corresponding subclass axiom.

## 3 Multi-Hop Query Example

Question: Which pignistic transformation is supported by evidence correlated with the lift required by PCI DSS requirement Req10.2?

Walk the links:  
R001.y = L001  
L001.y = E001  
E001.x = LogFileSet  
L001.x = TransactionVolumeLift  
P001.y = L002 (different lift)  

No direct path reaches a pignistic row from R001. Instead, start from L002 (fraud lift required by R002):  
L002.y = E002  
P001.y = L002  

Resulting joined row:  
(R002, Req10.3, L002, E002, LogFileSet, P001, BetOnFraud)
