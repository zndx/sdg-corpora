# Modeling PCI DSS Compliance Evidence Structures

This chapter defines five relational tables that instantiate the ontological templates pci_dss_requirement, lift_with_baseline_rate, evidence_correlated_with, pignistic_transformation, and evidence_independent_of. The tables capture directive and descriptive information content entities used in PCI DSS audit evidence chains. Primary and foreign keys enforce the slot restrictions stated in each axiom, enabling cross-table joins that resolve multi-hop queries over requirements, baseline rates, correlations, transforms, and independence assertions.

## 1. Schema Overview and Domain Grounding

The tables are populated with audit records drawn from cardholder data environment assessments. Each row satisfies the Manchester axioms by construction: class references occupy the X and Y slots, and foreign-key values are drawn exclusively from the referenced primary-key domains. The resulting graph supports queries that traverse directive requirements into descriptive evidence structures and back.

## 2. Cross-Join Demonstration

To answer the query “which PCI DSS requirement is supported by evidence correlated with the baseline rate that itself references the lift produced by quarterly scanning,” join t_pci_dss_requirement to t_lift_with_baseline_rate on y = id, then to t_evidence_correlated_with on y = id. The path R001 → L001 → E001 yields the joined row (R001, Req11.2, L001, QuarterlyScanLift, E001, ASVScanFinding). A second path R002 → L002 → E002 produces (R002, Req6.2, L002, PatchComplianceLift, E002, FirewallRuleReview). Both results are obtained solely by following declared foreign-key constraints.
