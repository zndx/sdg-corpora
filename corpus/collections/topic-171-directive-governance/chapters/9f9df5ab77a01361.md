# Directive Governance Axioms in Municipal Audit Systems

This chapter presents five relational tables that instantiate OWL axioms for directive governance processes. The tables capture audit periods, attestations, conduct, verification evidence, and requirement specifications. Primary keys ensure unique process identification while selected columns function as foreign keys to enable joins across governance entities.

## 1 Schema Structure and Axiom Embodiment

### 1.1 Audit Period Linkage
The table t_audit_for_period embodies AXIOM 1 by recording processes that occur for a defined audit period. Column id serves as primary key; column y acts as foreign key referencing requirement identifiers in t_requirement_equiv_specifies_target.

| id | x | y |
| id | x | y |
| audit_2014_budget | MunicipalBudgetReview | req_budget_intro |
| audit_2014_proclamations | ProclamationCompliance | req_proclamation_signoff |
| audit_covid_food | FoodProcessingAudit | req_food_distribution |
| audit_knights_columbus | CommunityOrganizationReview | req_organization_attest |

### 1.2 Attestation Requirement
The table t_attestation_min_one_signer embodies AXIOM 2 by ensuring each listed process carries at least one signer. Column id serves as primary key with no foreign keys present.

| id | x |
| id | x |
| attest_budget | MunicipalBudgetReview |
| attest_proclamations | ProclamationCompliance |
| attest_covid | FoodProcessingAudit |
| attest_knights | CommunityOrganizationReview |
| attest_autism | NationalAwarenessDeclaration |

### 1.3 Conduct Attribution
The table t_audit_conducted_by embodies AXIOM 3 by associating each process with a conducting person. Column id serves as primary key; column x functions as foreign key to process identifiers in t_audit_for_period.

| id | x |
| id | x |
| conduct_budget | audit_2014_budget |
| conduct_proclamations | audit_2014_proclamations |
| conduct_covid | audit_covid_food |
| conduct_knights | audit_knights_columbus |

### 1.4 Evidence Production
The table t_verification_min_one_evidence embodies AXIOM 4 by linking each verification process to at least one evidence class. Column id serves as primary key; column x functions as foreign key to process identifiers in t_attestation_min_one_signer while column y references external evidence entities.

| id | x | y |
| id | x | y |
| verify_budget | attest_budget | SignedMinutesMarch2014 |
| verify_proclamations | attest_proclamations | CouncilResolutionRecord |
| verify_covid | attest_covid | MoFPI_Secretary_Letter |
| verify_knights | attest_knights | KnightsOfColumbusCharter |

### 1.5 Requirement Specification
The table t_requirement_equiv_specifies_target embodies AXIOM 5 by capturing directives that both specify an object and apply to a target class. Column id serves as primary key; columns y and z serve as foreign keys to period and subject entities respectively.

| id | x | y | z |
| id | x | y | z |
| req_budget_intro | 2014MunicipalBudgetDirective | 2014_Fiscal_Year | TownshipCouncil |
| req_proclamation_signoff | ProclamationDirective | April_2014_Meeting | CouncilMembers |
| req_food_distribution | EssentialGoodsDirective | COVID_Lockdown_Period | FoodProcessingUnits |
| req_organization_attest | CommunityReviewDirective | 2014_Calendar_Year | LocalOrganizations |

## 2 Cross-Join Demonstration

To determine the signer and evidence for the budget audit conducted during the 2014 fiscal year, join t_audit_for_period (y = req_budget_intro) to t_audit_conducted_by on x, then to t_attestation_min_one_signer on x, then to t_verification_min_one_evidence on x. The resulting row yields: MunicipalBudgetReview, conducted by conduct_budget, attested under attest_budget, producing evidence SignedMinutesMarch2014.
