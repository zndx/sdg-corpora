# Chapter 7: Directive Governance Ontologies in Municipal Audit Trails

This chapter presents five relational tables that implement the directive-governance family of OWL axioms. The tables record audit processes, their temporal bounds, signatories, conductors, evidence outputs, and requirement specifications. All column values are drawn from the slot types declared in the axioms; foreign-key references between tables enable reconstruction of multi-hop governance facts.

## 1. Table Definitions and Axiom Embodiment

### 1.1 t_audit_for_period
This table embodies AXIOM 1 by associating each audit process identifier (x) with exactly one audit period class (y). Column id is the primary key; column x functions as a foreign key that may be joined to the x columns of t_attestation_min_one_signer, t_audit_conducted_by and t_verification_min_one_evidence.

| id | x | y |
| id | x | y |
| ap-001 | audit-2024-03 | period-Q1-2024 |
| ap-002 | audit-2024-03 | period-Q1-2024 |
| ap-003 | audit-2024-06 | period-Q2-2024 |
| ap-004 | audit-2024-09 | period-Q3-2024 |
| ap-005 | audit-2024-12 | period-Q4-2024 |
| ap-006 | audit-2025-03 | period-Q1-2025 |

### 1.2 t_attestation_min_one_signer
This table embodies AXIOM 2 by recording each attestation process (x) that must be signed by at least one person. Column id is the primary key; column x is a foreign key referencing the same process identifiers used in t_audit_for_period and t_audit_conducted_by.

| id | x |
| id | x |
| at-001 | audit-2024-03 |
| at-002 | audit-2024-06 |
| at-003 | audit-2024-09 |
| at-004 | audit-2024-12 |

### 1.3 t_audit_conducted_by
This table embodies AXIOM 3 by linking each audit process (x) to the person who conducted it. Column id is the primary key; column x is a foreign key to the process identifiers appearing in t_audit_for_period and t_attestation_min_one_signer.

| id | x |
| id | x |
| ac-001 | audit-2024-03 |
| ac-002 | audit-2024-06 |
| ac-003 | audit-2024-09 |
| ac-004 | audit-2024-12 |

### 1.4 t_verification_min_one_evidence
This table embodies AXIOM 4 by associating each verification process (x) with at least one evidence class (y). Column id is the primary key; column x is a foreign key to the process identifiers used above; column y is a foreign key to evidence classes referenced by requirement specifications.

| id | x | y |
| id | x | y |
| ve-001 | audit-2024-03 | evidence-minutes-0314 |

### 1.5 t_requirement_equiv_specifies_target
This table embodies AXIOM 5 by recording each requirement (x) that is equivalent to a DirectiveICE specifying a target class (y) and applying to a subject class (z). Column id is the primary key; columns y and z are foreign keys to classes that appear as evidence or period values in the preceding tables.

## 2. Cross-Join Demonstration

To determine the signer, conductor, evidence and requirement target for the Q1-2024 audit, the following joins are executed on the shared process identifier “audit-2024-03”:

- t_audit_for_period.x = t_attestation_min_one_signer.x  
- t_audit_for_period.x = t_audit_conducted_by.x  
- t_verification_min_one_evidence.x = t_audit_for_period.x  
- t_verification_min_one_evidence.y = t_requirement_equiv_specifies_target.y  

Resulting joined row:

audit-2024-03 | period-Q1-2024 | at-001 | ac-001 | ve-001, ve-002 | rq-001, rq-002

The row shows that the audit for period Q1-2024 was attested under identifier at-001, conducted under identifier ac-001, produced two evidence items, and satisfied two requirements whose targets are the same period.
