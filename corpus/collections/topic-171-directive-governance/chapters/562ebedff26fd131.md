# Chapter 7: Directive Governance Axioms in Municipal Audit Records

This chapter defines five relational tables that instantiate OWL axioms for processes of audit, attestation, verification, and requirement specification. The tables are populated with instances drawn from township council records for the 2014 fiscal period. Primary-key and foreign-key columns enable cross-table joins that recover multi-hop facts such as the signer of an attestation produced by an audit conducted within a stated period.

## 1 Axiom-to-Table Mapping

### 1.1 Audit Period Association

Axiom 1 states that a process class is existentially restricted to an audit period class. Table t_audit_for_period therefore records each association as a distinct row whose id serves as primary key while y holds a foreign-key reference to a period individual.

| id      | x                    | y                |
|---------|----------------------|------------------|
| AFP001  | MunicipalBudgetAudit | 2014FiscalPeriod |
| AFP002  | ProclamationAudit    | 2014FiscalPeriod |
| AFP003  | AutismAwarenessAudit | 2014Q2Period     |
| AFP004  | MinutesAdoptionAudit | 2014Q1Period     |

### 1.2 Attestation Signature Constraint

Axiom 2 requires every attestation process to be signed by at least one person. Table t_attestation_min_one_signer therefore stores the attested process identifier in column x; its id column is the primary key and no foreign key is required because the minimum-cardinality constraint is satisfied by row existence.

| id      | x                    |
|---------|----------------------|
| AMS001  | MunicipalBudgetAudit |
| AMS002  | ProclamationAudit    |
| AMS003  | AutismAwarenessAudit |
| AMS004  | MinutesAdoptionAudit |

### 1.3 Audit Conductor Assignment

Axiom 3 asserts that an audit process is conducted by a person. Table t_audit_conducted_by therefore links each audit identifier in column x to an implicit person via the row itself; id is the primary key.

| id      | x                    |
|---------|----------------------|
| ACB001  | MunicipalBudgetAudit |
| ACB002  | ProclamationAudit    |
| ACB003  | AutismAwarenessAudit |
| ACB004  | MinutesAdoptionAudit |

### 1.4 Verification Evidence Production

Axiom 4 requires a verification process to produce at least one evidence individual. Table t_verification_min_one_evidence therefore records the verification process in x and the evidence individual in y; id is the primary key and y functions as a foreign-key reference to an evidence class.

| id      | x                    | y                  |
|---------|----------------------|--------------------|
| VME001  | MunicipalBudgetAudit | BudgetResolution   |
| VME002  | ProclamationAudit    | KnightsProclamation|
| VME003  | AutismAwarenessAudit | AwarenessReport    |
| VME004  | MinutesAdoptionAudit | MarchMinutes       |

### 1.5 Requirement Specification Equivalence

Axiom 5 defines a directive class as equivalent to a conjunction of specification and target applicability. Table t_requirement_equiv_specifies_target therefore captures each such equivalence with x as the directive, y as the specified class, and z as the target class; id is the primary key while y and z are foreign-key references.

| id      | x                       | y                    | z                    |
|---------|-------------------------|----------------------|----------------------|
| REQ001  | BudgetDirective         | 2014MunicipalBudget  | TownshipCouncil      |
| REQ002  | ProclamationDirective   | KnightsOfColumbus    | NationalAwareness    |
| REQ003  | AutismDirective         | AutismAwarenessMonth | DarbhangaRegion      |
| REQ004  | MinutesDirective        | AdoptionOfMinutes    | March2014Session     |

## 2 Cross-Join Demonstration

To recover the person who conducted the audit that produced the KnightsProclamation evidence within the 2014FiscalPeriod, first select the row in t_audit_for_period where y equals 2014FiscalPeriod and x equals ProclamationAudit (AFP002). Join on x to t_audit_conducted_by to obtain ACB002, then join on x to t_verification_min_one_evidence where y equals KnightsProclamation (VME002). The resulting joined tuple is (ProclamationAudit, 2014FiscalPeriod, MayorPannullo, KnightsProclamation).
