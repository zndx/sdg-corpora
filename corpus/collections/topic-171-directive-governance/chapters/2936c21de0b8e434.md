# Directive Governance in Audit Trail Systems

This chapter defines five relational tables that realize the listed OWL axioms for processes involving audit periods, attestations, conducted audits, evidence production, and requirement specifications. The tables use shared entity references across columns to support joins that answer multi-hop governance queries.

## 1 Table t_audit_for_period

This table embodies AXIOM 1 by recording each audit process X that is defined for a specific audit period Y. Column id is the primary key; columns x and y hold entity references that serve as foreign keys to audit identifiers appearing in t_attestation_min_one_signer and t_audit_conducted_by.

| id  | x       | y              |
|-----|---------|----------------|
| AP1 | Audit_A | Period_2023Q4  |
| AP2 | Audit_B | Period_2023Q4  |
| AP3 | Audit_C | Period_2024Q1  |
| AP4 | Audit_D | Period_2024Q1  |

## 1.1 Table t_attestation_min_one_signer

This table embodies AXIOM 2 by asserting that each listed process X requires at least one signer. Column id is the primary key; column x is a foreign key referencing audit processes also recorded in t_audit_for_period and t_audit_conducted_by.

| id  | x       |
|-----|---------|
| AS1 | Audit_A |
| AS2 | Audit_B |
| AS3 | Audit_C |
| AS4 | Audit_D |

## 1.2 Table t_audit_conducted_by

This table embodies AXIOM 3 by linking each process X to the requirement that it be conducted by a person. Column id is the primary key; column x is a foreign key referencing the same audit processes used in t_audit_for_period and t_attestation_min_one_signer.

| id  | x       |
|-----|---------|
| AC1 | Audit_A |
| AC2 | Audit_B |
| AC3 | Audit_C |
| AC4 | Audit_D |

## 2 Table t_verification_min_one_evidence

This table embodies AXIOM 4 by recording each verification process X that produces at least one evidence item Y. Column id is the primary key; columns x and y hold entity references usable as foreign keys to processes and evidence artifacts.

| id  | x         | y             |
|-----|-----------|---------------|
| VE1 | Audit_A   | Evidence_Log1 |
| VE2 | Audit_B   | Evidence_Log2 |
| VE3 | Audit_C   | Evidence_Log3 |
| VE4 | Audit_D   | Evidence_Log1 |

## 2.1 Table t_requirement_equiv_specifies_target

This table embodies AXIOM 5 by capturing each directive X that specifies a requirement Y and applies to a target Z. Column id is the primary key; columns x, y, and z contain entity references that can be joined to process and period identifiers in the preceding tables.

| id  | x             | y               | z              |
|-----|---------------|-----------------|----------------|
| RT1 | Req_Dir_01    | Spec_Verify_01  | Target_BatchX  |
| RT2 | Req_Dir_02    | Spec_Verify_02  | Target_BatchY  |
| RT3 | Req_Dir_01    | Spec_Verify_01  | Target_BatchZ  |
| RT4 | Req_Dir_03    | Spec_Verify_03  | Target_BatchX  |

## 3 Cross-join example

To determine the evidence produced for Audit_A during Period_2023Q4 together with its signing requirement, join t_audit_for_period on x to t_verification_min_one_evidence on x and to t_attestation_min_one_signer on x. The join yields the row (Audit_A, Period_2023Q4, Evidence_Log1, AS1).
