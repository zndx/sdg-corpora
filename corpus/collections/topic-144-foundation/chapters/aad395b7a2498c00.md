# ISO 27001 Attestation and Audit Record Schema

This chapter defines a five-table relational schema that materializes five governance axioms. The tables record requirement equivalences, Annex A subclassifications, conducted audits, evidence-supported attestations, and period-bounded attestations. Primary and foreign keys implement the slot restrictions declared in each axiom, enabling two- and three-hop joins that recover the full attestation context for any given control.

## 1 Requirement Equivalence and Target Specification

Axiom 5 states that a DirectiveICE class is equivalent to the conjunction of a specifies relation and an appliesTo relation. Table t_requirement_equiv_specifies_target therefore stores the three class slots as columns, with id serving as primary key and y serving as foreign key into t_iso27001_annexa_subclass. A reader can join on y to retrieve the Annex A control that a requirement both specifies and applies to.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_iso27001_annexa_subclass(id)
);
```

| REQ-001 | AccessControlPolicy            | ANNEX-005 | InformationSystem  |

## 1.1 Annex A Subclass Membership

Axiom 2 declares that a DirectiveICE subclass carries an iso27001AnnexA annotation. Table t_iso27001_annexa_subclass therefore records each Annex A control identifier together with its parent requirement, using id as primary key and y as foreign key into t_requirement_equiv_specifies_target. Joining on y recovers the requirement that the control refines.

```sql
CREATE TABLE t_iso27001_annexa_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_requirement_equiv_specifies_target(id)
);
```

## 1.2 Audit Execution and Personnel Assignment

Axiom 1 states that a process is conductedBy a person. Table t_audit_conducted_by therefore stores each audit instance and its responsible person, using id as primary key. No foreign key is required by the axiom; however, subsequent tables reference these audit identifiers through the attestation chain.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 2 Evidence-Supported Attestation

Axiom 3 states that a process occurs withSupportingEvidence of a given class. Table t_attestation_with_supporting_evidence therefore records each attestation together with its evidence class, using id as primary key and y as foreign key into t_iso27001_annexa_subclass. A cross-join on y followed by a join on t_requirement_equiv_specifies_target.y yields both the control and its governing requirement.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_iso27001_annexa_subclass(id)
);
```

## 2.1 Period-Bounded Attestation

Axiom 4 states that a process occurs atAttestationPeriod of a given class. Table t_attestation_at_period therefore records each attestation together with its temporal scope class, using id as primary key and y as foreign key into t_iso27001_annexa_subclass. Joining first on y and then through t_attestation_with_supporting_evidence recovers both evidence and period for any control.

```sql
CREATE TABLE t_attestation_at_period (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_iso27001_annexa_subclass(id)
);
```

## 3 Multi-Hop Query Example

To determine the person who conducted the audit whose attestation supplies evidence for control A.9.1.1 during period 2023-07-01, execute the following joins:

1. Start at t_iso27001_annexa_subclass where x = 'A.9.1.1' → ANNEX-005.
2. Join t_attestation_with_supporting_evidence on y = ANNEX-005 → ATT-EV-200.
3. Join t_attestation_at_period on y = ANNEX-005 → ATT-PR-300.
4. Join t_audit_conducted_by on id = AUD-100 (derived from the attestation context).

Result row:  
id = ATT-EV-200, x = AuditReport-2023-Q3, y = ANNEX-005, period = 2023-07-01, conductedBy = J. Thomas Cunningham.
