# Chapter 7: Relational Projections of Directive Governance Axioms

This chapter defines five tables that instantiate OWL axioms for audit processes, ISO 27001 Annex A controls, attestations, and requirement specifications. The tables share primary and foreign keys that support cross-table queries on multi-hop relationships such as evidence-supported attestations linked to Annex A subclasses and conducted audits.

## 1 Axiom-to-Table Mapping

### 1.1 Audit Conducted By
Axiom 1 projects processes conducted by persons into a table whose primary key identifies each process instance. The column x holds the process class; no foreign key is present because the conducting person is external to the schema.

```markdown
| id                        | x                          |
|---------------------------|----------------------------|
| acb-001                   | ComplianceAudit            |
| acb-002                   | ControlReview              |
| acb-003                   | EvidenceVerification       |
| acb-004                   | AnnualAttestation          |
| acb-005                   | AnnexAWalkthrough          |
```

### 1.2 ISO 27001 Annex A Subclass
Axiom 2 projects DirectiveICE subclasses annotated with an Annex A reference. The primary key identifies the subclass; the foreign key y references t_requirement_equiv_specifies_target to link each subclass to its specifying requirement.

```markdown
| id                        | x                          | y                          |
|---------------------------|----------------------------|----------------------------|
| iaa-001                   | A.5.1Policies              | req-001                    |
| iaa-002                   | A.6.1Organization          | req-002                    |
| iaa-003                   | A.8.1AssetManagement       | req-003                    |
| iaa-004                   | A.9.1AccessControl         | req-004                    |
| iaa-005                   | A.12.1Operations           | req-005                    |
| iaa-006                   | A.14.1SystemAcquisition    | req-006                    |
```

### 1.3 Attestation With Supporting Evidence
Axiom 3 projects processes that carry supporting evidence. The primary key identifies the attestation; the foreign key y references t_iso27001_annexa_subclass to bind evidence to a concrete Annex A control.

```markdown
| id                        | x                          | y                          |
|---------------------------|----------------------------|----------------------------|
| awe-001                   | EvidenceVerification       | iaa-001                    |
| awe-002                   | EvidenceVerification       | iaa-003                    |
| awe-003                   | AnnualAttestation          | iaa-002                    |
| awe-004                   | ControlReview              | iaa-004                    |
| awe-005                   | AnnexAWalkthrough          | iaa-005                    |
```

### 1.4 Attestation At Period
Axiom 4 projects processes located at a specific attestation period. The primary key identifies the attestation; the foreign key y again references t_iso27001_annexa_subclass.

```markdown
| id                        | x                          | y                          |
|---------------------------|----------------------------|----------------------------|
| aap-001                   | AnnualAttestation          | iaa-001                    |
| aap-002                   | AnnualAttestation          | iaa-002                    |
| aap-003                   | ControlReview              | iaa-003                    |
| aap-004                   | EvidenceVerification       | iaa-004                    |
| aap-005                   | AnnexAWalkthrough          | iaa-006                    |
```

### 1.5 Requirement Equivalent Specifies Target
Axiom 5 projects DirectiveICE classes that both specify a target and apply to a scope. The primary key identifies the requirement; foreign key y references t_iso27001_annexa_subclass.

```markdown
| id                        | x                          | y                          | z                          |
|---------------------------|----------------------------|----------------------------|----------------------------|
| req-001                   | PolicyDirective            | iaa-001                    | OrganizationScope          |
| req-002                   | OrgStructureDirective      | iaa-002                    | OrganizationScope          |
| req-003                   | AssetRegisterDirective     | iaa-003                    | AssetScope                 |
| req-004                   | AccessControlDirective     | iaa-004                    | SystemScope                |
| req-005                   | OperationsDirective        | iaa-005                    | SystemScope                |
| req-006                   | AcquisitionDirective       | iaa-006                    | ProjectScope               |
```

## 2 Cross-Join Demonstration

To retrieve the Annex A subclass and its specifying requirement for an attestation that carries supporting evidence, join t_attestation_with_supporting_evidence to t_iso27001_annexa_subclass on y, then to t_requirement_equiv_specifies_target on the same column. The query path is:

t_attestation_with_supporting_evidence.y → t_iso27001_annexa_subclass.id → t_requirement_equiv_specifies_target.y

Execution on rows awe-001, iaa-001, req-001 yields the joined tuple (awe-001, EvidenceVerification, iaa-001, A.5.1Policies, req-001, PolicyDirective, OrganizationScope). This single row answers the multi-hop question “which requirement and scope apply to the evidence-supported attestation of control A.5.1?”
