# eBPF Kernel Artifact Attachment Reference

This chapter defines the attachment constraints and subclass relations among eBPF artifacts and kernel hooks. The four tables that follow are derived directly from the supplied OWL axioms and are populated with concrete program and hook instances. Primary-key and foreign-key columns permit cross-table traversal to resolve attachment cardinality, subclass membership, and attachment restrictions.

## 1 Kernel Hook Cardinality Constraint

Table t_kernelhook_max_one_program_attached embodies axiom 1 (kernelhook_max_one_program_attached). Column id is the primary key. Columns x and y are foreign-key references to artifact identifiers; the combination asserts that hook x admits at most one attached program y.

```sql
CREATE TABLE t_kernelhook_max_one_program_attached (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_kh_001 | hook_kprobe_tcp_v4_connect | prog_tcpconn_01 |
| id_kh_002 | hook_kprobe_tcp_v4_connect | prog_tcpconn_02 |
| id_kh_003 | hook_tracepoint_sched_switch | prog_sched_03 |
| id_kh_004 | hook_kretprobe_vfs_read | prog_vfsread_04 |
| id_kh_005 | hook_kprobe_skb_recv | prog_skb_05 |

Table t_ebpfprogram_subclass embodies axiom 3 (ebpfprogram_subclass). Column id is the primary key. Column x is a foreign-key reference to a subclass program artifact; column y is a foreign-key reference to the hook class that the program attaches to.

```sql
CREATE TABLE t_ebpfprogram_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
```

## 4 eBPF Program Attachment Restriction

Table t_ebpfprogram_only_attached_to_kprobe embodies axiom 4 (ebpfprogram_only_attached_to_kprobe). Column id is the primary key. Column x is a foreign-key reference to a program artifact; column y is a foreign-key reference to the sole permitted hook class.

```sql
CREATE TABLE t_ebpfprogram_only_attached_to_kprobe (
```

## 5 Cross-Join Example

To determine which programs may attach to hook_kprobe_tcp_v4_connect and whether any cardinality violation exists, join t_ebpfprogram_subclass on y, t_kernelhook_max_one_program_attached on x, and t_ebpfprogram_only_attached_to_kprobe on x. The join yields:

- prog_tcpconn_01 attaches to hook_kprobe_tcp_v4_connect (subclass row id_sub_001), satisfies max-one constraint (kh_001), and is restricted to kprobe (only_001).
- prog_tcpconn_02 also attaches to the same hook (id_sub_002) yet appears in a second max-one row (kh_002), indicating a cardinality violation that must be resolved by detaching one program.
