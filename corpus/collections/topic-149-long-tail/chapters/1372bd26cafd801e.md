# eBPF Artifact Attachment Constraints

This chapter specifies four relational tables that encode attachment cardinality and scoping constraints between eBPF programs and kernel hooks. Each table directly implements one Manchester axiom, with identifiers serving as stable references to artifact classes. Primary keys ensure uniqueness of each constraint instance; foreign-key-style references in columns x and y enable cross-table joins that recover allowed attachment configurations.

## 1 Kernel-Hook Cardinality Table

Table t_kernelhook_max_one_program_attached embodies axiom kernelhook_max_one_program_attached. Column id is the primary key. Columns x and y are entity references; x identifies the kernel hook artifact while y identifies the single permitted program class. A reader can join on x to determine whether a given hook already carries its maximum attachment.

```
CREATE TABLE t_kernelhook_max_one_program_attached (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_kh_01 | kprobe/sys_enter | prog_trace_enter |
| id_kh_02 | kprobe/sys_exit | prog_trace_exit |
| id_kh_03 | tracepoint/sched_switch | prog_sched_switch |
| id_kh_04 | perf_event/cpu_clock | prog_perf_clock |
| id_kh_05 | kprobe/tcp_v4_connect | prog_tcp_connect |

## 2 eBPF Program Attachment Cross-Reference Table

Table t_ebpfprogram_attaches_kernelhook_xref embodies axiom ebpfprogram_attaches_kernelhook_xref. Column id is the primary key. Column x references an eBPF program artifact that participates in at least one attachment. The table supplies the minimal existence link required before subclass or restriction tables are evaluated.

```
CREATE TABLE t_ebpfprogram_attaches_kernelhook_xref (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
| id_xr_01 | prog_trace_enter |
| id_xr_02 | prog_trace_exit |
| id_xr_03 | prog_sched_switch |
| id_xr_04 | prog_perf_clock |
| id_xr_05 | prog_tcp_connect |
| id_xr_06 | prog_kretprobe_file |

## 3 eBPF Program Subclass Attachment Table

Table t_ebpfprogram_subclass embodies axiom ebpfprogram_subclass. Column id is the primary key. Column x references the program class; column y (NOT NULL) references the concrete kernel hook class to which the program attaches. The foreign-key relationship between x and t_ebpfprogram_attaches_kernelhook_xref.x together with y permits verification that every declared subclass attachment corresponds to an existing program.

```
CREATE TABLE t_ebpfprogram_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_sc_01 | prog_trace_enter | kprobe/sys_enter |
| id_sc_02 | prog_trace_exit | kprobe/sys_exit |
| id_sc_03 | prog_sched_switch | tracepoint/sched_switch |
| id_sc_04 | prog_perf_clock | perf_event/cpu_clock |
| id_sc_05 | prog_tcp_connect | kprobe/tcp_v4_connect |
| id_sc_06 | prog_kretprobe_file | kretprobe/vfs_read |

## 4 eBPF Program Restriction Table

Table t_ebpfprogram_only_attached_to_kprobe embodies axiom ebpfprogram_only_attached_to_kprobe. Column id is the primary key. Column x references the program class; column y references the sole permitted hook class. The structure supports a join against t_ebpfprogram_subclass on x to confirm that every recorded attachment satisfies the universal restriction.

```
CREATE TABLE t_ebpfprogram_only_attached_to_kprobe (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x | y |
| id_rs_01 | prog_trace_enter | kprobe/sys_enter |
| id_rs_02 | prog_trace_exit | kprobe/sys_exit |
| id_rs_03 | prog_tcp_connect | kprobe/tcp_v4_connect |
| id_rs_04 | prog_kretprobe_file | kretprobe/vfs_read |

## 5 Cross-Join Example

To determine the hook and cardinality limit for program prog_trace_enter, first locate its attachment record in t_ebpfprogram_attaches_kernelhook_xref, then retrieve the subclass hook from t_ebpfprogram_subclass and the restriction from t_ebpfprogram_only_attached_to_kprobe, finally confirming the single-attachment rule via t_kernelhook_max_one_program_attached on the hook value. The joined result is:

prog_trace_enter attaches exclusively to kprobe/sys_enter; that hook permits at most one program (prog_trace_enter).
