# Ontological Foundations of Compliance Artifacts

This chapter defines five OWL-derived concepts that govern the representation of organizations, claims, directives, and product attributes. The concepts are projected into a fixed relational schema whose foreign-key constraints enforce the subclass and property restrictions stated in the axioms. All instances satisfy the Manchester syntax restrictions; cross-table joins therefore retrieve only axiom-compliant tuples.

## 1 Schema Projection and Table Definitions

Each table corresponds to one axiom. Primary-key columns uniquely identify individuals; foreign-key columns realize the existential and cardinality restrictions.

### 1.1 t_outlier_claim_min_one_attribute

Axiom 2 states that every descriptive information content entity must possess at least one attribute set. The table therefore stores the entity identifier (primary key `id`), the entity class (`x`), and a mandatory reference (`y`) to a tax-identifier record. The foreign-key constraint guarantees the minimum cardinality.

```sql
SELECT oc.x, ot.y
FROM   t_outlier_claim_min_one_attribute oc
JOIN   t_schemaorg_org_taxid ot ON oc.y = ot.id;
```

### 1.2 t_schemaorg_org_taxid

Axiom 1 classifies an artifact by the existence of a tax identifier. The table records the artifact class (`x`) and the required tax-identifier reference (`y`), which points back to an outlier claim, closing the mutual existential dependency between the two tables.

```sql
SELECT so.x, oc.x
FROM   t_schemaorg_org_taxid so
JOIN   t_outlier_claim_min_one_attribute oc ON so.y = oc.id;
```

### 1.3 t_iso27001_clause_subclass

Axiom 3 asserts that a directive information content entity is further specified by an ISO 27001 clause. The foreign key `y` links each directive to an outlier claim that supplies the required attribute set.

```sql
SELECT ic.x, oc.x
FROM   t_iso27001_clause_subclass ic
JOIN   t_outlier_claim_min_one_attribute oc ON ic.y = oc.id;
```

### 1.4 t_schemaorg_product_price

Axiom 5 requires every artifact that is a product to carry a price. The foreign key again resolves to an outlier claim, ensuring the price datum participates in the same descriptive context as the tax identifier.

```sql
SELECT sp.x, oc.x
FROM   t_schemaorg_product_price sp
JOIN   t_outlier_claim_min_one_attribute oc ON sp.y = oc.id;
```

### 1.5 t_attribute_set_min_one

Axiom 4 declares that a descriptive information content entity must contain at least one designative information content entity. Because the restriction is internal, the table contains only an identifier and the entity class; no foreign key is required.

## 2 Worked Multi-Hop Query

Question: “Which ISO 27001 clause governs the priced product whose organization carries tax identifier ‘FR-774-129’?”

Resolution proceeds through three tables:

1. Locate the tax identifier in `t_schemaorg_org_taxid`.
2. Follow its foreign key to the outlier claim in `t_outlier_claim_min_one_attribute`.
3. Follow that claim’s foreign key from `t_iso27001_clause_subclass`.

Resulting joined row:

- Organization artifact: `schemaorg:Organization`
- Tax identifier: `FR-774-129`
- Outlier claim: `sdg:OutlierClaim_42`
- ISO 27001 clause: `iso27001:Clause_A12.4.1`
- Product: `schemaorg:Product`
- Price: `1240.00 EUR`
