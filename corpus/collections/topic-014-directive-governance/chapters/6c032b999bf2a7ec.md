# Chapter 4: Ontological Structures for Anomaly Detection and Metric Governance

## 4.1 Scope and Regulatory Context

This chapter delineates the formal ontological structures required to classify descriptive information content entities (ICE) within a high-frequency trading and risk management environment. In accordance with the Basic Formal Ontology (BFO) upper-level structure and the Common Core Ontologies (CCO), the definitions provided herein establish the necessary semantic rigor for audit trails, compliance reporting, and automated governance protocols. The mapping of these axioms to relational schemas ensures that system-generated alerts, outlier claims, and metric emissions are anchored in a deterministic data model, facilitating both forensic analysis and real-time monitoring. As regulatory frameworks increasingly demand evidence-anchored provenance for algorithmic decision-making, the precise articulation of these concepts serves as a foundational requirement for system certification.

## 4.2 Outlier Claims with Minimum Attribute Constraints

### 4.2.1 Conceptual Definition

The concept of an `outlier_claim_min_one_attribute` represents a specialized subclass of descriptive information content entities (DescriptiveICE) that serves as a formal assertion of deviation from expected operational parameters. Unlike basic descriptive claims, this entity is structurally constrained to possess a minimum of one attribute set, ensuring that any outlier identification is not merely a null assertion but is accompanied by qualifying metadata. In the context of systems governance, this axiom enforces data integrity by mandating that any claim of an anomaly must be intrinsically linked to a specific, observable attribute or triggering event. This structure prevents the generation of orphaned exception records within the audit log, thereby maintaining the chain of custody for risk-related data.

## 4.3 Alert Triggering Mechanisms

### 4.3.1 Conceptual Definition

The `alert_triggered_by` axiom defines a process-oriented entity (`X`) that is instantiated as a direct consequence of a specific metric (`Y`). Formally, this class is a subclass of `bfo:0000015` (a process), which implies that it represents an occurrence or change in state rather than a static object. The verbalization "{X} is something that triggered by metric {Y}" establishes a causal chain where the metric acts as the antecedent condition for the alert process. In a governance framework, this distinction is vital for root cause analysis; it separates the signal (the metric) from the response mechanism (the alert process). By defining the alert as a process dependent on a metric, the ontology captures the dynamic nature of system monitoring, where thresholds are evaluated and state transitions occur.

### 4.3.2 Relational Implementation and Evidence

The schema for `t_alert_triggered_by` (Table 4.2) enforces a circular dependency with the outlier claims table, a design choice that reflects the closed-loop nature of anomaly detection systems. Here, the alert process (`x`) is triggered by a metric (`y`), which in turn is identified as an outlier claim. This recursive reference ensures that the system can trace an alert back to the specific metric deviation that caused it, while that metric retains a link back to the alert as its attribute.

## 4.4 Basic Outlier Claims

### 4.4.1 Conceptual Definition

The `outlier_claim_basic` axiom provides the foundational definition for the simplest unit of anomaly reporting: a descriptive information content entity without the complex attribute constraints found in the specialized subclass. While it shares the superclass `cco:DescriptiveICE` with the more complex claims, it serves as the base node for assertions that may not yet have a full attribute set attached or are used in contexts where the attribute linkage is implicit. This distinction allows the ontology to support both preliminary observations (basic claims) and fully substantiated anomaly reports (claims with minimum attributes). In practice, basic claims are often generated during the initial data ingestion phase, where a value is identified as statistically significant but prior to the full correlation with alerting processes.

### 4.4.2 Relational Implementation and Evidence

Table 4.3 represents the `t_outlier_claim_basic` structure. This table functions as a catalog of descriptive entities where the primary requirement is the unique identification of the claim itself. The absence of foreign key constraints in this specific table reflects its role as an independent registry of observations.

This separation of concerns ensures that the logging system remains flexible enough to capture raw anomalies without requiring immediate resolution of all relational dependencies.

## 4.5 Metric Emission Subclasses

### 4.5.1 Conceptual Definition

The `metric_emission_subclass` axiom describes a process (`X`) that is responsible for the generation or emission of a metric (`Y`). As a subclass of `bfo:0000015`, this entity is fundamentally active; it represents the mechanism by which data is produced, measured, or calculated. The relationship `emitsMetric some {Y}` indicates that the process is characterized by its output. In a technical infrastructure, this maps to telemetry sources, such as sensors, software agents, or database triggers, that output performance or state metrics. The ontological rigor here ensures that every metric in the system can be traced back to a specific emission process, which is essential for validating the authenticity of the data and for debugging the data pipeline itself.

### 4.5.2 Relational Implementation and Evidence

The relational schema for `t_metric_emission_subclass` (Table 4.4) links the emitting process to the resulting metric. The foreign key constraint directs the metric column (`y`) to the outlier claim table, positing that the output of these processes is formally classified as an outlier claim. This creates a provenance chain where the source of the anomaly is explicitly recorded.

## 4.6 Basic Aggregations

### 4.6.1 Conceptual Definition

The `aggregation_basic` axiom defines a descriptive information content entity that represents the synthesis of multiple data points into a singular summary form. As a subclass of `cco:DescriptiveICE`, it is distinct from raw observational data in that it implies a transformation function—such as summation, averaging, or histogram generation—has been applied. In the context of audit and compliance, aggregations are critical for high-level reporting, trend analysis, and resource utilization reviews. However, they also present a challenge for forensic depth; the aggregation itself is a descriptive entity that must be managed distinctly from the raw events that comprise it. This axiom provides the necessary ontology to classify these summary entities as first-class citizens within the information model.
