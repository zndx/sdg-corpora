# Chapter 4: Evidence Structures in GDPR Compliance Audit Trails

This chapter introduces five ontological templates that formalize lawful basis, evidence requirements, and claim attestation within GDPR-directed controls. The templates are realized as a five-table relational schema drawn from audit-trail records. Primary and foreign keys encode the subclass and property restrictions stated in each axiom, permitting cross-table joins that recover multi-hop compliance facts.

## 1. Schema Overview and Domain Grounding

The chosen domain is the audit trail of a data-protection supervisory authority. Each row records either a directive class, an attestation event, or a trace that supports or refutes a compliance claim. Column values are drawn from the slot types declared in the axioms; identifiers serve as stable references across tables.

## 1.1 Table t_gdpr_lawful_basis

Axiom 1 states that a class X is a subclass of cco:DirectiveICE and possesses a lawful basis Y. The table therefore stores pairs (X, Y) where Y must already exist in t_control_with_evidence_requirement. Column id is the primary key; column y is a foreign key enforcing the existential restriction.

```sql
SELECT lb.x, lb.y
FROM t_gdpr_lawful_basis lb
JOIN t_control_with_evidence_requirement c
  ON lb.y = c.id;
```

## 1.2 Table t_control_with_evidence_requirement

Axiom 2 declares that a class X is a subclass of cco:DirectiveICE and requires evidence Y. The table stores the inverse direction of the mutual restriction between the two directive templates. Column id is the primary key; column y references t_gdpr_lawful_basis.

```sql
SELECT c.x, c.y
FROM t_control_with_evidence_requirement c
JOIN t_gdpr_lawful_basis lb
  ON c.y = lb.id;
```

## 1.3 Table t_attestation_about_compliance_claim

Axiom 4 states that an attestation event X is a subclass of bfo:0000015 and attests to a descriptive claim. The table therefore contains only the identifier of the attestation and the class it concerns. Column id is the primary key.

```sql
SELECT a.id, a.x
```

## 1.4 Table t_claim_refuted_by_evidence

Axiom 3 asserts that a claim X is refuted by evidence Y. The table records each refutation and requires Y to reference an existing attestation. Column id is the primary key; column y is a foreign key into t_attestation_about_compliance_claim.

```sql
SELECT r.x, a.x AS attested_claim
FROM t_claim_refuted_by_evidence r
JOIN t_attestation_about_compliance_claim a
  ON r.y = a.id;
```

## 2. Cross-Join Demonstration

Consider the multi-hop question: “Which lawful-basis control is attested by an event that is not refuted by any finding?” The following join walks from t_gdpr_lawful_basis through t_control_with_evidence_requirement, then links the resulting claim class to t_attestation_about_compliance_claim and excludes rows present in t_claim_refuted_by_evidence.

```sql
SELECT lb.x AS lawful_basis,
       c.x AS control,
       a.x AS attested_claim
FROM t_gdpr_lawful_basis lb
JOIN t_control_with_evidence_requirement c ON lb.y = c.id
JOIN t_attestation_about_compliance_claim a ON a.x = lb.x
LEFT JOIN t_claim_refuted_by_evidence r ON r.y = a.id
WHERE r.id IS NULL;
```

Result row (abridged):

lawful_basis: ConsentProcessing  
control: ConsentProcessing  
attested_claim: DataRetentionClaim

The absence of a matching row in t_claim_refuted_by_evidence confirms that the attestation remains unrebutted.
