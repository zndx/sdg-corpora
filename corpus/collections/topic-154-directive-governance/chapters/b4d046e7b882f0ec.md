# Chapter 7: Directive ICEs and Evidence Chains in GDPR Compliance Records

This chapter defines five core ontological templates that structure lawful-basis assertions, evidence requirements, and attestation traces. The templates are realized as a five-table schema that supports multi-hop joins between directive classes and descriptive claims.

## 1 Scope and Table Overview

The schema records how a processing activity obtains a lawful basis, how that basis imposes evidence requirements on controls, and how attestations or traces confirm or refute resulting compliance claims. All columns are populated with class references drawn from the BFO/CCO upper ontology and the SDG compliance extension. Primary keys are opaque identifiers; foreign keys encode the “some” restrictions stated in each axiom.

### 1.1 t_gdpr_lawful_basis

Axiom 1 states that a subclass of cco:DirectiveICE possesses a lawful basis. The table therefore stores pairs of class references; column id is the primary key while y is a foreign key into t_control_with_evidence_requirement, allowing a lawful-basis row to be joined directly to the control that operationalizes the chosen basis.

| id | x | y |
|---|---|---|
| lb-001 | ResearchDataProcessing | ctl-010 |
| lb-002 | MarketingOutreach | ctl-011 |
| lb-003 | EmployeeMonitoring | ctl-012 |
| lb-004 | ClinicalTrialRecruitment | ctl-010 |

### 1.2 t_control_with_evidence_requirement

Axiom 2 states that a subclass of cco:DirectiveICE requires evidence of a particular type. Column id is the primary key; y is a foreign key back into t_gdpr_lawful_basis, closing the mutual restriction between lawful basis and required evidence.

| id | x | y |
|---|---|---|
| ctl-010 | ConsentRecordRetention | lb-001 |
| ctl-011 | OptOutRegistryMaintenance | lb-002 |
| ctl-012 | AccessLogArchiving | lb-003 |
| ctl-013 | DataMinimizationAudit | lb-004 |

### 1.3 t_claim_refuted_by_evidence

Axiom 3 states that a subclass of cco:DescriptiveICE is refuted by evidence. Column id is the primary key; y is a foreign key into t_attestation_about_compliance_claim, linking a refuted claim to the attestation that supplies the refuting evidence.

| id | x | y |
|---|---|---|
| ref-020 | OverRetentionClaim | att-100 |
| ref-021 | MissingConsentClaim | att-101 |
| ref-022 | UnauthorizedDisclosureClaim | att-102 |

### 1.4 t_attestation_about_compliance_claim

Axiom 4 states that an instance of bfo:0000015 attests to a descriptive ICE. The table therefore contains only an identifier and the class that performs the attestation; no foreign key is required.

| id | x |
|---|---|
| att-100 | InternalAuditReport2021 |
| att-101 | ExternalDPOReviewQ3 |
| att-102 | RegulatorInspectionNotice |

### 1.5 t_trace_supports_claim

Axiom 5 states that an instance of bfo:0000015 supports a descriptive ICE. The table likewise stores only the identifier and the supporting class.

| id | x |
|---|---|
| trc-200 | ProcessingLogExport |
| trc-201 | SubjectAccessRequestArchive |
| trc-202 | DeletionCertificateSet |

## 2 Cross-Join Demonstration

To determine whether a lawful basis for research data processing is supported by an attestation that has not been refuted, the following mental join is performed:

- Start at t_gdpr_lawful_basis row lb-001 (x = ResearchDataProcessing, y = ctl-010).  
- Follow y into t_control_with_evidence_requirement to obtain ctl-010.  
- From ctl-010 follow its own y back to lb-001 (cycle confirms mutual restriction).  
- Separately, locate ref-020 (x = OverRetentionClaim, y = att-100) in t_claim_refuted_by_evidence.  
- Join att-100 to t_attestation_about_compliance_claim to confirm the attestation class InternalAuditReport2021.

The resulting joined tuple (ResearchDataProcessing, ConsentRecordRetention, InternalAuditReport2021, not-refuted) answers the multi-hop question “which processing activity possesses a lawful basis whose required control is attested by an unrebutted report?”
