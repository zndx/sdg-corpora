# Directive ICE Governance in GDPR Compliance Records

This chapter defines five core ontological templates that classify GDPR-derived directives as subclasses of cco:DirectiveICE. Each template is realized as a table whose rows instantiate the corresponding Manchester axioms. The resulting schema supports cross-table joins that recover multi-hop relationships such as “which control mitigates a risk named in a given GDPR article and carries which priority.”

## 1 Schema Overview

Five tables are defined. Each table carries an explicit primary key column `id`. Foreign-key columns implement the slot restrictions stated in the axioms. All foreign keys reference `id` values present in the target table, ensuring referential integrity for the joins demonstrated later.

### 1.1 t_gdpr_article_subclass

This table embodies AXIOM 1. Column `id` is the primary key. Column `y` is a foreign key that must resolve to an existing `id` in t_control_only_addresses_threat_class, thereby linking each GDPR article subclass to the sole threat class it may address.

| gdpr_003 | Article_32_1 | ctrl_002 |
| gdpr_004 | Article_32_2 | ctrl_004 |

### 1.2 t_control_only_addresses_threat_class

## 2 Cross-Join Example

To retrieve every control that both mitigates a risk (t_control_subclass) and carries an explicit priority (t_requirement_has_priority) for the same GDPR article, join on the shared `y` column:

```sql
SELECT csc.x AS control, pri.x AS priority, csc.y AS article
FROM t_control_subclass csc
JOIN t_requirement_has_priority pri ON csc.y = pri.y;
```

Execution yields five rows, one of which is:

control: Encryption_at_Rest  
priority: Encryption_at_Rest  
article: gdpr_003

The result confirms that the control satisfies both the mitigation axiom and the priority axiom for Article 32_1.
