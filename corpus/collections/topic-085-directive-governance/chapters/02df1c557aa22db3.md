# Chapter 4. Relational Encodings of Directive ICE Subclass Axioms for GDPR Article Compliance

This chapter specifies five tables that instantiate the Manchester OWL axioms for Directive ICE entities under GDPR. The tables encode subclass relations, risk-addressing restrictions, mitigation properties, and priority assertions. Primary and foreign keys enforce the slot restrictions given in each axiom, permitting cross-table joins that recover multi-hop compliance derivations.

## 1. Scope and Table Construction Principles

The schemas follow directly from the slot types of the five axioms. Each table contains an identifying primary key together with two class-valued columns. Foreign-key constraints implement the existential and universal quantifiers present in the original Manchester expressions. Four to eight rows per table suffice to illustrate valid instance combinations while preserving referential integrity.

## 1.1 Table t_gdpr_article_subclass

Axiom 1 states that any instance of the class variable X is a subclass of cco:DirectiveICE and stands in the relation gdprArticle to an instance of Y. The primary key id uniquely identifies each such subclass assertion. The column y is a foreign key into t_control_only_addresses_threat_class, ensuring that every GDPR article reference resolves to a control that addresses threats only.

## 2. Cross-Join Derivation Example

To recover the priority of the control that only addresses the threat linked to Article 5(1), join t_gdpr_article_subclass to t_control_only_addresses_threat_class on y = id, then to t_requirement_has_priority on x = x. The join yields:

gdpr_001, Article5_1, ctl_010, EncryptionAtRest, pri_001, High

The resulting tuple shows that EncryptionAtRest satisfies the universal restriction of Axiom 2, the existential of Axiom 3, the mitigation of Axiom 4, and carries the priority asserted by Axiom 5 for the article identified by Axiom 1.
