# Directive Governance and Evidence Chains in Regulatory Compliance

This chapter defines five core ontological patterns for modeling attestations, controls, and verifications under PCI DSS and HIPAA regimes. Each pattern is realized as a relational table whose foreign-key graph supports multi-hop queries over evidence provenance.

## 1 Attestation with Supporting Evidence

The table t_attestation_with_supporting_evidence embodies AXIOM 1. Column id is the primary key. Column y is a foreign key into t_pci_dss_requirement, establishing that every attestation instance must reference a concrete requirement. A reader can join on y to retrieve the requirement identifier that grounds any given attestation.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_pci_dss_requirement(id)
);
```

| id | x | y |
|----|---|---|
| att-001 | Quarterly Attestation Report Q3 | req-12 |
| att-002 | Quarterly Attestation Report Q3 | req-14 |
| att-003 | Annual Self-Assessment | req-12 |
| att-004 | Incident Response Attestation | req-09 |
| att-005 | Vendor Onboarding Attestation | req-14 |

## 2 PCI DSS Requirement

The table t_pci_dss_requirement embodies AXIOM 2. Column id is the primary key. Column y is a foreign key into t_control_with_evidence_requirement, linking each PCI DSS requirement to the control that supplies its evidence mandate. A reader can traverse y to locate the controlling directive for any requirement.

```sql
CREATE TABLE t_pci_dss_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_with_evidence_requirement(id)
);
```

| id | x | y |
|----|---|---|
| req-09 | Maintain an information security policy | ctl-03 |
| req-12 | Protect stored cardholder data | ctl-01 |
| req-14 | Track and monitor all access | ctl-02 |
| req-15 | Regularly test security systems | ctl-04 |

## 3 Control with Evidence Requirement

The table t_control_with_evidence_requirement embodies AXIOM 3. Column id is the primary key. Column y is a foreign key into t_pci_dss_requirement, closing the bidirectional governance link between controls and requirements. A reader can join on y to confirm which requirement a control is obligated to evidence.

```sql
CREATE TABLE t_control_with_evidence_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_pci_dss_requirement(id)
);
```

| id | x | y |
|----|---|---|
| ctl-01 | Access Control Policy | req-12 |
| ctl-02 | Logging and Monitoring Standard | req-14 |
| ctl-03 | Policy Governance Framework | req-09 |
| ctl-04 | Vulnerability Management Procedure | req-15 |

## 4 HIPAA Safeguard Physical

The table t_hipaa_safeguard_physical embodies AXIOM 4. Column id is the primary key. Column y is a foreign key into t_control_with_evidence_requirement, extending the control graph to physical safeguards required by HIPAA. A reader can join on y to determine which control supplies evidence for a given physical safeguard.

```sql
CREATE TABLE t_hipaa_safeguard_physical (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_with_evidence_requirement(id)
);
```

| id | x | y |
|----|---|---|
| hip-01 | Facility Access Controls | ctl-01 |
| hip-02 | Workstation Use Policies | ctl-02 |
| hip-03 | Device and Media Controls | ctl-03 |
| hip-04 | Physical Security Perimeter | ctl-04 |

## 5 Verification Produces Evidence

The table t_verification_produces_evidence embodies AXIOM 5. Column id is the primary key. Column y is a foreign key into t_pci_dss_requirement, recording that each verification process yields evidence for a specific requirement. A reader can join on y to list all verification events that have produced evidence for any given requirement.

```sql
CREATE TABLE t_verification_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_pci_dss_requirement(id)
);
```

| id | x | y |
|----|---|---|
| ver-01 | Quarterly ASV Scan | req-15 |
| ver-02 | Policy Review Walkthrough | req-09 |
| ver-03 | Access Log Audit | req-14 |
| ver-04 | Encryption Validation Test | req-12 |
| ver-05 | Annual Penetration Test | req-15 |

## 6 Cross-Join Demonstration

To answer “which physical safeguard supplies evidence for the PCI DSS requirement that is attested in att-001?”, traverse the foreign-key chain:

- att-001.y = req-12  
- req-12.y = ctl-01  
- ctl-01.id is referenced by hip-01.y
