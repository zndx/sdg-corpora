# Modeling Directive Governance and Evidence Requirements in Compliance Systems

This chapter defines five ontological templates that capture directed governance relations among compliance artifacts. Each template is realized as a table whose foreign-key constraints encode the existential restrictions stated in the corresponding Manchester axioms. The resulting schema supports multi-hop queries that traverse requirement–control–evidence chains.

## 1 Scope and Table Overview

Five tables implement the axioms. Primary keys are opaque identifiers. Foreign keys enforce the “some” restrictions and permit the reader to reconstruct, for any given control, the PCI DSS requirement it satisfies, the evidence it demands, and the verifications that produce that evidence.

## 1.1 t_pci_dss_requirement

Axiom 2 states that a directive is something that pci dss requirement some other directive. The table therefore stores pairs whose y column is a foreign key into t_control_with_evidence_requirement, making every PCI DSS requirement traceable to exactly one controlling directive.

## 2 Cross-Join Example

Question: Which HIPAA physical safeguard supplies evidence for the PCI DSS requirement that is attested by the Annual ROC Attestation?

Start at ATT-100 (y = REQ-001).  
Join REQ-001 (y = CTL-010).  
Join HPS-020 and HPS-022 (both reference CTL-010).  

Result rows:  
(ATT-100, REQ-001, CTL-010, HPS-020, “Facility Access Control”)  
(ATT-100, REQ-001, CTL-010, HPS-022, “Device and Media Controls”)
