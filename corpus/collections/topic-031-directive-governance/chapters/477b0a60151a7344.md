# Chapter 12. Modeling Protocol Compliance and Kernel Subsystem Verification

This chapter defines five relational tables that instantiate the slot structures of five OWL axioms governing laboratory runs, security-tiered syscalls, NIST control subclasses, syscall subsystem equivalence, and verified eBPF artifacts. The tables share primary-key identifiers that function as entity references, enabling deterministic cross-table joins that recover multi-hop facts such as the security tier of a protocol followed by a verified eBPF program.

## 1. Axiom Projection into Schema

Each table directly encodes one axiom. Column “id” is the primary key. Column “y” is a foreign key in four tables and participates in the single permitted cycle between the first two tables. Column “x” holds the subject class of the axiom. All foreign-key values are drawn from the id column of the referenced table, guaranteeing referential integrity.

### 1.1 Table t_labrun_with_protocol

This table embodies Axiom 1 (labrun_with_protocol). Its primary key is id; column y is a foreign key to t_syscall_at_security_tier.id. A reader can join on y to retrieve the security tier of the protocol followed by any laboratory run.

```sql
CREATE TABLE t_labrun_with_protocol (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_syscall_at_security_tier(id)
);
```

| LRP001 | LabRun_EBPF_Verify         | SAT003  |
| LRP002 | LabRun_NIST_Mapping        | SAT001  |

### 1.2 Table t_syscall_at_security_tier

## 2. Cross-Join Demonstration

EPS001 | eBPF_Trace_Syscall | LRP001 | LabRun_EBPF_Verify | SAT003 | Syscall_Execve_Tier4 | NCS003 | CM-7(2)
