# Compliance Ontology for Branded Artifacts and Directives

This chapter introduces three ontological subclass relations that link artifacts to brands and directives to ISO 27001 controls. The relations are realized as a minimal relational schema whose rows represent concrete instances drawn from product compliance records. Primary keys identify each assertion; shared class references in the value columns permit reconstruction of multi-hop facts such as the brand and controlling annex applicable to a given artifact.

## 1. Artifact–Brand Relation

The first axiom states that an artifact class stands in the has-brand relation to a brand class. The corresponding table records each such assertion with a surrogate identifier.

Table t_schemaorg_product_brand embodies axiom schemaorg_product_brand. Column id is the primary key. Columns x and y hold class references; no foreign-key constraint exists between this table and the ISO tables, yet values in y may be joined on literal equality with class names appearing in other tables.

| id  | x                  | y            |
|-----|--------------------|--------------|
| pb1 | Elios2             | Flyability   |
| pb2 | Elios3             | Flyability   |
| pb3 | InspectionDrone    | SenseFly     |
| pb4 | SurveyPayload      | Pix4D        |
| pb5 | SecureController   | Flyability   |

## 1.1 ISO 27001 Annex A Subclass Relation

The second axiom states that a directive class is a subclass of DirectiveICE and stands in the iso27001AnnexA relation to an Annex A control class. The table records each such assertion.

Table t_iso27001_annexa_subclass embodies axiom iso27001_annexa_subclass. Column id is the primary key. Column y references Annex A control classes that may be matched by value against other tables.

| id  | x                       | y          |
|-----|-------------------------|------------|
| ia1 | AccessControlPolicy     | A.9.1.1    |
| ia2 | EncryptionStandard      | A.10.1.1   |
| ia3 | LoggingDirective        | A.12.4.1   |
| ia4 | SupplierAssessment      | A.15.1.1   |
| ia5 | IncidentResponsePlan    | A.16.1.1   |

## 1.2 ISO 27001 Clause Subclass Relation

The third axiom states that a directive class is a subclass of DirectiveICE and stands in the iso27001Clause relation to a main-clause control class. The table records each such assertion.

Table t_iso27001_clause_subclass embodies axiom iso27001_clause_subclass. Column id is the primary key. Column y references clause classes usable for value-based joins.

| id  | x                       | y     |
|-----|-------------------------|-------|
| ic1 | AccessControlPolicy     | 9.1   |
| ic2 | EncryptionStandard      | 10.1  |
| ic3 | LoggingDirective        | 12.4  |
| ic4 | SupplierAssessment      | 15.1  |
| ic5 | IncidentResponsePlan    | 16.1  |

## 2. Cross-Table Retrieval Example

Consider the multi-hop question: “Which brand and Annex A control apply to the artifact whose directive is AccessControlPolicy?”  
Start with row ia1 in t_iso27001_annexa_subclass (x = AccessControlPolicy, y = A.9.1.1).  
Match x = AccessControlPolicy in t_schemaorg_product_brand to obtain y = Flyability.  
The joined result is the single row (AccessControlPolicy, Flyability, A.9.1.1). No additional foreign-key traversal is required; equality on the shared class literal suffices.
