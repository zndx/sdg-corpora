# Chapter 7: Modeling Artifact Branding and ISO 27001 Directive Subclasses

This chapter defines three tables that instantiate the supplied OWL axioms for artifact branding and directive subclassing under ISO 27001. The tables are populated with corporate governance and compliance records drawn from meeting agendas, attendance slips, and brand-controlled documents. Primary keys are stable identifiers; repeated class references in the y columns permit mental cross-table traversal without additional foreign-key columns.

## 1. Schemaorg Product Brand Table

The table t_schemaorg_product_brand embodies AXIOM 1. Each row states that an artifact class (x) is a subclass of cco:Artifact and stands in the sdg:hasBrand relation to a brand class (y). Column id is the primary key. Column y functions as an implicit reference target for any subsequent table whose x or y value matches a known brand class.

```markdown
| id          | x                        | y             |
|-------------|--------------------------|---------------|
| pb-001      | AttendanceSlip           | GEECEE        |
| pb-002      | GuidelinesDocument       | bp            |
| pb-003      | PayrollClassification    | GEECEE        |
| pb-004      | CourtConvenedNotice      | GEECEE        |
| pb-005      | SpecialMeetingAgenda     | bp            |
| pb-006      | BrandIdentityManual      | bp            |
```

## 1.1 Iso27001 Annexa Subclass Table

The table t_iso27001_annexa_subclass embodies AXIOM 2. Each row states that a directive class (x) is a subclass of cco:DirectiveICE and stands in the sdg:iso27001AnnexA relation to an Annex A control family (y). Column id is the primary key. Matching y values against x values in the clause table or against brand references in the product table enable two-hop navigation.

```markdown
| id          | x                        | y             |
|-------------|--------------------------|---------------|
| ia-001      | AttendanceVerification   | A.5           |
| ia-002      | DocumentControl          | A.5           |
| ia-003      | AccessReview             | A.9           |
| ia-004      | MeetingRecordRetention   | A.5           |
| ia-005      | BrandAssetHandling       | A.8           |
| ia-006      | PayrollDataProtection    | A.9           |
| ia-007      | NoticeDistribution       | A.5           |
```

## 1.2 Iso27001 Clause Subclass Table

The table t_iso27001_clause_subclass embodies AXIOM 3. Each row states that a directive class (x) is a subclass of cco:DirectiveICE and stands in the sdg:iso27001Clause relation to a numbered clause (y). Column id is the primary key. Shared class names across the three tables support the multi-hop query demonstrated in section 2.

```markdown
| id          | x                        | y             |
|-------------|--------------------------|---------------|
| ic-001      | AttendanceVerification   | 5.1           |
| ic-002      | DocumentControl          | 7.5           |
| ic-003      | AccessReview             | 9.2           |
| ic-004      | MeetingRecordRetention   | 7.5           |
| ic-005      | BrandAssetHandling       | 8.2           |
| ic-006      | PayrollDataProtection    | 9.2           |
| ic-007      | NoticeDistribution       | 5.1           |
| ic-008      | GuidelinesApproval       | 7.5           |
```

## 2. Cross-Join Demonstration

Consider the multi-hop question: “Which brand controls the artifact whose directive is governed by both Annex A.5 and Clause 5.1?”  

Start at t_iso27001_annexa_subclass row ia-001 (x = AttendanceVerification, y = A.5).  
Join on x to t_iso27001_clause_subclass row ic-001 (x = AttendanceVerification, y = 5.1).  
Join on x to t_schemaorg_product_brand row pb-001 (x = AttendanceSlip, y = GEECEE).  

The joined result row is:  
AttendanceSlip (artifact) – brand GEECEE – Annex A.5 – Clause 5.1.
