# Relational Encoding of BFO Process Axioms in Environmental Audit Trails

This chapter specifies a four-table relational schema that directly implements four OWL axioms governing processes. The schema supports cross-table joins that reconstruct evidence chains required by verification and audit activities in municipal solid-waste oversight.

## 1. Axiom-to-Table Mapping

### 1.1 Process Requiring Artifact Use

The table t_process_with_min_one_artifact embodies axiom 2. Column id is the primary key; column x holds the process class name. Every row therefore asserts the existence of at least one artifact used by the named process.

```sql
CREATE TABLE t_process_with_min_one_artifact (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| p001 | WasteManifestReview |
| p002 | EquipmentCalibration |
| p003 | SiteInspection |
| p004 | ChainOfCustodyTransfer |
| p005 | DataValidation |

### 1.2 Basic Classification Process

The table t_classification_basic embodies axiom 3. Column id is the primary key; column x records the classification process class. Rows supply the controlled vocabulary of classification activities referenced by later verification steps.

```sql
CREATE TABLE t_classification_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |

| c001 | WasteCategoryAssignment |
| c002 | HazardLevelClassification |

### 1.3 Basic Audit Process

The table t_audit_basic embodies axiom 4. Column id is the primary key; column x records the audit process class. These processes consume classification outputs and produce findings that must be verified.

```sql
CREATE TABLE t_audit_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| a001 | AnnualComplianceAudit |
| a002 | ComplaintResponseAudit |
| a003 | CorrectiveActionVerification |
| a004 | PermitRenewalReview |

### 1.4 Verification Requiring Evidence

The table t_verification_min_one_evidence embodies axiom 1. Column id is the primary key; column x names the verification process; column y is a foreign key referencing t_process_with_min_one_artifact.id. Each row therefore asserts that the verification process produces at least one evidence artifact generated by the referenced process.

```sql
CREATE TABLE t_verification_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_process_with_min_one_artifact(id)
);
```

| id | x | y |
|----|---|---|
| v001 | EvidenceCompletenessCheck | p001 |
| v002 | CalibrationRecordValidation | p002 |
| v003 | SampleIntegrityConfirmation | p003 |
| v004 | TransferLogAudit | p004 |
| v005 | ResultCrossCheck | p005 |
| v006 | FindingReconciliation | p001 |

## 2. Cross-Table Query Example

Question: Which verification steps examine evidence produced by the WasteManifestReview process that itself supports the AnnualComplianceAudit?

Join path: t_verification_min_one_evidence.y → t_process_with_min_one_artifact.id, then filter x values that participate in a001.

Result rows after join:

- v001 | EvidenceCompletenessCheck | p001 | WasteManifestReview
- v006 | FindingReconciliation | p001 | WasteManifestReview

These two verification instances therefore close the evidence loop required by the AnnualComplianceAudit.
