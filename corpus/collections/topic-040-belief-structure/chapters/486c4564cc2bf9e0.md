# Modeling Verification Processes in Regulatory Audit Systems

This chapter defines four tables that implement axioms for process classification, artifact usage, evidence production, and basic audits. The tables support cross-table queries that trace verification outcomes through linked processes and artifacts in a compliance audit domain.

## 1 Process Classification

Axiom 3 states that any instance of classification_basic is a process. Table t_classification_basic therefore stores process identifiers together with their class labels. Column id is the primary key; column x holds the class reference.

```sql
CREATE TABLE t_classification_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id       | x                          |
|----------|----------------------------|
| cls_001  | FinancialAudit             |
| cls_002  | ComplianceReview           |
| cls_003  | EvidenceVerification       |
| cls_004  | ArtifactInspection         |
| cls_005  | ReportGeneration           |

## 2 Artifact-Bound Processes

Axiom 2 states that any instance of process_with_min_one_artifact is a process that uses at least one artifact. Table t_process_with_min_one_artifact records such processes. Column id is the primary key; column x stores the process class.

```sql
CREATE TABLE t_process_with_min_one_artifact (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id       | x                          |
|----------|----------------------------|
| proc_101 | AnnualFinancialAudit       |
| proc_102 | SampleTesting              |
| proc_103 | EquipmentCalibration       |
| proc_104 | TechnicianLogReview        |
| proc_105 | DistrictComplianceCheck    |

## 3 Verification Requiring Evidence

Axiom 1 states that verification_min_one_evidence is a process that produces at least one evidence item and therefore references a process_with_min_one_artifact. Table t_verification_min_one_evidence implements the constraint. Column id is the primary key; column x holds the verification class; column y is a foreign key to t_process_with_min_one_artifact.id.

```sql
CREATE TABLE t_verification_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_process_with_min_one_artifact(id)
);
```

| id       | x                        | y        |
|----------|--------------------------|----------|
| ver_201  | EvidenceCheck            | proc_101 |
| ver_202  | ResultConfirmation       | proc_102 |
| ver_203  | CalibrationValidation    | proc_103 |
| ver_204  | LogIntegrityAudit        | proc_104 |
| ver_205  | ComplianceVerification   | proc_105 |

## 4 Basic Audit Processes

Axiom 4 states that any instance of audit_basic is a process. Table t_audit_basic stores audit process identifiers and their class labels. Column id is the primary key; column x holds the class reference.

```sql
CREATE TABLE t_audit_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id       | x                          |
|----------|----------------------------|
| aud_301  | IndependentAuditorsReport  |
| aud_302  | RegulatoryBasisReview      |
| aud_303  | SupplementaryInfoCheck     |
| aud_304  | BoardOversightAudit        |
| aud_305  | FiscalYearClose            |

## 5 Cross-Join Example

To retrieve the verification class, the linked process class, and an associated audit class for a given evidence check, join t_verification_min_one_evidence to t_process_with_min_one_artifact on y = id and then to t_audit_basic on shared domain context (proc_101 maps to aud_301). The query returns one row:

ver_201 | EvidenceCheck | proc_101 | AnnualFinancialAudit | aud_301 | IndependentAuditorsReport
