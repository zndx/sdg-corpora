# Regulatory Audit Processes in Environmental Compliance Systems

This chapter defines four process classes drawn from a BFO-aligned ontology and shows how their slot restrictions are realized in a minimal relational schema. The schema supports verification that every audit process uses at least one artifact and that verification steps produce at least one evidence artifact. All examples are taken from county-level solid-waste compliance records.

## 1 Ontology-to-Relation Mapping

The four axioms project directly onto four tables. Primary-key columns hold stable identifiers for process instances. Foreign-key columns encode the existential restrictions stated in the axioms.

### 1.1 t_process_with_min_one_artifact

This table embodies Axiom 2. Column id is the primary key. Column x stores the process class that must use at least one artifact. Every row therefore satisfies the minimum cardinality on the uses relation.

```sql
CREATE TABLE t_process_with_min_one_artifact (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| p001 | AnnualWasteAudit |
| p002 | SampleChainOfCustody |
| p003 | EquipmentCalibrationCheck |
| p004 | ManifestReview |
| p005 | QuarterlyVolumeReconciliation |

### 1.2 t_classification_basic

This table embodies Axiom 3. Column id is the primary key. Column x stores the classification process class. No foreign keys are required because the axiom asserts only that the entity is a process.

```sql
CREATE TABLE t_classification_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| c001 | WasteTypeClassification |
| c002 | HazardCategoryAssignment |
| c003 | GeneratorStatusDetermination |
| c004 | StorageMethodClassification |

### 1.3 t_audit_basic

This table embodies Axiom 4. Column id is the primary key. Column x stores the audit process class. The table supplies candidate values for the x column of t_verification_min_one_evidence.

```sql
CREATE TABLE t_audit_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| a001 | AnnualFacilityAudit |
| a002 | ManifestCompletenessAudit |
| a003 | EquipmentLogAudit |
| a004 | VolumeReportAudit |
| a005 | TrainingRecordAudit |

### 1.4 t_verification_min_one_evidence

This table embodies Axiom 1. Column id is the primary key. Column x stores the verification process class. Column y is a foreign key referencing t_process_with_min_one_artifact.id, enforcing the requirement that verification produces at least one evidence artifact.

```sql
CREATE TABLE t_verification_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_process_with_min_one_artifact(id)
);
```

| id | x | y |
|----|---|---|
| v001 | EvidenceVerification | p001 |
| v002 | ChainOfCustodyVerification | p002 |
| v003 | CalibrationVerification | p003 |
| v004 | ManifestVerification | p004 |
| v005 | VolumeReconciliationVerification | p005 |
| v006 | TrainingVerification | p002 |

## 2 Cross-Table Query Example

Question: Which verification steps reference an artifact used by the AnnualWasteAudit process?

Walk the foreign key:

1. Locate p001 in t_process_with_min_one_artifact.
2. Find rows in t_verification_min_one_evidence whose y column equals p001.
3. Result row: v001, EvidenceVerification, p001.
