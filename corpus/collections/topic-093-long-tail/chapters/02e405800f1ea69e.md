# Directive Governance in Municipal Land Use Regulation

This chapter defines five core ontological patterns for representing directive information content entities and their spatial grounding. The patterns are realized as a five-table relational schema drawn from municipal zoning administration. Primary and foreign keys encode ownership, verification, enforcement, and checking relations, enabling cross-table queries that traverse from a directive instance through its controlling address to related requirements, policies, and constraints.

## 1. Foundational Tables and Key Constraints

### 1.1 Control Ownership Table

Axiom 2 is embodied by table t_control_min_one_owner. Column id is the primary key that uniquely identifies each directive instance. Column x stores the directive class or individual. No foreign keys exist; every subsequent table that references a directive must join on this primary key.

```sql
CREATE TABLE t_control_min_one_owner (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|---|---|
| ctrl-001 | SpecialExceptionApplication |
| ctrl-002 | ZoningVarianceDirective |
| ctrl-003 | SitePlanReviewDirective |
| ctrl-004 | ConditionalUsePermit |
| ctrl-005 | SignageComplianceDirective |

### 1.2 Place Address Table

Axiom 1 is embodied by table t_schemaorg_place_address. Column id is the primary key. Column x identifies the place artifact. Column y is a foreign key referencing t_control_min_one_owner(id), asserting that the place is governed by at least one owned directive.

```sql
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_control_min_one_owner(id)
);
```

### 1.5 Constraint Checking Table

Axiom 5 is embodied by table t_constraint_min_one_check. Column id is the primary key. Column x names the constraint directive. Column y is a foreign key referencing t_schemaorg_place_address(id), recording the place at which the check is performed.

## 2. Cross-Table Query Example

To determine the enforcement place and controlling directive for the constraint “ImperviousSurfaceRatio”, join t_constraint_min_one_check to t_schemaorg_place_address on y = id, then to t_control_min_one_owner on the address y value. The resulting row is:

- con-401, ImperviousSurfaceRatio, addr-101, 54913 Commercial Corridor, ctrl-002, ZoningVarianceDirective

This three-table traversal answers the multi-hop question “which directive owns the address that checks the impervious-surface constraint?”
