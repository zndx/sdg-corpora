# Municipal Directive Governance for Special Exception Applications

This chapter defines a minimal relational schema that implements five OWL axioms for directive information content entities. The schema supports queries that traverse ownership, verification, enforcement, and checking relationships anchored to postal addresses. All tables use entity references consistent with cco:DirectiveICE and cco:Artifact classes.

## 1 Schema Overview

The five tables realize the slot structures of the supplied axioms without extension or renaming. Primary keys are synthetic identifiers. Foreign keys enforce the minimum-cardinality restrictions expressed by the Manchester syntax axioms.

### 1.1 t_control_min_one_owner

This table embodies Axiom 2. Column id is the primary key. Column x stores the directive class that must possess at least one owner. No foreign key is present because the axiom asserts only the existence of an owner.

## 2 Cross-Join Example

To determine which verification, enforcement, and checking directives apply to the SpecialExceptionDirective at 1900 W Grand Chute Blvd, join on the foreign-key chain:

```
SELECT c.x AS directive,
       r.x AS requirement,
       p.x AS policy,
       k.x AS constraint
FROM   t_control_min_one_owner c
JOIN   t_schemaorg_place_address a ON a.y = c.id
JOIN   t_requirement_min_one_verification r ON r.y = a.id
JOIN   t_policy_min_one_enforcer p ON p.y = a.id
JOIN   t_constraint_min_one_check k ON k.y = a.id
WHERE  c.id = 'ctrl-001';
```

Result row:  
directive = SpecialExceptionDirective,  
requirement = PlanNarrativeRequirement,  
policy = CommunityDevelopmentPolicy,  
constraint = SinglePDFConstraint.
