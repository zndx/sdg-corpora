# Chapter 4: Relational Encoding of ISO 27001 Directive Subclasses and Evidence Chains

This chapter specifies a five-table schema that materializes five OWL axioms governing ISO 27001 directive subclasses, requirement equivalence, attestation, and verification. The schema supports cross-table joins that recover multi-hop provenance from requirement to annex clause to supporting evidence.

## 1 Scope and Table Overview

The tables implement the deterministic projections of axioms 1–5. Each table carries a primary key column named `id`. Foreign-key columns enforce the slot restrictions declared in the Manchester syntax. Four to eight rows per table suffice to demonstrate transitive retrieval while remaining within the bounds of a reference example.

## 1.1 t_requirement_equiv_specifies_target

Axiom 5 states that a requirement class is equivalent to a `cco:DirectiveICE` that both specifies an annex-A target and applies to a concrete scope. The table therefore stores the three slots `x`, `y`, and `z`. Column `id` is the primary key; column `y` is a foreign key into `t_iso27001_annexa_subclass(id)`.

| id | x | y | z |
|----|---|---|---|
| req-001 | AccessControlRequirement | annex-A-5.1 | AssetRegistry |
| req-002 | EncryptionRequirement | annex-A-5.2 | DataFlow |
| req-003 | LoggingRequirement | annex-A-5.3 | EventLog |
| req-004 | SupplierRequirement | annex-A-5.4 | VendorList |
| req-005 | BackupRequirement | annex-A-5.5 | StorageVolume |

## 1.2 t_iso27001_annexa_subclass

Axiom 1 asserts that each annex-A control class is a subclass of `cco:DirectiveICE` and stands in the `sdg:iso27001AnnexA` relation to a requirement target. Column `id` is the primary key; column `y` is a foreign key into `t_requirement_equiv_specifies_target(id)`.

## 2 Cross-Join Example

To retrieve the annex-A control, its governing requirement, and the verification process that produced evidence for a given scope, the following mental join is executed:

```
t_iso27001_annexa_subclass.y = t_requirement_equiv_specifies_target.id
t_verification_produces_evidence.y = t_iso27001_annexa_subclass.id
```

For scope `AssetRegistry` the join yields:

- requirement `req-001`
- annex subclass `annex-A-5.1`
- verification `ver-001`

The resulting tuple (`AccessControlRequirement`, `AnnexA5.1`, `PenetrationTest`) demonstrates that the access-control requirement is attested by an internal audit whose evidence originates from a penetration test.
