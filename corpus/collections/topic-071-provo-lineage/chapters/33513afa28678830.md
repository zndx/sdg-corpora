# Chapter 7. Modeling ISO 27001 Directives and Evidence Chains in Audit Trail Schemas

This chapter defines five relational tables that instantiate the core axioms of ISO 27001 directive subclassing, requirement equivalence, verification, and attestation. The tables support multi-hop queries that trace a requirement through its specified target, produced evidence, and supporting attestation.

## 1. Axiom Embodiment and Table Construction

The five tables are derived directly from the supplied Manchester axioms. Each table carries a primary key column named id. Foreign-key columns enforce the slot restrictions stated in the axioms and enable the cross-table joins required for evidence traceability.

### 1.1 t_requirement_equiv_specifies_target

This table embodies axiom 5. Column id is the primary key. Column y is a foreign key to t_iso27001_annexa_subclass.id; column z records the target class to which the directive applies. A reader can join this table to t_iso27001_annexa_subclass on y to retrieve the Annex A control that a given requirement specifies.

| id | x | y | z |
| id | x | y | z |
| req-001 | AccessControlRequirement | ann-001 | SystemAsset |
| req-002 | EncryptionRequirement | ann-002 | DataStore |
| req-003 | LoggingRequirement | ann-003 | AuditLog |
| req-004 | IncidentResponseRequirement | ann-004 | IncidentRecord |
| req-005 | SupplierAssessmentRequirement | ann-005 | ExternalParty |

### 1.2 t_iso27001_annexa_subclass

This table embodies axiom 1. Column id is the primary key. Column y is a foreign key to t_requirement_equiv_specifies_target.id. The table therefore records which Annex A control each requirement subclass instantiates.

## 2. Cross-Join Demonstration

To determine the clause, verification process, and attestation that together cover Annex A control A.9.1.1, execute the following mental join sequence. Start at t_iso27001_annexa_subclass where x = "A.9.1.1" (row ann-001). Follow y to t_requirement_equiv_specifies_target (row req-001) to obtain the linked clause via t_iso27001_clause_subclass (row cl-001). Return to ann-001 and follow its incoming references from t_verification_produces_evidence (row ver-001) and t_attestation_with_supporting_evidence (row att-001). The resulting joined row is:

ann-001 | A.9.1.1 | req-001 | cl-001 | Clause 9.1 | ver-001 | InternalAudit2024Q1 | att-001 | ManagementAttestationQ1
