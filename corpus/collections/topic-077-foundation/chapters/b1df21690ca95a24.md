# System Call Audit Modeling

This chapter defines two ontological templates for representing system call classes as designative information content entities and demonstrates their projection into a minimal relational schema for audit trail systems. The model supports verification of syscall classifications and their associations to audit processes through primary and foreign key linkages.

## 1 Ontological Templates

The templates are drawn directly from the supplied axioms. Each template classifies a named entity X as a subclass of cco:DesignativeICE, with the second template adding an existential restriction on the auditedBy property.

### 1.1 Basic Classification

Axiom 1 states that any X declared under syscall_basic is a designative information content entity. This captures static syscall identifiers used in kernel tracing without reference to dynamic execution context.

### 1.2 Audited Classification

Axiom 2 extends the same base classification by requiring that X is auditedBy some bfo:0000015 (a process). The restriction introduces an explicit link from the designative entity to an auditing occurrence, enabling provenance tracking in eBPF-generated logs.

## 2 Relational Projection

The axioms project to four tables that together realize the required relationships. Three tables contain foreign-key columns. Each table is preceded by a description of the axiom(s) it embodies, its key structure, and an example cross-join.

t_syscall_basic embodies axiom 1. Column id is the primary key; column x holds the class name. A reader can join this table to t_syscall_instance on x to retrieve all observed instances of a given designative class.

| id | x |
|---|---|
| sb_001 | SyscallOpen |
| sb_002 | SyscallRead |
| sb_003 | SyscallWrite |
| sb_004 | SyscallClose |

t_syscall_audited_by embodies axiom 2. Column id is the primary key; column x again holds the class name. Joining on x to t_syscall_basic confirms that only audited classes appear in this table.

| id | x |
|---|---|
| sa_001 | SyscallOpen |
| sa_002 | SyscallRead |
| sa_003 | SyscallWrite |

t_audit_process represents the bfo:0000015 process that satisfies the auditedBy restriction. Column process_id is the primary key. Column syscall_x is a foreign key referencing t_syscall_audited_by.x, establishing the existential link required by axiom 2.

| process_id | start_time | syscall_x | operator |
|---|---|---|---|
| ap_1001 | 2024-06-12T08:15:00Z | SyscallOpen | eBPF_probe |
| ap_1002 | 2024-06-12T08:15:03Z | SyscallRead | eBPF_probe |
| ap_1003 | 2024-06-12T08:15:07Z | SyscallWrite | eBPF_probe |
| ap_1004 | 2024-06-12T08:15:11Z | SyscallOpen | eBPF_probe |

t_syscall_instance stores concrete occurrences. Column instance_id is the primary key. Column syscall_x is a foreign key referencing t_syscall_basic.x; column process_id is a foreign key referencing t_audit_process.process_id. This table supplies the data needed for multi-hop queries.

| si_9001 | SyscallOpen | ap_1001 | 4721 | 2024-06-12T08:15:00.120Z |
| si_9002 | SyscallRead | ap_1002 | 4721 | 2024-06-12T08:15:03.450Z |
| si_9003 | SyscallWrite | ap_1003 | 4721 | 2024-06-12T08:15:07.810Z |

| si_9005 | SyscallClose | ap_1001 | 4721 | 2024-06-12T08:15:12.600Z |

## 3 Cross-Join Example

Question: which operator recorded the first observed SyscallRead performed by process 4721?

Walk the keys: start at t_syscall_instance where pid = 4721 and syscall_x = 'SyscallRead' (row si_9002). Follow process_id to t_audit_process (ap_1002). Read the operator column. The result is the single row (si_9002, SyscallRead, ap_1002, eBPF_probe).
