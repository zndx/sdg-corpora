# Compliance Artifacts in Organizational Records

This chapter presents five tables that encode selected ontological distinctions for compliance artifacts. The tables are derived directly from the axioms schemaorg_place_address, pci_dss_requirement, schemaorg_product_price, schemaorg_org_taxid and trace_supports_claim. Each table uses an identifier column as primary key; values in the x and y columns function as entity references that support equi-joins across tables.

## 1. Schemaorg Place Address Table

The table t_schemaorg_place_address embodies the axiom that an artifact X has postal address Y. Column id is the primary key. Columns x and y contain entity references; a join on y with an identifier from another table yields the address associated with a given organization or claim.

## 1.1 Pci Dss Requirement Table

The table t_pci_dss_requirement embodies the axiom that a directive X carries a PCI DSS requirement Y. Column id is the primary key. Column x references an organizational artifact; column y references a requirement identifier. Joining x to the x column of t_schemaorg_org_taxid links a requirement to the tax identity of the obligated organization.

| id | x | y |
| id | x | y |

## 1.2 Schemaorg Product Price Table

The table t_schemaorg_product_price embodies the axiom that an artifact X has price Y. Column id is the primary key. Column x references a product or service artifact; column y stores the monetary value. A join on x with the x column of t_schemaorg_place_address associates price information with the address of the offering organization.

## 1.3 Schemaorg Org Taxid Table

The table t_schemaorg_org_taxid embodies the axiom that an artifact X has tax identifier Y. Column id is the primary key. Column x references an organization; column y stores the tax identifier string. Joining x to the x column of t_pci_dss_requirement retrieves the tax identity of the organization subject to a given requirement.

| id | x | y |
| id | x | y |
| tst-001 | Acme Payments Inc. | 74-2841932 |

## 1.4 Trace Supports Claim Table

The table t_trace_supports_claim embodies the axiom that a process X supports a descriptive claim. Column id is the primary key. Column x references an audit trace or log artifact. Joining x to the y column of t_schemaorg_place_address or to the x column of t_pci_dss_requirement supplies the organizational context of the supported claim.

| id | x |
| id | x |
| tsc-001 | AuditLog-2023-0412 |
| tsc-002 | EvidenceBundle-19Q4 |
| tsc-003 | TraceFile-REQ-12.1 |
| tsc-004 | ScanReport-20231105 |

## 2. Cross-Table Query Example

To determine the tax identifier and PCI DSS requirement for the organization whose address is 1200 Commerce Blvd, Suite 400, Austin, TX 78701 and whose product price record references the Tokenization Module, perform the following equi-joins. First join t_schemaorg_place_address (y = "1200 Commerce Blvd, Suite 400, Austin, TX 78701") to t_schemaorg_org_taxid on x, yielding tax identifier 74-2841932. Next join the same x value to t_pci_dss_requirement, yielding requirement PCI-DSS-12.1. Finally join t_schemaorg_product_price (x = "Tokenization Module") to confirm the price 18500 USD belongs to the same organization. The resulting joined row is:

Acme Payments Inc. | 1200 Commerce Blvd, Suite 400, Austin, TX 78701 | 74-2841932 | PCI-DSS-12.1 | 18500 USD
