# Chapter 4: Relational Encodings of Artifact and Directive Slots in Payment Compliance Records

This chapter presents five tables that instantiate the slot structures of five OWL axioms drawn from the cco, sdg, and bfo namespaces. The tables record merchant organizations, their addresses and tax identifiers, product pricing, PCI DSS directive references, and process traces that support compliance claims. All column values are drawn from the slot types declared in the axioms; primary keys are synthetic identifiers while selected x and y columns function as foreign keys that permit cross-table joins.

## 1. Schemaorg Place Address Table

The table t_schemaorg_place_address embodies axiom 1 (schemaorg_place_address). Column id is the primary key. Column x references an organization identifier; column y stores the postal-address identifier. A reader can join on x to retrieve every address recorded for a given merchant.

```sql
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 1.1 Pci Dss Requirement Table

The table t_pci_dss_requirement embodies axiom 2 (pci_dss_requirement). Column id is the primary key. Column x references an organization; column y stores the PCI DSS requirement identifier. Joining on x yields the set of requirements applicable to each merchant.

```sql
CREATE TABLE t_pci_dss_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 1.2 Schemaorg Product Price Table

The table t_schemaorg_product_price embodies axiom 3 (schemaorg_product_price). Column id is the primary key. Column x references a product identifier; column y stores the price identifier. The table can be joined to organization tables through an intermediate mapping of products to merchants.

```sql
CREATE TABLE t_schemaorg_product_price (
  id VARCHAR(255),
```

## 2. Schemaorg Org Taxid Table

The table t_schemaorg_org_taxid embodies axiom 4 (schemaorg_org_taxid). Column id is the primary key. Column x references an organization; column y stores the tax identifier. Joining on x links tax data to address and requirement rows for the same organization.

```sql
CREATE TABLE t_schemaorg_org_taxid (
  id VARCHAR(255),
```

## 2.1 Trace Supports Claim Table

The table t_trace_supports_claim embodies axiom 5 (trace_supports_claim). Column id is the primary key. Column x references an audit-trace process. The table supplies the process identifiers that can be joined to requirement or address rows when those rows are treated as the descriptive ICE supported by the trace.

```sql
CREATE TABLE t_trace_supports_claim (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 3. Cross-Table Query Example

To determine the price associated with a product sold by an organization that maintains both a specific tax identifier and a PCI DSS requirement supported by a recorded trace, the following join path is used:

- Start at t_schemaorg_org_taxid where y = 'tax_12-3456789' → x = 'org_acme'
- Join t_pci_dss_requirement on x = 'org_acme' → y = 'req_12_1'
- Join t_trace_supports_claim on x = 'trace_audit_2023q4'
- Join t_schemaorg_product_price on an external product-to-organization mapping (prod_widget belongs to org_acme) → y = 'price_49_99'

The resulting joined row is:

org_acme | tax_12-3456789 | req_12_1 | trace_audit_2023q4 | prod_widget | price_49_99
