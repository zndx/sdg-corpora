# Directive Attestation and Audit Modelling in Educational Data Governance

This chapter defines a five-table relational schema that captures the subclass relationships, signing events, evidence linkages and audit processes required by the listed ontology axioms. The schema supports cross-table joins that resolve multi-hop queries about signed attestations, referenced GDPR articles, SOC 2 criteria and supporting evidence within a primary-school data-protection programme.

## 1. Core Attestation Signing Table

Table t_attestation_signed_by realises axiom 2. Column id is the primary key; column x holds the class name of the attestation process. No foreign keys are present, allowing the table to serve as a stable target for later references.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255)
);
```

Example rows:

| id   | x                                      |
|------|----------------------------------------|
| att1 | AnnualDataProcessingAttestation        |
| att2 | PupilRecordAccessAttestation           |
| att3 | ThirdPartySharingAttestation           |
| att4 | RetentionScheduleAttestation           |

## 2. GDPR Article Subclass Table

Table t_gdpr_article_subclass realises axiom 1. Column id is the primary key; column y is a foreign key referencing t_attestation_signed_by(id). Column x stores the GDPR article class.

```sql
CREATE TABLE t_gdpr_article_subclass (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  FOREIGN KEY (y) REFERENCES t_attestation_signed_by(id)
);
```

Example rows:

| id     | x          | y    |
|--------|------------|------|
| ga1    | Article5_1a| att1 |
| ga2    | Article6_1c| att2 |
| ga3    | Article9_2a| att3 |
| ga4    | Article30_1| att4 |

## 3. SOC 2 Trust Criterion Table

Table t_soc2_trust_criterion realises axiom 3. Column id is the primary key; column y is a foreign key referencing t_attestation_signed_by(id). Column x stores the SOC 2 criterion class.

```sql
CREATE TABLE t_soc2_trust_criterion (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  FOREIGN KEY (y) REFERENCES t_attestation_signed_by(id)
);
```

Example rows:

| id     | x               | y    |
|--------|-----------------|------|
| sc1    | CC6_1           | att1 |
| sc2    | CC6_2           | att2 |
| sc3    | CC7_1           | att3 |
| sc4    | CC8_1           | att4 |

## 4. Attestation with Supporting Evidence Table

Table t_attestation_with_supporting_evidence realises axiom 4. Column id is the primary key; column y is a foreign key referencing t_gdpr_article_subclass(id). Column x stores the attestation class that carries evidence.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  FOREIGN KEY (y) REFERENCES t_gdpr_article_subclass(id)
);
```

Example rows:

| id     | x                                      | y   |
|--------|----------------------------------------|-----|
| ev1    | AnnualDataProcessingAttestation        | ga1 |
| ev2    | PupilRecordAccessAttestation           | ga2 |
| ev3    | ThirdPartySharingAttestation           | ga3 |
| ev4    | RetentionScheduleAttestation           | ga4 |

## 5. Audit Subclass Table

Table t_audit_subclass realises axiom 5. Column id is the primary key; column x holds the audit-process class name.

```sql
CREATE TABLE t_audit_subclass (
  id VARCHAR(255) PRIMARY KEY,
  x VARCHAR(255)
);
```

Example rows:

| id    | x                          |
|-------|----------------------------|
| au1   | TermlyDataProtectionAudit  |
| au2   | ExternalSOC2ReadinessAudit |
| au3   | ParentAccessRequestAudit   |
| au4   | SupplierRiskAudit          |

## 6. Cross-Join Demonstration

To determine the person class responsible for the attestation that supplies evidence for GDPR Article 5-1a and that is itself audited under TermlyDataProtectionAudit, the following mental join is performed. Start at t_gdpr_article_subclass where x = 'Article5_1a' (row ga1), follow foreign key y to t_attestation_signed_by (row att1), then follow the reverse link from t_attestation_with_supporting_evidence where y = 'ga1' (row ev1). The resulting joined row set contains:

attestation id = att1, gdpr subclass = ga1, evidence id = ev1, signed class = AnnualDataProcessingAttestation.
