# Chapter 4: Directive Governance Ontologies in Corporate Audit Processes

This chapter defines five core ontological templates that formalise audit processes, attestations and requirement specifications within a directive-governance framework. Each template is materialised as a relational table whose rows instantiate the corresponding OWL axiom. The tables share entity references through the x, y and z columns, enabling cross-table joins that recover multi-hop facts such as “which person conducted the audit of a given control directive during a stated period”.

## 1 Audit Period Association

Axiom 1 states that an audit process exists for a designated audit period. Table t_audit_for_period embodies the axiom by recording the audit entity (x) and its temporal scope (y). Column id is the primary key; column x functions as a foreign key that may be joined to the x columns of tables 2–4.

```sql
CREATE TABLE t_audit_for_period (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 2 Conducted-By Relation

Axiom 2 asserts that an audit process is conducted by a person. Table t_audit_conducted_by captures this fact. Column id is the primary key; column x references the same audit entities used in t_audit_for_period, permitting a direct equi-join on x.

```sql
CREATE TABLE t_audit_conducted_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
```

## 3 Audit Subclass Relation

Axiom 3 classifies an audit process as one that audits a control directive information content entity. Table t_audit_subclass records the audited directive. Column id is the primary key; column x again references the audit entities, enabling a three-table join with t_audit_for_period and t_audit_conducted_by.

```sql
CREATE TABLE t_audit_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
```

## 4 Attestation Signature Relation

Axiom 4 states that an attestation process is signed by a person. Table t_attestation_signed_by materialises the axiom. Column id is the primary key; column x references attestation entities that may be linked to the audit entities via shared governance identifiers.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255),
```

## 5 Requirement Equivalence Specification

Axiom 5 defines a requirement as a directive information content entity that both specifies a target and applies to a control. Table t_requirement_equiv_specifies_target records these two relata. Column id is the primary key; columns y and z serve as foreign keys to directive and control entities respectively.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```
