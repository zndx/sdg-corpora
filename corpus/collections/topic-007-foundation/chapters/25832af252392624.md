# Chapter 4: Directive Governance in Audit Trail Systems

This chapter defines five axioms for representing directives, requirements, verifications and policies within regulatory compliance systems. The axioms are projected to a relational schema consisting of five tables that support primary-key and foreign-key references. Instances are drawn from audit records of laboratory procedure compliance under animal welfare regulations.

## 1 Axiom-to-Table Mappings

### 1.1 Requirement equivalence

Table t_requirement_equiv_specifies_target embodies axiom requirement_equiv_specifies_target. Column id is the primary key. Columns y and z are foreign keys referencing identifiers in t_policy_equiv_jurisdiction_and_scope and t_verification_min_one_evidence respectively. A reader can join on z to retrieve the verification process that satisfies a given requirement.

| id | x | y | z |
| id | x | y | z |
| req_001 | Requirement_SamplePrep | pol_003 | ver_002 |
| req_002 | Requirement_EquipmentCal | pol_001 | ver_001 |
| req_003 | Requirement_StaffAttest | pol_002 | ver_003 |
| req_004 | Requirement_RecordRetain | pol_003 | ver_004 |
| req_005 | Requirement_ProcedureScope | pol_001 | ver_002 |

### 1.2 Verification evidence cardinality

Table t_verification_min_one_evidence embodies axiom verification_min_one_evidence. Column id is the primary key. Column y is a foreign key referencing identifiers in t_attestation_with_supporting_evidence. A reader can join on y to list the supporting evidence items attached to each verification process.

| id | x | y |
| id | x | y |
| ver_001 | Verification_CalibrationCheck | att_001 |
| ver_002 | Verification_SampleIntegrity | att_002 |
| ver_003 | Verification_StaffCompetency | att_003 |
| ver_004 | Verification_DataCompleteness | att_004 |
| ver_005 | Verification_EquipmentStatus | att_001 |

### 1.3 Attestation with evidence

Table t_attestation_with_supporting_evidence embodies axiom attestation_with_supporting_evidence. Column id is the primary key. Column y is a foreign key referencing identifiers in t_directive_not_obsolete. A reader can join on y to confirm that an attestation references only non-obsolete directives.

| id | x | y |
| id | x | y |
| att_001 | Attestation_Calibration | dir_001 |
| att_002 | Attestation_Integrity | dir_002 |
| att_003 | Attestation_Competency | dir_003 |
| att_004 | Attestation_Completeness | dir_004 |
| att_005 | Attestation_Status | dir_001 |

### 1.4 Policy jurisdiction and scope

Table t_policy_equiv_jurisdiction_and_scope embodies axiom policy_equiv_jurisdiction_and_scope. Column id is the primary key. Columns y and z are foreign keys referencing identifiers in t_requirement_equiv_specifies_target. A reader can join on y to obtain the requirements governed by each policy within a stated jurisdiction.

| id | x | y | z |
| id | x | y | z |
| pol_001 | Policy_LaboratoryOps | req_002 | req_005 |
| pol_002 | Policy_StaffQualification | req_003 | req_001 |
| pol_003 | Policy_RecordManagement | req_001 | req_004 |
| pol_004 | Policy_EquipmentUse | req_002 | req_005 |

### 1.5 Directive non-obsolescence

Table t_directive_not_obsolete embodies axiom directive_not_obsolete. Column id is the primary key. Column x is a foreign key referencing identifiers in t_attestation_with_supporting_evidence. A reader can join on x to verify that an attested directive remains current.

| id | x | y |
| id | x | y |
| dir_001 | att_001 | ObsoleteDirective |
| dir_002 | att_002 | ObsoleteDirective |
| dir_003 | att_003 | ObsoleteDirective |
| dir_004 | att_004 | ObsoleteDirective |
| dir_005 | att_005 | ObsoleteDirective |

## 2 Cross-table query example

To determine the verification process and its supporting attestation for requirement req_001 under policy pol_003, perform the following joins. Start at t_requirement_equiv_specifies_target where id = req_001, follow foreign key z to t_verification_min_one_evidence (ver_002), then follow foreign key y to t_attestation_with_supporting_evidence (att_002). The resulting joined row is:

req_001 | Requirement_SamplePrep | pol_003 | ver_002 | Verification_SampleIntegrity | att_002 | Attestation_Integrity | dir_002
