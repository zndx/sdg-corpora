# Directive Governance Ontologies in Compliance Audit Systems

This chapter presents five ontological templates drawn from directive governance axioms and projects them into a relational schema for audit trail systems. The schema records class equivalences and process constraints as primary-key and foreign-key references among five tables. Cross-table joins recover multi-hop relations such as the jurisdiction of a policy that governs a requirement whose verification produces evidence.

## 1. Requirement Equivalence and Target Specification

Table t_requirement_equiv_specifies_target realizes axiom 1 by storing the three class arguments of the Manchester equivalence that defines a requirement as a directive specifying a target and applying to a scope. Column id is the primary key. Columns x, y and z are foreign-key references to class identifiers; any value in y or z may be joined to matching values in other tables to traverse specification and application links.

| id | x | y | z |
| id | x | y | z |
| req-001 | DataRetentionRequirement | RetentionPeriodTarget | ElectronicRecordsScope |
| req-002 | ConsentWithdrawalRequirement | MechanismTarget | PersonalDataScope |
| req-003 | BreachNotificationRequirement | TimeLimitTarget | SupervisoryAuthorityScope |
| req-004 | AccessRequestRequirement | ResponseDeadlineTarget | DataSubjectScope |
| req-005 | EncryptionStandardRequirement | AlgorithmTarget | SensitiveDataScope |

## 2. Verification Requiring Minimum Evidence

Table t_verification_min_one_evidence realizes axiom 2 by recording processes that must produce at least one evidence class. Column id is the primary key. Column x references the verification process class; column y is a foreign-key reference to the required evidence class and supports joins that confirm evidence existence.

| id | x | y |
| id | x | y |
| ver-001 | RetentionAudit | LogInspectionEvidence |
| ver-002 | ConsentAudit | SignedFormEvidence |
| ver-003 | BreachAudit | TimestampedReportEvidence |
| ver-004 | AccessAudit | RequestReceiptEvidence |
| ver-005 | EncryptionAudit | CertificateEvidence |
| ver-006 | ScopeAudit | JurisdictionMapEvidence |

## 3. Attestation Supported by Evidence

Table t_attestation_with_supporting_evidence realizes axiom 3 by recording attestation processes linked to supporting evidence classes. Column id is the primary key. Column x references the attestation process; column y is a foreign-key reference to the evidence class and enables joins that trace supporting material.

## 4. Policy Equivalence with Jurisdiction and Scope

Table t_policy_equiv_jurisdiction_and_scope realizes axiom 4 by storing the three class arguments of the Manchester equivalence that defines a policy as a directive possessing a jurisdiction and governing a scope. Column id is the primary key. Columns x, y and z are foreign-key references; joins on y recover jurisdiction and joins on z recover governed scope.

| id | x | y | z |
| id | x | y | z |
| pol-001 | DataProtectionPolicy | EUMemberStatesJurisdiction | PersonalDataProcessingScope |
| pol-002 | CybersecurityPolicy | NationalRegulatorJurisdiction | CriticalInfrastructureScope |
| pol-003 | RecordsManagementPolicy | SectorAuthorityJurisdiction | RetentionScheduleScope |
| pol-004 | IncidentResponsePolicy | CrossBorderAuthorityJurisdiction | BreachEventScope |

## 5. Directive Non-Obsolescence Constraint

Table t_directive_not_obsolete realizes axiom 5 by asserting that a directive class is not an obsolete class. Column id is the primary key. Column x references the directive; column y references the obsolete class and supports exclusion joins that filter superseded directives.

| id | x | y |
| id | x | y |
| dir-001 | DataRetentionRequirement | SupersededDirective |
| dir-002 | ConsentWithdrawalRequirement | SupersededDirective |
| dir-003 | BreachNotificationRequirement | SupersededDirective |
| dir-004 | AccessRequestRequirement | SupersededDirective |

## 6. Cross-Table Query Example

To determine the jurisdiction and evidence supporting an attestation of a requirement governed by policy pol-001, join t_policy_equiv_jurisdiction_and_scope on z to locate the requirement class, then join t_requirement_equiv_specifies_target on x to the requirement, then join t_attestation_with_supporting_evidence on y to the evidence class, and finally join t_verification_min_one_evidence on y. The resulting row set contains:

- pol-001, EUMemberStatesJurisdiction, PersonalDataProcessingScope
- req-001, DataRetentionRequirement, RetentionPeriodTarget, ElectronicRecordsScope
- att-001, RetentionAttestation, LogInspectionEvidence
- ver-001, RetentionAudit, LogInspectionEvidence
