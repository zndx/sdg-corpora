# Chapter 4: Directive Governance Patterns in Regulatory Compliance Systems

This chapter defines five core ontological templates for modeling directives, verifications, and attestations within institutional compliance regimes. Each template is realized as a relation whose columns correspond directly to the axiom slots. The resulting schema supports cross-table joins that recover multi-hop chains from a directive to its verification evidence and supporting attestations.

## 1 Scope and Schema Overview

The domain is regulatory compliance documentation for an educational institution operating under national lockdown directives. Five tables instantiate the supplied axioms. Primary keys are the id columns. Foreign-key semantics arise when values in x, y, or z columns match identifiers stored as primary keys in other tables or as stable class labels used across the schema.

### 1.1 Requirement Equivalence

Table t_requirement_equiv_specifies_target embodies axiom requirement_equiv_specifies_target. Column id is the primary key. Columns y and z act as foreign-key references to target classes and applicable scopes, respectively.

## 2 Cross-Join Example

To determine the evidence supporting the headteacher declaration for the lockdown operational requirement, join t_requirement_equiv_specifies_target to t_verification_min_one_evidence on y values, then to t_attestation_with_supporting_evidence on the same evidence class. The joined row is:

REQ-001, LockdownOperationalRequirement, NationalHealthGuidelines, SchoolPremises  
VER-010, DailyComplianceCheck, InspectionLog  
ATT-020, HeadteacherDeclaration, InspectionLog

The result shows that InspectionLog satisfies the evidence requirement for both verification and attestation of the operational directive.
