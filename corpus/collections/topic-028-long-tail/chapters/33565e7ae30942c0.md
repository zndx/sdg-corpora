# Attestation and Verification Structures in Administrative Records

This chapter defines five relational tables that realize the slot structures of five OWL axioms governing attestations, requirements, verifications, and postal addresses. The tables support cross-table joins that recover multi-hop facts such as the signer of an attestation linked to a verified requirement at a given address.

## 1. Core Axioms and Table Projections

### 1.1 Table t_attestation_min_one_signer

Axiom 1 states that any instance of class X is a process that must be signed by at least one person. The table therefore stores the attested process class in column x; column id serves as the primary key that later tables reference when they require an attestation instance.

```sql
CREATE TABLE t_attestation_min_one_signer (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id     | x                              |
|--------|--------------------------------|
| att001 | EmploymentApplicationReview    |
| att002 | CivilServiceExamApplication    |
| att003 | HeadmistressTermLetter         |
| att004 | CommitteeAgendaDistribution    |
| att005 | LibraryAccessAttestation       |

### 1.2 Table t_schemaorg_place_address

Axiom 2 states that any instance of class X is an artifact that has at least one postal address Y. Column y is a foreign key to t_attestation_min_one_signer, ensuring every address record is anchored to a signed attestation process.

```sql
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_attestation_min_one_signer(id)
);
```

| id      | x                       | y      |
|---------|-------------------------|--------|
| addr01  | WayneCountyHROffice     | att001 |
| addr02  | SUNYSB Library          | att002 |
| addr03  | MoonAcademyMainBuilding | att003 |
| addr04  | LSCConferenceRoom       | att004 |
| addr05  | DanaArchiveDeposit      | att005 |

### 1.3 Table t_requirement_min_one_verification

Axiom 3 states that any instance of class X is a directive information content entity verified by at least one Y. Column y is a foreign key to t_schemaorg_place_address, linking each requirement to the attested address at which verification occurs.

```sql
CREATE TABLE t_requirement_min_one_verification (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_schemaorg_place_address(id)
);
```

| id     | x                                | y      |
|--------|----------------------------------|--------|
| req01  | QualifiedYesConditional          | addr01 |
| req02  | LSCAgendaItemReview              | addr02 |
| req03  | PupilTermStartConfirmation       | addr03 |
| req04  | MeetingAttendanceRecord          | addr04 |
| req05  | DocumentDepositVerification      | addr05 |

### 1.4 Table t_attestation_signed_by

Axiom 4 states that any instance of class X is a process signed by a person. The table records the process class; its primary key id may be joined to other attestation tables when signer identity must be asserted.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id     | x                              |
|--------|--------------------------------|
| sig01  | EmploymentApplicationReview    |
| sig02  | CivilServiceExamApplication    |
| sig03  | HeadmistressTermLetter         |
| sig04  | CommitteeAgendaDistribution    |
| sig05  | LibraryAccessAttestation       |

### 1.5 Table t_verification_min_one_evidence

Axiom 5 states that any instance of class X is a process that produces at least one evidence entity Y. Column y is a foreign key to t_schemaorg_place_address, ensuring every verification process is tied to an attested location.

```sql
CREATE TABLE t_verification_min_one_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_schemaorg_place_address(id)
);
```

## 2. Cross-Join Example

To determine the verification evidence produced for the requirement “QualifiedYesConditional” at the address anchored to attestation att001, execute the following mental join:

- Start at t_requirement_min_one_verification where x = QualifiedYesConditional → y = addr01
- Join t_schemaorg_place_address on id = addr01 → y = att001
- Join t_verification_min_one_evidence on y = addr01 → x = ReviewerInitialsCheck

The resulting row set is (req01, QualifiedYesConditional, addr01, ver01, ReviewerInitialsCheck). The same pattern extends to any requirement whose address foreign key resolves to a signed attestation.
