# Attestation and Verification Structures in Administrative Records

This chapter specifies a five-table relational schema that implements five OWL axioms for processes of attestation, verification, and requirement satisfaction. The tables record signed administrative acts, addressed artifacts, and evidence-producing verifications within a civil-service examination workflow. Primary and foreign keys are defined so that cross-table joins recover multi-hop facts such as the postal address used in a verified requirement that itself attests a signed process.

## 1. Tables Derived from the Axioms

### 1.1 Table t_attestation_min_one_signer
This table directly implements axiom attestation_min_one_signer, recording every process that must be signed by at least one person. Column id is the primary key; column x holds the class identifier of the attested process.

| id | x |
|----|---|
| att-001 | ApplicationReviewProcess |
| att-002 | QualificationDetermination |
| att-003 | ConditionalApproval |
| att-004 | FinalEligibilityRuling |
| att-005 | ExaminationScoring |

### 1.2 Table t_schemaorg_place_address
This table implements axiom schemaorg_place_address, capturing artifacts that carry a postal address. Column id is the primary key; column y is a foreign key referencing t_attestation_min_one_signer.id, ensuring every addressed artifact is grounded in a signed process.

| id | x | y |
|----|---|---|
| addr-001 | ApplicantMailingAddress | att-001 |
| addr-002 | ReviewerOfficeAddress | att-002 |
| addr-003 | ExaminationSiteAddress | att-003 |
| addr-004 | ConditionalNoticeAddress | att-004 |
| addr-005 | EligibilityCertificateAddress | att-001 |

### 1.3 Table t_requirement_min_one_verification
This table implements axiom requirement_min_one_verification, recording directive information content entities that must be verified by at least one entity. Column id is the primary key; column y is a foreign key referencing t_schemaorg_place_address.id.

| id | x | y |
|----|---|---|
| req-001 | MinimumQualificationDirective | addr-001 |
| req-002 | ExaminationEligibilityDirective | addr-002 |
| req-003 | ConditionalEmploymentDirective | addr-003 |
| req-004 | FinalCertificationDirective | addr-004 |
| req-005 | ScoringIntegrityDirective | addr-005 |

### 1.4 Table t_attestation_signed_by
This table implements axiom attestation_signed_by, recording processes that are signed by a person. Column id is the primary key; column x holds the class identifier of the signing act.

| id | x |
|----|---|
| sig-001 | DirectorSignature |
| sig-002 | BiologistSignature |
| sig-003 | SecretarySignature |
| sig-004 | ChiefSignature |
| sig-005 | ReviewerSignature |

### 1.5 Table t_verification_min_one_evidence
This table implements axiom verification_min_one_evidence, recording processes that produce at least one evidence item. Column id is the primary key; column y is a foreign key referencing t_schemaorg_place_address.id.

| id | x | y |
|----|---|---|
| ver-001 | DocumentAuthenticityCheck | addr-001 |
| ver-002 | AddressConfirmationCheck | addr-002 |
| ver-003 | SiteInspectionCheck | addr-003 |
| ver-004 | ConditionalTermCheck | addr-004 |
| ver-005 | ScoringAuditCheck | addr-005 |

## 2. Cross-Join Demonstration

To recover the postal address that supports verification of a requirement grounded in a signed attestation, join t_requirement_min_one_verification to t_schemaorg_place_address on y, then to t_attestation_min_one_signer on the resulting y value. The following mental execution of the join for req-001 yields:

- requirement id: req-001
- requirement class: MinimumQualificationDirective
- address id: addr-001
- address class: ApplicantMailingAddress
- attestation id: att-001
- attestation class: ApplicationReviewProcess
