# Chapter 4: Directive Governance in Audit Documentation

This chapter examines five ontological templates that formalize attestation, verification, and address relations within corporate governance records. The templates are instantiated through five tables that together record signed attestations, postal addresses, verified requirements, and evidence-producing verifications. Primary and foreign keys enable multi-table joins that recover chains of custody and authorization.

## 1 Scope and Table Overview

The five tables implement the axioms directly. Each row satisfies the minimum cardinality or existential restrictions stated in the Manchester syntax. The primary key of every table is the column named id. Foreign-key columns reference only the id values of the tables named in the schema comments.

### 1.1 t_attestation_min_one_signer

This table embodies axiom 1 (attestation_min_one_signer). Column id is the primary key. Column x holds the class that is a subclass of bfo:0000015 and is signed by at least one person. A reader can join this table to t_attestation_signed_by on x to list the persons who satisfy the minimum-signer restriction for any given attestation.

| id          | x                          |
|-------------|----------------------------|
| attest-001  | AuditReport                |
| attest-002  | ComplianceDeclaration      |
| attest-003  | RiskAssessment             |
| attest-004  | FinancialStatement         |
| attest-005  | SafetyInspection           |

### 1.2 t_schemaorg_place_address

This table embodies axiom 2 (schemaorg_place_address). Column id is the primary key. Column y is a foreign key to t_attestation_min_one_signer.id. Column x records the artifact class that possesses the postal address. The join on y yields the attestation that authorizes the address-bearing artifact.

| id          | x                          | y           |
|-------------|----------------------------|-------------|
| addr-001    | RegisteredOffice           | attest-001  |
| addr-002    | LaboratorySite             | attest-002  |
| addr-003    | WarehouseFacility          | attest-003  |
| addr-004    | Headquarters               | attest-004  |
| addr-005    | FieldStation               | attest-005  |

### 1.3 t_requirement_min_one_verification

This table embodies axiom 3 (requirement_min_one_verification). Column id is the primary key. Column y is a foreign key to t_schemaorg_place_address.id. Column x records the directive information content entity that must be verified by at least one process. Joining on y recovers the address-linked attestation that supplies the verification target.

| id          | x                          | y           |
|-------------|----------------------------|-------------|
| req-001     | SOXControl                 | addr-001    |
| req-002     | ISO9001Clause              | addr-002    |

| req-005     | SafetyStandard             | addr-005    |

### 1.4 t_attestation_signed_by

This table embodies axiom 4 (attestation_signed_by). Column id is the primary key. Column x records the attestation process that is signed by a person. The table supplies the signer instances required by the minimum-cardinality constraint in axiom 1.

| id          | x                          |
|-------------|----------------------------|
| sign-001    | Chris Kalinski             |

| sign-003    | ComplianceOfficer          |

### 1.5 t_verification_min_one_evidence

This table embodies axiom 5 (verification_min_one_evidence). Column id is the primary key. Column y is a foreign key to t_schemaorg_place_address.id. Column x records the verification process that produces at least one evidence artifact. Joining on y recovers the address that contextualizes the evidence.

| id          | x                          | y           |

## 2 Cross-Join Example

To determine the signer of the attestation that authorizes the address used by a verified requirement, execute the following mental join path:

t_requirement_min_one_verification.y → t_schemaorg_place_address.id  
t_schemaorg_place_address.y → t_attestation_min_one_signer.id  
t_attestation_min_one_signer.x → t_attestation_signed_by.x

For requirement req-001 the path yields:

- y = addr-001  
- addr-001.y = attest-001  
- attest-001.x = AuditReport  
- signer = Chris Kalinski

The resulting joined row is therefore (req-001, SOXControl, addr-001, attest-001, AuditReport, Chris Kalinski).
