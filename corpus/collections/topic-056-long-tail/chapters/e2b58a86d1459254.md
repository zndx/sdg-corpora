# Evidence Structures in Certification Processes

This chapter defines four ontological patterns that relate processes of verification and attestation to designative information content entities. The patterns are realized as four tables whose foreign-key links permit retrieval of multi-hop chains such as “which attestation rests on evidence produced by a given verification.”

## 1 Ontological Patterns

The patterns are expressed in the Manchester OWL syntax supplied by the governing axioms. Each pattern is realized by exactly one table whose column structure follows the slot types declared in the axiom.

### 1.1 Designative Subclass Basic

Axiom 2 states that any individual filling the X slot is a subclass of cco:DesignativeICE. The table therefore stores only the identifiers of such subclasses; its single-column primary key supplies the target for all subsequent foreign-key references.

```sql
CREATE TABLE t_designative_subclass_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example cross-join: join any verification row to this table on y = id to obtain the human-readable label of the evidence class.

### 1.2 Subclass to Designative ICE

Axiom 4 repeats the same subclass relation under a different template identifier. The table therefore contains a second set of designative-ICE subclasses that are referenced only by attestation rows.

```sql
CREATE TABLE t_subclass_to_designative_ice (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example cross-join: an attestation row joined to this table yields the label of the supporting-evidence class without traversing the verification table.

### 1.3 Verification Produces Evidence

Axiom 1 asserts that a verification process (X) produces evidence (Y). The table records the pair together with a surrogate primary key; the y column is a foreign key into t_designative_subclass_basic.

```sql
CREATE TABLE t_verification_produces_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_designative_subclass_basic(id)
);
```

Example cross-join: select verification.x together with designative_subclass_basic.x to list every verification class and the exact evidence class it produces.

### 1.4 Attestation with Supporting Evidence

Axiom 3 asserts that an attestation process (X) occurs with supporting evidence (Y). The table again uses a surrogate primary key and a foreign key into t_designative_subclass_basic.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_designative_subclass_basic(id)
);
```

Example cross-join: join attestation rows to designative_subclass_basic on y = id to retrieve the evidence label that supports each attestation.

## 3 Multi-Hop Retrieval Example

Question: “Which attestation rests on evidence produced by HydrostaticVerification?”

Step 1. Locate the verification row:  
vpe-010 | HydrostaticVerification | dsb-001

Step 2. Follow the foreign key y = dsb-001 into t_designative_subclass_basic to confirm the evidence class label “PressureTestReport”.

Step 3. Scan t_attestation_with_supporting_evidence for any row whose y column equals dsb-001:  
awe-020 | TypeApprovalAttestation | dsb-001

Resulting joined row:  
verification.x = HydrostaticVerification, evidence.x = PressureTestReport, attestation.x = TypeApprovalAttestation
