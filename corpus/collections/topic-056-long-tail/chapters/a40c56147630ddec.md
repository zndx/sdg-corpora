# Audit Trail Representation Using Designative Information Content Entities

This chapter specifies four tables that encode verification and attestation processes as subclasses of designative information content entities within regulatory audit trails. The tables implement the supplied OWL axioms directly, enabling cross-table joins that recover multi-hop relationships such as the evidence supporting a given attestation.

## 1 Foundational Designative Entities

Table t_designative_subclass_basic embodies axiom 2 by recording classes that are direct subclasses of cco:DesignativeICE. Column id is the primary key; column x holds the class name.

| id | x |
| --- | --- |
| d001 | ComplianceCertificate |
| d002 | AuditLogEntry |
| d003 | VerificationStatement |
| d004 | FindingReport |
| d005 | RegulatoryFiling |

## 1.1 Subclass Mappings to Designative ICE

Table t_subclass_to_designative_ice embodies axiom 4 by recording additional classes that are likewise subclasses of cco:DesignativeICE. Column id is the primary key; column x holds the class name.

## 2 Verification Processes Producing Evidence

Table t_verification_produces_evidence embodies axiom 1 by linking verification processes to the designative evidence they produce. Column id is the primary key; column y is a foreign key referencing t_designative_subclass_basic(id).

| id | x | y |

| v001 | SampleVerification | d001 |
| v002 | LogIntegrityCheck | d002 |

## 3 Attestations Supported by Evidence

Table t_attestation_with_supporting_evidence embodies axiom 3 by linking attestation processes to the designative evidence that supports them. Column id is the primary key; column y is a foreign key referencing t_designative_subclass_basic(id).

## 4 Worked Multi-Hop Query Example

To determine the designative evidence supporting the attestation whose identifier is a001, first locate row a001 in t_attestation_with_supporting_evidence to obtain foreign key y = d001, then locate row d001 in t_designative_subclass_basic to obtain x = ComplianceCertificate. The joined result is therefore (a001, QuarterlyAttestation, d001, ComplianceCertificate). The same pattern applied to v001 yields (v001, SampleVerification, d001, ComplianceCertificate), confirming that both the attestation and the verification share the identical evidence class.
