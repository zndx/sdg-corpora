# Civic Asset Registry Schema

This chapter defines the relational projection of five schema.org-derived axioms for civic artifacts. The model supports attribute attachment to places and organizations through foreign-key references that enable multi-hop retrieval of addresses, coordinates, and tax identifiers.

## 1. Schema Organization and Scope
The registry covers municipal places and organizations within a single township. Each axiom is realized as a dedicated table whose columns map directly to the slot types X (subject artifact) and Y (attribute value). Primary keys ensure uniqueness of each attribution statement; shared X values across tables permit joins that reconstruct complete entity profiles.

### 1.1 Place Address Attribution
Axiom 1 states that an artifact X possesses a postal address Y. The table records each such statement once. Column id is the primary key. Column x references an artifact identifier; column y stores the address literal. Joining on x with other attribute tables yields the full address set for any place.

```sql
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.2 Place Geo-Coordinate Attribution
Axiom 2 states that an artifact X possesses geo-coordinates Y. The table stores each coordinate pair as a single Y value. Column id is the primary key. Column x references the same artifact identifiers used in the address table, enabling direct equi-join on x to retrieve both address and coordinate data for any place.

```sql
CREATE TABLE t_schemaorg_place_geocoord (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.3 Place Latitude Attribution
Axiom 3 isolates the latitude component of a place. Column id is the primary key. Column x again references the artifact; column y holds the latitude literal. Cross-table joins on x allow reconstruction of full coordinate pairs when latitude and longitude tables are combined.

```sql
CREATE TABLE t_schemaorg_place_latitude (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.4 Organization Tax Identifier Attribution
Axiom 4 attaches a tax identifier to an organization artifact. Column id is the primary key. Column x references the organization; column y stores the tax identifier literal. The same x values appear in the address table, permitting joins that return both postal address and tax identifier for any organization.

```sql
CREATE TABLE t_schemaorg_org_taxid (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

### 1.5 Place Longitude Attribution
Axiom 5 isolates the longitude component of a place. Column id is the primary key. Column x references the artifact; column y holds the longitude literal. Joining this table with the latitude table on x produces complete coordinate pairs without reference to the geocoord table.

```sql
CREATE TABLE t_schemaorg_place_longitude (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

## 2. Multi-Hop Retrieval Example
To retrieve the tax identifier and full address for the organization that shares its address reference with the Knights of Columbus, first locate the x value in t_schemaorg_place_address where y contains “Knights of Columbus”, then join that x value into t_schemaorg_org_taxid on the x column. The join returns:

- x = org_knights_columbus
- address y = PO Box 6504, Manchester Township, NJ 08844
