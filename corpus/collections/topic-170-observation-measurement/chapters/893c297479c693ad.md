# Artifact Location and Identification Schema

This chapter defines a minimal relational representation for artifacts that carry postal addresses, geographic coordinates, and tax identifiers. The five tables are direct projections of the listed Manchester axioms; each row asserts a single slot filler. Primary keys ensure uniqueness of assertions; shared values in the x column permit cross-table joins that reconstruct complete location profiles for any artifact.

## 1. Postal Address Assertions

Table t_schemaorg_place_address realizes AXIOM 1. Column id is the primary key. Column x identifies the artifact; column y identifies the postal address. Joining this table to any coordinate table on x produces the address paired with latitude or longitude for the same artifact.

```text
id                  x                              y
addr-001            Beachbody LLC                  3300 Ocean Park Blvd, Santa Monica, CA 90405
addr-002            Wayne County HR Office         500 Griswold St, Detroit, MI 48226
addr-003            Manchester Registry            1 City Hall Plaza, Manchester, NH 03101
addr-004            IKPONMWOSA O. OLOMU            1234 Maple Ave, Lansing, MI 48933
```

## 2. Geocoordinate Assertions

Table t_schemaorg_place_geocoord realizes AXIOM 2. Column id is the primary key. Column x references the artifact; column y references the coordinate pair. A join on x with the address table yields both postal and geocoordinate data for one artifact.

```text
id                  x                              y
geo-001             Beachbody LLC                  34.0195,-118.4568
geo-002             Wayne County HR Office         42.3314,-83.0458
geo-003             Manchester Registry            42.9908,-71.4634
geo-004             IKPONMWOSA O. OLOMU            42.7325,-84.5555
```

## 3. Latitude Assertions

Table t_schemaorg_place_latitude realizes AXIOM 3. Column id is the primary key. Column x references the artifact; column y stores the latitude literal. Joining on x with the longitude table assembles a complete coordinate pair.

```text
id                  x                              y
lat-001             Beachbody LLC                  34.0195
lat-002             Wayne County HR Office         42.3314
lat-003             Manchester Registry            42.9908
lat-004             IKPONMWOSA O. OLOMU            42.7325
```

## 4. Tax Identifier Assertions

Table t_schemaorg_org_taxid realizes AXIOM 4. Column id is the primary key. Column x references the organization artifact; column y stores the tax identifier. Because the same x values appear in the address table, a join on x links tax identifiers directly to postal addresses.

```text
id                  x                              y
tax-001             Beachbody LLC                  46-1234567
tax-002             Wayne County HR Office         38-9876543
tax-003             Manchester Registry            02-4567890
```

## 5. Longitude Assertions

Table t_schemaorg_place_longitude realizes AXIOM 5. Column id is the primary key. Column x references the artifact; column y stores the longitude literal. A three-table join on x across address, latitude, and longitude tables returns the full address and coordinate set for any artifact.

```text
id                  x                              y
lon-001             Beachbody LLC                  -118.4568
lon-002             Wayne County HR Office         -83.0458
lon-003             Manchester Registry            -71.4634
lon-004             IKPONMWOSA O. OLOMU            -84.5555
```

## 6. Cross-Table Query Example

To retrieve the longitude associated with the postal address of Beachbody LLC, first locate the artifact identifier in t_schemaorg_place_address where y equals “3300 Ocean Park Blvd, Santa Monica, CA 90405”, yielding x = “Beachbody LLC”. Then select from t_schemaorg_place_longitude where x matches that value. The joined result row is:

Beachbody LLC | 3300 Ocean Park Blvd, Santa Monica, CA 90405 | -118.4568

The same pattern extends to any combination of address, latitude, longitude, or tax identifier by additional equi-joins on the shared x column.
