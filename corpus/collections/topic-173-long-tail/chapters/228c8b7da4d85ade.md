# Laboratory Process Ontologies in ISO 27001-Compliant Testing Environments

This chapter presents four ontological templates that formalize laboratory runs, measurements, and directive clauses. The templates are projected to a fixed relational schema whose foreign-key links permit multi-hop retrieval of process outcomes and compliance references.

## 1 Scope and Schema Overview

The selected domain is laboratory information management under ISO 27001 controls. Four tables realize the supplied axioms. Primary keys are uniformly named id. One foreign-key column (y) enforces a directed relationship from ISO 27001 clause directives to laboratory runs. All column values are drawn from realistic laboratory and compliance records.

### 1.1 Table t_labrun_produces_measurement

Axiom 1 states that a laboratory run is a process that produces a descriptive information content entity. The table therefore stores run identifiers (primary key id) and the run class label (x). No foreign keys are present; each row is an independent process instance.

```sql
CREATE TABLE t_labrun_produces_measurement (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id   | x                          |
|------|----------------------------|
| LR001 | VisceralOilCetaneRun       |
| LR002 | DieselBlendCalorificRun    |
| LR003 | EquipmentCalibrationRun    |
| LR004 | SampleReceiptLogRun        |
| LR005 | TechnicianShiftAuditRun    |

### 1.2 Table t_iso27001_clause_subclass

Axiom 2 states that a directive information content entity is a subclass of an ISO 27001 clause. The table stores directive identifiers (primary key id), the directive class (x), and a foreign key (y) that references a laboratory run. The foreign-key constraint permits retrieval of the run that generated evidence for a given clause.

```sql
CREATE TABLE t_iso27001_clause_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_produces_measurement(id)
);
```

| id    | x                        | y     |
|-------|--------------------------|-------|
| CL001 | A.12.4.1EventLogging     | LR001 |
| CL002 | A.14.2.7SystemTesting    | LR002 |
| CL003 | A.9.2.1UserRegistration  | LR003 |
| CL004 | A.8.2.3InformationLabeling | LR004 |
| CL005 | A.12.1.1DocumentedProcedures | LR005 |

### 1.3 Table t_measurement_produced_by_run

Axiom 3 states that a descriptive information content entity is produced by a process. The table stores measurement identifiers (primary key id) and the measurement class (x). No foreign keys are declared; linkage to runs occurs through shared identifiers in application logic.

```sql
CREATE TABLE t_measurement_produced_by_run (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id    | x                          |
|-------|----------------------------|
| M001  | CetaneNumberValue          |
| M002  | GrossCalorificValue        |
| M003  | EquipmentDriftReading      |
| M004  | ChainOfCustodyTimestamp    |
| M005  | AccessLogIntegrityHash     |

### 1.4 Table t_state_basic

Axiom 4 states that an entity is a descriptive information content entity. The table stores state identifiers (primary key id) and the state class (x). The table functions as a controlled vocabulary of measurement or compliance states.

```sql
CREATE TABLE t_state_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id   | x               |
|------|-----------------|
| ST01 | Validated       |
| ST02 | PendingReview   |
| ST03 | NonConforming   |
| ST04 | Archived        |
| ST05 | UnderAudit      |

## 2 Cross-Join Demonstration

To retrieve the ISO 27001 clause, the laboratory run that produced supporting evidence, and the measurement class associated with that run, execute the following mental join:

```sql
SELECT c.id AS clause_id, c.x AS clause, r.id AS run_id, r.x AS run_class, m.x AS measurement
FROM t_iso27001_clause_subclass c
JOIN t_labrun_produces_measurement r ON c.y = r.id
JOIN t_measurement_produced_by_run m ON m.id LIKE '%' || SUBSTR(r.id,3,3);
```

For clause CL001 the join yields: clause A.12.4.1EventLogging, run LR001 (VisceralOilCetaneRun), measurement CetaneNumberValue. The same pattern applied to CL002 returns run LR002 and measurement GrossCalorificValue.
