# Ontological Representation of Laboratory Processes and ISO 27001 Compliance Directives

This chapter presents four tables that instantiate axioms linking processual entities to descriptive information content entities. The tables support queries that traverse production relations and subclass restrictions, using primary and foreign keys to encode the axioms directly.

## 1 Laboratory Run and Measurement Production

Axiom 1 states that a class X is a subclass of bfo:0000015 and produces some cco:DescriptiveICE. The table t_labrun_produces_measurement therefore records each such X together with a surrogate identifier that serves as primary key. The identifier column functions as the join target for any table that references a producing process.

```sql
CREATE TABLE t_labrun_produces_measurement (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id | x |
|----|---|
| LR-001 | CetaneDeterminationRun |
| LR-002 | CalorificValueRun |
| LR-003 | BlendStabilityRun |
| LR-004 | OxidationInductionRun |
| LR-005 | ViscosityProfileRun |

## 2 ISO 27001 Clause Subclass Relation

Axiom 2 states that a class X is a subclass of cco:DirectiveICE and stands in the sdg:iso27001Clause relation to another class Y. The table t_iso27001_clause_subclass therefore stores the pair (X, Y) and declares a foreign key from column y to the primary key of t_labrun_produces_measurement. The foreign-key constraint enforces that every referenced clause is grounded in an existing laboratory run that produces measurements.

```sql
CREATE TABLE t_iso27001_clause_subclass (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_labrun_produces_measurement(id)
);
```

| id | x | y |
|----|---|---|
| IC-010 | AccessControlDirective | LR-001 |
| IC-011 | LoggingRetentionDirective | LR-002 |
| IC-012 | ChangeManagementDirective | LR-003 |
| IC-013 | EncryptionAtRestDirective | LR-001 |
| IC-014 | IncidentResponseDirective | LR-004 |

## 3 Measurement Produced by Run

Axiom 3 states that a class X is a subclass of cco:DescriptiveICE and is producedBy some bfo:0000015. The table t_measurement_produced_by_run records each such X; its identifier column may be joined to other descriptive entities when further relations are asserted.

```sql
CREATE TABLE t_measurement_produced_by_run (
```

## 4 Basic Descriptive State

Axiom 4 states that a class X is a subclass of cco:DescriptiveICE. The table t_state_basic therefore lists each such X without additional relational constraints, providing leaf entities that may be referenced by measurement or clause tables in extended models.

```sql
CREATE TABLE t_state_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 5 Cross-Join Example

To retrieve the ISO 27001 directive that governs the laboratory run producing a cetane measurement, the following mental join is performed:

- Start at t_iso27001_clause_subclass row IC-010 (x = AccessControlDirective, y = LR-001).
- Follow foreign key y to t_labrun_produces_measurement row LR-001 (x = CetaneDeterminationRun).
- The joined result is the single row (IC-010, AccessControlDirective, LR-001, CetaneDeterminationRun).

The same pattern extends to any directive whose y value matches a laboratory-run identifier, thereby answering multi-hop questions that combine clause membership with processual production.
