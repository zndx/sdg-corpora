# Regulatory Audit Processes for Compliance Datasets

This chapter specifies the relational encoding of five axioms that distinguish audit processes, datasets subject to audit, evidence requirements, classifications, and findings. The model supports verification of multi-hop relationships such as the evidence produced by a verification step within an audit that carries findings.

## 1. Process and Dataset Tables

### 1.1 Basic Audit Processes
Axiom 1 defines any audit as a process. Table t_audit_basic therefore stores only process identifiers; its single-column primary key permits direct reference from dependent tables that record evidence or findings produced by the same process.

### 1.2 Datasets Under Audit
Axiom 2 classifies an artifact as being under audit when it participates in at least one process instance. Table t_dataset_under_audit records these artifacts; its primary key supplies the foreign-key targets required by verification and findings tables.

### 1.3 Verification Steps Requiring Evidence
Axiom 3 requires every verification process to produce at least one evidence artifact. Table t_verification_min_one_evidence therefore contains a non-null foreign key to t_dataset_under_audit; the composite primary key (id) together with the foreign key enables a two-table join that lists every verification and its supporting dataset.

### 1.5 Audits That Generate Findings
Axiom 5 extends an audit process with the production of findings. Table t_audit_with_findings therefore carries a non-null foreign key to t_dataset_under_audit; its primary key permits a three-table join across an audit, its verification step, and the dataset that both references and yields findings.

## 2. Cross-Table Query Example

To retrieve the dataset that supplied evidence for a verification step belonging to an audit that also recorded findings, join t_verification_min_one_evidence to t_audit_with_findings on the shared dataset identifier. The query

```
SELECT v.x AS verification, a.x AS audit, d.x AS dataset
FROM t_verification_min_one_evidence v
JOIN t_audit_with_findings a ON v.y = a.y
JOIN t_dataset_under_audit d ON v.y = d.id
WHERE a.x = 'QuarterlyDatasetReview'
```

returns the single joined row (vm-202, QuarterlyDatasetReview, InsuranceReg20FilingQ3), confirming that the same dataset served both as evidence for verification vm-202 and as the finding carrier for audit af-402.
