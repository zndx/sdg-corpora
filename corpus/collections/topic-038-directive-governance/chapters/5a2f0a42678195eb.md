# Chapter 7: Audit Processes for Dataset Classification and Verification

This chapter defines five core process classes drawn from an OWL ontology fragment governing regulatory audits. Each class is projected to a relational table whose columns encode the axiom slots directly. The resulting schema supports joins that recover multi-hop facts such as “which classification process produced evidence for a dataset that later received findings.”

## 1. Axiom-to-Table Mapping

The five axioms are realized by five tables. Primary-key columns hold stable identifiers for process instances. Foreign-key columns enforce the existential restrictions stated in the axioms.

### 1.1 t_audit_basic

Axiom 1 states that every instance of the class is a bfo:0000015 (process). The table therefore contains only an identifier and a label for the process; no foreign keys are required.

| id | x |
|---|---|
| AB-001 | AnnualDataSubmissionAudit |
| AB-002 | QuarterlyReservesReview |
| AB-003 | AdHocDisclosureAudit |
| AB-004 | PostMergerDataReconciliation |

### 1.2 t_dataset_under_audit

Axiom 2 asserts that the class is both an artifact and the subject of an audit process. The table records each dataset instance; its identifier is referenced by later verification and findings tables.

| id | x |
|---|---|
| DS-101 | 2015OICExchangeFiling |
| DS-102 | PTACProductionReportQ3 |
| DS-103 | MarmaraStockExchangeAnnex |

### 1.3 t_verification_min_one_evidence

Axiom 3 requires every verification process to produce at least one evidence artifact. The foreign key y therefore references t_dataset_under_audit.id, guaranteeing the existential restriction.

| id | x | y |
|---|---|---|
| VE-201 | EvidenceCollectionRun1 | DS-101 |
| VE-202 | EvidenceCollectionRun2 | DS-102 |
| VE-203 | EvidenceCollectionRun3 | DS-103 |
| VE-204 | EvidenceCollectionRun4 | DS-105 |

### 1.4 t_classification_basic

Axiom 4 again treats the class as a bfo:0000015 process. The table is structurally identical to t_audit_basic and supplies classification labels used in downstream findings.

| id | x |
|---|---|
| CL-301 | SensitivityClassification |
| CL-302 | RetentionClassification |
| CL-303 | DisclosureClassification |
| CL-304 | IntegrityClassification |

### 1.5 t_audit_with_findings

Axiom 5 states that an audit process has findings about a dataset. The foreign key y again references t_dataset_under_audit.id.

| id | x | y |
|---|---|---|
| AF-401 | FindingsReport2015 | DS-101 |
| AF-402 | FindingsReportQ3 | DS-102 |
| AF-403 | FindingsReportAnnex | DS-103 |
| AF-404 | FindingsReportReserves | DS-105 |

## 2. Cross-Join Demonstration

To recover “the classification process and verification evidence linked to the same dataset that received findings,” join t_audit_with_findings to t_dataset_under_audit on y = id, then to t_verification_min_one_evidence on the same dataset identifier. The query path traverses two foreign-key columns.

Execution on the populated rows yields:

AF-401 | FindingsReport2015 | DS-101 | VE-201 | EvidenceCollectionRun1

The joined tuple shows that dataset DS-101 was verified by VE-201 and later received findings AF-401.
