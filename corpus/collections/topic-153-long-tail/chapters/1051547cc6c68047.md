# Chapter 4: Modeling Service Traces, Addresses and Ratings in Consultant Registries

This chapter presents three tables that instantiate the axioms trace_in_service, schemaorg_place_address and schemaorg_review_rating. The tables support primary-key and foreign-key navigation sufficient to answer multi-hop queries over consultant organisations, their service processes and associated address and rating entities.

## 1 Trace-in-service records

The table t_trace_in_service embodies axiom 1. Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_schemaorg_place_address. A reader can therefore start from any service trace and immediately locate the postal address that participates in the same service relation.

| id | x | y |
|----|---|---|
| tr-001 | Atkins Group | pa-010 |
| tr-002 | Babtie Group | pa-011 |
| tr-003 | Binnie and Partners | pa-012 |
| tr-004 | CARES | pa-013 |
| tr-005 | Delft Hydraulics | pa-014 |
| tr-006 | Dar al Handasah | pa-015 |

## 2 Postal-address records

The table t_schemaorg_place_address embodies axiom 2. Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_trace_in_service. The mutual foreign-key constraint between this table and t_trace_in_service permits direct verification that every address participates in at least one documented service trace.

| id | x | y |
|----|---|---|
| pa-010 | 1st Floor, Chadwick House, Warrington | tr-001 |
| pa-011 | 1st Floor, 40 Broadway, London | tr-002 |
| pa-012 | 2nd Floor, 20-22 Stukeley Street, London | tr-003 |
| pa-013 | 1 Northumberland Avenue, London | tr-004 |
| pa-014 | Rotterdamseweg 183c, Delft | tr-005 |
| pa-015 | 1st Floor, 11-15 Dix's Field, Exeter | tr-006 |

## 3 Review-rating records

The table t_schemaorg_review_rating embodies axiom 3. Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_trace_in_service. Each row therefore attaches a rating entity to a service trace without altering the address linkage already recorded for that trace.

| id | x | y |
|----|---|---|
| rr-100 | 4.2 | tr-001 |
| rr-101 | 3.8 | tr-002 |
| rr-102 | 4.5 | tr-003 |
| rr-103 | 3.9 | tr-004 |
| rr-104 | 4.1 | tr-005 |
| rr-105 | 4.0 | tr-006 |

## 4 Cross-table navigation example

A multi-hop query can be formed by joining t_trace_in_service to t_schemaorg_place_address on the mutual foreign keys and then to t_schemaorg_review_rating on the service-trace identifier. Consider the question: “What postal address and review rating are recorded for the service trace of Atkins Group?”  

Start with row tr-001 in t_trace_in_service (x = Atkins Group, y = pa-010). Follow y to row pa-010 in t_schemaorg_place_address (x = 1st Floor, Chadwick House, Warrington). Return to tr-001 and follow its id into t_schemaorg_review_rating to obtain row rr-100 (x = 4.2). The joined result is therefore the single tuple (Atkins Group, 1st Floor, Chadwick House, Warrington, 4.2).
