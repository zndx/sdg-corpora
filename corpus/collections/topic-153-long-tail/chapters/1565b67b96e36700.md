# Chapter 7: Traceable Service Relations in Artifact Registries

This chapter defines three interlinked tables that implement the axioms trace_in_service, schemaorg_place_address and schemaorg_review_rating. The tables record how engineering consultancies perform in-service processes at specific postal addresses and carry review ratings. All column values are drawn from the same controlled vocabulary of firm identifiers, address identifiers and rating identifiers used in the 2013 Benchmarking Working Group records.

## 1. Table t_trace_in_service

The table embodies axiom 1 (trace_in_service). Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_schemaorg_place_address, thereby linking each service trace to the place at which the service occurs. A reader can answer the two-hop question “which address is associated with service trace T1” by following the single foreign-key reference.

| id | x | y |
|----|---|---|
| TRC-001 | Atkins Group | ADR-014 |
| TRC-002 | Babtie Group | ADR-027 |
| TRC-003 | Binnie and Partners | ADR-014 |
| TRC-004 | CARES | ADR-031 |
| TRC-005 | Delft Hydraulics | ADR-027 |
| TRC-006 | Dar al Handasah | ADR-019 |

## 1.1 Table t_schemaorg_place_address

The table embodies axiom 2 (schemaorg_place_address). Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_trace_in_service, closing the reciprocal link required by the axiom pair. A reader can answer the two-hop question “which service trace references address A” by traversing the foreign key in the opposite direction.

| id | x | y |
|----|---|---|
| ADR-014 | 1 Friary, Temple Quay, Bristol BS1 6EA | TRC-001 |
| ADR-027 | 1 Park Road, Winchester SO22 6RR | TRC-002 |
| ADR-019 | 1 Knightsbridge Green, London SW1X 7NE | TRC-006 |
| ADR-031 | 100 Europa Blvd, Warrington WA5 7TN | TRC-004 |

## 1.2 Table t_schemaorg_review_rating

The table embodies axiom 3 (schemaorg_review_rating). Column id is the primary key. Column y is a foreign key that must resolve to an existing id in t_trace_in_service. The table therefore attaches a single rating instance to each service trace without duplicating address data.

| id | x | y |
|----|---|---|
| RAT-100 | 4 | TRC-001 |
| RAT-101 | 3 | TRC-002 |
| RAT-102 | 5 | TRC-003 |
| RAT-103 | 2 | TRC-004 |
| RAT-104 | 4 | TRC-005 |
| RAT-105 | 3 | TRC-006 |

## 2. Cross-table query example

Question: “What postal address and review rating are recorded for the service trace performed by Binnie and Partners?”

Step 1. Locate the trace row where x = “Binnie and Partners” (TRC-003).  
Step 2. Follow foreign key TRC-003.y to t_schemaorg_place_address row ADR-014, yielding address “1 Friary, Temple Quay, Bristol BS1 6EA”.  
Step 3. Follow foreign key TRC-003.id to t_schemaorg_review_rating row RAT-102, yielding rating value 5.

Joined result row:

TRC-003 | Binnie and Partners | ADR-014 | 1 Friary, Temple Quay, Bristol BS1 6EA | RAT-102 | 5
