# Chapter 4: Directive Governance Patterns in Regulatory Attestations

This chapter defines five core ontological templates for modeling attestations, requirements, and controls within governance processes. Each template is realized as a relational table whose columns correspond directly to the template slots. The tables share entity references through identifier values, enabling cross-table joins that reconstruct multi-hop governance facts such as “which control requires evidence for a given attestation period and signatory.”

## 1. Attestation with Supporting Evidence

Axiom 1 classifies an attestation as a process that is existentially linked to supporting evidence. Table t_attestation_with_supporting_evidence implements the axiom by storing the attestation class in column x and the evidence class in column y. Column id is the primary key; column y functions as a foreign-key reference to evidence entities that may appear in other tables.

```sql
CREATE TABLE t_attestation_with_supporting_evidence (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

Example rows:

| id | x | y |
| id_att_001 | HeadmistressLetter | Evidence_PupilRecords |
| id_att_002 | QuarterlyReport | Evidence_FinancialControls |
| id_att_003 | CourtBrief | Evidence_GuardianStatement |
| id_att_004 | Form10Q | Evidence_AuditWorkpapers |

## 1.1 Requirement Equivalent to Specification and Target

Axiom 2 states that a requirement is equivalent to a directive that specifies a target and applies to a subject. Table t_requirement_equiv_specifies_target materializes the three slots. Column id is the primary key; columns y and z are foreign-key references to specification and subject entities respectively.

```sql
CREATE TABLE t_requirement_equiv_specifies_target (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  z VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

Example rows:

| id | x | y | z |
| id_req_001 | TermStartRequirement | Specification_Activities | Subject_Parents |
| id_req_002 | FilingRequirement | Specification_Disclosures | Subject_Issuer |
| id_req_003 | AmicusRequirement | Specification_LegalBasis | Subject_District |

## 1.2 Attestation at Period

Axiom 3 restricts an attestation process to a defined attestation period. Table t_attestation_at_period records the period class in column y. Column id is the primary key; column y references period entities usable in join conditions.

```sql
CREATE TABLE t_attestation_at_period (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

Example rows:

| id | x | y |
| id_per_001 | HeadmistressLetter | Period_September2024 |
| id_per_002 | QuarterlyReport | Period_Q2_2020 |
| id_per_003 | CourtBrief | Period_AppealCycle |
| id_per_004 | Form10Q | Period_Q2_2020 |

## 2. Control with Evidence Requirement

Axiom 4 asserts that a control requires evidence. Table t_control_with_evidence_requirement stores the required evidence class in column y. Column id is the primary key; column y is a foreign-key reference to evidence entities.

```sql
CREATE TABLE t_control_with_evidence_requirement (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
);
```

Example rows:

| id | x | y |
| id_ctl_001 | AttendanceControl | Evidence_PupilRecords |
| id_ctl_002 | DisclosureControl | Evidence_AuditWorkpapers |
| id_ctl_003 | LegalControl | Evidence_GuardianStatement |
| id_ctl_004 | FinancialControl | Evidence_FinancialControls |

## 2.1 Attestation Signed By

Axiom 5 requires that an attestation process be signed by a person. Table t_attestation_signed_by records the attestation class in column x. Column id is the primary key; the implicit signatory is resolved through external person identifiers joined on x.

```sql
CREATE TABLE t_attestation_signed_by (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

Example rows:

| id | x |
| id_sig_001 | HeadmistressLetter |
| id_sig_002 | QuarterlyReport |
| id_sig_003 | CourtBrief |
| id_sig_004 | Form10Q |

## 3. Cross-Join Demonstration

To determine the evidence required by the control that governs the attestation signed for the September 2024 period, join t_attestation_at_period, t_attestation_signed_by, t_control_with_evidence_requirement, and t_attestation_with_supporting_evidence on shared x values:

- Start with id_per_001 (HeadmistressLetter, Period_September2024).
- Join to t_attestation_signed_by on x yields signatory linkage.
- Join to t_control_with_evidence_requirement on x yields Evidence_PupilRecords.
- Join to t_attestation_with_supporting_evidence on y confirms the same evidence class.

Resulting joined row: (HeadmistressLetter, Period_September2024, Evidence_PupilRecords, signed by Chloe Moon).
