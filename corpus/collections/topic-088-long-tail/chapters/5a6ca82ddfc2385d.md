# Directive Governance in Pension Scheme Compliance

This chapter presents five relational tables that implement core axioms of directive governance. The tables capture attestations, requirements, and controls as they arise in pension scheme administration, enabling verification of compliance statements through explicit evidence, periods, signatories, and targets.

## 1 Attestation and Evidence Linkage

The table t_attestation_with_supporting_evidence embodies AXIOM 1 by recording each attestation process together with its required supporting evidence class. Column id is the primary key; columns x and y hold class references that may be joined to identifiers in t_attestation_at_period and t_control_with_evidence_requirement.

| id     | x                                | y                                |
|--------|----------------------------------|----------------------------------|
| ATT001 | AnnualComplianceAttestation      | ActuarialValuationReport         |
| ATT002 | AnnualComplianceAttestation      | TrusteeMinutes2024Q1             |
| ATT003 | LifetimeAllowanceAttestation     | MemberDataExtract                |
| ATT004 | DisputeResolutionAttestation     | ComplaintsLog                    |
| ATT005 | LifetimeAllowanceAttestation     | HMRCValuationCertificate         |

## 1.1 Requirement Specification

The table t_requirement_equiv_specifies_target embodies AXIOM 2 by equating a directive class to the conjunction of specification and applicability relations. Column id is the primary key; columns y and z are foreign-key references to evidence and target classes that support multi-hop traversal to attestation rows.

| id     | x                                      | y                                | z                                |
|--------|----------------------------------------|----------------------------------|----------------------------------|
| REQ001 | LifetimeAllowanceRequirement           | ActuarialValuationReport         | PensionMember                    |
| REQ002 | DisputeHandlingRequirement             | ComplaintsLog                    | SchemeAdministrator              |
| REQ003 | CommunicationUpdateRequirement         | MemberDataExtract                | AdministratorStaff               |
| REQ004 | EvidenceRetentionRequirement           | HMRCValuationCertificate         | TrusteeBoard                     |

## 1.2 Temporal Attestation Constraint

The table t_attestation_at_period embodies AXIOM 3 by associating each attestation process with a defined attestation period class. Column id is the primary key; column y provides the period reference that can be joined with requirement and control tables to reconstruct compliance timelines.

| id     | x                                | y                                |
|--------|----------------------------------|----------------------------------|
| ATT001 | AnnualComplianceAttestation      | TaxYear2018                      |
| ATT002 | AnnualComplianceAttestation      | TaxYear2024                      |
| ATT003 | LifetimeAllowanceAttestation     | TaxYear2018                      |
| ATT004 | DisputeResolutionAttestation     | TaxYear2024                      |
| ATT005 | LifetimeAllowanceAttestation     | TaxYear2024                      |

## 2 Control Evidence Obligations

The table t_control_with_evidence_requirement embodies AXIOM 4 by stating that each control directive requires a specific evidence class. Column id is the primary key; column y is a foreign-key reference to evidence that appears in attestation rows, permitting verification of whether a control is satisfied.

| id     | x                                      | y                                |
|--------|----------------------------------------|----------------------------------|
| CTL001 | LifetimeAllowanceControl               | HMRCValuationCertificate         |
| CTL002 | DisputeHandlingControl                 | ComplaintsLog                    |
| CTL003 | CommunicationUpdateControl             | MemberDataExtract                |
| CTL004 | EvidenceRetentionControl               | TrusteeMinutes2024Q1             |
| CTL005 | LifetimeAllowanceControl               | ActuarialValuationReport         |

## 2.1 Signature Authority

The table t_attestation_signed_by embodies AXIOM 5 by recording the person responsible for signing each attestation. Column id is the primary key; column x references an attestation identifier that can be joined to the preceding four tables.

| id     | x                                |
|--------|----------------------------------|
| SIG001 | ATT001                           |
| SIG002 | ATT002                           |
| SIG003 | ATT003                           |
| SIG004 | ATT004                           |
| SIG005 | ATT005                           |

## 3 Cross-table Verification Example

To determine the evidence and signatory for the 2018 lifetime allowance attestation, first select the row ATT003 from t_attestation_with_supporting_evidence and t_attestation_at_period. Join on x = 'ATT003' to obtain y = 'HMRCValuationCertificate' and period 'TaxYear2018'. Then join t_attestation_signed_by on x = 'ATT003' to retrieve signatory SIG003. The resulting joined row is (ATT003, LifetimeAllowanceAttestation, HMRCValuationCertificate, TaxYear2018, SIG003), confirming that the attestation is supported by the required certificate, applies to the correct period, and carries an authorised signature.
