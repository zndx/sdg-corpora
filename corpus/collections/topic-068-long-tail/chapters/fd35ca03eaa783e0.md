# Directive Governance in HIPAA Compliance Systems

This chapter defines five relational tables that instantiate axioms for directive equivalence, HIPAA physical and administrative safeguards, verification processes, and attestation signing. The tables support cross-table joins that resolve multi-hop queries over requirements, safeguards, evidence, and signers.

## 1 Scope and Table Overview

The schema encodes five axioms drawn from an OWL ontology of directives and processes. Each table corresponds to one axiom. Primary keys are unique identifiers within each table. Foreign keys enforce the slot restrictions declared in the axioms and enable deterministic joins.

## 2 Tables

### 2.1 t_requirement_equiv_specifies_target

This table embodies axiom 1 by recording classes that are equivalent to DirectiveICE instances specifying a target class while applying to a safeguard class. Column id is the primary key. Column y is a foreign key to t_hipaa_safeguard_physical.id. A reader can join on y to retrieve the physical safeguard that satisfies a given requirement specification.

## 3 Cross-Join Example

To determine the administrative safeguard and verification process linked to requirement req-001, execute the following joins. First join t_requirement_equiv_specifies_target to t_hipaa_safeguard_physical on y = id, then join the result to t_verification_min_one_evidence on phy-101 = y. The resulting row is:

req-001, PhysicalAccessControl, phy-101, LockedServerRoom, ver-201, QuarterlyPhysicalAudit
