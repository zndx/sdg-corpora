# Chapter 12: Descriptive and Designative Information Content Entities in County Equipment Registries

This chapter defines three interlinked tables that record equipment locations, procedure designations, and descriptive specifications for county road maintenance assets. The tables implement the axioms schemaorg_place_address, lift_basic, and syscall_max_one_return, allowing cross-table queries that trace an artifact to its postal address, a designative procedure to its return type, and the shared descriptive entities that ground both.

## 1. Descriptive Information Content Entities

The table t_lift_basic embodies axiom 2. Each row is an instance of cco:DescriptiveICE. Column id is the primary key. Column x holds the literal content of the descriptive entity. These rows serve as targets for foreign-key references from the other two tables.

```sql
CREATE TABLE t_lift_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

## 1.1 Artifact–Address Relations

The table t_schemaorg_place_address embodies axiom 1. Each row states that an artifact (column x) possesses a postal address (column y). Column id is the primary key. Column y is a foreign key to t_lift_basic.id. A reader can join on y to retrieve the address literal for any listed artifact.

```sql
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_lift_basic(id)
);
```

## 1.2 Designative Procedures with Bounded Return Types

The table t_syscall_max_one_return embodies axiom 3. Each row states that a designative information content entity (column x) has at most one return type (column y). Column id is the primary key. Column y is a foreign key to t_lift_basic.id. The max-1 cardinality is enforced by the data pattern; each x appears with at most one y.

```sql
CREATE TABLE t_syscall_max_one_return (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_lift_basic(id)
);
```

| id     | x                    | y      |
|--------|----------------------|--------|
| sig01  | PreUse-Inspection    | desc03 |
| sig02  | Torque-Check         | desc04 |
| sig03  | Calibration-Verify   | desc06 |
| sig04  | Load-Test            | desc03 |
| sig05  | Alignment-Set        | desc04 |

## 2. Cross-Table Query Example

To determine the postal address of the artifact on which procedure “Torque-Check” was executed and the literal outcome type recorded, perform the following joins:

- Start at t_syscall_max_one_return where x = 'Torque-Check' (row sig02).  
- Follow y to t_lift_basic (desc04) to obtain the return-type literal “Outcome: Torque Value (Nm)”.  
- Separately follow an artifact address join: Grader-Unit-07 (addr01) references desc01, yielding address “4500 County Shop Rd, Ellensburg, WA 98926”.

The joined result row is therefore:

artifact = Grader-Unit-07, address = 4500 County Shop Rd, Ellensburg, WA 98926, procedure = Torque-Check, return_type = Outcome: Torque Value (Nm)
