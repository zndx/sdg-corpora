# Chapter 12: Descriptive and Designative Information Content Entities in Kernel Interface Specifications

This chapter defines three tables that record descriptive information content entities, designative information content entities, and artifacts that carry postal addresses. The tables implement the slot structures of the supplied axioms and support cross-table queries that recover return-type specifications for named system calls together with the physical location of their reference documentation.

## 1 Scope and table organisation

Section 1 presents the base table of descriptive information content entities. Section 2 presents the table of artifacts that possess postal addresses. Section 3 presents the table of designative information content entities restricted to a single return type. Section 4 demonstrates a multi-hop query that traverses the foreign-key references.

### 1.1 Base descriptive entities

Table t_lift_basic embodies AXIOM 2. Each row asserts that the value in column x is an instance of cco:DescriptiveICE. Column id is the primary key; column x holds the textual label of the entity. No foreign keys are present.

```
CREATE TABLE t_lift_basic (
  id VARCHAR(255),
  x VARCHAR(255),
  PRIMARY KEY (id)
);
```

| id          | x                          |
|-------------|----------------------------|
| L001        | SysReadDescription         |
| L002        | SysWriteDescription        |
| L003        | SysOpenDescription         |
| L004        | ReturnTypeInt              |
| L005        | ReturnTypeLong             |
| L006        | ManualLocationSeattle      |
| L007        | ManualLocationPortland     |

### 1.2 Artifacts carrying postal addresses

Table t_schemaorg_place_address embodies AXIOM 1. Each row asserts that the value in column x is a cco:Artifact that hasPostalAddress some value drawn from t_lift_basic. Column id is the primary key. Column y is a foreign key referencing t_lift_basic(id) and supplies the address descriptor.

```
CREATE TABLE t_schemaorg_place_address (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255) NOT NULL,
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_lift_basic(id)
);
```

| id          | x                          | y     |
|-------------|----------------------------|-------|
| A001        | PrintedKernelManualV4      | L006  |
| A002        | PrintedKernelManualV5      | L007  |
| A003        | ErrataSheetRead            | L006  |
| A004        | ErrataSheetWrite           | L007  |

### 1.3 Designative entities with return-type cardinality

Table t_syscall_max_one_return embodies AXIOM 3. Each row asserts that the value in column x is a cco:DesignativeICE that hasReturnType max 1 a value drawn from t_lift_basic. Column id is the primary key. Column y is a foreign key referencing t_lift_basic(id) and supplies the single permitted return type.

```
CREATE TABLE t_syscall_max_one_return (
  id VARCHAR(255),
  x VARCHAR(255),
  y VARCHAR(255),
  PRIMARY KEY (id),
  FOREIGN KEY (y) REFERENCES t_lift_basic(id)
);
```

| id          | x                          | y     |
|-------------|----------------------------|-------|
| S001        | SysReadDesignation         | L004  |
| S002        | SysWriteDesignation        | L004  |
| S003        | SysOpenDesignation         | L005  |
| S004        | SysCloseDesignation        | L004  |

## 2 Cross-table query example

A reader may obtain the return type of the system call whose documentation resides at the Seattle address by joining the three tables. The query path is:

t_syscall_max_one_return.y → t_lift_basic.id  
t_schemaorg_place_address.y → t_lift_basic.id

Execution yields the joined row:

S001 | SysReadDesignation | L004 | ReturnTypeInt | A001 | PrintedKernelManualV4 | L006 | ManualLocationSeattle

The result states that the designative entity SysReadDesignation carries return type ReturnTypeInt and that its reference artifact PrintedKernelManualV4 is located at ManualLocationSeattle.
