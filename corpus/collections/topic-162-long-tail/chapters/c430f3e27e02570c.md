# Chapter 12: Relational Encoding of Artifact Addresses and Information Content Entities in Kernel Interface Registries

This chapter specifies the relational projection of three ontology axioms governing descriptive and designative information content entities together with place-address relations. The resulting schema supports verification of address bindings and return-type constraints through primary-key and foreign-key joins.

## 1. Schema Construction Principles

The tables implement the axioms without extension or omission. Each table name corresponds directly to a template identifier. Column domains follow the declared slot types: entity references for classes and typed literals for data properties. Foreign-key columns enforce the existential and cardinality restrictions stated in the Manchester syntax forms.

## 2. Table Specifications

### 2.1 t_lift_basic

This table embodies Axiom 2. Column id is the primary key. Column x holds the identifier of each descriptive information content entity. No foreign keys are present.

```sql
SELECT id, x FROM t_lift_basic WHERE x = 'KernelBufferDescriptor';
```

| id    | x                        |
|-------|--------------------------|
| lb001 | KernelBufferDescriptor   |
| lb002 | ReturnValueType          |
| lb003 | AddressSpecification     |
| lb004 | ProcessContext           |
| lb005 | FileDescriptor           |
| lb006 | ErrorCode                |
| lb007 | MemoryRegionSize         |
| lb008 | SyscallIdentifier        |

### 2.2 t_schemaorg_place_address

This table embodies Axiom 1. Column id is the primary key. Column x references an artifact class. Column y is a foreign key to t_lift_basic.id and records the postal-address descriptor required by the subclass axiom.

```sql
SELECT p.x, b.x
FROM t_schemaorg_place_address p
JOIN t_lift_basic b ON p.y = b.id;
```

| id    | x                    | y     |
|-------|----------------------|-------|
| pa001 | VirtualMemoryRegion  | lb003 |
| pa002 | PhysicalAddressMap   | lb001 |
| pa003 | UserSpaceAllocation  | lb004 |
| pa004 | KernelStackLocation  | lb005 |
| pa005 | SharedMemorySegment  | lb007 |
| pa006 | DeviceRegisterBlock  | lb003 |

### 2.3 t_syscall_max_one_return

This table embodies Axiom 3. Column id is the primary key. Column x names a designative information content entity. Column y is an optional foreign key to t_lift_basic.id constrained to at most one value.

```sql
SELECT s.x, b.x
FROM t_syscall_max_one_return s
LEFT JOIN t_lift_basic b ON s.y = b.id;
```

| id    | x     | y     |
|-------|-------|-------|
| sc001 | read  | lb002 |
| sc002 | write | lb006 |
| sc003 | open  | lb005 |
| sc004 | close | lb002 |
| sc005 | mmap  | lb002 |
| sc006 | ioctl | lb006 |

## 3. Multi-Hop Query Example

Question: For the syscall whose return type is recorded under lb002 and whose associated address descriptor references lb003, retrieve the artifact class and the descriptive entity.

Execution path:  
1. Locate rows in t_syscall_max_one_return where y = 'lb002' (sc001, sc004, sc005).  
2. Join each result on y to t_lift_basic to confirm the return-type label.  
3. Join the corresponding address rows in t_schemaorg_place_address where y = 'lb003' (pa001, pa006).  
4. Cross-reference the artifact class in column x of t_schemaorg_place_address.

Resulting joined row:  
sc001 | read | lb002 | ReturnValueType | pa001 | VirtualMemoryRegion | lb003 | AddressSpecification

The same pattern extends to any combination of the three tables by following the declared foreign-key constraints.
